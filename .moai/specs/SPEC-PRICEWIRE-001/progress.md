## §F Phase 4 Mode Selection

**입력 파라미터**
- tier: L · 영향 단위: 게시 위젯 194 / 상품 193 · 도메인 수: 2(결정론 추출 스크립트 · webadmin 실화면)

- 병렬 이점: **LOW** — M0-1~M0-6 은 선후 의존(재추출 → 재집계 → worklist 재산출 → 배치 diff), M5 는 M0 산출 소비

**모드 평가**

| 모드 | 선택 | 사유 |
|---|---|---|
| `direct` | 미선택 | 타이핑 수정 아님. 스크립트 신규 작성 + 실행 + 집계 판정 포함 |
| `serial` | **선택** | 마일스톤 내 단계가 선후 의존이고 코드 중심(Anthropic coding-task 병렬성 유보) |
| `fanout` | 미선택 | 다도메인 리서치가 아님. 단계 간 의존으로 동시 실행 불가 |
| `sweep` | 미선택 | 균일 기계 변환 ≥30파일 조건 불충족(신규 러너 2개 + 상수 교체) |

**Decision: serial**

**정당화** — M0 6단계는 각각 앞 단계 산출을 입력으로 받는 사슬이라 동시 실행이 불가능하다. 성격은 코드 중심(Python 러너 작성·실행)이며, Anthropic 의 coding-task 병렬성 유보에 따라 순차가 안전 기본값이다. 지니가 **단계마다 확인**을 선택했으므로, M0 의 결정론 스크립트 단계는 오케스트레이터가 직접 실행한다 — 각 단계의 verbatim 출력 자체가 AC 증거이고(AC-PW-001/002/003/004/022), 서브에이전트에 위임하면 그 출력이 요약되어 증거성이 소실된다. serial 봉투 안에서 실행 주체만 오케스트레이터인 형태다. M5 스윕(게시 194 전수)은 실행 시점에 재평가한다.

**범위 결정(지니)**: 이번 세션 = M0 + M5 진단 스윕. M1~M4 는 `design.md §7` 이 저장 건마다 인간 승인을 [HARD] 로 요구하므로 이번 세션 대상 아님.
