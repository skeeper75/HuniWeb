## 2. 목표 모델 [HARD · 사용자 directive]

각 셋트 = **표지 + (내지) + 면지(1개)**. 면지색(화/블/그/[인쇄])은 **그 면지 멤버 내부에서 택1**.

1. **면지 멤버 1개 통합** — 빈 멤버 중 첫 1개(072=074·077=079·082=084·088=090)를 "…-면지"로 유지(리네이밍), 나머지 빈 멤버는 셋트에서 은퇴(`t_prd_product_sets.del_yn=Y`).
2. **자재를 면지 멤버로 이관** — 부모의 면지자재(USAGE.03: MAT_382/383/384[/385])를 면지 멤버 `prd_cd`에 적재. **이것이 색 택1의 실동작 수단** — 시뮬레이터/위젯 구성원 UI는 옵션그룹이 아니라 **구성원 자재 드롭다운(용지 select)**을 렌더하므로(`price_simulator.html renderInsts`·`_set_members_meta`), 자재 3~4종 = 화/블/그/[인쇄] 택1로 그대로 발현. 기본자재(dflt_yn=Y)=화이트.
3. **면지색 옵션그룹도 면지 멤버로 이관**(CPQ/주문 계층) — 부모 OPT_064~067(+옵션+아이템)을 면지 멤버로 이동(동일 코드 재사용, PK=prd_cd 스코프). **★fn_chk_opt_item_ref 트리거**: `OPT_REF_DIM.03` 옵션아이템은 참조 자재가 **같은 prd_cd(면지 멤버)에 실재**해야 함 → 반드시 [자재 이관] 후 [옵션 이관] 순서. (자재가 부모에만 있으면 트리거 위반.)
4. **부모의 면지색 옵션·면지자재 은퇴** — 이관 완료 후 부모(072~088)의 OPT_064~067 및 USAGE.03 면지자재를 논리삭제(del_yn=Y). 셋트공식 use_dims에 mat_cd 없음(§3) → 가격 무영향. **USAGE.07 자재는 미변경.**

### 옵션그룹 이관의 실효성 주의 (DEV-REQUEST 후보)
- 현 셋트 시뮬레이터는 **구성원 옵션그룹을 렌더하지 않는다**(`_set_members_meta`가 sizes/materials/print/page/plate만 동봉, opt_groups 미포함). 따라서 면지 멤버로 이관한 옵션그룹은 시뮬레이터에서 **휴면**(색 택1은 자재 드롭다운으로 발현). 위젯/주문 경로가 구성원 옵션그룹을 읽는지에 따라 실효 — **구성원 옵션그룹을 셋트 시뮬레이터/위젯 구성원 UI에 렌더**하려면 코드 보강 필요 → §6 DEV-REQUEST 후보. 옵션그룹 이관 자체는 mand=Y지만 evaluate_set_price가 제약을 참조하지 않아 **가격/계산 무손상**(휴면 descriptor).

## 4. ★배경설명 메커니즘 정정 (코드 실증 — 사용자 확인 요망)

배경: "min/max_cnt는 load-bearing — `price_simulator.html:624 memberMulti`가 max_cnt로 내지 수량입력창(=페이지 선택)을 띄워 내지 단가형과 물려 작동 중."

**코드 실측 결과 = 이 전제는 거짓이다:**
- `price_simulator.html:624` `memberMulti(m){ return m.max_cnt==null || m.max_cnt>1; }` → **line 699에서 "+ 추가"(멤버 인스턴스 복제) 버튼 표시 여부만** 제어. 페이지 입력과 무관.
- 내지 페이지 입력(line 692)은 **`m.is_inner`**(= role `SEMI_ROLE.01`) + **`m.page_rule`**(t_prd_product_page_rules)로 게이트. `max_cnt` 아님.
- **내지 284/285/286은 semi_role_cd가 비어있음**(SEMI_ROLE.01 아님) → 실 시뮬레이터에서 `is_inner=false` → 페이지 입력창이 **렌더되지 않고 "출력매수"(manual) 입력**만 뜬다. 이 manual 경로에서 내지 기여 = **0**(라이브 실측). ← 현재 라이브 골든 34,100/159,100/796,900이 셋트공식 단독인 이유.
- 참고: 내지에 semi_role.01을 부여(derived pages)하면 내지 페이지비가 실현되어 골든이 34,284/160,944/815,338로 **상승**(라이브 실측). 이는 §23-inner 승격(별개 트랙·별도 골든/승인 필요)이며 면지 재설계 스코프 아님.

→ 따라서 max_cnt는 페이지 가격과 **무관**하고, 내지 개수필드 정정은 페이지가격을 **깨지 않는다**(page_rule은 부모 072에 24/300/2로 별도 보유).

## 5. 내지 개수필드(min/max/incr) 정정 결정

- 현재: 내지 284 `min_cnt=24, max_cnt=300, cnt_incr=2` = **페이지수를 구성원 개수 필드에 오등록**. db_comment = `구성최소/최대개수`(구성원 개수 의미). 실 페이지수는 page_rule(부모 072: page_min24/page_max300/page_incr2)에 이미 보유.
- 정정안(의미 정합): 내지 `min_cnt=1, max_cnt=1, cnt_incr=NULL`(책당 내지 블록 정확히 1개). 효과: `memberMulti(284)=false` → 무의미한 "+ 내지 추가" 버튼 제거(UX 개선). **가격 무영향**(page_rule·manual 기여 0 불변 — §4 실증).
- **결정: 파일럿 apply.sql에는 미포함(스코프·무손상 우선).** 이유:
  1. 개수 정정만으론 내지 페이지가격 미실현(is_inner=false)이라 **반쪽 모델** — 진짜 정합은 내지 semi_role.01 부여(derived pages)와 **묶어야** 코히런트(그러면 골든이 34,100→34,284로 바뀌므로 별도 골든·승인 필요).
  2. 면지 파일럿의 골든 불변(34,100/159,100/796,900)을 크리스프하게 유지.
  → **§23-inner 트랙**으로 라우팅: [내지 semi_role.01 부여 + min/max/incr=1/1/NULL + page_rule 발현] 일괄 재설계(별도 골든·codex·게이트). 개수 정정 단독(가격중립)은 `apply.sql` 말미 **선택 블록(주석 처리)**으로 동봉해 인간이 택할 수 있게 함.
