# M4-27 전면 정정 — 「과소청구 20상품」은 오판이었다 (2026-08-29)

M4-28. 지니 교정으로 M4-27 을 다시 검증했고, **결론이 뒤집혔다.**
라이브 읽기 전용 (가격조회·설정조회·webadmin 화면) · 쓰기 0.

## 0. 지니 교정 — 세 가지

1. **「고객이 선택하지 않는다고 선택이 되지 않는 것이 아니다」** — 고객은 최소 옵션만 고르고,
   나머지 자재·공정은 내부에서 생산에 필요해 정해진다. 위젯이 안 보여주는 축이 있는 것은 정상이다.
2. **가격이 안 나오면 가격구성요소↔가격공식 매핑을 의심하라** — 위젯 축 부족은 원인이 아니다.
3. **상품뷰어는 실무진 담당이므로, 세팅되어 있으면 가격 빼고 모두 연결되어 있다는 뜻이다.**
   그리고 **가격공식·가격구성요소·가격뷰어 메뉴얼을 읽고 코드/DB/실화면과 매핑하라.**

## 1. 매뉴얼이 말하는 구조 (앱 내장 `admin-manual` / `tools/manual_content.py`)

상품뷰어 섹션이 무엇에 영향을 주는지 매뉴얼이 직접 적어 둔다.

| 섹션 | 영향 |
|---|---|
| 사이즈 | 위젯 사이즈 선택지 · **단가표 사이즈 차원 매칭** |
| 도수/인쇄옵션 | 위젯 인쇄옵션 선택지 · **인쇄비 단가 차원** |
| 판형 | **판수 환산 → 디지털/옵셋 인쇄비** |
| 자재 | 위젯 자재 선택지 · **용지비** |
| 공정 | 위젯 후가공 선택지 · **공정비** |

계산 흐름: `주문조건 → 차원 매칭 → 구성요소 단가 → 합산 → 할인 → 최종가`

## 2. 실화면 — 상품뷰어는 완비되어 있었다 (프리미엄엽서)

| 섹션 | 상태 |
|---|---|
| 사이즈 | 7종 |
| 도수/인쇄옵션 | 2종 (양면 기본 Y) |
| **판형** | `316x467`(`SIZ_000499`) · **적용 완제품 사이즈 = 빈값(공통)** · 기본판형 Y |
| 자재 | 22종 |
| **공정** | 7종 — **디지털인쇄 `PROC_000004` 필수공정여부 Y, 표시순서 −1** |
| 추가상품 7 · 제약규칙 7 | 세팅됨 |

두 가지가 M4-27 의 전제를 깼다.

- **판형의 「적용 완제품 사이즈(빈값=공통)」** — M4-27 이 `item_siz_cd` 빈 문자열을 이상하다고 본 것은
  **정상 설계**였다. 빈값이면 전 사이즈 공통이라 1행이 맞다.
- **디지털인쇄가 「필수공정 Y · 표시순서 −1」** — 고객에게 안 보이지만 반드시 적용되는 공정이다.

## 3. 가격 시뮬레이터 — 공정을 안 골라도 인쇄비가 붙는다

webadmin 가격 시뮬레이터에서 공정을 선택하지 않고 계산했다.

```
디지털인쇄비  6,000원
  매칭 차원:  판형사이즈 316x467 (SIZ_000499)
             인쇄옵션   양면 (POPT_000002)
             공정      디지털인쇄 (PROC_000004)   ← 자동으로 잡혔다
             수량(이상) 1 이상 구간
  매칭단가 6,000 × 판수 1 = 6,000원
  📄 판(plate) 단위 계산 — 주문 8장 ÷ 판걸이수 9 = 1판
```

**엔진은 필수공정을 자동으로 채운다.** 매핑은 정상이다.

## 4. 원인 — 내가 위젯 응답을 잘못 읽었다

코드가 계약을 명시한다.

- `catalog/models.py:701` — 「상품-공정의 `mand_proc_yn`(필수공정)과 같은 계약
  (**위젯이 항상 켠 채 '필수' 배지 + 클릭 차단**)」
- `catalog/price_views.py` — 공정 목록 조립기는 「**시뮬레이터·위젯 config·빌더 미리보기 공통 진입**」
- `catalog/widget_api.py api_widget` — 응답이 `{"ok", "widget", "meta"}` 이고
  **`meta` 는 `widget` 안이 아니라 최상위**다.

그래서 위젯 응답에는 공정이 **실려 있었다**:

```
meta.prod_dims: siz_cd(7) · print_opt_cd(2) · mat_cd(22) · proc_cd(7)
meta.prod_dims[proc_cd].options → {"v":"PROC_000004","t":"디지털인쇄","mand":true}
```

**M4-27 의 오류 세 겹**:

1. `cfg.items[].ref_key` 를 「위젯이 주는 축」으로 단정 — **`cfg` 는 레이아웃, `meta` 가 데이터**다
2. `meta` 를 `widget` 안에서 찾아 「없다」고 판단 — 실제로는 최상위
3. **DB 에서 역산**해 결론 — 매뉴얼·실화면을 보지 않았다

세 가지 모두 §G 함정표가 이미 경고한 형태(「실화면 건너뛰기」·「DB 만으로 판정」)다.

## 5. 재검증 — 위젯이 실제로 보내는 조합으로

`meta.prod_dims` 에서 기본값(또는 첫 옵션)을 고르고 **`mand:true` 공정을 반드시 포함**,
수량은 `meta.size_qty_rules`/`qty_rule` 을 따르게 해 게시 위젯 192개를 다시 호출했다.

```
판정: OK 174 · ERR 18 · ZERO 0 · NEGATIVE 0
```

**M4-27 이 「누락」이라 한 금액은 전부 정상 청구되고 있었다.**

| 상품 | M4-27 주장 | 실제 (meta 기반) |
|---|---|---|
| 미니접지카드 30장 | 212원 · 누락 12,900 | **13,112** = 디지털인쇄비 12,900 + 용지비 212 |
| 3단접지카드 8장 | 212원 · 누락 12,900 | **13,112** = 12,900 + 212 |
| 2단접지카드 8장 | 142원 · 누락 9,200 | **9,342** = 9,200 + 142 |
| 와이드 접지리플렛 2장 | 180원 · 누락 9,200 | **9,496** = 9,200 + 296 |
| 접지리플렛 2장 | 31원 (0.5%) | **6,031** = 6,000 + 31 |
| 프리미엄엽서 8장 | 71원 | **6,071** = 6,000 + 71 |
| 소량전단지 4장 | 31원 | **4,031** = 4,000 + 31 |
| 쿠폰/상품권 2종 | 31~113원 | **4,078 / 4,113** |

**과소청구는 없다. M4-27 의 결함 3종(A/B/C 중 이 건)은 철회한다.**

## 6. 남은 것 — 미판정 18건 (결함으로 부르지 않는다)

| 사유 | 건수 | 성격 |
|---|---:|---|
| 「페이지수를 입력하세요」 (캘린더 5종) | 5 | 페이지 축을 도구가 못 채움 |
| 「선택값에 매칭되는 구성요소가 없습니다」 (책자 6 · 포토카드 2 · 엽서북) | 9 | 내지/표지·묶음수 등 축 부족 |
| 최소 주문수량 미달 (떡메모지 · 미니보드스탠딩) | 2 | 수량 규칙 |
| 단가 미등록 (투명케이스 · 고무판 · 아크릴쉐이커) | 3 | **진짜 미적재 후보** |

앞의 15건은 **도구가 meta 만으로 조합을 완성하지 못한 것**이다. 결함이라 부르지 않는다.
뒤의 3건은 「사이즈 … 단가가 등록되지 않아 주문할 수 없습니다」로 미적재를 지목하지만,
축이 더 필요한 경우와 구분하지 않았으므로 **미판정**으로 남긴다.

**화이트인쇄엽서(`PRD_000020`)** 는 meta 기반에서도 용지비만 나왔다. 다만 이 상품은 디지털인쇄가 아니라
`PROC_000008 화이트인쇄`(필수)를 쓰고 위젯 meta 도 그것을 `mand` 로 잡는다. 별색인쇄비 구성요소가
`spot_side_cnt` 축을 더 요구하는데 도구가 못 채운 것으로 보인다 — **단정하지 않고 미판정**으로 남긴다.

## 7. 이 정정이 남기는 방법론

**가격 검증의 올바른 입력은 `meta.prod_dims` + `mand:true` 다.** DB 에서 조합을 지어내면
위젯이 실제로 보내는 것과 다른 조합을 만들게 되고, 그 결과를 결함으로 읽게 된다.

순서도 바뀐다: **매뉴얼 → 실화면(상품뷰어·가격뷰어·시뮬레이터) → 코드 → DB**.
DB 역산이 첫 단계가 되면 안 된다.
