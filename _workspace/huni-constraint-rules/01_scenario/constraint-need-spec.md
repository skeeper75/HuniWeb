> §31 Huni-Constraint-Rules · Phase 1 · hcr-scenario-curator(scenario-spec) · 2026-07-02
> 목적: **규칙을 쓰기 전에 "언제 제약규칙을 쓰는 게 맞는가"를 먼저 못박는다.**
> 규정 없이 쓴 규칙은 옵션그룹 오용과 같은 관리 곤란(그룹 폭발)을 재생산한다.

## 0. 경계 원칙 [HARD]

- **옵션그룹 = 무엇을 고를 수 있나(선택지 집합).**
- **제약규칙 = 고른 것들 사이의 조건부 관계.**
- 이 경계를 흐리면 조합별로 그룹을 복제하게 되어 **그룹 폭발 → 관리 붕괴**(이 하네스의 출발점).

## 1. 제약 그릇(계약) — 선행 확정 사실 (재발견 금지)

- 저장: `t_prd_product_constraints`(복합PK `prd_cd`+`rule_cd`).
  `rule_typ_cd`=**RULE_TYPE.01 호환** / **.02 금지(상호배제)** / **.03 필수동반**.
  `logic` JSONB(JSONLogic·panzi-json-logic)·`err_msg`·`use_yn`/`del_yn`·`disp_seq`.
  평가 = 활성규칙 `{"and":[...]}` 즉석 병합.
- **var 계약(VAR_KEY_MAP)**: `siz_cd`·`plt_siz_cd`·**`mat_cd__usage_cd`(결합키)**·`proc_cd`·
  `bdl_qty`(int)·`opt_id`(int)·`sub_prd_cd` + 옵션 배열 `sel_opt_grps`/`sel_opts`(in 비교) + 자유치수 `width`/`height`/`size_mode`.
- ★**강제 지점 한계[HARD]**: `evaluate_price`/`simulate`는 **제약을 전혀 안 본다**. 엇갈림 조합=0원을
  그대로 반환. 서버 강제는 SKU 저장 콜백 + `/validate/` Ajax뿐 — **위젯/주문 경로가 validate를 호출해야
  차단**된다(§6 위젯 계약에 포함 필요). [[constraint-builder-contract-demo-260702]]

## 2. CN 분류체계 (CN-1 ~ CN-6)

| 유형 | 정의 | RULE_TYPE | 근거 원천 | 유도 방식 |
|------|------|-----------|----------|----------|
| **CN-1** 물리·제조 불가 | 도메인상 만들 수 없는 조합 | .02 금지 | 권위 엑셀·인쇄 도메인 | 수동(근거 필수) |
| **CN-2** 단가행 부재 엇갈림 | 가격 격자 sparse — 팔 가격이 없는 조합 | .01/.03 | component_prices 실측 | ★단가행에서 자동 유도 가능 |
| **CN-3** 필수 동반 | X 선택 시 Y 필수 | .03 | 권위 엑셀·도메인 | 수동 |
| **CN-4** 상호 배제 | X·Y 동시 불가 | .02 | 권위 엑셀·도메인 | 수동 |
| **CN-5** 범위·증분 | 수량/치수 min·max·incr | .01/.02/.03 | 권위 엑셀·상품컬럼 | 수동 — 컬럼/옵션 정의에 이미 있으면 제약 금지(중복) |
| **CN-6** 옵션그룹 오용 이관 | 옵션그룹 분열로 조건부 관계를 흉내낸 사례 | 재설계 | 라이브 CPQ 실측 | 이관 설계(그룹 정규화+명시 제약) |

### CN-2 핵심 원칙 [HARD]
단가행 부재는 **자동 차단이 아니다.** `evaluate_price`는 매칭 실패 시 0원을 반환하고 제약을 안 보므로,
제약 없으면 **0원 견적이 그대로 노출**된다. → 팔 가격이 없는 조합은 제약(.03 필수동반 = 자재별 유효 사이즈만
허용)으로 **명시 차단**해야 한다. 129/130 데모가 이 유형의 전형.

## 3. 도구 결정 트리 [HARD]

```
조합 문제 발견
├─ ① 근본이 기초데이터 모델링 결함인가? (예: 자재명에 사이즈 내장 = 정규화 안 됨)
│     → 근본 교정은 별도 트랙(§7 dbmap / §12 basecode)으로 라우팅.
│       제약은 "증상 완화" 태그로 병기만(근본 아님).
├─ ② 모든 조합에서 그 선택지 자체가 무의미한가? (전 조합 공통)
│     → 옵션그룹/차원 정리(선택지 집합 축소). 제약 아님.
└─ ③ 조건부 관계인가? ("A를 고르면 B는 ~해야 한다")
      → 제약규칙. 옵션그룹으로 표현 금지(그룹 폭발=관리 곤란).
```

## 4. 이 프로젝트의 판례 (확정 사실 기반 판정 예시)

### 판례 P-1 — 129/130 자재↔사이즈 엇갈림 = CN-2 전형 [확정]
- **상품**: PRD_000129 폼보드 · PRD_000130 포맥스보드.
- **현상**: 자재명에 사이즈 내장(A3/A2 전용 mat)이라 `COMP_POSTER_*BOARD_BOARD`가 상품제공
  **mat4×siz2 = 8셀 중 4셀만 단가행 존재(50%)**. 나머지 대각선-밖 4셀은 견적 0원. [증거: verify_cn2b.py]
- **판정**: CN-2. RULE_TYPE.03 `R_DEMO_MATSIZ`(자재별 필수동반 사이즈, AND-4 implication)로 COMMIT됨.
- **도구트리**: ①이 근본(자재 모델링 미정규화) — **근본 교정은 §7/§12**, 제약은 증상 완화. ★단가행(mat×siz
  대각선)에서 **자동 유도 가능**(단가행 존재 조합만 허용 → 수동 drift 제거)이 개선 방향.

### 판례 P-2 — 오시·미싱 동시 불가 = CN-4, 그러나 두 그룹 자체는 정상 [확정]
- **상품**: PRD_000016 프리미엄엽서. '오시'(OPT-000005)·'미싱'(OPT-000006) = 각각 단일선택 옵션그룹.
- **판정**: 두 그룹을 **하나로 합치지 않은 것이 정상**(각자 독립 on/off 가능). "둘 다 on"만 불가 →
  RULE_TYPE.02 `R_DEMO_EXC`로 처리. **선택지=그룹 2개, 관계=제약 1개** — 경계 원칙의 정석 사례(레퍼런스).

### 판례 P-3 — 별색(spot color) 명명 분열 = CN-6 오용 [보드 이관]
- '화이트인쇄'·'클리어인쇄'·'핑크인쇄'·'화이트별색'·'클리어(별색)' 등 **같은 의미축(별색 인쇄)이 색상을
  그룹명에 박아** 상품·그룹마다 파편화. PRD_000020은 한 상품에 '클리어인쇄'+'화이트인쇄' 2그룹 동시 = 축 분열.
- **판정**: CN-6. 정규 '별색' 그룹 1개(색상=옵션항목) + 필요 시 명시 제약으로 이관. → `optiongroup-misuse-board.md`.

### 판례 P-4 — nonspec 자유치수 범위 = CN-5, 단 컬럼 중복 주의 [확정]
- PRD_000118·120·121·122·124·125·139 = `t_prd_products.nonspec_*_min/max` 컬럼 + RULE_TYPE.01 범위규칙
  **둘 다 존재**. 컬럼에 이미 있으면 제약은 **중복** — 그러나 evaluate_price가 컬럼을 강제하지 않으므로
  **UI/주문 차단용 규칙은 유효**(중복이 아닌 강제 계층). 범위규칙 미비 상품(19건)이 CN-5 실질 갭.

### 판례 P-5 — 아크릴 3D류 단가 TBD = CN-2 아님(단가 문제) [AMBIG·실무진]
- PRD_000165/168/169/170/226 = `PRF_ACRYL_*_TBD` dead_wire(단가/구성 확인필요). 견적 0.
- **판정**: 0원이지만 **해법은 단가 적재(실무진 답변)이지 제약이 아니다.** 제약으로 막으면 상품 자체가
  주문 불가가 됨. → **AMBIG, 사용자 컨펌 큐**(designer로 넘기지 않음). [§27 wiring round22 dead_wires]
