> 크기 차원을 쓰는 상품의 **권위(상품컬럼 nonspec_*_min/max = 상품마스터 260702)** ↔ **라이브 단가행 최대구간(상한 tier)** 정합을 검증한다.
> 불일치 시 위험: ① nonspec_max > 단가행 max tier → 상품이 허용하는 유효 크기가 **엔진 예상외 ERR_ABOVE_MAX로 차단**(매출 차단) ② 단가행 max tier > nonspec_max → 미도달 tier(무해·낭비).
> ★[HARD] 이 크기 범위는 **엔진이 이미 처리**(tier ceiling + 상한 차단) — 별도 t_prd_product_constraints 신설=중복·drift 위험(단가행 자동유도 원칙 위반).

## 0. 사상 요약 — 왜 크기 범위는 제약규칙이 아닌가

`evaluate_price`의 크기 차원(siz_width/siz_height)은 **구간 티어(TIER_DIMS)**로, 손님 크기를 담는 **가장 작은 구간으로 올림(ceiling)** 한다.
- 손님 크기 ≤ 최대 tier → 해당 tier 단가 적용(정상).
- 손님 크기 > 최대 tier → **ERR_ABOVE_MAX**(치명·계산 차단).
- 손님 크기 < 최소 tier → 최소 tier로 올림(무료 차단 없음·주문가드는 nonspec_min).

즉 **상한(max)은 엔진+단가행이 이미 강제**하고, **하한(min)은 nonspec 상품컬럼이 정의**한다. 따라서 크기 범위 제약규칙은
상품컬럼·엔진과 **삼중 중복**이다. 필요한 건 "권위 max ↔ 단가행 max tier 정합" 검증 + 위젯 UI 유효범위 배선(§6)뿐.
