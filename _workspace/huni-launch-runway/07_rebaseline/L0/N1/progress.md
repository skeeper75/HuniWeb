### ④ 미충족의 내용 — 무엇까지 했고 무엇이 남았나

**확정한 것**: 셋트 라벨 붕괴의 기전. 표지 구성원의 `procs[0]` 이 필수공정 `PROC_000004`(디지털인쇄)인데, 위젯 `summary` 배열의 **표지코팅·박가공·형압 세 항목이 각자 선택값 대신 그 필수공정을 공통으로 집어** 표시한다(`M1/customer-journey.md:238-244`, `M1/production-payload.md:123`). **UI 는 정상이고 붕괴는 `summary` 에서만 일어난다.**

**단정하지 않은 것**: 「셀러어드민에 디지털인쇄 3줄이 보인다」. 위젯의 **배열** `summary` 와 셀러어드민에 실리는 **문자열** `summary` 는 다른 값이고, 문자열 생성 규칙이 미확인이다.

**닫는 방법 두 가지** — 하나는 셀러어드민 주문 상세 1건 캡처(A-1), 다른 하나는 **승인 전에도 가능한** 셋트 상품 토큰으로 `POST /api/w/v1/cart/items` 1회 호출해 응답 문자열 `summary` 확인(E-4, 서버키 필요). **후자가 ④ 를 가장 싸게 닫는다.**

## 카드 명세 정정 [기록 · 후속 카드 주의]

**1. 재료 경로가 틀렸다.** 카드가 적은 `huni-skin-shopby/docs/api/`(28건)는 이 저장소에 **없다**. 실물은 위 §재료 경로 정정 표 참조. **N2·N3 가 같은 경로를 참조하면 같이 막힌다.**

**2. 고정 IP 는 웹훅 제약이 아니다.** 카드는 고정 IP 를 인바운드 웹훅 제약처럼 적었으나, 실제로는 **아웃바운드**(후니가 샵바이 server API 를 호출할 때) 제약이다(`workspace.mdx §Auth` — 장기토큰은 「앱에 등록된 IP에서만」). 인바운드 웹훅 URL 제약은 **미확인**이다. **N3 지도 v2 가 이 서술을 그대로 옮기면 틀린다.**

**3. SDK 가이드의 「상품준비중부터 즉시취소 불가」는 맞지만 상한이 열려 있다.** 취소요청이 가능한 구간은 **상품준비중·배송준비중 두 상태뿐**이고, 배송중부터는 취소 경로 자체가 없고 반품으로만 간다(`claim-order/cancel/condition.mdx`).

**4. 기존 43기능 분류표(`docs/shopby/admin-analysis/`)가 stale.** 생성일 2026-03-18 로 **10원×수량 확정(8/26)·텍스트 옵션 등록(8/27) 이전**이다. 3항목이 현행 계약과 충돌하고 일일 동선 핵심 화면 6종이 분모에서 빠져 있다(`selleradmin-ops.md` §6.1 A-1~A-6). **N2 가 분모를 다시 만들 때 입력으로 쓰면 안 된다.**

## 다음 카드로 넘기는 것

**테스트 시나리오 착수 가능 여부**: ★상태 머신이 나왔으므로 **착수 가능**하다. 다만 두 가지를 먼저 닫아야 시나리오 기대값이 확정된다 — **G-2 부분취소 허용 범위**(수량이 곧 금액이라 환불액 직결)와 **G-1 교환 가능 상태 충돌**.

**시나리오 검증 수단을 확보했다**: 샵바이가 항목마다 `nextActions`(15개 `nextActionType`)와 `cancelable`/`exchangeable`/`returnable`/`refundable` 플래그를 내려준다 → **기대값을 런타임으로 교차검증할 수 있다**(`shopby-order-state-machine.md` §5).

**N3 지도 v2 로 넘기는 확정 사실** — 「주문 이후」 절을 채울 재료:
- 주문상태 16 · 클레임상태 24 · 명시 전이 34
- **배송보류는 상태가 아니라 플래그**(`holdDelivery` bool, 상품준비중·배송준비중 위에 겹침, 상태변경/클레임 시 자동 해제)
- **주문 성립 후 옵션·수량 변경 API 부재 = ㉠플랫폼 불가**
- 결제승인 경계: 입금대기에서 이미 주문번호 발급 + **재고 차감** + 즉시취소 가능, 결제완료 전에는 상품준비중 진입·송장 입력·교환신청 불가
