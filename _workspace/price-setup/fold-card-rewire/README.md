# 접지비 카드 2단 은퇴 + 오시비 배선 (2026-08-30)

승인자: 지니 · 범위: **가격공식 · 가격구성요소 · 가격뷰어만** (위젯 제외)

---

## 1. 조사에서 드러난 것 — 배선을 추가할 게 아니라 잔재를 끄는 일이었다

지시는 「실제 가격구성요소의 차원을 확인해서 배선」이었다. `COMP_FOLD_CARD_2H`(접지비 카드
2단)에 판별축(`proc_cd`)을 채우려고 형제 구성요소를 대조하다가, **이미 이관이 끝나 있는 것을
발견**했다.

`COMP_FOLD_LEAF_HALF`(이름은 「접지비 리플렛 반접지」)의 144행 내역:

| 행 수 | 공정 | 비고 |
|---:|---|---|
| 48 | `PROC_000065` | 카드접지/2단가로접지 (권위 price-folding B01 · 2026-06-30 027/029 저청구교정) |
| 48 | `PROC_000066` | 카드접지/2단세로접지 (동일) |
| 48 | `PROC_000107` | 리플렛접지/반접지 |

즉 **카드접지 2단은 2026-06-30 에 공정 축과 함께 이관 완료**됐고, 접지카드 상품들은 그쪽에서
값을 받는다(`PRD_000027` 2단접지카드 실계산: `접지비 리플렛 반접지 · 공정=PROC_000066 · 800원`).

같은 이관을 한 **3단은 옛 구성요소를 끈 기록이 남아 있다**:

> `COMP_FOLD_CARD_3H` 비고 — `[use_yn=N 260702: 리플렛 COMP_FOLD_LEAF_3FOLD(단가 verbatim 동일)로 대체 운영·중복 은퇴]`

**2단만 끄는 것을 빠뜨렸다.** 그래서 `PRF_DGP_C` 에 남아 계속 붙고 있었다.

### 1.1 verbatim 동일성 실측 (3단이 근거로 삼은 것과 같은 검증)

백업한 `COMP_FOLD_CARD_2H` 48행과 `COMP_FOLD_LEAF_HALF` 의 해당 공정 행을 대조:

```
PROC_000065  행수 48 | 카드2단 행수 48 | 완전일치
PROC_000066  행수 48 | 카드2단 행수 48 | 완전일치
```

수량구간·금액이 모두 같다. 은퇴해도 잃는 값이 없다.

### 1.2 도메인 문서 §7.4 의 일부는 stale 이었다

`huni-product-lifecycle.md` §7.4 는 「2단·미니·3단접지카드 — 카드접지 구성요소 미배선,
800~1,100원 누락」이라고 기록한다. **이미 해소됐다**(위 실계산). 인용 전 재실측이 필요하다.

## 2. 무엇을 바꿨나

| # | 대상 | 변경 |
|---|---|---|
| A | 공식 `PRF_DGP_C` | 구성요소에서 `COMP_FOLD_CARD_2H`(접지비 카드 2단) **제거** |
| B | 구성요소 `COMP_FOLD_CARD_2H` | **`use_yn=N`** (3단 260702 처리와 동형) · 비고에 이력 기록 |
| C | 공식 `PRF_DGP_C` | 구성요소에 `COMP_PP_CREASE_1L`(오시비) **추가** (`disp_seq=2`) |

공식 비고에도 변경 이력을 남겼다. **단가 데이터는 하나도 지우지 않았다** — 구성요소는
비활성일 뿐 48행 그대로 살아 있다.

### 2.1 C 의 권위 근거

`COMP_PP_CREASE_1L` 오시비 — 공유 마스터(공식 3개 · 상품 11개 사용 중), 30행 전부
`PROC_000090`(오시), 공정그룹 오시:

| 줄수 | 고정금액 |
|---:|---:|
| 1줄 | 5,000 |
| 2줄 | 6,000 |
| 3줄 | 7,000 |

인쇄헤더택 `PRD_000045` 의 공정은 **오시 `PROC_000090`(필수 Y) · 상세입력 줄수 1~3줄** —
정확히 일치한다(상품뷰어 실측). 새 단가를 만들지 않고 기존 마스터를 배선했다.

## 3. 검증 — 실계산

| 상품 | 변경 전 | 변경 후 | 확인 |
|---|---:|---:|---|
| 인쇄배경지(일반형) `PRD_000043` | 6,356 | **5,756** | 접지비 600원 사라짐 (인쇄 5,600 + 용지 156) |
| 인쇄배경지(커팅형) `PRD_000044` | 6,356 | **5,756** | 동일 |
| 인쇄헤더택 `PRD_000045` (시뮬레이터) | — | **10,756** | 인쇄 5,600 + 용지 156 + **오시비 5,000**(1줄) |
| 인쇄헤더택 `PRD_000045` 줄수 2 | — | **11,756** | 오시비 **6,000** — 줄수 축 정상 작동 |

**판별축이 제 역할을 한다**: 오시비를 같은 공식에 붙였지만 오시 공정이 없는 `043`·`044` 에는
매칭되지 않는다(위 5,756원 그대로). 이것이 판별축 없는 구성요소와의 결정적 차이다.

## 4. 남은 사실 — 범위 밖

인쇄헤더택 `PRD_000045` 의 **위젯 화면은 아직 156원**(용지비만)이다.
가격 진단 「보낸 입력」의 `procs` 가 **`[]`** — 필수공정 디지털인쇄조차 실리지 않아
인쇄비와 오시비가 모두 매칭되지 않는다. 위젯 구성은 이 작업의 범위가 아니므로
**손대지 않았다.** 시뮬레이터에서는 정상 계산된다(§3).
