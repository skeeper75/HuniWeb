## 3. 이 숫자로 정리되는 것

- **44 를 쓰는 문서는 전부 낡았다.** 업무용 표는 그 뒤로 15개가 늘었다.
- **「120개」로 겁먹을 필요가 없다.** 101개는 백업이고, 지우는 것도 안전한지 따로 봐야 할 뿐 구조가 복잡한 게 아니다.
- **백업 101개는 그 자체로 정리 대상이다.** 다만 지우는 판단은 이 카드 밖이다 — X 트랙 `X-REPO-GITIGNORE-01` 계열과 성격이 같다(정리 대상 · 오픈 차단 아님).

## 4. 재현 방법

```bash
# 저장소 루트에서 (자격증명은 .env.local · 값은 어떤 파일에도 적지 않는다)
set -a && . ./.env.local; set +a
PGPASSWORD="$RAILWAY_DB_PASSWORD" psql -h "$RAILWAY_DB_HOST" -p "$RAILWAY_DB_PORT" \
  -U "$RAILWAY_DB_USER" -d "$RAILWAY_DB_NAME" -At -F'|' -c "
SELECT split_part(table_name,'_',1), count(*)
  FROM information_schema.tables
 WHERE table_schema='public' AND table_type='BASE TABLE'
 GROUP BY 1 ORDER BY 2 DESC;"
```

## 5. 미확인 (추정하지 않은 것)

- **백업 101개가 지워도 되는 것인지는 보지 않았다.** 이름만 세었고 내용·참조 여부는 확인하지 않았다.
- 뷰 2개가 무엇인지는 확인하지 않았다. 표 수 논쟁과 무관해서 범위 밖으로 뒀다.
- 이 실측은 **한 시점의 사진**이다. 적재 작업이 돌면 백업 수는 계속 늘어난다 — 업무용 59 가 기준값이다.
