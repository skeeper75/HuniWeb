# 후니프린팅 온톨로지 기반 AI 자동견적·주문 시스템 — 구현 로드맵 (분석/설계)

> 작성: 2026-07-04 · 산출 = "먼저 분석/설계하고 진행" 요청의 핵심 로드맵 문서.
> **[HARD] 이 문서는 로드맵까지다.** 새 코드/DB 적재 없음 — 기존 30여 하네스 산출을 종합해 현재 상태·단계·의존성·결정 대기를 정리한다.
> **경계 존중**: 가격·배정 **값**은 엔진 권위(evaluate_price·routing 엔진). 온톨로지/AI 에이전트는 오케스트레이션·호출까지(D-18·D-ROUTE).
> **architecture-neutral**: §33 통합 / 독립 §35 결정과 무관하게 재사용 가능.
> **정직**: 불명확·미착수는 GAP로 명시. 시간 추정 없음 — 우선순위(High/Medium/Low)·단계 순서만.
> 향후 §36 "시스템 구현" 하네스로 정식화 가능(현재는 로드맵까지·하네스 인프라 생성은 인간 확정 후).

## 0. 비전문가용 요약 (쉬운 말 1페이지)

**우리가 만들려는 것 한 줄**: 손님이 "카페 오픈용 고급 명함 500장 얼마?" 처럼 **평소 말로 물으면**, 컴퓨터가 알아듣고 → **알맞은 상품과 가격을 알려주고** → **주문까지 받고** → (나중에) **어느 인쇄소에 넘길지까지 정하는** 대화형 AI 시스템.

이 시스템을 **6개 층(레이어)**으로 나눠 보면 지금 어디까지 왔는지가 한눈에 보인다. 아래는 건물 짓기에 비유한 것이다.

| 층 | 쉬운 이름 | 비유 | 지금 상태 |
|---|---|---|---|
| ① 데이터 기반 | 재료 창고 정리 | 벽돌·시멘트 종류별 정리 | **진행 중** (거의 다 됨·일부 상품 가격 비었음) |
| ② 온톨로지 지식 | 재료 설명서·관계도 | "이 벽돌은 저 시멘트랑 쓴다" 지도 | **완료** (275개 상품 지식 그래프 완성) |
| ③ 질의 결합 | 질문 알아듣기 | 손님 말 → 지도에서 길 찾기 | **설계도 완성·아직 안 지음** |
| ④ 견적 엔진 | 가격 계산기 | 재료 넣으면 값 나옴 | **작동 중** (실화면 계산 확인됨) |
| ⑤ 주문 | 계산대·배송 | 장바구니→결제 | **설계 완성·구현 전** |
| ⑥ AI 에이전트 | 대화하는 점원 | 손님과 말로 주고받는 직원 | **미착수 (프론티어·최종 목표)** |

**핵심 메시지 3가지**:
1. **바닥(①②④)은 이미 튼튼하다.** 상품 지식 그래프와 가격 계산기는 실제로 돌아간다. 이건 "새로 만들 것"이 아니라 "이미 있어서 재사용할 것"이다.
2. **다음 결정적 한 걸음 = ③ 질의 결합을 실제로 짓는 것.** 지금은 설계도(query-simulator-spec)만 있다. 이걸 만들면 "말로 물어보면 그래프를 훑어서 답+가격을 내는" 데모가 처음으로 돌아간다. 이게 **크리티컬 패스**(제일 중요한 외길)다.
3. **⑥ 대화형 AI 점원은 맨 위층이다.** ③이 서고 나서 그 위에 얹는다. AI는 **직접 가격을 계산하지 않는다** — 계산기(④)와 그래프(②)를 **불러 쓰는 지휘자** 역할만 한다. (이 경계를 안 지키면 AI가 값을 지어내 손님에게 틀린 가격을 줄 위험이 있다.)

**전문용어 병기**: 온톨로지=상품 지식을 개념·관계로 적은 지도 / 그래프=그 지도의 컴퓨터 형태 / evaluate_price=가격 계산 함수 / RAG·GraphRAG=AI가 답하기 전에 그래프·문서를 찾아보고 답하게 하는 방식 / 라우팅=주문을 어느 인쇄소에 배정할지 정하는 것.

## 2. 단계별 구현 로드맵 (의존성 순서)

각 단계: 목표 · 선행 의존성 · 재사용 자산 · 산출물 · 완료 판정(무엇이 되면 다음). 순서는 의존성 기반이며 **시간 추정 없음**.

### Stage 0 — 데이터 기반 마감 (층 ①) · 우선순위 High · 진행 중
- **목표**: 우선순위 상품군의 미가격·미배선 셀을 채워 "견적가능" 커버리지를 목표선까지 끌어올림.
- **선행**: 없음(현재 진행 중). 권위=상품마스터+가격표 엑셀·webadmin 실화면.
- **재사용**: dbmap 적재 파이프라인·상시게이트·CPQ 레이어·evaluate_price.
- **산출물**: 라이브 COMMIT(인간 승인)·미가격 잔여 목록·`plate_wiring_integrity_check.sql` 결함0 유지.
- **완료 판정**: 대표 질의(Q1~Q10)에 걸리는 상품이 전부 PRICE≠0 + 판형 자동선택 실화면 확인. (전 283상품 100%가 아니라 **질의 커버리지 상품 우선** — Stage 2 파일럿을 막지 않는 선.)
- **주의**: Stage 2 파일럿(Q1 "고급 명함")에 필요한 명함류 가격만 서 있으면 Stage 2는 병렬 착수 가능. 전체 데이터 완성이 Stage 2의 hard 선행은 아님.

### Stage 1 — 질의 형식화 선행 (층 ②→③ 브릿지) · 우선순위 High
- **목표**: 산문/의사코드 상태의 nl-query-paths를 **실행 가능한 형식 쿼리**로 승격 + intent(용도) 원자 분해 키스톤 착수.
- **선행**: ② 온톨로지 KB(완료)·nl-query-paths ×3(존재).
- **재사용**: nl-query-paths(§33/§35/라우팅)·상위 온톨로지·TOVE식 CQ 테이블 패턴(structure-recommendations 개선-2)·tykimos N+ 승격 임계값(보완-T1).
- **산출물**: ① nl-query-paths → 4열 형식 CQ 테이블(동기 시나리오|비정형 CQ|형식 질의=재귀CTE/그래프탐색|통과판정) ② intent 원자 분해 파일럿(속성 우선·과분해 금지·badge=candidate·N+ 승격 규칙).
- **완료 판정**: Q1 하나가 형식 쿼리로 표현되고 그래프에서 순회 가능(수동 실행이라도). G-SIM-1 해소.
- **경계**: 여전히 값 계산 안 함 — 순회 경로만. intent 원자는 candidate로 두고 실 질의로 검증(생성≠검증).

### Stage 2 — 질의 결합 시뮬레이터 P1 파일럿 (층 ③) · 우선순위 High · ★크리티컬 패스
- **목표**: 한 질의(Q1 "고급 명함 후니vs와우")를 **종단 실행** — 용어 해석 → 경로 순회 → evaluate_price 호출 → 답 합성 → 시각화.
- **선행**: Stage 1(형식 쿼리)·Stage 0 부분(명함류 가격 적재)·④ 엔진(작동 중).
- **재사용**: query-simulator-spec 5단계 명세·nl-query-paths·§29 product_viewer/Cytoscape·evaluate_price 호출 어댑터.
- **신규(최소)**: ①경로 실행 엔진(경로→쿼리) ②순회 하이라이트 로직 ③엔진 호출 어댑터(경계).
- **산출물**: P1 종단 데모(1브랜드 최소)·순회 부분그래프 하이라이트·엔진 호출 지점 표시.
- **완료 판정**: Q1 자연어 입력 → 상품 추천 + 정확한 가격(엔진 결과) + 순회 경로 시각화가 한 번에 나옴. 가격은 evaluate_price 결과와 일치(자기 승인 금지·엔진 결과로만 검증).
- **왜 크리티컬**: 이 단계가 서면 "온톨로지→추천→가격"이 처음으로 실동한다. ⑥ AI 에이전트가 얹힐 토대이자, 시스템 북극성의 첫 실증.

### Stage 3 — 시뮬레이터 P2 확장 (층 ③) · 우선순위 Medium
- **목표**: Q1~Q10 브랜드-무관 질의 전체 + 시각화 다듬기(OntoAir 아이디어: 개체/클래스 구분·소스↔그래프 양방향 하이라이트).
- **선행**: Stage 2(P1).
- **재사용**: §35 상위 온톨로지·crossbrand `same_family_as`·시각화 자산.
- **산출물**: Q1~Q10 회귀검증 스위트(형식 CQ 통과판정)·브랜드 교차 답(왜 다른가)·단면 GAP 정직 노출.
- **완료 판정**: Q1~Q10 전건 형식 CQ 통과 + 못 하는 질의(N1~N6)는 정직 거절. self-refine 루프(질의 실패→보강 티켓→재검증) 명문화.

### Stage 4 — AI 에이전트 런타임 층 (층 ⑥) · 우선순위 Medium · ★프론티어
- **목표**: 대화형 에이전트가 시뮬레이터 파이프라인을 **툴로 호출**해 고객↔에이전트↔온톨로지↔견적 엔진을 잇는다.
- **선행**: Stage 2(시뮬레이터 실동·필수)·④ 엔진. Stage 3(다질의)는 강화이나 hard 선행 아님.
- **재사용**: 시뮬레이터 5단계(에이전트의 툴 셋)·evaluate_price·그래프.
- **산출물**: 대화 런타임(§4 설계 방향 참조)·툴 호출 계약·RAG/GraphRAG 접합.
- **완료 판정**: 고객이 멀티턴 대화로 질의를 좁혀가며 추천+가격을 받고, 에이전트가 값을 **지어내지 않고 엔진 호출로만** 답함(경계 준수 검증).

### Stage 5 — 주문 통합 (층 ⑤ 커머스) · 우선순위 Medium · Stage 2~4와 병렬 가능
- **목표**: 추천→가격 뒤에 장바구니→주문을 붙임(Shopby). 계산가 무손실 주입 해결.
- **선행**: ④ 엔진(가격 산출)·Shopby 설계(SB1~SB7 GO)·launch-scope(L1~L7). **핵심 난제 G1**(Shopby 카트 동적 계산가 직접 주입=스펙상 불가) 해소 방안 확정.
- **재사용**: Shopby 통합 설계·런칭 fit-gap·회원/프린트머니 마이그레이션 설계.
- **산출물**: 카트→주문 종단 구현·정산 권위·주문서 submit 경로.
- **완료 판정**: 견적형 가격이 무손실로 주문서에 실려 결제까지 감. 마이그레이션 안전장치(G3) 통과.
- **독립성**: 이 트랙은 ③/⑥(에이전트)과 독립. 병렬 진행 가능(웹 위젯 주문 흐름은 §6 위젯 하네스와 접합).

### Stage 6 — 인쇄소 라우팅 (층 ⑤ 이행) · 우선순위 Low · 데이터 GAP 블록
- **목표**: 주문을 어느 인쇄소에 넘길지(routing). 라우팅 스키마에 실 데이터 채움.
- **선행**: **공급자 레지스트리 확보**(외부·미도입 도메인·인간 결정) = G-ROUTE-1. 이게 없으면 전 노드 candidate.
- **재사용**: routing-layer-schema(E22~E25·RT-1~6·형 완성)·capability_covers(기존 생산 축 재사용·재발명 0).
- **산출물**: 공급자·능력 노드 실 앵커 승격·can_produce 포섭 매칭·routing_function 호출 어댑터.
- **완료 판정**: 주문 사양 ⊆ 공급자 능력 포섭으로 후보 필터 + routing 엔진이 최종 배정(값=엔진). 지금은 "추후" — 형만 열려 있음.

## 3. 핵심 의존성 · 병목 · 크리티컬 패스

### 크리티컬 패스 (북극성으로 가는 외길)
```
Stage 0(명함류 가격) ──┐
                       ├─→ Stage 2(시뮬레이터 P1) ─→ Stage 3(P2) ─→ Stage 4(AI 에이전트 ⑥)
Stage 1(질의 형식화) ──┘        ▲
                          (④ 견적 엔진 = 이미 작동·호출 대상)
```
- **크리티컬 노드 = Stage 2(시뮬레이터 P1).** 여기가 막히면 ⑥ AI 에이전트로 못 간다. Stage 0·1이 P1의 두 선행.
- **병렬 트랙**: Stage 5(주문 통합)는 위 외길과 독립 — ④만 있으면 착수 가능. Stage 6(라우팅)은 외부 데이터 대기라 별도.

### 주요 병목 (무엇이 무엇을 막나)
1. **G-SIM-1 (Stage 1) → Stage 2**: 시뮬레이터 순회 엔진은 nl-query-paths가 **실행 가능 형식 쿼리**여야 돈다. 현재 산문/의사코드 → 형식화가 P1의 선행 병목.
2. **intent 원자 분해 키스톤 (Stage 1) → 추천 정밀도**: 용어 해석 정밀도가 intent 원자 분해에 의존. 미완이면 "카페 오픈"류 용도 질의의 추천이 거칠다. 파일럿과 동시 진행 권장.
3. **Stage 0 가격 갭 → Stage 2 커버리지**: 질의에 걸리는 상품이 미가격이면 시뮬레이터가 엔진 호출 지점에서 GAP. 단, **전체가 아니라 파일럿 상품군만** 서 있으면 P1은 진행 가능.
4. **G1 (Shopby 동적 계산가 무손실 주입) → Stage 5**: Shopby 카트는 동적가격 직접 주입이 스펙상 불가 → 견적형 무손실 경로 미확정이 주문 통합의 1차 리스크.
5. **G-ROUTE-1 (공급자 레지스트리 부재) → Stage 6**: 라우팅은 실 공급자·능력 데이터가 0 → 스키마만 있고 전 노드 candidate. 외부 도메인·인간 결정 대기(하드 블록).
6. **④ 엔진은 병목 아님**: 이미 작동. 시뮬레이터·에이전트는 **호출만** 하면 됨(경계 D-18).

## 4. AI 에이전트 런타임 층(⑥) 설계 방향

> 프론티어 층. 아래는 **설계 방향**이며 구현 명세가 아니다(현재 로드맵까지).

### 접합 구조 (경계 존중)
```
고객(자연어)
   ↕  멀티턴 대화
[AI 에이전트 런타임]  ← 오케스트레이션·툴 호출까지 (값 생성 금지)
   ↓ 툴 호출
[질의 결합 시뮬레이터 5단계]  ← ③ Stage 2~3 산출을 툴로 노출
   ├─ ①용어 해석(intent 원자 분해)     → 그래프 노드 매핑
   ├─ ②경로 순회(nl-query-paths)        → ② 온톨로지 KB 읽기
   ├─ ③경계 호출 ────────────────────→ [④ evaluate_price] · [⑥ routing_function]  ← 값=엔진 권위
   ├─ ④답 합성(근거 노드 id·앵커 병기)
   └─ ⑤시각화(순회 부분그래프)
   ↓ 주문 확정
[⑤ Shopby 카트→주문] · (추후 [Stage 6 라우팅])
```

### 핵심 경계 원칙 [HARD]
- **에이전트는 값을 지어내지 않는다.** 가격 = evaluate_price 권위(D-18). 배정 = routing_function 권위(D-ROUTE). 에이전트는 **어느 툴을 언제 부를지**만 결정(오케스트레이션).
- **답에 근거 병기**: 온톨로지 스튜디오식 "[상품 product-037·공식 PRF_NAMECARD_FOIL]"처럼 근거 노드 id·앵커를 답에 붙임 → 환각 추적·감사 가능.
- **못 하는 질의는 정직 거절**(N1~N6·라우팅 N-R1~6). GAP를 지어내지 않음.

### 검색·툴 호출 패턴 (개략)
- **GraphRAG(결정론 우선)**: 임베딩·벡터스토어가 아니라 **결정론 그래프 순회(nl-query-paths 형식 쿼리)**를 1차 검색 경로로. 후니 283상품·1485노드 규모엔 임베딩이 과공학(structure-recommendations 수정-1). 임베딩은 **결정론 alias로 안 풀리는 표현의 NL 진입 fallback으로만** 보류(D3·초기 미채택).
- **툴 세트 = 시뮬레이터 5단계를 각각 함수로**: `resolve_terms`(용어→노드)·`traverse_paths`(경로 순회)·`call_price_engine`(evaluate_price 어댑터)·`synthesize_answer`·`visualize_subgraph`. 라우팅 확장 시 `call_routing_engine` 추가.
- **집계 질의 대응**: "명함류 흔한 후가공?"류는 community 요약 노드(family/category 파생·결정론·GraphRAG global) 재사용(structure-recommendations 확장-1).
- **confidence·reasoning-log**(tykimos 차용): 파생/추론 엣지에 confidence + 추론 이력 병기 → 추천 순위·"왜 이 후보" 설명 품질.
- **자기개선 루프**: 질의 실패(경로 안 그려짐)→보강 티켓→재검증(self-refine). 단 **자기 산출 자기 승인 금지** — refine 제안=생성, 채택=검증 게이트+인간.

### 참조 시스템 (아이디어만)
- uEngine Ontology Studio(질의→순회→답+경로 하이라이트 *행위* 채택·기질은 후니 경량 유지)·tykimos onto-osint(confidence·시간태깅·N+ 승격·경량 추론 규칙·config 브랜드 확장). **OntoAir 코드 재사용 불가**(연구용 비오픈·RDF/OWL 기질 기각) — 시각화 아이디어만.

## 6. GAP (정직 기록 · 미착수·불명확)

- **G-SIM-1**: nl-query-paths 형식 쿼리화 미완(산문→재귀CTE/그래프 순회). Stage 1 선행.
- **G-SIM-2/키스톤**: intent 원자 분해 미완(후니 편향 가능·와우/레드 용도 코퍼스 미보강). 추천 정밀도 직결.
- **G-SIM-3**: 시각화 자산(product_viewer·Cytoscape) 실제 재사용성 코드 확인 필요.
- **G-SIM-4**: 실 질의 품질·결합 정확성은 P1 구현 후에만 실측(명세까지).
- **G-DATA**: 미가격 잔여(굿즈 무가격5·프리미엄명함 견적0·아크릴 TBD4·폰케이스 준비단계·자재 price_gap 26/8상품). 실무진 단가/등록 대기.
- **G-ENGINE**: 미배선 공식 잔여(wire-batch·삼중/이중전무 상품군 CPQ+공식 신설). 엔진은 작동하나 일부 상품 배선 미완.
- **G1 (주문)**: Shopby 동적 계산가 무손실 주입 경로 미확정.
- **G-ROUTE-1 (라우팅·최대)**: 공급자·능력·라우팅 데이터 0. 전 노드 candidate. 외부 도메인 대기.
- **G-ARCH**: 교차 질의 엔진 실 성능(§33 단일 vs §35 조인) 구현 전 미측정.
- **G-AGENT**: ⑥ AI 에이전트 런타임 = 산출 0. Stage 2 완성 후 착수(설계 방향만 §4).
