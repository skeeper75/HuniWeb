## §B 결정 기록

### B-1. 인수 기준의 축 — **절차** [결정, 번복 시 SPEC 재작성]

「결함 N 건 해소」를 종료 조건의 주축으로 삼지 않는다. 그 형태의 AC 는
다음 세션이 소스 하나를 건너뛰고 새 결함을 만들어도 여전히 PASS 이기 때문이다.
주축은 `acceptance.md §A` — 상품마다 다섯 소스를 순서대로 소비하고 각 근거를 인용했는가.

### B-2. 분모의 소유자 — **상품뷰어** [결정, 지니 판정]

엑셀-존재/뷰어-부재는 결함이 아니다. 「미적재 4건」오판이 여기서 나왔다.
동시에 **가격 값의 소유자는 엑셀**이다. 존재 판정과 값 판정의 권한을 분리한다(spec.md §2.1·§2.2).

### B-3. 8/22 감사 — **소비하되 신뢰 범위를 제한** [결정]

194건 감사 결과를 우선순위 정렬 입력으로 쓴다. 다만 그 감사는 「0원 또는 산출 실패」만 본다 —
오늘 교정한 결함류(0 이 아닌 잘못된 값)는 검출 대상이 아니었다.
따라서 **「통과 88」을 값 정합의 근거로 쓰지 않는다**(AC-PC-020).

### B-4. 쓰기 경로 — **WebUI 단일** [결정, 지니 지시]

「절대 라이브DB로 쓰지말고 WebUI 를 통해서 하자」. 라이브 DB 는 분석용 읽기 전용.
저장은 건별 인간 승인. 이 결정이 마일스톤 크기를 결정한다 — 화면 조작은 병렬화되지 않으므로
마일스톤은 **한 세션에 편안히 들어가는 상품군 단위**로 자른다.

### B-5. 코드 결함의 출구 — **문서** [결정]

`raw/webadmin/**` 는 우리 소스가 아니다. 가드도, 화면 개선도 요청 문서로만 나간다(트랙 B).

## §C 상시 절차 — 새 세션이 이 절만 읽고 착수할 수 있어야 한다

### C-1. 상품 1건을 처리하는 순서

```
① 매뉴얼      manual_content.py / widget_manual_content.py 에서 해당 화면의 의미 확인
                 → 무엇을 보고 있는지 먼저 안다
② 상품뷰어    그 상품이 실제로 보유한 사이즈·자재·공정·옵션그룹을 실화면에서 확인
                 → 분모 확정. 여기 없는 것은 이 SPEC 의 대상이 아니다
③ 권위 엑셀   가격표(19시트) + 상품마스터(13시트, 「계산공식집초안」·「MAP」·「(가격포함)」5시트)
                 → 정답값 확정. 셀 좌표를 적는다
④ 코드+DB     pricing.py 의 계산 경로 + t_prc_* / t_prd_* 실측
                 → 배선이 ②③ 을 어떻게 계산하는지 교차검증. 질의에 자연키 전 컬럼 포함
⑤ 위젯        /sdk/demo/?wgt=<WGT_CD> → supply 를 ③ 의 값과 대조
                 → 종단 증거. total 이 아니라 supply
```

### C-2. 각 단계에서 기록할 것

| 소스 | 기록 필드 |
|---|---|
| ① | `파일:라인` |
| ② | 화면 경로 + 조회 일시 |
| ③ | 파일명 + 시트명 + 셀 좌표 |
| ④ | 테이블 + 컬럼 + 실행한 SELECT |
| ⑤ | `WGT_CD` + 조회 일시 + `supply` + 권위값 + 일치 여부 |

다섯 중 하나라도 비면 그 상품은 미판정이다(AC-PC-001).

### C-3. 착수 전 필독 (가정 세우기 전에)

- `.claude/rules/moai/domains/huni-pricing-engine-map.md` (§0.5 [HARD] 선참조 절차)
- `.claude/rules/moai/domains/huni-webadmin-manual-first.md` (도구 함정표 포함)
- `_workspace/webadmin-map/menu-map.md` (복합 PK 24종의 유일 편집 경로)
- `_workspace/pricing-principles/component-split-rule.md` (묶음/분리 판단)

### C-4. 저장 전 체크

1. 파급 범위(참조 상품 수) 확인 → 2 이상이면 승인 요청에 명시
2. 변경 전후 값 + 권위 근거 셀 제시 → 건별 인간 승인
3. 단가 그리드 저장이면 전후 행수 대조(줄어들면 되돌린다)
4. 저장 후 축 ④ 재확인

## §D 마일스톤

한 마일스톤 = 한 세션. 위험 순 정렬 — **게시 위젯이 있고 알려진 실패가 있는 상품군 먼저**.

### M0 — 기준선 (상품군 아님, 선행 필수)

- 게시 분모 실측(§6.1 SELECT) + 실측 일시 원장 기재
- 8/22 감사 결과를 상품군별로 분해해 M1~M9 우선순위 입력으로 배치
- `_workspace/postersign-audit/` 하네스를 상품군별 파서 규칙 확장 지점 식별(비교 로직은 공유)

현수막 · 배너 · 거치대 · 족자 · 행잉 · 포스터. **오늘 교정 3건이 전부 이 군**이고 알려진 실패가 가장 많다.

## §E 리스크

| 리스크 | 징후 | 완화 |
|---|---|---|
| 절차 게이트가 형식화 — 근거 필드를 채우되 실제로는 안 봄 | 근거가 모두 같은 셀/같은 라인을 가리킴 | 축 ④ 종단 대조가 실질 검사 역할. 불일치가 나오면 그 상품의 ①~③ 근거를 역추적 |
| 라이브가 세션 사이에 움직임 | 과거 문서 숫자와 실측이 어긋남 | 분모·상태는 매 세션 재실측(AC-PC-025). 문서 숫자 인용 금지 |
| 런타임 가드가 중복을 정상으로 보고 | `_price_gap_errors` 가족형 쌍 면제 | 축 ② 의 중복 그리드 구성요소 판정을 가드에 의존하지 않고 직접 수행 |
| 화면 마찰로 오조작 | 유사 구성요소명 · 코드 비표시 · `disp_seq` 빈 저장 | 저장 전 체크 4단계(§C-4) + 파급 명시. 마찰 자체는 트랙 B 로 |
| 원장 비대화(선행 SPEC 356 KB / 4,408줄 전례) | `progress.md` 800줄 초과 | 마일스톤 마감 시 즉시 세대 분리(REQ-PC-026) |
| 추가상품 `None` 5분 캐시로 교정 직후 값이 안 바뀜 | 저장했는데 위젯이 옛값 | 축 ④ 재확인 시 캐시 창을 감안(engine-map 참조) |
