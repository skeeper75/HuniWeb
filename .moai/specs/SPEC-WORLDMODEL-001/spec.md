## 1. 배경 — 확정된 문제 명제

가설 *"webadmin에 월드모델이 없다"* 는 **REFUTED**다. 행동→결과를 실행 없이 계산하는 결정론 함수가 최소 4개 실재한다 — `pricing.evaluate_price`(`raw/webadmin/webadmin/catalog/pricing.py:428-429`, `as_of`·`only_comps` 반사실 인자 보유), `price_views._sim_disallowed`(`raw/webadmin/webadmin/catalog/price_views.py:2701-2734`, 후보값 실대입 forward simulation), `fn_best_plate`/`fn_calc_pansu`(`raw/webadmin/sql/33_fn_best_plate.sql`·`sql/32_fn_calc_pansu.sql`), `cfg_utils.delete_usage`(`raw/webadmin/webadmin/catalog/cfg_utils.py:294-343`, 실행 전 영향 사전집계). 월드모델이 신경망 latent일 필요는 없고 SQL 함수·룩업 테이블도 전이함수다(`01_research/R2-world-model-theory.md:208`).

정확한 명제는 **PARTIALLY_CONFIRMED** — 월드모델이 **가격 단일축 · 커버리지 59.4%(`02_diagnosis/D8-live-schema.md:79`) · 비결합 · 무상태 · 계획 미사용** 상태다. 가설의 "계획에 쓰는"이라는 요건이 4지점에서 무너진다.

| # | 무너지는 요건 | 근거 |
|---|---|---|
| W-1 | 결과축이 가격 1개뿐 — 납기·수율·제작가능성 테이블이 라이브 46개 도메인 테이블에 0개 | `D8-live-schema.md:205`, `models.py:583-608` |
| W-2 | 가격 예측기와 가능성 예측기가 비결합 — 제약 위반 조합의 가격이 태연히 계산됨 | `02_diagnosis/D2-pricing-engine.md:290`(F12), `_workspace/huni-constraint-rules/CHANGELOG.md:7` |
| W-3 | 서버 완전 무상태 · 주문·견적 실체 테이블 부재 | `02_diagnosis/D3-widget-cascade.md:213-224`, `models.py:883-899` |
| W-4 | 뉴로 계층에 결과 예측·다중 후보 비교·이력 누적 계획 0건, `evaluate_price` 반사실 인자조차 도구 미노출 | `02_diagnosis/D4-neuro-layer.md:379-387`, `assistant_tools.py:281-282` |

즉 **"빠진 것은 모델이 아니라 루프"**(`R2:246`)이며, 적재 트랙에는 커밋 전 시뮬레이션이 이미 있고 **고객 견적 트랙에만 없다**(`R2:302`).

## 2. 범위 (Scope)

### 2.1 범위 안

**기존 webadmin 위에 지식계층을 추가한다.** 라이브에서 이미 돌고 있는 결정론 엔진 6종(`evaluate_price` · `_sim_disallowed` · `_price_gap_errors` · `tmpl_combo.resolve` · `qty_rule_error` · 판걸이수 룩업)을 **규칙 한 줄 쓰지 않고 import**해 하나의 부작용 없는 전이함수로 묶은 얇은 롤아웃 계층(`simcore`)을 `raw/webadmin` **바깥**(`_workspace/huni-simcore/`)에 얹는다. 그 위에서 고객이 옵션을 하나 고를 때마다 후보를 실행 없이 전부 굴려 비교 제시하는 MPC 루프를 돌리되, 재사용이 낳는 의무로서 루프가 딛고 선 전제(심볼 실재 · 차원 정의 일치 · 원천 신선도 · 전이함수 정확도)를 매 실행 기계 게이트로 계측한다.

## 3. 요구사항 (GEARS/EARS)

표기: **U**=상시(Ubiquitous) · **E**=사건구동(When) · **S**=상태구동(While) · **O**=선택(Where) · **X**=불가(If…then, unwanted behavior).

### 3.1 REQ-WM-001 계층 경계 (RULE-01·RULE-04)

> **검증**: AC-STR-02 · AC-AUT-02 · **AC-TR-01** — **(미커버 2건 — E-001.3 · U-001.5, 둘 다 (라) 범위 밖 · acceptance §H.3)**
- **U-001.1** simcore는 최종 금액의 권위를 `pricing.evaluate_price` 단일 함수로 유지하며, 반환값을 전재할 뿐 금액에 산술 연산을 하지 않는다.
- **U-001.2** simcore는 `raw/webadmin/**` 파일을 한 줄도 수정하지 않으며, 접합은 전부 import 또는 HTTP 호출이다.
- **E-001.3** LLM 계층(Actor·Explainer)이 출력을 낼 때, 그 출력의 도착지는 예외 없이 결정론 검증기(`IntentValidator` 또는 `RenderGuard`)여야 한다.
- **X-001.4** LLM이 금액·수량·코드값·가능여부를 직접 값으로 산출해 고객·주문 시스템에 도달하는 경로가 존재하면, 그것은 위반이며 배포를 차단한다.
- **U-001.5** 금액이 포함된 고객 대면 문장은 `PhraseRenderer`가 결정론 템플릿 치환으로 생성하며, LLM은 그 문장을 생성하지 않는다. Explainer 출력에 숫자 토큰이 포함되면 `RenderGuard`가 fail-closed 처리한다(N6 교정).

### 3.2 REQ-WM-002 Intent 스키마 — 뉴로→심볼릭 타입 경계 (RULE-02, FIX-1·FIX-2)

> **검증**: AC-M0-01 · AC-M0-02 · AC-M0-03 · AC-M0-12 · AC-AUT-03 · AC-STR-01 ⑫ · AC-G0 · AC-G0.5a — **(미커버 2건 — U-002.1 · U-002.2, 둘 다 (나) 구현 단계 · acceptance §H.3)**
- **U-002.1** 뉴로 계층이 심볼릭 계층으로 넘기는 산출물은 타입 있는 기호 자료구조 `Intent`이며, 자유 텍스트 전달은 금지된다.
- **U-002.2** 미확정 표현은 `UNKNOWN` 센티널 **단일**이다. 누락 · `None` · 빈문자열은 스키마 위반(=검증 실패)이다.
- **U-002.3** `Intent` 검증 지점은 `IntentValidator.validate()` **1곳**이며, 루프 진입 직전에 위치하고 실패 시 fail-closed(되묻기 라우팅)한다.
- **U-002.4 [FIX-1]** `selections` 값 도메인 출처는 blanket 1줄이 아니라 **축 부류별 3분류**로 선언한다.
  - **열거축 5** (`siz_cd`·`plt_siz_cd`·`mat_cd`·`proc_cd`·`bdl_qty`) → `price_views._sim_dim_candidates` 무수정 import (실제 처리 5축 확인: `price_views.py:2685-2691`, 그 외 축은 `:2692-2693`에서 무조건 `return []`)
  - **열거축 +1 `print_opt_cd`** → `t_prd_product_print_options(prd_cd=?, del_yn≠'Y')`의 `print_opt_cd` distinct. NULL 행 제외(`models.py:463` nullable) + 제외 건수를 G0에 카운트 기록(조용한 누락 금지). 라벨은 `print_side` 우선 → 마스터 `print_opt_nm` 폴백(`price_views.py:1832-1841` 계약 승계). `_dim_options`(`price_views.py:1775`) 내부 클로저와의 결과 집합 동일성은 G0.5a에 1항 추가해 기계 감시.
  - **비열거축 6** → `siz_width`·`siz_height`·`min_qty`는 `TIER_DIMS` 파생축(`pricing.py:52`)으로 표기하고 selections 키에서 제외 / `coat_side_cnt`·`spot_side_cnt`는 상품설정 파생 카운트로 표기 / `opt_cd`는 `opt_sels`와 중복이므로 selections 키에서 제외.
- **U-002.5 [FIX-1 부기 · 주장 1(C1) 판정 기록]** `print_opt_cd` 열거 로직은 라이브에 존재하나 `_dim_options`(`price_views.py:1775`) 내부 **중첩 클로저**라 import 불가하므로, **동등 SELECT 1개를 우리 층이 작성해야 한다**. 이 사실은 "조립 vs 신규작성" 판정 기록에 명시 기입한다.
  - 게이트 판정: **재배선**(비재사용 위치에 있던 기존 계약의 이식)이며 신규 도메인 규칙 작성이 아니다 — 값 집합·라벨 규칙·`del_yn` 필터가 전부 기존 계약의 복제이고 새 판단 규칙이 0건이기 때문이다(`gate-report.md:156`).

- **U-002.6 [FIX-2]** `Intent.provenance`에 `numeric_spans: {"qty": [int,int]|None, "budget_krw": [int,int]|None}`을 추가하며, **span 없는 수치는 스키마 위반**이다.

## 4. 설계 검증 거버넌스 (평가체계와 적대검증 규약)

> [HARD] 이 절은 부록이 아니라 본 SPEC의 **일급 요구사항**이다. 이 프로젝트가 반복해서 겪은 실패 — *"반대를 위한 반대로 잘 만든 설계가 무너진다"* — 를 구조적으로 막는 장치이기 때문이다. 이 절이 요구하는 산출물(루브릭 규칙 전문 · 각하 사유 기록 · 오판 감사 절)이 없는 검증 라운드의 판정은 **채택하지 않는다**.

### 4.1 [문제 정의] 근거 없는 적대검증의 3대 실패모드

반증자에게 공유된 기준 없이 공격만 시키면 세 가지가 동시에 일어난다(`evaluation-rubric.md:14-20`).

| # | 실패 | 결과 |
|---|---|---|
| ① **잣대의 즉석 생성** | 반증자가 공격 시점에 기준을 만든다 | 같은 설계가 반증자마다 다른 판정을 받는다 — 판정이 아니라 **판정자 교체**가 된다 |
| ② **입증책임의 비대칭** | 주장 측은 근거를 대야 하지만 반증 측은 "가능성"만 제기해도 이긴다 | 근거 없는 우려가 근거 있는 설계를 이긴다 |
| ③ **표면적 역선택** | 잘 만들어진 설계일수록 기술 분량이 많아 서술 표면적이 넓고 공격 지점이 많다 | **덜 쓴 설계가 이긴다** — 문서화를 처벌하는 인센티브 |

이 셋을 막는 방법은 하나뿐이다: 평가지표를 **설계를 보기 전에**, **심볼릭하게(명시적 규칙 집합으로)** 선언한다.

### 4.2 [해법 = 심볼릭 평가체계] 사전등록 루브릭

#### 4.2.1 사전등록(pre-registration) 사실과 그 이유

`evaluation-rubric.md`는 **작성 시점에 04_design의 설계안이 존재하지 않았고, 작성자가 어떤 설계안도 읽지 않은 상태**에서 작성되었다(`evaluation-rubric.md:4`). 입력은 `03_problem/problem-ledger.md`와 `01_research/R1·R2·R5·R6·R7`, `02_diagnosis/D7`뿐이었다.

**이유: 사후 선언된 기준은 결론을 역산할 수 있다.** 설계안을 본 뒤에 만든 규칙은 그 설계를 통과시키거나 떨어뜨리도록 조립될 수 있으며, 그 조립 여부는 외부에서 검증 불가능하다. 사전등록은 절차적 담보다 — 이후 루브릭을 수정하는 것은 금지되지 않으나, **설계안 제출 이후의 규칙 수정은 그 자체가 기록 대상**이다(개정 이력 의무, `evaluation-rubric.md:333-339`).

#### 4.2.2 왜 "심볼릭"인가

루브릭의 구조는 이 프로젝트가 도메인에 대해 내린 결론과 동일하다 — *"생성은 뉴로에 열어주되, 판정·산출·기록은 심볼릭이 독점한다"*(`R1-neurosymbolic-theory.md:103`), *"actions는 독립적으로 테스트할 수 있지만 instructions는 신뢰성 있게 테스트할 수 없다"*(`R7-agentic-commerce.md:29`). **설계 심사도 같은 구조를 받는다** — 심사자의 인상(instruction)이 아니라 규칙 적용(action)이 판정을 만든다. `violation_test`는 심사자가 **실행할 수 있는 절차**여야 하며, "느낌상 부족하다"는 규칙 위반의 근거가 될 수 없다(`evaluation-rubric.md:31`).

#### 4.2.3 규칙표 전문 (요약이 아니라 규칙 전문)

18개 규칙. BLOCKER 5개(27.8% — 상한 1/3 준수) · MAJOR 9 · MINOR 4.

**RULE-03 · 커밋 전 시뮬레이션 루프 · BLOCKER**

**RULE-18 · 층 귀속의 명시 · MINOR**
- **norm**: 모든 구성물을 neuro / symbolic / knowledge / worldmodel / ops **다섯 층 중 하나에 귀속시켜 표기**한다.
- **violation_test**: 구성물별 층 귀속 표가 없거나, 층 미표기 구성물이 1건 이상이면 위반.
- **source**: `problem-ledger.md:79-110`; `D7:145-150`

### 4.3 [반증 입증책임 규약]

#### 4.3.1 기본값 규정 [HARD]

> **근거가 불충분할 때의 기본값은 '반증 성립'이 아니라 '각하'다.**

반증은 **주장**이며, 주장하는 쪽이 입증책임을 진다. 이것은 설계 측을 편들기 위한 규정이 아니라 §4.1 ②(입증책임 비대칭)를 제거하기 위한 **대칭화 장치**다 — 설계가 근거를 대야 하듯 반증도 근거를 댄다. **"가능성"만으로는 반증이 성립하지 않는다** — "~할 수도 있다", "~가 우려된다", "~는 검증되지 않았을 수 있다"는 (b)(c)를 충족하지 않는 한 각하된다. 이는 이 프로젝트가 이미 자신에게 적용하는 규율과 같다(`verification-claim-integrity.md` §1.1 surface 3 — 텍스트 패턴 추론은 가설이지 검증된 결함이 아니다).

#### 4.3.2 심리 요건 5항 (전부 충족해야 심리)

| # | 요건 | 충족 기준 | 미충족 시 |
|---|---|---|---|
| **(a)** | **RULE-ID 지목** | 위반했다고 주장하는 규칙의 ID를 명시한다(복수 가능) | **각하** |
| **(b)** | **구체적 실패 시나리오** | 재현 가능한 형태로 입력(상품·옵션·수량) · 기대 결과 · 실제(예상) 결과를 쓴다 | **각하** |
| **(c)** | **원본 근거** | `파일경로:라인` 또는 WebFetch로 실재 확인한 URL 또는 선행 산출물 인용. 반증자의 일반 지식·경험은 근거가 아니다 | **각하** |
| **(d)** | **자기 반증조건** | "내 지적이 틀렸다면 무엇을 보면 알 수 있는가"를 밝힌다. 반증 불가능한 지적은 심리 대상이 아니다 | **각하** |
| **(e)** | **교정안(대안 부담)** | MAJOR 이상을 주장하면 교정 방향을 함께 제시한다 | **MINOR로 강등**(각하 아님) |

(e)만 강등인 이유: 대안을 못 내는 지적도 정보 가치가 있으나, 대안 없는 지적이 설계를 죽이게 두면 §4.1 ③(표면적 역선택)이 재발한다.

#### 4.3.3 자동 각하 사유 (요건 이전에 걸리는 것)

| # | 사유 |
|---|---|
| J-1 | **기각된 접근의 재제안** — N-01~N-19 / R1~R18 항목을 "설계가 이것을 안 해서 결함"이라 주장 (§4.3.4 relitigate 경로는 열려 있다) |
| J-2 | **이미 잘 되고 있는 것을 결함으로 제기** — N-20~N-30 |
| J-3 | **하네스 경계 밖 지적** — 다른 트랙(§7 dbmap 적재, §18 설계 등)이 소유한 작업을 이 설계가 안 했다는 지적 |
| J-4 | **원장이 [추정]/미확인으로 표시한 사항을 확정 결함으로 제기** |
| J-5 | **도메인 도구 없이 텍스트 패턴만으로 확정한 결함 주장** |

#### 4.3.4 relitigate 경로 (봉쇄가 아니라 통로)

기각된 접근을 뒤집으려는 반증은 자동 각하되지만, 다음 3항을 모두 갖추면 **별도 안건으로 심리**한다 — ① 기각 사유 원문을 인용한다(`파일경로:라인`) ② 그 사유가 **무효화되었음**을 새 증거로 보인다(측정값·라이브 실측·1차 출처) ③ 뒤집었을 때 영향받는 선행 자산을 열거한다. 3항을 못 갖추면 각하이며, **각하 자체는 §4.6 오판 감사 대상이 아니다**(각하는 판정이 아니라 요건 미달이므로).

### 4.4 [반박 라운드 의무] — 즉결 기각 금지 [HARD]

**모든 지적은 설계 측 반박 기회를 거친 뒤에만 판정된다.** 반박 없는 즉결 기각을 금지한다.

- 반증 제기 → **설계 측 반박 라운드**(설계 문서 내 해당 기술의 위치 제시 또는 교정안 제시) → 판정, 이 순서를 건너뛴 판정은 무효다.
- 설계 측이 **문서 내 해당 기술의 위치**를 제시해 `violation_test`를 통과시키면, 확정은 **취하**되고 그 반증은 §4.6의 **오판 1건**으로 집계된다.
- 설계 측이 문서를 **수정해서** 통과한 경우는 오판이 아니다(수정 전에는 실제 위반이었으므로).

### 4.5 [판정 등급] — 3분류와 승격 조건, 다수결 금지

| 등급 | 정의 | 효과 |
|---|---|---|
| **REJECT** | **BLOCKER 규칙 위반이 확정**됐다 | 설계 성립 불가. 해당 뼈대를 다시 세운다. 문서 부분 수정으로 통과시키지 않는다 |
| **AMEND** | MAJOR 위반이 확정됐고 BLOCKER 위반은 없다 | 설계 뼈대 유지. 지적된 규칙을 만족하도록 교정 후 **해당 규칙만 재심** |
| **NOTE** | MINOR 위반이거나, 위반은 아니나 기록할 위험이 있다 | 감수 위험으로 기록. 진행을 막지 않는다 |

**승격 조건**

| 승격 | 조건 |
|---|---|
| MINOR → MAJOR | 동일 근본원인의 MINOR 위반이 **3건 이상**이고, 반증이 그 셋을 하나의 구조적 원인으로 묶어 제시한 경우. 묶는 논증이 없으면 승격하지 않는다 |
| MAJOR → BLOCKER | 반증이 **교정 불가능성**을 논증한 경우 — 이 MAJOR를 고치려면 설계 뼈대를 바꿔야 함을 보인 경우. "심각하다"는 서술만으로는 승격하지 않는다 |
| NOTE → 상위 | 새 증거(라이브 실측·도메인 도구 출력)로 (b)(c)를 충족시킨 경우 |

**다수결 금지 [HARD]** — 등급은 규칙 위반의 **심각도와 근거**로 결정되며 반증 건수로 결정되지 않는다. MINOR 30건은 AMEND가 되지 않고 **MINOR 30건**이다. BLOCKER 1건은 나머지 17규칙을 모두 통과해도 REJECT다. 반증자 수·동의 수는 판정에 들어가지 않으며, 같은 위반을 3명이 지적해도 위반 1건이다(중복 병합).

**해석 분기 기록 의무** — `violation_test`의 기계 판정성은 균일하지 않다. 판단이 갈리면 다수결이 아니라 **규칙 문언 해석**으로 결정하며, 해석이 갈린 사실 자체를 기록에 남긴다.

### 4.6 [외부 독립 검증] — codex-cli 반증자 절차

#### 4.6.1 호출 규약

- 반증자: **codex-cli (gpt-5.5, `model_reasoning_effort=xhigh`, 읽기전용 샌드박스)**.
- 호출 헬퍼는 **재사용**한다 — `.claude/skills/hqv-codex-cross-verify/scripts/codex-review.sh`. 인자 규약: `codex-review.sh <prompt_file> [model] [workdir] [effort]`이며 `-s read-only`가 강제되어 codex는 파일을 쓰지 못한다(스크립트 헤더 주석 참조). 종료코드 `0`=성공 / `1`=프롬프트 없음 / `2`=codex 미가용(데드락·인증).
- 렌즈 분할: 최소 3렌즈(구조·실현 / 가격·돈 / 운영·자산). **각 렌즈에 어느 BLOCKER 규칙이 배정되는지를 라운드 시작 전에 표로 고정**하고, 미배정 규칙이 남으면 그 사실을 라운드 산출물에 기록한다(이번 라운드의 RULE-03 미검증 재발 방지).

#### 4.6.2 환각 가드 [HARD]

> **codex 출력은 확증 전까지 사실이 아니라 가설이다.**

- codex가 인용한 `파일경로:라인`은 **원본 재확인 의무** 대상이다. 게이트는 판정을 가르는 코드 사실을 직접 원본에서 재실측하고 그 목록을 산출물에 남긴다(이번 라운드 예: `gate-report.md:30-38`의 R-1~R-7 7건 재실측).
- 재확인되지 않은 codex 주장은 **미확정**으로 분리 표기하며, 사실로 승격하지 않는다.
- codex 주장이 원본과 어긋나면 그 건은 §4.6.4의 **FP-2(근거 오인용)**로 집계한다.

#### 4.6.3 reconcile 3분류

| 분류 | 정의 | 처리 |
|---|---|---|
| **합의** | codex ∧ Claude 양쪽이 같은 결함을 독립적으로 지적 | 중복 병합해 **1건**으로 센다(다수결 금지 — 합의는 등급을 올리지 않는다) |
| **불일치** | 한쪽만 지적 | 원본 재확인 결과로 **승격**(사실 인정) 또는 **미확정**(사실 승격 금지) |
| **미확정** | 양쪽 다 근거 부족 | 어느 쪽도 사실로 승격하지 않고 **미해결 항목으로 등재** |

#### 4.6.4 폴백 [HARD]

**codex 미가용(종료코드 2 — 인증 만료·모델 데드락) 시 Claude 단독 폴백으로 진행하고 멈추지 않는다.** 단 라운드 산출물에 `codex 가용 렌즈 N/3`을 명시하고, 미가용 렌즈는 "단일 판정자 라운드"로 표기해 다음 라운드의 재검증 대상에 올린다.

### 4.7 [오판 감사 의무] (false-positive audit) [HARD]

#### 4.7.1 왜 의무인가

검증자가 정당한 설계를 결함으로 오판한 건수를 집계하지 않으면, **검증은 판정이 아니라 판정자 교체가 된다** — 검증자가 무제한으로 틀려도 비용을 치르지 않으므로 "일단 다 걸고 본다"가 우세 전략이 되고 §4.1 ③(표면적 역선택)이 되살아난다. 근거는 이 프로젝트가 이미 채택한 실증이다 — 인수심사 에이전트가 **비판 에이전트 자신의 오탐률(12%)을 별도로 측정·공개**했고(`R7-agentic-commerce.md:45`) 전체 오탐 지표를 3.6%→1%로 관리했다(`:41`). **비판자도 측정 대상**이라는 것이 그 사례의 설계다.

#### 4.7.2 오판의 정의

| # | 유형 | 판정 시점 |
|---|---|---|
| FP-1 | 확정 위반으로 올렸으나, 설계 문서 내 해당 기술의 위치가 제시되어 `violation_test`를 통과한 경우(취하) | 취하 시점 |
| FP-2 | 근거로 인용한 `파일경로:라인`이 실제로 그 내용을 담고 있지 않은 경우 | 근거 확인 시점 |
| FP-3 | 실패 시나리오가 실제로 재현되지 않는 경우(도메인 도구·쿼리로 반례 확인) | 재현 시도 시점 |
| FP-4 | 위반이라 주장한 규칙의 `violation_test`를 적용하지 않고 **다른 기준**으로 판정한 경우 | 심리 시점 |

**오판이 아닌 것**: 자동 각하(요건 미달), 등급 강등((e) 미충족), 설계 측이 문서를 수정해서 통과한 경우.

#### 4.7.3 집계·기록 의무 [HARD]

모든 검증 라운드는 판정 기록에 다음을 반드시 포함한다.

```
오판 감사
  제기 총건: N
  심리:      P    (각하: Q)
  확정 위반: R
  오판:      S    (FP-1 .. FP-4 유형별 내역)
  정밀도:    R / P
```

- **정밀도가 기록되지 않은 검증 결과는 무효**로 취급하며, 그 라운드의 판정은 채택하지 않는다.
- 유형별 내역(어느 반증이 어느 FP 유형이었는지)을 반증 ID 단위로 남긴다.

#### 4.7.4 오판 누적의 효과 — 설계가 아니라 검증 프롬프트를 고친다

| 조건 | 효과 |
|---|---|
| 한 라운드 정밀도 < 0.5 | 그 라운드의 **BLOCKER 주장 전부 재심** — 다른 검증자 또는 다른 렌즈로 재판정 |
| 동일 검증자의 FP-2 2건 이상 | 그 검증자의 남은 반증 전건에 대해 근거 재확인 선행 |
| FP-3 발생 | 해당 반증을 각하로 전환하고, 재현 시도에 사용한 도구·쿼리를 기록 |

**[HARD] 오판률이 높으면 설계가 아니라 검증 프롬프트를 고친다.** FP-4(규칙 매핑 오류)가 오판의 다수를 차지하면 원인은 셋 중 하나이며 순서대로 검토한다 — ① **루브릭 커버리지 공백**(검증자가 실체 결함을 발견했으나 걸 규칙이 없어 가장 가까운 규칙을 억지로 걸었다) → 루브릭 개정 안건으로 등재 ② **검증 프롬프트의 등급 인플레이션**("어느 등급도 아닐 수 있다"는 선택지를 구조적으로 약하게 제시했다) → 프롬프트 교정 ③ **설계 품질**(위 둘로 설명되지 않는 잔여분).

### 4.9 재심 트리거 [HARD]

> **FIX-1 · FIX-2가 `design-FINAL.md`에 반영되지 않은 채 S1이 착수되면, 이 판정은 REJECT로 승격한다.** AMEND는 "고칠 것을 전제로 한 통과"이지 "안 고쳐도 되는 통과"가 아니다(`gate-report.md:366`).

이번 판정이 REJECT가 아닌 근거도 은폐하지 않고 기록한다 — RULE-02는 BLOCKER 규칙이고 A7이 그 `violation_test` ①을 직격했으므로 §4.5를 축자 적용하면 REJECT다. 게이트는 §4.2.3 BLOCKER 정의의 두 번째 절(*"고쳐 붙일 수 있는 결함이 아니라 구조가 틀렸다"*)을 **요건**으로 읽어 AMEND를 냈다 — (i) Intent 스키마 그릇이 제자리에 있고 (ii) 결손은 그릇 **안**의 필드 3부류 출처 선언 누락이며 (iii) 교정이 선언 3분류 + SELECT 1개 + 재파서 1개로 닫히기 때문이다(`gate-report.md:355-362`). **구조가 틀린 것이 아니라 구조가 미완결이다.**

[HARD] **[W-4 · 3차 정정] "해제"가 아니다.** 개정 전 이 표의 현재 상태 칸은 *"FEASIBLE — 해제"* 였으나, R3 재판정 §4.3 이 그것을 **한 칸 앞서 나간 표현**으로 판정했다. 정확한 상태는 다음과 같다 — **차단 요인 부재가 전수 실측으로 확인됐다(FEASIBLE). 그러나 AC-M0-10 이 요구하는 생성·폐기·대조·리플레이 각 1회의 실증은 아직 없다 — 리허설 1회가 남았고, 그때까지 P-1~P-4 는 미충족이다.** `acceptance.md:119` 의 기대가 *"'가능할 것이다'는 실증이 아니다"* 이므로 **FEASIBLE 은 그 기대를 충족하지 않는다.** plan.md 가 이미 *"리허설 1회가 남은 공백"* 이라 정확히 적은 것과 문장 강도를 일치시킨다. 리허설의 작업 단위는 **plan.md M1.0′ P-0**(신설)이다.

**근거 요지** — 라이브는 PostgreSQL **18.4** · `t_*` 46테이블 · DB 총 크기 **37 MB**(`g6-clone-feasibility.md:52-66` 직접 실측)이고, 무료·로컬·반복가능·라이브 무영향 경로(`pg_dump` → 로컬 `createdb`/`pg_restore` → 동일성 검사 → `dropdb`)가 열려 있다. 유일한 관문이었던 **로컬 PG18 부재**는 Homebrew `postgresql@18` 이 `stable 18.4` (bottled)로 **라이브와 major·minor 정확 일치**하므로 설치 한 줄로 해소된다(`:163`·`:171`·`:287`). 비용이 드는 경로(Railway PITR · 별도 인스턴스)가 **유일한 경로가 아니기 때문에** `FEASIBLE_WITH_COST` 가 아니다(`:285-287`).

[HARD] **미충족 시의 처방은 불변이다** — 리허설이 실패하면 G6·G10·G1.1 은 여전히 실행 불가이고, 그때의 처방은 임계 완화가 아니라 **주장 4의 반증 조건을 측정 없이 남겨 두는 것을 명시 기록**하는 것이며 G1 은 46테이블 전수로 되돌린다(§5 RK-13 · plan.md M1.0′ [처방]).

[HARD] **재심 트리거는 그대로 살아 있다** — FIX-1·FIX-2 가 문서에 반영됐어도 **구현 단계에서 이 선언과 어긋나면** 판정은 REJECT 로 승격한다(§4.9, `design-FINAL.md:1027`).

## 11. 자율성 경계 선언 (ESTC 3단 축)

### 11.0 왜 이 절이 필요한가 [HARD]

루브릭 18규칙에는 **자율성 스펙트럼 조율을 재는 규칙이 없다.** RULE-01은 판정권의 소재를, RULE-14는 사람 개입의 배치를, RULE-05는 종료 척도의 반증가능성을 재지만, **"이 설계가 자율성 스펙트럼의 어디에 서 있고 무엇이 충족되면 한 칸 올라갈 수 있는가"** 를 재는 규칙은 18개 중 어디에도 없다(§4.2.3 규칙 전문 전수 대조).

그래서 게이트는 이 축을 **한 번도 재지 않았고**, 설계가 이 축에서 강한 곳과 약한 곳이 **판정 기록 어디에도 남아 있지 않다.** 이 절이 그 공백을 메운다.

[HARD] 이 절은 부록이 아니라 **일급 요구사항**이다 — 없으면 나중에 "왜 자율 레벨을 못 올리는가"의 근거를 다시 만들어야 한다. 그리고 이 절은 **새 요구사항을 발명하지 않는다.** 이미 설계 문서에 있는 사실을 이 축으로 재조명해 기록하는 것이 범위 전부다.

### 11.1 원천 프레임 — 3단 구조

이주환 대표의 프레임을 **원문 인용 + 좌표**로 기록한다. 3단은 순서이자 의존이다 — ①이 있어야 ②가 안전하고, ③이 있어야 ②의 폭을 조절할 수 있다.

| 단 | 명제 | 원문 (좌표) |
|---|---|---|
| **①** | **사람이 세계(ESTC)를 선언한다** | *"모든 세계를 완벽하게 명세한다는게 사실 가능해요? 불가능해요? (…) 모든 것을 명세하지 않으면은 심볼릭 월드 모델은 못 만듭니다. 그래서 되게 작은 세계부터 만들기 시작해야 돼요."* — `R3:99`(F2:35). ESTC 4요소 정의는 `R3:313`(A-1) |
| **②** | **에이전트가 그 경계 안에서 자율 동작한다** | 경계 붕괴 경고 — *"리즈닝 트레이스에 문제가 하나도 없어요. 전부 다 논리적으로 완벽해요. (…) 추론이 기대어서 있는 세[계]가 잘못됐기 때문이에요. (…) 가장 위험한 경계 붕괴입니다."* — `R3:186`(F2:26~29) |
| **③** | **갭을 재서 자율 레벨을 조율한다** | 4단계 스펙트럼 — *"처음에는 룰베이스로 (…) 그다음에는 플로우 가이드 단계로 (…) 세 번째가 자율성이라는 스펙트럼을 내가 조율해서 세마이 어터노머스 레벨에서 (…) 마지막에 이제는 그 풀리 [어터노머스] 레벨로 넘어간다"* — `R3:104`(F4:56). 조율 신호는 갭 — *"갭이 경계 밖으로 나가면 자율모드를 낮추고"* — `R3:321`(A-9) |

[HARD] **원천의 한계를 함께 옮긴다.** 이 프레임의 출처 검증은 2차 자료 수준에서 멈춰 있다 — 두 권 **1,252쪽 원문을 대조하지 않았고**, ESTC의 구체적 스키마 정의와 월드 모델 캔버스의 실제 양식은 확인하지 못했으며, **ESTC의 학술적 신규성은 미판정**이다(`R4:162-167`). 다만 "그가 창시했다고 표기되는 것"의 범위 자체는 확인됐다 — 뉴로심볼릭·월드모델이 아니라 **ESTC 프레임워크와 월드 모델 캔버스**이며, "뉴로심볼릭 월드모델 창업자"는 틀린 압축이다(`R4:8`·`:39`·`:41`).

[HARD] **본 SPEC 은 이 프레임을 차용하되 그의 7단계 런타임 루프를 반영했다고 주장하지 않는다** — 원문 미확보이므로 대응 관계를 `[추정]`조차 하지 않는다(설계 §12-18 승계, `design-FINAL.md:878`·`:992`).

> 참고로 `R4:51`이 기록한 **에이전틱 AI 4대 조건**(① 상태 관리 ② 규칙 준수 ③ 감사 추적 ④ 오류 복구) 중 본 SPEC 이 그릇을 갖는 것은 ②(제약엔진)·③(RULE-11 anchor)·④(fail-closed 13지점)이고, **①(상태 관리)만 라이브 그릇이 없다**(§11.2 S 행). 이 비대칭이 §11.4 ③축 미충족의 뿌리다.

### 11.2 ESTC 4요소 × 후니 자산 — 그릇 유무와 편집 가능성

①축("사람이 세계를 선언한다")이 실제로 성립하려면 **그릇이 있고 사람이 그 그릇을 편집할 수 있어야** 한다. 두 조건을 분리해 잰다.

| 요소 | 후니 자산 | 그릇 실재 | **사람이 편집 가능한가** | 근거 |
|---|---|---|---|---|
| **E** (Entity) | 6축 기초데이터 (`t_prd_product_*` — 상품/자재/공정/사이즈/도수/인쇄옵션) | **있음 (라이브)** | **가능** — webadmin 편집 화면이 `admin.site.register` 루프로 `models.py` 선언 모델 전건에 자동 생성된다 | `R3:313`(A-1) · `design-FINAL.md:111`·`:872` |
| **C** (Constraint) | `t_prd_product_constraints` (JSONLogic) | **있음 (라이브)** | **가능** — 폼빌더 역파싱 가능한 정형 shape. 단 **34/288 = 11.8%만 채워져 있다** | `R3:313` · `design-FINAL.md:111` · `D8-live-schema.md:130` |
| **S** (State) | 견적 상태 (의도→후보→확정→발주) | **라이브 그릇 없음** — 서버 완전 무상태 · 주문·견적 실체 테이블 부재(W-3, P-01) | 해당 없음 — 본 설계는 **사이드카 원장**에 둔다(라이브 신설은 주문 트랙 침범 = RULE-15 ③) | §1 W-3 · `R3:313`("S/T는 현재 우리 스키마에 명시적 그릇이 없음 → 갭") · `design-FINAL.md:872` |
| **T** (Transition) | 상태 전이 전제조건 | **라이브 그릇 없음** — `JointTransition` **함수로 구현**((a)~(g) 호출 조립) | **불가** — 함수는 실무진 편집 표면이 아니다 | `design-FINAL.md:872` · plan.md M1.1 |

**요약: 4요소 중 사람이 편집할 수 있는 것은 E·C 둘뿐이고, 그중 C는 11.8%만 채워져 있다.**

### 11.3 T 를 함수로 구현한 딜레마 [HARD · 은폐 금지]

T의 그릇 선택은 **두 갈래가 모두 대가를 치르는** 문제다. 어느 쪽도 공짜가 아니라는 사실을 명시한다.

| 갈래 | 대가 | 근거 |
|---|---|---|
| **T를 선언 테이블로** (`t_wm_effects` 류) | 채울 **편집 화면이 없다.** webadmin 편집 화면은 `admin.site.register` 루프가 `models.py` 선언 모델만 순회해 생성하는데, `t_wm_*` 모델을 `models.py`에 추가하는 것은 A안 자신이 금지한 `raw/webadmin` 수정이다. **설계안 A가 정확히 이 사유로 확정 MAJOR**(RULE-12)를 받았다. 그리고 **제약 커버리지 11.8%가 "선언 비용이 지금까지 한 번도 지불된 적 없다"는 증거**다 | `design-FINAL.md:111` |
| **T를 함수로** (본 SPEC 의 선택) | **사람이 못 만진다.** 즉 T축에 한해 *"사람이 명세하는 세계"* 가 아니라 ***"개발자가 코딩하는 세계"*** 가 된다 | `design-FINAL.md:872` |

본 SPEC 은 **후자를 택했고** 그 근거는 `design-FINAL.md:872`다 — *"ESTC의 개념 축은 채택하되 테이블 4벌 신설은 채택하지 않는다."*

[HARD] **이 선택이 ①축의 절반 포기임을 인정한다.** E·C는 사람이 선언하고, S·T는 사람이 선언하지 않는다. 이것을 "설계가 ESTC를 채택했다"로 뭉개면 ①축 판정이 위조된다.

#### 11.4-a [② 축 정정 블록] 재심이 ②-1 에서 찾은 구멍과 그 복구 [HARD · 경위 보존]

[HARD] **이 블록은 "원래부터 강했다"로 고쳐 쓰지 않는다.** 판정이 한 번 흔들렸다가 교정된 기록이 남아야 나중에 같은 자리를 다시 점검할 수 있다.

**(i) 원 판정과 그 근거 — 보존.** 위 표의 ②축 판정은 **"충족(강함)"** 이었고, 그 **가장 강한 근거는 ②-1** 이었다 — *"`soft_prefs`(LLM 산출)가 Scorer ④ 가중치에만 들어가 LLM 은 순서에만 영향을 주고 ①가능성·②신뢰도·③도달성을 뒤집을 수 없다"*(`design-FINAL.md` §4.6). **이 명제 자체는 지금도 참이고 철회하지 않는다.**

**(ii) 재심이 찾은 구멍 — 명시.** 재심은 **정확히 그 지점**에서 결손을 찾았다. LLM 은 **순서를 뒤집지는 못하지만, ④ 안에서 존재하지 않는 축을 발명할 수 있었다** — `soft_prefs.axis` 가 **열린 `str`** 이어서 허용 축 집합이 어디에도 선언되지 않았고(`gate-rehearing.md:96`), 설계 자신의 워크스루가 쓰던 `axis:"mat_grade"` 는 12축 어디에도 없이 심볼릭 `Scorer ④`(`design-FINAL.md:488`)까지 도달했다(문서 전수 grep 결과 그 한 곳에서만 등장, `gate-rehearing.md:99`·`:343`).

  즉 ②축은 **"경계 안에서의 자율"** 인데 **경계 자체에 구멍이 하나 있었다.** 재심의 반박 검토도 이 점을 분리해 기록했다 — *"`soft_prefs` 는 Scorer ④ 에만 들어가 ①~③ 을 뒤집을 수 없다"* 는 반론은 **영향의 크기**를 말할 뿐 `violation_test` ① 이 묻는 **도메인 출처의 존재**를 답하지 않는다(`gate-rehearing.md:103`). 판정은 RULE-02 ① **STILL_OPEN · 효과 AMEND · S1 착수 전 필수**였다.

**(iii) R-02 교정 후 상태.** 화이트리스트 + fail-closed 로 그 구멍이 닫혔다 — `soft_prefs[].axis` 의 도메인은 **`PREF_AXES` 5축 닫힌 집합**(정의처 1곳, 원소는 전부 `DIM_META` 실재 축)이고, 미등록 축은 `IntentValidator.validate()` 에서 **되묻기로 fail-closed** 되어 Scorer 에 **도달조차 하지 못한다**(§3.2 U-002.9~X-002.11 · §3.8 U-008.1 ⑫). 따라서 ②축의 방어선은 이제 **두 겹**이다 — **(가) 위치**(`pref_score` 가 정렬 키 ④ 에만 존재) + **(나) 정의역**(축 어휘가 닫힌 화이트리스트). 교정 후 ②축 판정은 **충족(강함)으로 복원**되며, 복원의 근거는 ②-1 하나가 아니라 **②-1 + 정의역 폐쇄**다.

**(iv) 이 경위가 남기는 점검 지점.** ②축 판정은 *"LLM 기여의 위치"* 만으로는 완결되지 않는다 — **위치 + 정의역**을 함께 봐야 한다. 앞으로 뉴로 계층에 새 필드가 추가될 때마다 이 두 축을 같이 점검한다(§3.2 U-002.9 가 그 규약이다). 재심 자신도 이 해석(`violation_test` ① 을 "지적된 필드"가 아니라 "스키마 전 필드"로 읽는 것)을 **다음 라운드 재검증 대상**으로 올렸으므로(`gate-rehearing.md:434`), 이 항목은 확정된 해석이 아니라 **현재 채택된 해석**이다.

| # | 사유 |
|---|---|
| ③-1 | **측정이 자율 레벨을 조정하지 않는다.** G4(전이함수 정확도)·G7(비용)·G9(순증분)은 측정하지만, 임계 초과의 처방이 **"자율 다이얼 하향"이 아니라 "폐기"** 다 — G4 실패 = 전면 중단, G7 p95>2s = 고객 실시간 루프 폐기 후 관리자 도구로 강등, G9 (가)=(나) = 논지 부분 반증 기록(§7 게이트표 마지막 열 = "무엇을 버리는가"). `R3:321`이 말한 *"갭이 경계 밖으로 나가면 자율모드를 낮추고"* 의 **연속적 다이얼이 없다** — 본 설계의 처방은 이진(유지/폐기)이다 |
| ③-2 | **근본 원인 — 예측 vs 실제 갭 자체를 잴 수 없다.** 관측 채널이 구조적으로 얇아 관측이 O1(권위 엑셀)에 편중되고, `t_wgt_handoff_logs`는 현재 **0행**이다. *"고객이 실제로 무엇을 골랐고 그 주문이 어떻게 됐는가"가 원리적으로 들어오지 않는다* | `design-FINAL.md §11-1`(`:886-888`) · §5 RK-1 · `D8-live-schema.md:66-68` |

**즉 ③축은 "안 했다"가 아니라 "잴 재료가 없다"** — ①축 S 그릇 부재의 직접 귀결이다(§11.7).

### 11.5 현재 자율 레벨 선언 [HARD]

`R3:104`의 4단계 척도(룰베이스 → 플로우 가이드 → 세미 오토노머스 → 풀리 오토노머스)에서 **본 SPEC 이 구현하는 레벨을 단정한다.**

> **룰베이스 ~ 플로우 가이드 구간이며, 세미 오토노머스가 아니다.**

| 근거 | 왜 세미 오토노머스가 아닌가 |
|---|---|
| 자동 확정 경로 **부재** (②-2) | 세미 오토노머스는 *"자율성 스펙트럼을 조율해서"* 일부 결정을 에이전트에게 위임하는 단계인데, 본 설계는 위임 지점이 **0개**다 |
| 확정 = **인간 게이트 전용** (②-3) | 비가역 행위의 결정권이 전건 사람에게 있다 |
| LLM 판정권 **0** (②-4) | 뉴로 계층은 후보 제안·번역·설명만 하고 판정은 전부 결정론 엔진이다 |

[HARD] **그리고 이것은 결함이 아니라 의도적 선택이다.** 근거는 원천 프레임 자신의 경고다 — *"인쇄는 비가역이고 금액이 즉시 확정된다. 초기엔 **자동 확정 임계를 사실상 100%로** 두는 것이 안전"*(`R3:358`). 설계는 이 경고를 한 걸음 더 밀어 **임계를 두지 않고 경로 자체를 없앴다**(`design-FINAL.md:865` — *"루프는 자동 확정 경로가 아예 없다"*).

### 11.6 자율 레벨 상향 조건 [HARD]

세미 오토노머스로 올리려면 아래 (a)~**(e)** 가 **전건** 충족되어야 한다. 각 항은 기계로 확인 가능한 형태로 쓴다.

| # | 조건 | 확인 방법 (기계) | 현재 상태 |
|---|---|---|---|
| **(a)** | **③축이 성립할 것** — (i) 예측 vs 실제 갭을 실제로 **측정하는 경로가 존재**하고, (ii) 갭이 임계를 넘으면 자율 레벨이 **자동 하향되는 장치**가 있을 것 | (i) `sim_observation` 의 O2 채널에 실사용 유입 행 수 > 0 · (ii) 갭 임계 초과 시 레벨 하향을 수행하는 코드 경로가 실재하고 그 경로에 대한 게이트가 있을 것 | **미충족** — (i) `t_wgt_handoff_logs` 0행 · (ii) 하향 장치 0건(§11.4 ③-1) |

### 11.7 ①③ 이 열려 있는 이유 = 범위 선택의 직접 귀결 [HARD]

①축의 결손(S·T)과 ③축의 미충족은 **같은 원인에서 온다.** 셋 다 `raw/webadmin` 무수정 원칙과 충돌한다.

| 열린 항목 | 닫으려면 필요한 것 | 왜 지금 못 하는가 |
|---|---|---|
| **T 사람 편집** | webadmin 에 T 편집 화면(= `models.py` 모델 추가 + admin 등록) | `raw/webadmin/**` 수정 → **OS-1 · RULE-04 (c) 위반** |
| **S 그릇** | 라이브 `t_ord_*` 주문·견적 실체 테이블 신설 | 라이브 DDL · 테이블 신설 → **OS-2 위반**, 그리고 주문 트랙 소유 → **OS-4 · RULE-15 ③ 위반** |
| **갭 관측(③)** | 관측 결과를 쓸 수 있는 write 허용(또는 라이브 주문 데이터 읽기 경로) | 라이브 write 0건 고정 선언(§2.3) → **OS-2 위반** |

[HARD] **이것은 설계 역량의 문제가 아니라 범위 선택의 귀결이다.** 세 항목은 전부 "설계가 못 한 것"이 아니라 "설계가 하지 않기로 선언한 것"이며, 그 선언은 §2.2 범위 밖 표와 §2.3 고정 선언에 이미 기록되어 있다. 이 구분을 뭉개면 §4.3.3 J-3(하네스 경계 밖 지적)의 대상이 된다.

[HARD] **그리고 이 셋을 닫는 것은 경영 판단이며 본 SPEC 범위 밖이다.** webadmin 편집 화면 신설 · 라이브 `t_ord_*` 신설 · 관측 write 허용은 각각 다른 트랙(webadmin · 주문 · 위젯)의 소유이고, 셋 다 "라이브를 건드리지 않는다"는 전제를 바꾸는 결정이다. 본 SPEC 은 그 결정을 **요구하지 않고 기록만 한다.**

### 11.8 이 축이 재지 못하는 것 — 자기 한계

[HARD] **이 절 자체는 루브릭이 아니라 선언이다.** §4.2.3의 18규칙과 달리 이 절에는 `violation_test`가 없고, 따라서 **게이트가 이 축으로 판정한 적이 없다.** §11.4의 판정표는 게이트 판정이 아니라 **설계의 자기 서술**이며, RULE-10·RULE-18의 부분검증이 "설계의 자기 주장"이었던 것과 같은 지위다(§3.9 U-009.7).

이 공백을 닫는 경로는 하나뿐이다 — **루브릭에 이 축을 재는 규칙을 신설**하는 것. 그래서 §8 후속 안건에 **루브릭 개정안 ⑤(자율성 스펙트럼 축 신설)** 를 등재한다(FU-6). 본 SPEC 도 설계도 `evaluation-rubric.md` 를 수정할 권한이 없으므로(§4.8), 등재가 이 절이 할 수 있는 전부다.

또한 이 절은 다음을 **재지 못한다**:

| # | 못 재는 것 | 왜 |
|---|---|---|
| 1 | 현재 레벨 선언(§11.5)이 **구현과 일치하는가** | `simcore/*` 는 미래 산출물(§6 U-4). 지금 판정은 문서 문언 대조다 → plan.md M1 선행 확인 항목으로 이월 |
| 2 | 상향 조건 (a)~**(e)** 가 **충분조건인가** | 필요조건으로만 선언했다. 다섯을 다 채워도 안전하다는 논증은 하지 않았다. (e)[R-02 신설]도 마찬가지로 필요조건이며, 정의역이 닫혔다는 것이 LLM 기여 확대의 안전을 보증하지는 않는다 |
| 3 | 4단계 척도 자체의 **타당성** | `R3:104` 의 4단계는 원문 대조되지 않은 2차 자료 기반이다(`R4:162-167`) `[추정]` — 척도가 다르면 §11.5의 "룰베이스~플로우 가이드" 위치도 달라진다 |
