# 엽서북(PRD_000094) 부모-자식 가격공식 구조 판정 (2026-07-02)

사용자 질문(Q1): "부모-자식 가격공식이 제대로 매핑이 안 되어 가격이 안 나오는 것 아닌가? 공식을 자식(구성원)에 맞는 형태로 분리/개선해야 하는 것 아닌가?"

**한 줄 결론: 매핑 결함이 아니다.** 권위 가격표가 "책 1권 전체가(all-in)" 단일표이고, 라이브 공식·단가행이 그 표를 글자 그대로(verbatim) 담고 있으며, 엔진(evaluate_price)에 siz_cd만 넣어주면 정확히 450,000원이 나온다(A/B 실증). 화면 0원은 **시뮬레이터 화면 코드가 "셋트 공식 = 제본비만" 이라고 가정하고 사이즈 값을 서버로 안 보내는 코드 결함**(기지 R1-D3/R2-D1) 때문이다. 공식을 쪼개는 것은 권위에 분해 단가가 없어 **날조**가 되므로 불가.

라이브 읽기전용 준수: 본 판정의 모든 라이브 접근은 SELECT만. 쓰기 0건.

### 1-1. 가격표 형태 (인쇄상품 가격표 260527 · `엽서북떡메` 시트)

- 축: **사이즈 3종(100×150 / 150×100 / 135×135) × 인쇄(단면/양면) × 페이지(20P/30P) × 수량밴드(2 ~ 3,000부)** — 12열 × 39밴드.
- 값의 의미: **책 1권 전체 가격**(예: 2부 밴드 11,000원/권 → 100부 밴드 4,500원/권). 표지값·내지값·제본값을 따로 적은 칸은 **시트 어디에도 없음**.

## 3. 엔진 계약 — 파일:라인 근거

1. **엔진 자체는 셋트 공식에 siz_cd를 받을 수 있다**: `pricing.py:920-921`(evaluate_set_price 내) — 셋트 완제품 공식은 `evaluate_price(set_prd_cd, set_selections, copies)`로 평가. set_selections에 siz_cd가 들어오면 그대로 차원 매칭(주입 실증 450,000). 엔진은 무결.
2. **화면(프론트)이 siz_cd를 안 실음**: `price_simulator.html:635` `others=dims.filter(d=>d.name!=="proc_cd"&&d.name!=="siz_cd")` — 셋트 조건 UI에서 사이즈 콤보 미생성. `:722` `if(d.name==="proc_cd"||d.name==="siz_cd") continue;` — 전송 조립에서도 skip. 참고로 **단일상품 경로 `:452`는 siz_cd를 정상 수집** — 셋트 경로만 "셋트공식=제본/조립(공정)" 가정으로 걸러냄.
3. **서버도 백필하지 않음**: `price_views.py:1987-1988` — set_selections는 body를 그대로 통과(빈값 제거만). `:1929-1933`의 화이트리스트 복사 `("siz_cd","mat_cd","print_opt_cd")`는 **member.selections에만** 넣지 set_selections에는 안 넣음.
4. **member 레벨은 opt_cd(20P/30P)를 못 받는다**: 같은 `:1930` 화이트리스트에 `opt_cd` 없음 + 셋트 구성원 UI 페이로드(`price_simulator.html:742` — siz/mat/print_opt/pages/plate뿐)에 opt_cd 수집 자체가 없음 + `_set_members_meta(:1685~)`는 구성원의 sizes/materials/print_opts만 내려줌(옵션 미포함). → **"공식을 내지 member로 재바인딩" 대안은 코드 수정 없이는 성립 불가**(PRF_PCB_FIXED의 use_dims에 opt_cd·opt_grp:OPT_000082 포함).
   - 추가 함정: 내지 member는 derived 수량(총내지매수, 예: 100부→300장, `price_views.py:1961-1966`)으로 평가되므로 "권당 단가 × 300장" = 1,350,000 같은 **수량 축 자체가 어긋나는** 오계산 위험도 있음(권당가는 부수 축).

## 5. 최종 판정

- **isMappingDefect = false.** 부모-자식 가격공식 매핑은 권위 그대로다: 권위가 "권당 완제품가 단일표"이므로 부모(완제품) 공식 하나에 all-in으로 담는 현행 설계가 **유일하게 권위 정합적인 형태**다. 구성원 095/096에 공식이 없는 것도 결함이 아니라 이중합산 방지상 올바른 상태(R2-D2 확정과 동일).
- 0원의 진짜 원인은 이미 확정된 **R1-D3/R2-D1 코드 결함**: 시뮬레이터 셋트 경로가 "셋트 공식=제본비만(068/072 패턴)"을 전제로 siz_cd를 UI·전송에서 걸러내고(:635/:722), 서버도 백필하지 않음(:1987). 데이터·엔진·단가행은 전 층 건강(주입 시 450,000 verbatim).
- 권고: **(a) 현행 구조 유지 + 개발팀 위임(C트랙)** — `price_views.py price_simulate_set(:1987 부근)`에서 부모 현재공식 use_dims가 siz_cd를 요구하고 set_selections에 없으면 내지(SEMI_ROLE.01) member의 siz_cd를 백필(서버측 1점 수정·기존 068/072 동작에 무영향: 그들 공식은 siz_cd 미요구라 백필 자체가 발동 안 함). 검수 기대값: UI 동일 입력(100부·100×150·단면·20P) → final=450,000.
- 공식 분리/개선/확장은 **하지 말 것** — (b)는 코드 수정 없인 막히고(:1930 화이트리스트), (c)는 권위에 없는 단가를 만드는 날조, (d)는 모델 왜곡. 코드 1점 백필이 가장 작고 안전한 착지.
