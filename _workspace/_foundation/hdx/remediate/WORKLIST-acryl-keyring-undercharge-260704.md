## 무엇이 끊겼나

**아크릴키링(PRD_000146)** 은 가격공식으로 공용 `PRF_CLR_ACRYL`(투명 아크릴)을 쓰는데, 이 공식은
**투명아크릴 인쇄가공비(base)만** 물고 있음. 손님이 고르는 고리 옵션이 **가격에 전혀 안 닿음**:

- 공식에 고리/볼체인 **부품 구성요소가 안 물려 있음**(부품 comp 0개)
- 옵션→차원 환원(option_items) **0행** — 즉 어떤 경로로도 고리값이 계산에 안 들어감
- 결과: 손님이 은색고리·금색고리·은색구슬줄을 골라도 **0원 청구(저청구)**

부품 단가는 라이브에 실재하지만(아래) **아무 상품도 그 코드를 안 가리켜** 도달 불가 상태(고아 단가):
- `COMP_ACRYL_KEYRING`(키링 열쇠고리): 단가행 300 / 1,100 / 1,200원 (옛 코드 OPV_000474·OPV-000026·OPV-000027)
- `COMP_ACRYL_KEYRING_BALLCHAIN`(키링 볼체인): 단가행 1,000원 (옛 코드 OPV_000476~483)

원인 = 손님 옵션이 새 코드(`OPV_000624`…)로 재등록되며, 부품 단가행은 **옛 코드에 그대로 남아** 연결이 끊김.

## 교정 방식 (권위 확정·2단계·엔진 검증 후 SQL)

값은 확정(위). 교정은 **재연결 2단계** — 실 SQL 전 엔진 동작 확인 필수(생성≠검증):

**1단계 — opt_cd 재지정(값 불변·기계적)**: COMP_ACRYL_KEYRING 단가행 4개의 opt_cd 를 옛 코드 →
현행 손님 옵션코드로(위 매핑표). 값(0/300/1100/1200)은 그대로 → **가격중립 아님이 정상**(0→정상 복원).

**2단계 — 부품 comp 도달성 확인**: COMP_ACRYL_KEYRING 은 현재 어떤 공식에도 미배선(고아). 엔진이
opt_cd 매칭 단가행을 **공식 배선 없이도** 옵션 경로로 가산하는지 = **엔진 실동작 확인 필요**.
  - (a) 옵션-CPQ 가 배선 무관하게 opt_cd 단가를 가산하면 → 1단계만으로 충분.
  - (b) 공식 배선이 필요하면 → 아크릴키링 전용 공식 필요(공용 `PRF_CLR_ACRYL` 은 10상품 공유 →
        직접 comp 추가 시 타 9상품 오염). 고아 `PRF_ACRYL_KEYRING` 재사용 검토(단 볼체인 comp 정합 확인).

★ [HARD] SQL 생성 전 엔진(pricing.py)의 옵션 단가 가산 경로를 실측 → (a)/(b) 판정 → 그에 맞는
  교정본(백업·게이트·undo·P4 재실측: 은색고리 선택 시 +1,100원 반영 확인) → webadmin 실화면 → 인간 승인.

## 동종 스캔 결론 (같은 단절 다른 상품에 있나)

전 상품 양방향 스캔 결과 — **이 패턴은 격리됨**(널리 안 퍼짐):
- **PET배너**: 거치대가 전용 comp('PET배너 거치대 추가가격' 10,000/23,000원) + option_items 5행으로 **정상 청구**.
- **프리미엄엽서**: 오시·미싱·용지·별색 등 전 옵션이 option_items 41행으로 차원 환원 → **정상 청구**.
- 그 외 아크릴 9상품(맥세이프·포카키링·코스터 등): 부품옵션 없음 또는 연결 정상.

→ 엔진은 opt_cd 가 아니라 **차원(공정·인쇄옵션·자재)** 으로 매칭하므로 "opt_cd 불일치=저청구"는 오탐.
   진짜 신호 = **부품성 옵션인데 (공식에 부품 comp 없음) AND (option_items 차원환원 0)**. 이 조건 = 아크릴키링만 해당.
