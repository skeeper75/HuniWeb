# 권위 중복 code 블록 — POSTER_PETBANNER_PRINT (2026-09-03)

## 사실

권위 `후니프린팅_인쇄상품_가격표_260902_2.xlsx` 「포스터사인」 시트에 **같은 code 가 두 블록**에 적혀 있다.

| 블록 | 상품 머리(제목) | code 셀 | name 셀 | 값 |
|---|---|---|---|---|
| r265~r269 | **PET배너** | r266 `POSTER_PETBANNER_print` | 포스터_PET배너_제작가 | **22,000** |
| r276~r280 | **메쉬배너** | r277 `POSTER_PETBANNER_print` ← 복붙 오기 | 포스터_PET배너_제작가 | **38,000** |

`authority-blocks-trackA.csv` 전수 확인: 44블록 · 고유 code 43 → **중복은 이 한 건뿐**이다.

두 번째 블록의 code 는 실무진 복붙 오기이며, 정식 code 는 `POSTER_MESHBANNER_PRINT` 다
(LEAD-BRIEF §1 · §8 #2 에 이미 결정돼 있다).

## 무슨 일이 있었나

M1 매핑(`mapping-43-trackA.csv` 39행)이 `POSTER_PETBANNER_PRINT` 의 값 출처를 **뒤 블록
`r279~r280`**(메쉬배너)으로 잡았다. 중복 code 를 뒤엣것으로 덮어쓴 것이다. 그 결과
M3 적재에서 PET배너 그릇에 **메쉬배너 값 38,000** 이 들어갔다(라이브 옛 값은 22,000).

2026-09-03 00:08:17 에 라이브 행(`comp_price_id` 107309)이 22,000 으로 고쳐졌고,
이는 **권위 PET배너 블록 r269 와 일치**한다. 즉 이 수정은 되돌림이 아니라 **교정**이다.

`POSTER_MESHBANNER_PRINT` 는 23:19:28 에 38,000 으로 적재됐고 이 역시 권위 r280 과 맞다.
따라서 두 그릇 모두 현재 권위와 일치한다.

## 조치

- `grid/POSTER_PETBANNER_PRINT.csv` 를 22,000 · 출처 `r266~r269` 로 정정했다(본 커밋).
  정정 전 파일은 38,000 · `r279~r280` 이었다 — M3 diff 재실행 시 이 파일이 옛 상태면
  라이브와 어긋난다.
- 라이브는 이미 맞으므로 **추가 화면 조작 없음**.

## 남은 것 (실무진 확인)

엑셀 r277 의 code 를 `POSTER_MESHBANNER_print` 로, r278 의 name 을 `포스터_메쉬배너_제작가`
로 정정 요청(LEAD-BRIEF §8 #2 결정 그대로). 정정 전까지는 **code 만으로 블록을 찾으면
안 되고 상품 머리(r265 「PET배너」 / r276 「메쉬배너」)를 함께 봐야 한다.**

## 교훈 (다음 시트에 그대로 적용)

권위에서 code 로 블록을 찾을 때 **먼저 code 중복 여부를 세고**, 중복이면 상품 머리로
가른다. 중복을 모른 채 마지막 것을 취하면 조용히 다른 상품 값이 실린다 — 이번엔
16,000 원 과청구가 될 뻔했다.
