# 상품마스터·인쇄상품가격표 — 구조와 가격 아키타입

> 출처: 260702 통화 P4. 신우진이 엑셀 두 파일을 화면에 띄우고 구조를 설명한 내용을, 기존 검증 데이터(243상품·11시트, 옵션-사이즈 매핑 302건)와 대조해 정리. 이 문서는 DB 적재(P0→P6 의존성 체인)와 온톨로지 작업의 입력 사양이다.

## 1. 데이터 모델의 전체상 (통화 17:40 발화 기준)

신우진이 정의한 엑셀의 논리 계층:

```
상품 마스터 (권위 소스, authority)
 └─ 상품 구성 요소 (옵션 그룹)
     └─ 기초 데이터 (소재·공정·규격 사전)
         └─ 기초 데이터의 가격
             └─ 구성 요소 결합 공식  ⇒  견적
```

핵심 질문이었던 "이 두 파일을 AI에 던지면 의미론적 연결·자동 태깅이 되는가"에 대해 두 사람 모두 **불가** 판정(김동학: "구조화된 게 아니라서 안 될 것 같다"). 결론: **룰 합의 → 룰 기반 학습/스킬·에이전트 절차화**가 선행되어야 함. (→ 03 문서의 온톨로지 전략)

## 2. 가격 아키타입 3종 (통화에서 재확인)

기존 세션에서 AI와 함께 명명한 분류가 통화에서 그대로 교육됨. 명칭 대응:

| 통화 명칭 | 기존 스킬 명칭 | 공식 | 대표 상품 |
|-----------|---------------|------|----------|
| **원자합산형** | sheet_based | Σ(출력비+지대+별색+코팅+가공+후가공) × 수량 — "레시피처럼 조각을 결합" | 디지털인쇄, 스티커, 책자, 캘린더 |
| **고정가형** | (협의가격, unit_price의 특수형) | 계산하지 않고 **정의된 테이블 값을 차원 매칭으로 조회** | 엽서북 등 세트상품 |
| **매트릭스형** | area_based 계열 | 행×열 교차 지점 값 조회 (크기×등급 등) | 박, 아크릴, 실사 |

### 2.1 고정가형이 존재하는 이유 — 시장 역산 가격

엽서북 사례: 원자합산으로 계산하면 시장가(예: 11,000원)보다 **비싸게 나옴** → 계산을 포기하고 "시장 대비 이 가격으로 받자"고 **협의한 가격을 테이블로 고정**. 조회 차원 = 사이즈 × 단/양면 × 수량.

→ 설계 시사점: 고정가형은 원가 로직이 없으므로 **가격 개정 시 재계산이 불가능**하다. 시장가 스냅숏임을 메타데이터(`price_origin: negotiated`)로 남겨야 향후 마진 분석·가격 개정에서 원자합산형과 구분 관리된다.

### 2.2 "가격 포함" 표기의 해독

일부 상품은 가격 테이블 자체가 필요 없음 — "바깥에서 선택만 하게 해주고 실제 가격은 이거야"를 **"가격 포함"이라고만 써 놓음(작성자 표현으로 '암호')**. 옵션이 가격에 영향을 주지 않는 display-only 옵션의 존재 → `price_effect: none` 플래그 필요.

## 3. 옵션 분류 체계

### 3.1 옵션의 4가지 용도 (통화 27:51)

1. 선택을 하게 하는 옵션 (UI 선택지)
2. 상품에 관련된 옵션 (상품 정의)
3. 가공에 필요한 옵션 (공정 파라미터)
4. 추가 상품에 관련된 옵션 (부가 판매)

### 3.2 색상 코딩 (기존 검증과 일치)

| 색 | 의미 | 통화 발화 |
|----|------|----------|
| 🔴 빨강 | 필수 노출 (required) | "빨간색은 다 필수로 보여줘야 되는 부분" |
| 🟠 주황 | 선택 (optional) | — |
| ⬜ 회색 | 내부 전용 (internal) | "바깥에서 보이면 안 되지만 생산·가격을 위해 필요. JPG 등 출력파일 사양 포함" |

회색 열의 역할이 통화에서 구체화됨: **생산처에 전달할 파일 사양(JPG 등)과 공정 데이터**. 즉 internal 옵션은 CPQ의 출력이 아니라 **MES/생산 핸드오프의 입력**이다.

### 3.3 엑셀 내 옵션 순서 = 위젯 노출 순서

"이 순서대로 위젯에서 보이게 된다" + 위젯 빌더에서 상하 이동·컴포넌트 변경(드롭다운 등) 가능. → 옵션 그룹에 `display_order`가 1급 속성이고, 엑셀의 열 순서가 그 초기값.

## 4. 두 파일의 역할 분담

| 파일 | 역할 | 통화 근거 |
|------|------|----------|
| 상품마스터 | **권위(authority)** — 상품 정의·옵션 구성·노출 규칙 | "상품마스터라고 하는 애가 권위가 있는 애" |
| 인쇄상품가격표 | 가격 테이블 — 아키타입별 시트(후가공/박/제본/아크릴/실사/스티커…) | "가격을 보려면 요게 있는 거고" |
| 출력소재관리 | 소재 사전 + ● 적용 매핑 + 판걸이수(국4절 316×467 조인 키) | "소재에 관련된 모든 것을 알 수 있다" |

## 5. 시트 내부 패턴 (통화에서 확인된 것)

- **11개 섹터 / 280개 상품**: "상품이 280개, 11개 섹터로 나눠 놓음" — 기존 검증치 243상품·11시트와 근사(신우진의 어림수 또는 세트·파생 포함 수치로 추정. 적재 시 243 기준 유지, 280 발언은 세트 전개 포함 가능성으로 메모).
- **같은 가격끼리 묶음**: 접지 가로/세로 동액 묶음, 스티커 용지 동가 묶음 → **"테이블에 들어가려면 슬래시(묶음)를 다 쪼개서 각각 넣어야 함"** — 정규화 원칙의 통화 내 재확인.
- **구간 규칙**: "100장당 천 원", "천 장당 2만 원" 식 증분 규칙이 산재 → 구간 테이블 or 증분 공식 중 표현 방식 통일 필요.
- **수량 구간 할인**: 아크릴·굿즈·문구·파우치. 카라비너는 독자 구간(오버라이드).

## 7. DB 적재 관점 정리

기존 확정된 7단계 의존성 체인(P0 기초코드 → P5 옵션 계층 → P6 제약조건)에 이번 통화 내용을 대입하면:

- **P0 기초코드**: §3.1 옵션 4용도 + 인쇄 방식 스위치(디지털/옵셋/UV/실사)를 코드 체계에 반영.
- **P2~P3 소재·가격**: 아키타입 3종별 테이블 분리 + `price_origin`, `price_effect` 메타 추가.
- **P4 판걸이**: 국4절 316×467 조인 키 유지, 상품 유형별 판 여백 파라미터 추가(그리퍼).
- **P5 옵션 계층**: `display_order`, required/optional/internal 3분류, 옵션→공정 매핑 테이블 신설.
- **P6 제약조건**: JSONLogic — 위젯 테스트에서 확인된 발동조건 문법과 정합 (→ 04 문서).
