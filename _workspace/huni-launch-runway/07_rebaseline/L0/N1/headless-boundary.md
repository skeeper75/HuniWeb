**알림톡 우선 + SMS(LMS) 대체 발송** — 알림톡과 자동 SMS 를 같은 항목에 함께 켜면 알림톡이 우선이고, 알림톡 발송 요청이 실패하거나 요청은 성공했으나 실제 미수신이면 **같은 템플릿 내용이 SMS(LMS)로 대체 발송**된다. 카카오톡 미사용자·알림톡 수신거부로 실패한 경우에는 대체 발송하지 않는다 — 매뉴얼 `management/kakao-notification/undefined.mdx:75-85`.

**즉 하나의 트리거가 최대 두 채널로 고객에게 나간다.** 알림톡 템플릿에서 수량 치환을 빼도 SMS 대체 발송본이 같은 문구를 쓰므로 한 벌만 고치면 되지만, 자동 SMS 템플릿을 별도로 켜 둔 항목은 **템플릿이 두 벌**이다(알림톡용·SMS용). 어느 항목이 이중으로 켜져 있는지는 **미확인**(셀러어드민 실화면 필요).

## A-2. ★수량 노출 전모 (M2 카드 (b))

### A-2-0. 왜 노출되는가

가이드 §11 이 확정한 적재 방식: **판매가 10원짜리 상품을 「금액 ÷ 10」 만큼의 수량으로 주문한다** — 15,000원이면 `orderCnt = 1,500` (가이드:949-951, 1035, 1044-1046). 주문서 API `POST /order-sheets` 가 금액을 직접 받지 않고 상품번호·옵션번호·수량만 받기 때문이며(가이드:953-957), 샵바이가 2026-08-26 미팅에서 외부 금액 지정 불가를 공식 회신했다(가이드:979-981). 판매중 226개 상품의 판매가를 10원으로 일괄 변경 완료(가이드:1052-1054).

**"수량 칸에 실제 인쇄 수량을 넣지 마세요. '명함 200장'의 200은 샵바이 수량 칸에 들어가지 않습니다"** — 가이드:1047-1048.

가드 하나가 걸려 있다: 청구액이 10원 배수가 아니면 후니 서버가 토큰 발급 단계에서 **`price_unit_mismatch` 422 로 거절**한다(가이드:1064-1065, 운영 중). "임의로 반올림해서 재시도하지 마세요"(가이드:1066-1067, 오류표 `:583`). 청구액이 10원 미만이면 절삭하지 않으므로 이 가드가 걸리는 유일한 정상 경로다(가이드:1068-1069).

## A-3. 가이드 표가 덮지 않는 경로 — 셀러어드민 거래명세서

가이드:1411 은 「거래명세표 = 자사몰, 수량 노출 아니오」로 적는다. 그런데 **샵바이 셀러어드민에도 거래명세서 출력 기능이 있다.**

- 전체주문 조회 화면에서 "주문상태 업데이트 및 **거래명세서 출력** 등의 주문관리 업무가 가능" — 매뉴얼 `order/list.mdx:9`
- `⑥ 거래명세서 출력` — "해당 주문 건의 거래명세를 출력할 수 있는 창이 노출됩니다. 거래명세서는 **배송번호 기준으로만** 출력됩니다" — 매뉴얼 `order/list.mdx:95-97`
- 주문상세에도 같은 기능 — 매뉴얼 `order/list/detail.mdx:74-77`
- API 에 **`viewShopSpecification`("거래명세서 쇼핑몰 노출 설정", boolean)** 과 **`shopSpecificationFields`("거래명세서 쇼핑몰 출력 항목 설정")** 가 존재 — `order-shop-public.yml:39688`, `:39593`

**판정**: 이 거래명세서는 **샵바이가 만든다**. 가이드 표의 「거래명세표 = 자사몰」 행과 층위가 다른 별개 경로다. 여기에 수량이 어떻게 찍히는지, `viewShopSpecification` 이 현재 켜져 있는지 — **둘 다 미확인**. 셀러어드민 실화면으로만 닫힌다.

### A-4-3. 가짜 수량이 증빙에 미치는 영향

- **총액(공급가액+부가세)은 맞다.** `10원 × 1,500 = 15,000원`이 실제 청구액이고, 청구액은 항상 10원 배수라 정확히 표현된다(가이드:1056-1058). 가드(`price_unit_mismatch` 422)가 배수 위반을 막는다(가이드:1064-1065).
- **품목의 단가·수량 칸이 사실과 다르다.** 단가란에 `10원`, 수량란에 `1,500`이 찍힌다면 「명함 200장」이라는 실제 거래 내용이 증빙 어디에도 남지 않는다. 담당자가 셀러어드민에서 겪는 것과 같은 문제다 — "「10원 × 1,500개」만 보여서 취소·환불·문의 응대를 할 수 없습니다"(가이드:1427-1428).
- **실제 표기 형식은 확인되지 않았다** — 「수량 1,500 / 단가 10원」인지 「총액만」인지 (I6:344). 표기 형식이 확인되기 전에는 회계·세무 영향의 크기도 확정할 수 없다.
- **완화책이 진술된 적이 없다.** 알림 템플릿은 "수량 치환 제거"라는 권장 대응이 있으나(가이드:1421), 현금영수증·세금계산서에는 대응책 자체가 없다 — "이 계약에서 **해법이 제시된 적 없는 유일한 항목**"(C2:296), "완화책이 어디에도 없다"(L0C:219).

# B. 회원 · 비회원

## B-0. 두 층을 분리한다

- **플랫폼(샵바이)이 무엇을 지원하는가** — API 표면과 매뉴얼로 판정.
- **우리 몰(`huni-skin-shopby`)에서 무엇이 깨지는가** — C2 §5 가 HEAD `30cb88a`(2026-08-30, 「비회원(게스트) 구매 — 장바구니·바로구매·주문조회」, 16파일 +1,129/−46) 기준으로 이미 판정했다. 여기서는 재도출하지 않고 인용한다.

**C2 의 종합 판정은 「부분 성립」이다** — C2:493.

매뉴얼측 비회원 제약:
- 상품별 **「비회원 구매 불가」** 개별 설정 존재 — `product/add-list/add/basic-info.mdx:105`. **현재 후니 상품 226개의 설정값은 미확인.**
- 비회원은 **1회 최대구매수량 제한만** 적용 가능(회원 아이디 1인/1회/기간제한 중) — `product/add-list/add/sale-info.mdx:119`. 다만 이 설정은 수량=금액이라 **영구 금지 대상**이다(가이드:1103-1104).
- 성인 카테고리 상품은 비회원 결제 제한 — `product/category-commissionrate.mdx:43`.
- 수기주문: 비회원 선택 시 주문자·배송지 정보를 운영자가 전부 입력, **쿠폰·적립금 할인 적용 불가** — `order/manual-order.mdx:28`, `:57`, `:65`, `:75`.
- 비회원에게 SMS 를 발송하려면 사전에 휴대폰번호 수집동의 및 광고성 SMS 수신동의가 필요 — `management/sms/sms.mdx:76` (수동 발송 기준).

## B-3. 판정

> **플랫폼(샵바이)은 비회원 주문을 폭넓게 지원한다** — 주문·조회·클레임·구매확정·배송·현금영수증까지 전용 엔드포인트가 열려 있고, 막는 것은 쿠폰·적립금(회원 전용)과 상품별 「비회원 구매 불가」 설정뿐이다. **깨지는 지점은 대부분 우리 쪽이다** — 재견적 401(비회원 고유), 결제 직전 갱신 부재(회원·비회원 공통), 주문등록 부재(회원·비회원 공통). 여기에 **비회원 고유의 구조적 취약점 하나**가 남는다: 결제 전까지 장바구니가 브라우저 안에만 존재하고, 서버측 복구 수단이 없다.

C2 의 문장 그대로: **주문등록 미성립은 "게스트 고유 문제가 아니라 몰 전체의 결함"이다**(C2:499).
