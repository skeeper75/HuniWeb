2. 오픈일 이후에 완성되는 기능 — 21건

왜 중요한가요? 약관은 고객에 대한 약속입니다. 아직 없는 기능을 약관에 적으면, 고객이 그 기능을 요구했을 때 회사가 거절할 근거가 없습니다. 오픈 목표일은 2026년 10월 6일입니다.

특히 짚을 것 세 가지

  • 고객 직접취소 — 지금 기능이 없습니다. 사이트 FAQ는 「주문취소는 인터넷상에서는 고객님께서 취소할수 없으며, 고객센터로 연락」이라고 안내하는데 이게 현재 사실입니다. 엑셀은 「접수대기 이전의 주문에 한해 직접 취소가 가능」이라고 미래를 적어 두었습니다. 엑셀대로 약관에 쓰면 없는 기능을 약속하게 됩니다.
  • 증빙서류 — 화면 문구는 이미 다 있는데 기능이 안 돕니다. 발행 조건·기한·대상이 화면에 전부 쓰여 있지만, 뒤에서 서버를 부르는 코드가 없는 껍데기 상태입니다.
  • 결제수단 — 약관은 6종, 화면은 3종입니다. 신용카드·무통장·계좌이체만 있고 프린팅머니 탭이 없습니다. 약관 조항까지 만들어 둔 핵심 결제수단입니다.

오픈 전 반드시 (7건)

#결정할 것충돌하는 값안 정하면
1프린팅머니 유효기간 엑셀 5년 / FAQ 1년 / 미팅확정·개발계획 소멸없음 소멸기한 세 개를 동시에 공표한 상태. 어느 쪽으로 운영해도 다른 문구가 고객 주장의 근거가 됩니다. 소멸은 되돌릴 수 없습니다.
2탈퇴 시 잔액 처리 엑셀 「유효기간내 100% 환불」 / FAQ 「탈퇴와 동시에 프린팅머니 포함 모든 정보 삭제」 현금 환불 청구권이 있는 잔액이 탈퇴 즉시 사라지는 구조입니다. 탈퇴 화면에 잔액 환불 단계가 없으면 배포되는 순간부터 매 건이 분쟁입니다.
3기존 충전 잔액 소급 8/27판 「유효기간 없음」 → 9/18판 「5년 소멸」 무기한이라 공지해 두고 소멸시효를 새로 부과하는 셈입니다. 다만 아직 피할 수 있어 보입니다 — 구 잔액 이관(T6-1 11/05 목표)이 미착수이고 신규 충전 경로도 아직 닫혀 있어, 지금 정하면 「이미 들어온 잔액에 소급」이 아니라 「이관 시점에 조건을 붙여 신규 부여」로 설계할 수 있습니다. 확인 필요 단, 이는 잔액을 직접 조회한 것이 아니라 원장 기록에서 추론한 것입니다. 판단 전에 신규몰 적립금 잔액 합계가 0인지 한 번 조회해 주십시오 — 5분이면 되고, 이 논거 전체가 그 숫자 하나에 걸려 있습니다.
4미입금 자동취소 기산일 엑셀 안에서 충돌 — 삭제기준 「주문완료일로부터」 / 결제방법·구매배송정보 「발급 후」 기산점이 둘이라 어느 쪽도 집행 근거가 되지 못합니다. 취소당한 고객이 늦은 쪽 해석을 주장하면 반박할 수 없습니다.
5쿠폰 적용 단위 9/18판 「1회 주문 시 1장」 / 현행 약관·8/27판 「상품 1개당 1장」 고객에게 불리한 축소입니다. 공표된 약관이 "상품당"인 한 그쪽이 구속력을 가져, 다건 주문 고객이 상품 수만큼 요구하면 거절 근거가 없습니다.
6자동 삭제 4종 고지 신설 — 미입금 7일 / 장바구니 7일 / 편집보관함 30일 / 주문파일 30일 고객 자산을 공지 없이 자동 삭제하는 것이라 그 자체가 분쟁거리입니다. 편집물·원고는 고객이 재확보를 기대하는 구간입니다. FAQ의 「방문수령 15일」도 이 목록에 빠져 있습니다.
7할인 계산순서 · 초과분 환급 8/27판에 있던 두 조항이 9/18판에서 사라짐 순서를 안 정하면 개발이 임의로 정합니다. 결과가 고객에게 불리하면 근거 없이 덜 할인한 셈이 되고, 환급불가 조항이 없으면 초과분 환급 요구를 거절할 근거도 없습니다. 양방향으로 샙니다.

확인하지 못한 것 — 실제 결제 연동 설정(주문마다 계좌를 새로 만드는지, 고정 계좌인지)과 자동취소가 실제로 도는지는 문서로 확인할 수 없어 확인 요청 16번으로 넘겼습니다. 구현 현황 판정은 개발 계획서와 코드 두 가지 근거로만 했습니다 — 관리자 화면 목록은 고객 화면을 담고 있지 않아 이번 판정에 쓰지 못했습니다.
