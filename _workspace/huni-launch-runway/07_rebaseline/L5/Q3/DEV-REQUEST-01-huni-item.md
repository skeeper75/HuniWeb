## 1. 증상

**장바구니는 정상으로 보이는데, 토큰이 필요한 두 자리가 아무 메시지 없이 건너뛰어진다.**

| 고객이 하는 일 | 지금 일어나는 일 |
|---|---|
| 장바구니에서 수량을 바꾼다 | **아무 일도 안 일어난다.** 오류 문구도 안 뜬다 |
| 결제로 넘어간다 | **결제 직전 재견적이 통째로 건너뛰어진다.** 담을 때의 옛 금액이 그대로 결제된다 |

화면·금액 표시는 멀쩡하다. `huni_order` 하나로 표시가 성립하기 때문이다. **조용한 실패**라서 QA 로도 잘 안 잡힌다.

## 2. 재현

호출 없이 코드만으로 재현되는 종류다. 실호출로 보려면:

1. 아무 위젯 상품이나 담는다
2. 샵바이 주문조회로 그 장바구니 항목의 `optionInputs` 를 본다
   → `huni_token`(값 있음) + `huni_order`(값 있음) 두 칸이 실려 있고, **`huni_item` 칸은 비어 있다**
3. 장바구니 화면에서 수량을 바꾼다 → 네트워크 탭에 `/api/printly/requote` 요청이 **한 건도 안 나간다**

정적 재현(즉시 가능):

```bash
cd /Users/innojini/Dev/huni-skin-shopby
grep -rn "huni_item" src     # → 0건  (등록된 칸을 안 쓴다)
grep -rn "huni_token" src    # → 8건  (없는 칸에 넣는다)
```

## 3. 원인 — file:line

### 3-1. 샵바이 쪽 실측 (전수 297건 · GET 303 전건 200)

| 라벨 | 샵바이 상품에 등록됨 | 자사몰이 싣나 | 결과 |
|---|---|---|---|
| `huni_order` | **O** (판매중 226 전건) | **O** | 정상 |
| `huni_item` | **O** (판매중 226 전건) | **✕** | **등록된 칸이 비어 있다** |
| `huni_token` | **✕ 0건** | **O** | **실을 칸이 없다** |

근거 `L5/Q0/label-check.csv` 297행 · `L5/Q0/huni-token-label-check.md` §2.
**`huni_token` 라벨이 없는 것은 결함이 아니라 의도**다 — SDK 가이드 `raw/webadmin/docs/widget-sdk-guide.html:1912-1922` 가 「토큰 전용 라벨을 **일부러 만들지 않았습니다**」라고 명시한다. 토큰이 주문조회 응답으로 그대로 읽히고, 값 길이 상한이 미확인이라 **조용히 잘리면 서명 검증이 전부 실패**하기 때문이다.

### 3-2. 자사몰 코드 — 없는 칸에 싣는 자리 2곳

- `huni-skin-shopby/src/components/product/huni-widget.tsx:69-71`
  ```ts
  const inputs: OptionInput[] = [
    { inputLabel: "huni_token", inputValue: r.token },   // ← 미등록 라벨
  ];
  ```
  같은 파일 `:73-76` 에서 `huni_order` 를 push. **`huni_item` 은 없다.**
- `huni-skin-shopby/src/lib/api/requote.ts:72-75` — 동일 패턴

### 3-3. 조용히 삼키는 자리 3곳

| 자리 | file:line | 무슨 일이 일어나나 |
|---|---|---|
| 파싱 | `src/lib/api/widget-order.ts:106-111` | `huni_token` 이 없으면 `?? ""` 로 **빈 문자열**이 된다. `undefined` 를 반환하지 않으므로 **조용히 통과** |
| 수량 변경 | `src/components/cart/cart-page.tsx:118-119` | `const token = l.widget?.token;` / `if (!token) return;` — `toast.error` 가 이 `return` **뒤**에 있어 안 뜬다 |
| 결제 직전 재견적 | `src/components/cart/cart-page.tsx:172-175` | `if (!token \|\| l.widget?.qtyRule \|\| …) continue;` — 재견적을 **통째로 건너뛴다** |

서버는 제대로 막도록 만들어져 있다 — `src/app/api/printly/requote/route.ts:42-48` 이 토큰 없으면 `400` 을 준다.
**그런데 위 두 가드가 호출 자체를 막아서 서버까지 도달하지 못한다.** 서버는 시끄럽게 거절하는데 클라이언트가 조용히 삼킨다.

## 4. 수정 방향

**갈래는 둘이고, 계약이 이미 정답을 정해 뒀다.**

| 갈래 | 무엇을 하나 | 판정 |
|---|---|---|
| **(가) 코드를 계약에 맞춘다** ★ | `huni_token` 을 **빼고** `huni_item`(36자 항목 키)을 싣는다. 토큰은 후니 항목 보관소(`t_wgt_cart_items`)에서 항목 키로 찾아 쓴다 | **정본** |
| (나) 샵바이에 `huni_token` 라벨을 만든다 | 226개 상품에 라벨 추가 | **권고하지 않음** — 가이드가 명시적으로 반대. 토큰이 주문조회 응답으로 노출되고, 길이 상한 미확인이라 조용히 잘릴 수 있다 |

**(나)를 고르면 조용한 실패는 없어지지만 노출이 시작된다.** 지금 상태(라벨 없음)가 오히려 보안상 옳은 쪽이다 — 서명 토큰·S3 원고 키·Edicus `prjid` 가 현재는 노출되지 않고 있다.

### 4-1. (가)를 고를 때 손대는 곳

1. `huni-widget.tsx:69-71` · `requote.ts:72-75` — `inputLabel` 을 `huni_token` → `huni_item`, 값을 `r.token` → **항목 키(`item_id`)** 로 교체
2. `widget-order.ts:106-111` — `huni_token` 대신 `huni_item` 을 읽는다. **`?? ""` 폴백을 없앤다** — 없으면 `undefined` 를 반환해 위쪽에서 알아채게 한다
3. `cart-page.tsx:118-119` · `:172-175` — 값이 없을 때 **조용히 `return`/`continue` 하지 말고 오류를 띄운다**. 지금은 이미 있는 `toast.error` 가 `return` 뒤에 있어 죽어 있다
4. 재견적·주문등록 경로가 토큰 대신 **항목 키**로 가도록 배선 (→ `DEV-REQUEST-02` 의 `item_id` 경로와 같은 값이다. 두 요청은 같은 키를 쓴다)

### 4-2. 같이 정해야 하는 것 (쇼핑개발 단독으로 못 정함)

- `item_id` 경로는 **`X-Huni-Server-Key` 헤더가 무조건 필수**다(`widget_api.py:4210-4223`). **서버키 발급이 선행**이다 → `DEV-REQUEST-02` §4-2 와 동일 선행조건
- **주의**: 서버키를 발급받기 **전에** 헤더를 미리 실어 보내면 `403 bad_server_key` 로 **결제 경로 3개(verify·requote·order/register)가 한꺼번에 막힌다.** 가이드가 가장 강하게 경고하는 함정이다

## 5. 확인 방법

| # | 무엇을 | 어떻게 | 기대값 |
|---|---|---|---|
| 1 | 안 쓰는 라벨이 사라졌나 | `grep -rn "huni_token" src` | **0건** |
| 2 | 등록된 라벨을 쓰나 | `grep -rn "huni_item" src` | **1건 이상** |
| 3 | 실제로 실리나 | 담기 1건 후 주문조회 `optionInputs` 확인 | `huni_item` + `huni_order` **두 칸에 값** |
| 4 | 수량 변경이 도나 | 장바구니 수량 변경 → 네트워크 탭 | `/api/printly/requote` **요청 발생** · 금액 갱신 |
| 5 | 실패가 보이나 | 값을 일부러 비운 상태로 수량 변경 | **오류 문구가 뜬다**(지금은 아무것도 안 뜸) |
| 6 | 결제 직전 재견적 | 결제 진행 | 재견적 호출 발생 · 결제 금액 = 재견적 금액 |

**5번이 이 요청의 핵심**이다. 4번만 통과하고 5번이 안 되면 조용한 실패가 그대로 남는다.
