## 1. 개념 목록 초안 (프린틀리 7엔티티 · 도메인 의미 기반)

> 각 개념에 "기존 근거(재사용)" 또는 "신규(지니 대기)"를 표기. 속성 확정은 Step 1.

### 1-A. 업종 (industry / 추천의 출발점)
- 개념: 고객의 사업 맥락(카페·음식점·미용실·학원·꽃집·병원·부동산…). 추천 루프의 진입 슬롯.
- 근거: §33 `intent` 축(고객 표현→상품군 연결). 단 현재는 "용도"(카페오픈 이벤트) 중심 → 프린틀리는 "업종"(지속적 사업체) 중심이라 **의미 결이 다름**(질문 Q1).
- 정규화 방향: 업종을 원자 기능으로 분해(예 카페 = {대면접객 + 메뉴노출 + 브랜딩 + 이벤트}) → 홍보물 추천 정밀화(§35 구조 리서치 키스톤·AliCoCo 패턴).

### 1-B. 홍보물 (인쇄 아키타입)
- 개념: 명함·전단·배너·메뉴판·스티커·현수막·리플렛·쿠폰… (§33 상품군 그대로).
- 근거: §33 `product`/`category`·§35 `product_family` — **재사용**.
- 주의: 프린틀리 "홍보물"은 마케팅 용도 인쇄물 중심 → §33 275상품 중 마케팅 아키타입 부분집합일 수 있음(질문 Q2).

### 1-C. 사양 (하위 4축)
- `규격`=§33 size / `색상(CMYK 등)`=§33 print_option(도수·인쇄방식) / `후가공(코팅·재단…)`=§33 process / `용지·소재`=§33 material.
- 근거: **전량 재사용**. 인쇄방식(합판/독판·§35 U-4 print_method)은 §35에서 1급 축으로 승격됨.

### 1-D. 장비 (생산 설비)
- 개념: 인쇄소가 보유한 설비 1대(옵셋기·디지털기·UV·대형출력·재단기·코팅기…).
- 근거: §35 `production_capability`가 "능력 프로파일"을 표현하나, "설비 1대=1노드"의 세분 여부 미정. §35는 능력이 생산축(print_method·material…)을 `capability_covers`로 가리킴.
- 질문 Q3: 장비를 개별 노드로 둘지 vs §35 capability 프로파일로 접을지.

### 1-E. 인쇄소 (시설)
- 개념: 지역·납기·품질·보유장비를 가진 생산 시설(후니 자사 + 외주 trade printer).
- 근거: §35 `E22 supplier`(형만·roles=[broker,supplier]). **실 데이터 0**(G-ROUTE-1).
- 질문 Q4: 파일럿 인쇄소 seed(후니 자사 1 + 외주 소수)를 지니가 제공하는지.

### 1-F. 파일포맷 (장비별 RIP-ready) ★신규
- 개념: 각 장비가 요구하는 입고 파일 사양(재단여백·컬러프로파일·해상도·PDF/X 규격·터잡기 전제…).
- 근거: **없음**. §35 CIP4 리서치가 XJDF/PrintTalk를 다뤘으나 "장비별 파일 요구"는 미모델.
- 질문 Q5: 파일포맷 요구사항 원천(장비 매뉴얼? 후니 실무 규칙?) 지니 제공.

### 1-G. 배송 ★신규
- 개념: 배송 방식·리드타임·지역·비용.
- 근거: **없음**(§35 라우팅에서 schema.org deliveryLeadTime 이름표만).
- 질문 Q6: 배송 모델 범위(1차엔 리드타임 축만? 실배송 연동?).

## 2. 설계 노트 — tykimos ANA 참조의 경계

지니가 준 참조 `agent-native-agent`(ANA)·`agent-native-lifestyle`(ANL)은 **"Use=Build·에이전트가 곧 런타임/백엔드·watch+converse+act·대화로 성장"** 철학이다. 이는 프린틀리 **PART 2 런타임 루프의 상호작용 스타일**(관찰+대화, 계약 연쇄)에 유용하다.

**단 결정적 경계:** ANA는 **명시적 온톨로지 대신 스킬 기반 모듈화**를 쓰고 에이전트가 코드를 다시 쓴다. 프린틀리 PART 0 원칙 1은 **온톨로지=유일 진실원본(명시적 그래프)**을 못박았다 → **프린틀리는 ANA와 여기서 갈린다.** 프린틀리 = "Ontology Studio(명시적 그래프·근거 node_id) + 에이전트-네이티브 런타임 루프". ANA에서 가져올 것 = 런타임 상호작용·계약 연쇄·자체 하네스 소유. **안 가져올 것 = 온톨로지 없이 스킬로만 지식 표현**(원칙 1 위반). 이 구분을 Step 1 이후 유지한다.

## 3-B. 지니 확정 (2026-07-04 · 게이트 3건 — relitigate 금지)

- **Q0 = 기존 §33/§35 정규화 코퍼스 재사용.** 백지 재정규화 안 함. 신규 3(파일포맷·배송·프리플라이트/임포지션)만 지니 입력 대기.
- **Q1 = "업종"은 §33 용도(intent) 축을 확장·재사용.** 새 축 신설 안 함 — intent를 업종으로 원자 분해·확장(키스톤). 그맷 재사용.
- **Q2 = 마케팅 아키타입 우선.** 명함·전단·배너·스티커·메뉴판 등 홍보용 인쇄물 부분집합으로 파일럿(§33 275상품 전체 아님).
- 잔여 대기(해당 단계에서): Q3 장비 세분(파일럿=capability 재사용)·Q4 인쇄소 seed·Q5 파일포맷 원천·Q6 배송 범위·Q7 엔진 인터페이스.
