## 먼저 — 지금 우리가 아는 것

이 요청서는 **모르는 것을 물어보는 글이 아니다.** 이미 아는 것을 **화면으로 한 번 확증하려는** 요청이다.

지니가 2026-09-02 에 확인해 준 사실:

1. 결제대행(PG) 신청은 **심사 중**이다. **신청서는 이미 제출했다.**
2. 이니시스 가맹점관리자에서 해야 하는 추가 작업(상점ID 추가·지불수단 추가)은 **실무진이 진행 중**이다. 개발이 손댈 수 있는 영역이 아니다.

저장소의 문서만으로는 이 단계를 확정할 수 없었다 — 갖고 있는 화면 사진 9장이 전부 **매뉴얼과 공개 화면**이고, 후니 계정으로 로그인한 실제 화면이 **한 장도 없다.** 그래서 문서 쪽에는 「미확인」으로 남아 있었다.

지니의 진술로 **판단은 이미 닫혔다.** 남은 것은 **기록에 남길 증거 한 장**이다.

## 요청 — 화면 사진 딱 1장

실무진의 이니시스 가맹점관리자 작업이 **끝난 다음에** 아래 화면을 한 장만 찍어 주세요.

```
이니시스 가맹점관리자(PC) 로그인
  → 상단 「변경/추가」
    → 「8. 서비스 신청현황」
```

이 화면에는 **신청일 · 신청서비스 · 처리결과** 가 표로 나옵니다. 그 표가 나온 상태로 한 장이면 됩니다.

- 계정 아이디·비밀번호는 **찍지 마세요.** 표 부분만 나오면 됩니다.
- 급하지 않습니다. **실무진 작업이 끝난 뒤**에 주시면 됩니다.
- 지금 당장 찍어 주셔도 좋습니다 — 「진행 중」이라는 사실 자체가 기록이 됩니다.

## 해석표 — 무엇이 보이면 어느 단계인가

찍어 주신 화면의 **처리결과** 칸을 이 표에 대보면 우리가 지금 어디에 있는지 확정됩니다.

| 화면에 보이는 것 | 뜻하는 단계 | 우리가 할 일 |
|---|---|---|
| **행이 하나도 없음** | 아직 **신청 전** | 신청서 작성부터 다시. 사내 확인 3건(F 팩)이 먼저 |
| **접수대기 · 처리대기** | **심사 중** | 지니 진술과 일치. 기다리면서 다른 준비를 진행 |
| **처리완료** | **승인 완료** | 결제 경로가 열린다. 실주문 검증을 시작할 수 있다 |
| **반려** | 사유 조치가 필요 | 반려 사유를 확인해 다시 신청. **가장 나쁜 경우** — 일정이 통째로 밀린다 |

> 반려는 보통 세 가지 이유로 납니다 — 신청서 기재값이 틀렸을 때, 판매 상품이 심사에 걸릴 때, 필요한 서류가 빠졌을 때.

## 무엇이 열리는가 — 해석값별로

이 한 장이 우리 진행의 어디를 여는지 정리합니다. **닫히지 않은 미확인 6건이 여기에 묶여 있습니다.**

| 화면 결과 | 곧바로 열리는 것 | 그때 닫을 수 있게 되는 미확인 |
|---|---|---|
| 행 없음 / 반려 | 아무것도 안 열림 | 없음. 대신 **F 팩(사내 확인 3건)** 이 앞으로 당겨진다 |
| 접수대기·처리대기 (심사 중) | 준비만 — 결제 경로는 아직 안 열림 | 없음. 다만 **결제수단 결정(D 팩 ①)** 을 지금 하지 않으면 승인이 나도 못 연다 |
| **처리완료 (승인)** | 결제 경로가 열리고 **실주문 1건**을 흘릴 수 있게 됨 | **E-1 · E-2 · E-3 · E-5 · E-6** 다섯 건. 아래 표 참조 |

### 승인이 나야 비로소 닫히는 5건

| # | 무엇을 못 보고 있는가 | 승인 후 어떻게 닫히나 |
|---|---|---|
| E-1 | 현금영수증·세금계산서에 수량이 **실제로 어떤 모양으로** 찍히는가 | 실주문 1건을 결제하고 증빙 실물을 본다 |
| E-2 | 결제가 승인된 뒤 주문이 어떻게 움직이는가 — 상태, 다음에 할 수 있는 일, 취소 가능 여부 표시 | 같은 주문을 주문조회로 읽어 본다 |
| E-3 | 「입금대기부터 재고 차감」이 후니의 금액-수량 방식과 만나면 재고가 얼마나 깎이는가 | 무통장 주문 1건으로 확인 |
| E-5 | 비회원(게스트) 주문에도 샵바이 자동 알림이 나가는가 | 게스트로 1건 주문 후 발송내역 조회 |
| E-6 | 게스트 경로 전체(간편결제·로컬 장바구니)가 실제로 도는가 | 브라우저로 게스트 주문 1건 |

**주의**: 위 다섯 건은 **승인 전에는 원천적으로 못 닫습니다.** 실물이 아직 존재하지 않기 때문입니다. 「아직 안 해봤다」이지 「안 만들었다」가 아닙니다.

**한 가지 예외** — `E-4`(장바구니 담기 응답의 요약 문자열이 만들어지는 규칙)는 **승인 전에도 닫을 수 있습니다.** 서버키만 있으면 한 번 호출해 보면 되기 때문입니다. 절차는 **F 팩** 뒷부분에 있습니다.

## 함께 물어볼 것 2가지

캡처를 부탁드리는 김에, 이니시스 상담(1588-4954) 또는 담당 영업에게 **아래 두 가지도 함께** 확인해 주시면 좋겠습니다.

### ① 네이버페이가 어느 방식으로 열리는가 (C-2)

> 「이니시스에서 네이버페이를 열면, 샵바이 쪽에서는 **주문형**으로 붙나요, **결제형**으로 붙나요?」

- **왜 묻는가**: 이니시스 매뉴얼은 이 둘을 구분하지 않고 「네이버페이」라고만 씁니다. 그런데 샵바이는 둘을 다른 결제수단으로 나눠서 다룹니다. **주문·취소·환불의 책임이 어디로 가는지가 이 둘 사이에서 갈립니다.**
- 샵바이 쪽 담당자에게 물어도 됩니다(B 팩과 함께 보내도 좋습니다).

### ② 상점ID 를 더 발급받을 때 비용이 붙는가 (C-3)

> 「상점ID(MID)를 추가로 발급받을 때 저희에게 비용이 발생하나요? 발생한다면 얼마인가요?」

- **왜 묻는가**: 이니시스 안내는 「호스팅에 따라 발생할 수 있으며, 발생 시 별도 연락」 이라고만 되어 있습니다. **비용이 붙는 경우 납부가 확인돼야 발급이 되므로, 모르고 있으면 그만큼 발급이 늦어집니다.**

## 참고 — 결제수단마다 여는 데 걸리는 시간이 다릅니다

승인이 난 뒤에도 **결제수단은 하나씩 따로 신청**해야 하고, 수단마다 걸리는 시간이 크게 다릅니다. 이것이 D 팩 첫 번째 결정(어떤 결제수단을 열 것인가)이 급한 이유입니다.

| 결제수단 | 신청부터 쓸 수 있을 때까지 |
|---|---|
| **네이버페이** | **3~4주** ← 가장 오래 걸린다 |
| **카카오페이** (처음 추가할 때) | **2주** |
| PAYCO · L.pay (새로 신청할 때) | 10~12영업일 |
| 신용카드 | 3~5영업일 (카드사 심사가 붙으면 7~10영업일 추가) |
| 계좌이체 | 3~5영업일 (처음 신청이면 3영업일 추가) |
| 가상계좌 · 간편결제 일반 · 에스크로 | 3~5영업일 |
