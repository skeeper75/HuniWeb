# OPV/OPT 코드 하이픈/언더스코어 네임스페이스 충돌 진단 (260706)

> 지니 기준: **모든 코드는 `-`가 아니라 `_`가 표준**. opt/opv를 `_`로 정규화 + 끊긴 배선 재연결 후 (가) 접근.
> ★진단 결과: 단순 형식중복이 아니라 **번호 겹치는 두 별개 네임스페이스** → 단순 문자열치환은 데이터 손상.

## 1. 실태 (라이브 실측)
| 테이블 | OPV- 하이픈 | OPV_ 언더 | OPT- 하이픈 | OPT_ 언더 |
|---|---|---|---|---|
| t_prd_product_options | 96종(활성85·삭제11) | 815종 | 36 | 240 |
| t_prd_product_option_items | 51종(활성50·삭제5) | 748종 | — | — |
| t_prd_product_option_groups | — | — | 46 | 240 |
| t_prc_component_prices | 4종 | 48종 | — | — |
- 하이픈 OPV 범위 = **OPV-000001~000096**. 언더 OPV 범위 = OPV_000006~000833. **91개 번호 겹침**.

## 2. ★핵심: 겹치는 번호가 "같은 옵션"이 아니다 (병합 불가)
| 번호 | OPV-(하이픈) 뜻 | OPV_(언더) 뜻 |
|---|---|---|
| 000014 | "2개"(PRD_000016) | "끈(4개)추가"(PRD_000138) |
| 000026 | "화이트"(PRD_000004) | "말아박기"(PRD_000124) |
| 000074 | "원형 80mm"(PRD_000058) | "유광"(PRD_000024) |
| 000006 | "옵션1"(PRD_000066·del) | "열재단"(PRD_000138) |
→ 하이픈·언더는 **번호만 겹치는 완전히 다른 옵션**. `-`→`_` 문자열 변환 시 서로 다른 옵션이 **PK 충돌·병합**되어 데이터 파괴.

| 구성요소 | 하이픈 opt_cd | 의도(단가) | 실제 해결처(오참조) |

## 4. 별개로: 진짜 미등록 11 (하이픈/언더 둘 다 없음)
OPV_000473~483(키링 고리/볼체인 단가행) = **양쪽 형식 모두 옵션 정의 부재**. 형식문제 아니라 **옵션 미등록**.
(+ 키링 addon이 죽은 공식 PRF_ACRYL_KEYRING[상품0]에 갇힘 = 배선 끊김).

## 5. 왜 단순 변환이 안 되나 + 올바른 접근
- ❌ **단순 `-`→`_` 치환**: 91개 충돌 번호에서 서로 다른 옵션 병합 → 데이터 파괴. 절대 금지.
- ✅ **올바른 정규화 = 하이픈 코드 재번호(re-number)**: OPV- 96종을 미사용 언더 번호(OPV_000834+)로 재발급하되,
  각 코드의 **전 참조를 원자적으로 갱신**(options·items·component_prices·formula 배선). 또는 하이픈 코드가
  기존 언더 옵션과 **의미상 동일**하면 그 언더로 repoint(중복 제거), 고유하면 신 언더번호 부여.
- 판별 필요: 하이픈 96종 각각이 (a) 언더에 의미상 쌍이 있나(repoint) vs (b) 고유한가(신번호). 이 판별이 선행.

## 6. 미해결 질문 (사용자 확인 필요)
1. 하이픈 OPV/OPT 체계의 **출처** — 구 import 잔재인가? 언더가 정본이고 하이픈은 폐기 대상인가?
2. 재번호 vs repoint 정책 — 하이픈 코드를 신 언더번호로 살릴지, 의미 동일 언더로 흡수할지.
3. 실행 게이트 — 라이브 코드 재번호+참조갱신은 돈/기능 크리티컬 → 백업+DRY-RUN+webadmin 후 COMMIT.
