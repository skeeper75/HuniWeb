## 4. 규칙별 판정표

### 4.1 RULE-02 — **STILL_OPEN (잔여 · 원 위반보다 좁아짐)**

| 항 | 판정 | 근거 |
|---|---|---|
| ① 필드 목록 + **각 필드의** 도메인 출처 | **미충족(잔여)** | `design-FINAL.md:297`(`soft_prefs.axis: str`) · `:299`(`budget_krw` — `t_*` 출처 없음) vs `:306` 의 blanket 주장 |
| ② 미확정(unknown) 표현 방법 | 충족 | `:286` UNKNOWN 센티널 유일 · `:307` 누락/None/빈문자열 = 검증 실패 |
| ③ 스키마 검증 지점의 위치 | 충족 | `:308` `IntentValidator.validate()` 1곳 fail-closed · `:330-333` FIX-2 재파싱 대조 |

**[HARD] 원 위반(A7)과의 관계 — 교정은 실효했으나 규칙을 완전히 닫지 못했다.**

- **FIX-1 은 A7 이 지목한 것을 정확히 닫았다.** 원 위반은 *"`selections` 값 도메인 출처가 `_sim_dim_candidates` 1개 blanket 인데 그 함수가 실제 처리하는 축은 5축뿐"* 이었다. FIX-1 은 축 부류별 3분류(열거축 5 / 열거축 +1 / 비열거축 6)로 교체했고(`:315-321`), 비열거축 6은 `selections` 키에서 **제외**를 명시했다(`:319-321`). `print_opt_cd` 는 출처·NULL 제외·라벨 폴백·G0.5a 감시까지 닫았다(`:318`). **`selections` 축에 대해 blanket 은 소멸했다.**
- **그러나 `:306` 의 blanket 문장 자체는 살아 있다.** *"각 주석의 `t_*` 축 (요건 ①)"* 은 `Intent` **전 필드**를 덮는 주장인데, `soft_prefs`(`:297`)와 `budget_krw`(`:299`)의 주석에는 `t_*` 축이 없다. **A7 과 동일한 결함 유형(선언 범위 > 실효 범위)이 다른 필드에서 잔존한다.**
- 즉 이것은 새 결함이 아니라 **같은 규칙·같은 항의 미완 잔여분**이며, `selections` 축에서 비-`selections` 필드로 **좁아졌다.**

**등급 — 규칙 severity 는 BLOCKER, 판정 효과는 AMEND.**

codex 는 BLOCKER 를 주장했으나 §4.4 `MAJOR → BLOCKER` 승격이 요구하는 **교정 불가능성 논증**(뼈대를 바꿔야 함)을 제시하지 않았다. §4.2 의 구분을 적용하면:

- **구조가 틀렸다(REJECT)** — 아니다. `Intent` 그릇·UNKNOWN 센티널·단일 검증 지점 fail-closed·FIX-2 재파싱이 전부 제자리에 있다(`:286-308`, `:330-333`).
- **구조가 미완결이다(AMEND)** — 그렇다. 결손은 그릇 **안** 두 필드의 출처 선언 1줄씩이며, 교정이 **선언 추가**로 닫힌다.

원 라운드가 A7 에 대해 낸 해석(`gate-report.md:6.2`)과 **동일 논리를 동일하게 적용**했다. 해석 분기를 은폐하지 않고 기록한다.

> **재심 트리거** — 이 잔여 위반이 문서에 반영되지 않은 채 S1 이 착수되면 REJECT 로 승격한다(원 판정의 재심 트리거와 동일 구조).

### 4.3 `print_opt_cd` SELECT — 재배선인가 신규 규칙 작성인가 (렌즈 지정 쟁점)

**판정: 재배선. RULE-12 ① 위반 아님.** 근거와 반론 양쪽을 기록한다.

- **위반 방향 논거**: `_dim_options`(`price_views.py:1775`) 내부 중첩 클로저가 이미 이 열거를 계산하는데(`:323` 이 import 불가를 명시), 우리 층이 **동등 SELECT 1개를 작성**한다. 결과 집합을 산출하는 코드가 두 곳이 된다. 라벨 폴백 규칙(`print_side` → `print_opt_nm`)도 기존 계약의 복제다.
- **비위반 논거(채택)**: (i) violation_test ① 이 묻는 것은 **"정의가 사는 곳"** 이며, `print_opt_cd` 의 정의처는 여전히 `t_prd_product_print_options` + `del_yn` 계약 **1곳**이다 — 우리 SELECT 는 그 권위에 대한 **질의**이지 두 번째 **정의**가 아니다. (ii) 새 판단 규칙 0건 — 값 집합·라벨 규칙·필터가 전부 기존 계약의 전재(`:324`). (iii) 두 산출이 갈리는 사건 자체를 **G0.5a 가 기계 감시**하고 불일치 1건이면 빌드 FAIL·롤아웃 금지(`:318`, `:451`) — 즉 분기 상태가 조용히 지속될 경로가 봉쇄돼 있다.
- **재현 시도**: 이 항목으로 잘못된 산출이 나오는 시나리오를 구성하려면 두 산출의 불일치가 필요한데, 그 상태는 G0.5a 에서 fail-closed 로 차단된다(`:451` *"빌드 FAIL. 불일치 1건이면 롤아웃 금지"*). **재현 불가 → §2.1 기본값에 따라 각하.**
- **정직 기록**: 설계 스스로 이 지점이 §9 주장 1의 반증조건(*"새 도메인 규칙을 1줄이라도 작성해야 하면 틀렸다"*)과 접촉함을 은폐 없이 기록하고 *"'조립만으로 성립'이라 말한 강도는 약화된다"* 고 적었다(`:323-324`, `:785-787`). **이 자기신고는 RULE-12 위반이 아니라 RULE-05 계열의 정직성 자산이다.**

## 5. codex 오판 의심 건 [HARD · §6 오판 감사]

### 5.1 오판으로 집계한 것 — **0건**

codex 가 제기한 유일한 지적(RULE-02 ①)은 4개 FP 유형 어디에도 해당하지 않는다.

| FP 유형 | 해당 여부 | 사유 |
|---|---|---|

| **FP-3**(재현 실패) | 아님 | 설계 **자신의 워크스루 예시**(`:608` `axis:"mat_grade"`)가 재현 사례다. `mat_grade` 는 12축 어디에도 없고 문서 내 타 언급 0건 — 문서 존재성 테스트이므로 문서 자체가 재현 도구다(J-5 비해당: 이 항에 선행할 도메인 도구가 존재하지 않는다) |

### 5.2 오판은 아니나 조정한 것 — 주장 등급 1건

codex 의 **BLOCKER 주장 → 판정 효과 AMEND(MAJOR급)로 조정**. 사유는 §4.1 에 기록. §4.2 *"오판이 아닌 것"* 은 **등급 강등을 오판에서 제외**하므로 FP 로 집계하지 않는다. 다만 원 라운드 진단(§5.4 원인 ② *"검증 프롬프트의 등급 인플레이션"*)과 같은 방향의 신호이므로 기록한다 — **이번에도 유일한 지적이 최상위 등급으로 제출됐다.**

### 5.3 정밀도 집계 [HARD · §6.2 — 미기록 시 라운드 무효]

```
오판 감사 — R1 렌즈(스키마·구조) · codex 단독 제기

  제기 총건:  1    (codex RULE-02 ① · Claude 측 신규 제기 0)
  심리:       1    (각하: 0)
  중복 병합:  1 → 1  (합의 0쌍 — 단일 렌즈)
  확정 위반:  1    (RULE-02 ① 잔여 · 효과등급 AMEND)
  오판:       0    (FP-1 0 · FP-2 0 · FP-3 0 · FP-4 0)

  정밀도:     R/P = 1/1 = 1.00
```

원 라운드 정밀도 0.39 → 이 렌즈 1.00. **§6.4 진단 순서에 따른 해석**: 원 라운드의 낮은 정밀도 원인 진단(①루브릭 커버리지 공백 ②검증 프롬프트 등급 인플레이션)이 옳았다는 방향의 증거다 — 이번 프롬프트는 **"violation_test 의 정확한 항을 지목하고 그 문언으로만 판정하라 · test 가 묻지 않는 것을 재면 오판이다 · 위반이 없으면 없다고 답하는 것이 정상 결과다"** 를 명시했고, FP-4 가 0건으로 떨어졌다. **표본 1건이므로 일반화하지 않는다**(§7 일반화 금지 규율).

- `[범위 밖 관찰] 없음` — RULE-01·RULE-03 등 범위 밖 규칙으로 판정을 확장하지 않았다.
