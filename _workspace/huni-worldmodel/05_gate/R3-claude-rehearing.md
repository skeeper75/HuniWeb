## 0. 이 재심이 스스로에게 건 구속

1. **`violation_test` 축자 적용만 한다.** 원 라운드 오판 12건 중 11건이 FP-4(주장한 규칙의 test 를 적용하지 않고 다른 기준으로 판정)였다(`gate-report.md:317`). "test 가 재지 않는 것을 재면 오판이다"(`gate-report.md:296`)를 이 재심의 1번 규율로 삼는다.
2. **교정 여부를 사전에 가정하지 않는다.** "교정됐을 것"도 "안 됐을 것"도 가정하지 않고, test 항별로 문언을 대조한 결과만 쓴다.
3. **CLOSED 에도 근거를 댄다.** 근거 없는 CLOSED 는 §6.6 커버리지 정직 위반이다. 각 항의 충족처를 `파일:라인` 으로 지목한다.
4. **원본 재확인**(§3-1). 설계가 인용한 코드 좌표는 `raw/webadmin` 원본에서 직접 읽었다(읽기 전용).
5. **새 §11(자율성 경계 선언 · ESTC 3단 축)은 판정하지 않는다** — 루브릭 18규칙에 대응 규칙이 없다. 없는 규칙을 만들어 재면 그것이 FP-4다.

## 1. RULE-09 · 불확실성의 가시화 (MAJOR)

### 1.1 violation_test 축자 인용 (`evaluation-rubric.md:93`)

> 다음 두 시나리오에서 출력이 서로 **구별 가능**해야 한다 — ① 권위 판걸이수 룩업이 있는 사이즈의 견적 vs 기하 폴백으로 계산된 견적, ② 단가행이 실제로 0원인 구성요소 vs 단가행이 **없어서** 0원으로 처리된 구성요소. 설계 출력 스키마에서 두 쌍 중 하나라도 구별 필드가 없으면 위반.

이 test 가 묻는 것은 정확히 하나다: **설계 출력 스키마에 두 쌍을 구별하는 필드가 있는가.** 탐지 완전성·발생 건수·후속 처리의 적정성은 이 test 의 문언에 없다.

### 1.2 항 ① — 룩업 vs 기하 폴백

| 요구 | 충족처 | 판정 |
|---|---|---|
| 출력 스키마의 구별 필드 | `design-FINAL.md:360-361` — `price.confidence ∈ {CONFIRMED, PROVISIONAL, NONE}` + `confidence_reasons: [str]`(예시값 `'PANSU_GEOMETRIC_FALLBACK'`) | **구별 필드 존재** |
| 판정 입력 | `design-FINAL.md:438` §4.4 (f) — `SELECT ... FROM t_siz_pansu` 존재 조회 → `confidence` | — |
| 기계 검증 | `design-FINAL.md:719` G5 — `t_siz_pansu` 존재 조회 vs `confidence`, 불일치 0건 | — |

**항 ① 위반 없음.** (원 라운드도 ①을 위반으로 확정하지 않았다 — 확정 위반은 ②였다, `gate-report.md:272`.)

### 1.3 항 ② — 정당한 0원 vs 단가행 부재 0원 (원 확정 위반 A8)

**원 위반의 성격**: 개정 전 이분류(1차축 = `data_gap` 유무)가 무경고 경로(`matched_row is None ∧ data_gap == [] ∧ error is None`)를 `TRUE_ZERO`(정당한 0원)로 **오분류**해, 언더차지 1경로가 구별 대상에서 사라졌다(`gate-report.md:63`, R-7).

**FIX-8 교정본 대조**:

| 요구 | 충족처 | 확인 |
|---|---|---|
| 출력 스키마에 구별 필드 | `design-FINAL.md:367` — `"zero_reason": "TRUE_ZERO"\|"MISSING_PRICE_ROW"\|"UNSELECTED_DIM"\|"UNMATCHED_NO_GAP"\|None` (병기 `:365` `matched_row_id`) | 필드 실재 |
| 1차축 전환 | `design-FINAL.md:408-410` — *"1차축을 `data_gap` 이 아니라 **`matched_row`** 로 바꾼다"* | 오분류 원인 제거 |
| 4분류 판정표 | `design-FINAL.md:412-419` — 1 `TRUE_ZERO`(`included==True ∧ subtotal==0`) / 2 `MISSING_PRICE_ROW` / 3a `UNSELECTED_DIM` / 3b `UNMATCHED_NO_GAP` | 무경고 경로가 **1번(TRUE_ZERO)과 다른 값**으로 라벨링됨 |
| 판정 입력 배선 | `design-FINAL.md:439-440` §4.4 (g)(g′) — `matched_row`+`data_gap`+`error` 판독 + 3a/3b 판별용 **읽기전용 SELECT 1건** | 실행 경로 명시 |
| 기계 검증 | `design-FINAL.md:723` G8 — *"0원 구성요소의 `zero_reason` 4분류 정확성 … 3b 가 1건이라도 나오면 언더차지 후보로 실적재, 0건이면 그 사실 자체를 기록"*, 분모 = **0원 구성요소 전수** | 분모·임계 구비 |

**원본 재확인 (§3-1 · 읽기 전용)** — 설계가 근거로 든 무경고 경로를 라이브 원본에서 직접 읽었다:

```
raw/webadmin/webadmin/catalog/pricing.py:651-659   (_match_entry no_match 분기)
    if m["row"] is None:
        # no_match — … 경고는 내지 않음
        gap = _no_match_detail(rows, sel, use_dims)
        if gap:
            entry["data_gap"] = [...]
            entry["note"] = "단가 없음 — …"
        return entry, warns
```

`if gap:` 이 거짓이면 `data_gap` 도 `note` 도 붙지 않고 반환된다 — 설계가 기술한 무경고 경로가 **실재**한다. 설계 인용 좌표 `:655-660` 는 실제 `:651-659` 로 ±5행 오프셋이나 **내용은 그 범위 안에 실재**하므로 FP-2 로 집계하지 않는다(원 게이트의 동일 규약, `gate-report.md:300`).

3a 의 근거로 든 "미선택 vs 행 없음" 구분도 원본에서 확인된다 — `widget_api.py:462-463`: *"data_gap 은 '행이 실제로 구분하는 차원에 선택값이 있는데 그 값의 행이 없음'만 담는다(미선택·와일드카드 차원은 애초에 안 잡힘)"*.

**항 ② 판정**: test 가 요구하는 구별 필드가 스키마에 존재하고, 원 위반의 원인이던 오분류 경로가 별도 값(`UNSELECTED_DIM` / `UNMATCHED_NO_GAP`)으로 분리됐다. **위반 없음 — FIX-8 이 RULE-09 ②를 닫는다.**

### 2.3 항 ② — 인간 승인 게이트 (원 확정 위반 A2)

**원 위반의 성격**: G6 오라클(리플레이)이 **인간 승인 게이트 없는 라이브 write** 를 유발했다(`gate-report.md:272` A2 → RULE-13②·RULE-14② 동반 확정). 즉 "라이브 write 0건"이라는 전제가 거짓이었고, 거짓인 채로 게이트가 없었다.

**FIX-4 교정본 대조** — test 가 열거한 3종 행위 각각에 대해:

| 행위 | 교정 후 상태 | 충족처 |
|---|---|---|
| **라이브 write** | **경로 자체가 폐기**됐다. G6 리플레이는 **clone DB 단일 경로**이며, 라이브 대상 리플레이는 경로를 폐기 — `/handoff` 는 `t_wgt_handoff_logs` INSERT/DELETE(`widget_api.py:1677`·`:1733`), `/validate` 는 공통 게이트 `_gate` 에서 `t_wgt_widgets` UPDATE(`widget_api.py:135`)와 rate-limit 캐시 mutation(`:195-196`)을 유발하므로 "라이브 write 0건"과 양립 불가로 판정 | `design-FINAL.md:59`(§0 'G6 실행 환경' 행) · `:720`(§7 G6) · `:721`(오라클 경로 폐기 기록) · `:976`(§12-2) |
| 〃 (분모 정정의 근거 부담) | G1 분모에서 2테이블 제외는 **G1.1 대체 계측과 한 쌍으로만** 성립. *"근거 없는 제외는 RULE-13 ② 우회다"* 를 [HARD] 로 못박고, 대체 계측 미실행 시 **G1 을 46테이블 전수로 되돌리고 리플레이 자체를 금지** | `design-FINAL.md:713-714` |
| **주문 확정** | 위젯 `/price` 라이브 재계산 → **사람이 확인 버튼** → `/handoff` 서명. *"루프는 어떤 경우에도 스스로 주문을 확정하지 않는다"* | `design-FINAL.md:654`(§6 T6) · `:576`(§5.3) · `:987`(§12-13) |
| **가격 예외 승인** | `sim_escalation` 큐 → 실무진 라우팅(7종 매핑표, 미정 행 0건) | `design-FINAL.md:520-529` · `:512` |

**원본 재확인 (§3-1 · 읽기 전용)** — FIX-4 의 폐기 사유가 실재하는지 라이브 코드에서 직접 확인:

```
widget_api.py:131-135   (M.TWgtWidgets.objects.filter(pk=w.pk).filter(...)
                         .update(last_used_dt=timezone.now(), last_used_org=org))
widget_api.py:193-196   (cache.get_or_set(key, 0, timeout=120); cache.incr(key))
widget_api.py:140       (RATE_LIMIT_PER_MIN = 240   # LocMem — 프로세스 단위)
```

`/validate` 경유 공통 게이트가 **DB UPDATE 와 캐시 mutation 을 실제로 발행**한다 — 설계가 라이브 오라클 경로를 폐기한 근거는 원본에서 확인된다. 즉 FIX-4 는 **없는 위험을 이유로 한 과잉 축소가 아니라 실측된 위험에 대한 축소**다.

**test 문언 적용 결과**: test 는 *"라이브 write·주문 확정·가격 예외 승인 **중** 인간 승인 게이트가 없는 것이 1건이라도 있으면 위반"* 을 묻는다. 교정 후 (i) 라이브 write 를 수반하는 단계가 **0건**이므로 "게이트 없는 라이브 write"가 성립할 대상이 없고, (ii) 주문 확정은 사람 확인 게이트가 명시되며, (iii) 가격 예외는 실무진 큐로 라우팅된다. **위반 없음 — FIX-4 가 RULE-14 ②를 닫는다.**

**미정 행 0건**(`design-FINAL.md:531`). test 는 *"라우팅 목적지가 문서에 없으면 위반"* 만 묻는다 — 매핑표가 존재하는 이상 통과한다.

**자발 회피 기록 (FP-4 후보)**: *"목적지 중 일부가 큐가 아니라 트랙·화면이라 운영 실체가 불완전하다"*(`design-FINAL.md:531`·`:930`)는 사실 자체는 참이나, 원 라운드에서 **동일 취지의 지적 2건이 FP-4 로 집계**됐다(F6-2 `gate-report.md:296`, F3-2 `:291`) — *"test 가 재지 않는 것을 재면 오판이다"*. 이 재심도 같은 판정을 반복하지 않는다. 설계는 이 잔여 위험을 §11-10 에 감수 위험으로 등재했다(`:928-930`).

**추가 자발 회피**: *"'제약 미커버'에 대응하는 `esc_kind` 가 7종 중에 명시적으로 없다"* 는 후보를 검토했으나 제기하지 않는다 — (i) test 는 예시 3종의 **목적지가 문서에 있는가**를 묻고 매핑표가 미정 행 0건으로 존재하며, (ii) 제약 미커버 상황이 실제로 목적지 없이 통과한다는 **재현 가능한 실패 시나리오를 구성할 근거**(파일:라인)를 얻지 못했다. §2.1 기본값은 각하다.

## 3. FIX-5(과세 기준 3필드)의 효과 — 렌즈 R3 "돈" 축의 부기

FIX-5 는 원 라운드가 **"루브릭 커버리지 밖(실체 결함)"** 으로 분류한 항목이다(`design-FINAL.md:26`, `gate-report.md:273`). 즉 **어느 규칙도 이 축을 재지 않는다.** 따라서 이 재심은 FIX-5 에 대해 **위반/비위반 등급을 내지 않는다** — 없는 규칙을 만들어 재면 FP-4 이고, `gate-report.md:326` 이 이미 이를 **루브릭 개정안 ①**(RULE-04 에 과세 기준 항 추가)으로 등재해 다음 라운드 심의 대상으로 넘겼다.

렌즈 R3 의 관심사인 **언더차지 경로**에 대해서만 사실을 기록한다(등급 없음):

- `price` 가 `supply_amount` / `vat_amount` / `payable_total` **3필드로 분리**됐고(`design-FINAL.md:356-361`), `feasible != PROVEN_OK` 시 **3필드 전부 `None`** 강제(`:383`), `evaluate_price` 예외 시에도 **3필드 전부 `None` · 0원 대체 절대 금지**(`:772` §8-1 8번).
- 축별 판정 기준이 못박혔다 — 고객 표시·예산 = `payable_total`, 권위 격자(260705) 대조 = `supply_amount`(`:393-395`, `:718` G4, `:486-489` Scorer).
- 갈림의 **실측 오차 규모는 미측정**임을 `[미확정 · U-1]` 로 유지하고(`:396`, `:963`), 첫 실측을 **G10 신설**(clone 환경에서 `payable_total` vs `/handoff` 서명 `total`, 허용오차 0)로 걸었다(`:725`).

이 세 사실은 RULE-06(제약×가격 결합)·RULE-13①(fail-open 금지)의 test 와도 정합하나, **그 두 규칙은 이 렌즈의 재심 대상이 아니므로 판정하지 않는다.**
