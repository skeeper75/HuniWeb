# 접지카드(027/028/029) 접지비 배선 — 가격표 대조 + 정립 설계 (260701)

권위: `docs/huni/후니프린팅_인쇄상품_가격표_260527.xlsx` 시트 `접지옵션`.
검토 대상: PRD_000027(2단접지카드)·PRD_000028(미니접지카드)·PRD_000029(3단접지카드).
결론 한 줄: **(a) 리플렛 단가 재사용이 권위상 정확 — 단가는 손대지 말고, 깨진 옵션→공정 매핑(option_items)만 복구.**

## 1. 가격표 원본 대조 결과 (결정적)

`접지옵션` 시트는 **두 개의 단가표**를 담는다:
- **카드접지 단가 (오시+접지)**: 컬럼 `2단(2단가로/세로접지)`·`3단(3단가로/세로접지)`·`6단(6단오시/미싱접지)`.
- **리플렛 접지 단가 (오시+접지)**: 컬럼 `반접지`·`3단접지`·`4단병풍접지`·`4단대문접지`.

즉 "카드전용 접지 단가표"는 문서상 **개념적으로 실재**한다(별도 섹션·별도 행 헤더). 그러나 숫자를 48개 제작수량 tier 전부 대조하면:

| 카드접지 컬럼 | 리플렛 컬럼 | tier 불일치 수 |
|---|---|---|
| 2단 (가로/세로) | 반접지 | **0 / 48** (완전 동일: 5000·3000·2000…40) |
| 3단 (가로/세로) | 3단접지 | **0 / 48** (완전 동일: 6000·4000·3000…50) |
| 6단 (오시/미싱) | 4단병풍/대문 | 다름(6단=6000·5600…, 병풍=7000·5000…) |

→ **카드 2단 = 리플렛 반접지, 카드 3단 = 리플렛 3단접지 (단가 verbatim 동일).** 6단만 카드 고유(단, 6단=지그재그엽서030 몫이고 027/028/029 는 2단·3단만 사용 → 무관).

## 2. 라이브 실측 (오늘 재확인)

- `t_prc_component_prices`: `COMP_FOLD_LEAF_HALF`(proc 065/066/107)=5000·3000…, `COMP_FOLD_LEAF_3FOLD`(proc 060/067/068)=6000·4000… → 권위 카드표와 셀 단위 일치. `COMP_FOLD_CARD_2H/3H`(proc_cd NULL 와일드카드)도 같은 숫자(중복).
- 공정명: PROC_000065=2단가로, 066=2단세로, 067=3단가로, 068=3단세로.
- `t_prd_product_processes`: 027·028 = 065+066 등록, 029 = 067+068 등록(모두 del_yn=N).
- `t_prc_formula_components`: PRF_DGP_E / PRF_DGP_E_FOIL 는 FOLD_LEAF_HALF(4)·3FOLD(5)·4ACC(6)·4GATE(7) 배선. **CARD_2H → PRF_DGP_C·PRF_FOLD_SUM 뿐(DGP_E 미배선)**, CARD_3H → **어디에도 미배선(진짜 고아)**, CARD_6CR → PRF_DGP_C_6CR.
- 따라서 가격 인프라(단가+배선)는 027/029 접지비를 이미 **권위대로** 계산할 준비 완료. FOLD_LEAF 가 proc_cd 065/066/067/068 로 키잉되어 방향별 단가를 정확히 낸다.

## 3. 진짜 결함 = option_items(옵션→공정 활성) 층 (배경 기술 일부 정정)

배경은 "비기본값 세로접지의 ref_key1 이 NULL(깨진 참조)"이라 했으나, 스키마상 `ref_dim_cd`·`ref_key1` 은 NOT NULL → NULL 참조 자체가 불가. 라이브 실측 결과 정확한 상태는:

| 상품 | 옵션 | 이름 | dflt | item 상태 |
|---|---|---|---|---|
| 027 | OPV_000107 | 2단 가로접지 | Y | item 존재하나 **del_yn=Y**(오늘 15:07 생성 직후 논리삭제) |
| 027 | OPV_000108 | 2단 세로접지 | N | **item 행 자체 부재** |
| 029 | OPV_000135 | 3단 가로접지 | Y | **item 행 자체 부재** |
| 029 | OPV_000136 | 3단 세로접지 | N | **item 행 자체 부재** |

→ 손님이 어느 방향을 골라도 해당 proc_cd 가 활성화되지 않아 접지비가 **무료(0)**로 빠진다. 특히 029 는 기본값(3단가로)마저 item 이 없어 접지비 전방향 0. 027 기본값도 del_yn=Y 라 위젯/주문 리졸버가 del_yn 을 필터하면 가로마저 0(배경의 "가로는 정상" 가정은 라이브와 불일치 — 안전측으로 함께 복구).

## 4. 심의 — 경로 (a) vs (b)

**경로 (a) 리플렛 단가 재사용 + 옵션 참조 복구 [권고]**
- 근거: 권위 카드 2단/3단 단가 = 리플렛 반접지/3단접지 단가 verbatim 동일 → FOLD_LEAF 재사용의 청구액이 카드전용표 청구액과 원단위까지 같다. 돈 변화 0.
- 작업: option_items 3행 추가(108→066, 135→067, 136→068) + 107 del_yn Y→N 복원. 단가·배선 무수정.
- CARD_2H/3H: 미사용 확정(중복). **use_yn=N 후보로 표시만, 삭제 금지**(기초코드 삭제금지 원칙). CARD_6CR·CARD_2H(PRF_DGP_C/FOLD_SUM 쪽)는 타 상품 몫이라 불건드림.

**경로 (b) 카드전용 단가로 전환 [비권고]**
- PRF_DGP_E/E_FOIL 에서 FOLD_LEAF_HALF(065/066)·3FOLD(067/068) 배선을 제거하고 CARD_2H/3H 에 proc 065~068 판별차원 신설 대체.
- 트레이드오프: (i) 청구액 이득 0(단가 동일). (ii) 049 와이드접지리플렛(PROC_000060 via 3FOLD)·리플렛류 전체가 같은 comp 를 공유 → 배선 제거 시 회귀 위험. (iii) 028 은 065/066 을 027 과 공유. 이득 없는데 리스크만 도입.
- 결론: 기각. 단가가 동일한 이상 comp 를 갈아끼울 이유가 없다.

## 5. 이중과금 0 증명 (경로 a)

PRF_DGP_E 내에서 proc_cd 별로 매칭되는 FOLD comp 를 라이브 조인으로 전수 확인:
`065·066·107 → HALF 단독`, `060·067·068 → 3FOLD 단독`, `071 → 4ACC 단독`, `106 → 4GATE 단독`. **한 proc_cd 가 두 FOLD comp 에 동시 매칭되는 경우 0.** CARD_2H/3H 는 PRF_DGP_E 조인에 애초 등장하지 않음(미배선). 따라서 손님이 방향 하나를 고르면 정확히 한 comp·한 단가만 적용 → 이중과금 불가.

## 6. 골든 기대치 (COMMIT 후, 위젯/주문 리졸버 기준)

- 027 qty1 **가로접지**: proc 065 → HALF@065 q1 = **5,000** (복원 후 유지).
- 027 qty1 **세로접지**: proc 066 → HALF@066 q1 = **5,000** (수정 후 신규 발현, 가로와 동일).
- 029 qty1 **가로접지**: proc 067 → 3FOLD@067 q1 = **6,000**.
- 029 qty1 **세로접지**: proc 068 → 3FOLD@068 q1 = **6,000**.
