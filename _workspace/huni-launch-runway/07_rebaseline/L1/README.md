# L1 — 인쇄 이커머스 표준 기능목록 (독립 수립)

> 카드 t28 / 07_rebaseline L1 · 작성 2026-09-02 · plan-huniweb 세션
> 산출: `standard-feature-canon.csv` (353행)

## 1. 이 목록이 무엇인가

**"후니가 지금 무엇을 가졌는가"가 아니라, "인쇄 이커머스라면 무엇이 있어야 하는가"** 를 밑에서부터 세운 목록이다.
현행 자산(260616 IA 엑셀·launch-scope 162기능·runway 410항목)은 **분모로 참조하지 않았다.** 대조는 L4의 일이며,
여기서 오염되면 L4의 핵심 성과인 「IA가 놓친 기능(`new`)」을 찾을 수 없기 때문이다.

## 2. 분류 체계와 그 근거

기능을 16개 대분류로 나눴다. 분류 축은 임의로 정한 것이 아니라 **주문 한 건이 실제로 지나가는 경로**와
**그 경로를 떠받치는 운영 축**을 따랐다.

### 2.1 고객 경로 축 (주문 1건의 생애)

```
카탈로그 → 옵션·견적 → 원고·파일 → 장바구니·주문 → 결제 → 배송 → 클레임·CS
```

| 대분류 | 행수 | 왜 독립 축인가 |
|---|---:|---|
| 상품·카탈로그 | 22 | 인쇄는 **주문 시작 전에 이미 막힌다**. 레드프린팅은 명함을 10종 이상 별도 상품으로 분할해 "부분UV(구.스코딕스)"를 상품명으로 노출한다 — 상품 선택 자체가 도메인 지식을 요구하는 관문(`print-story/02_capture/order-flow-steps.md §A-0`) |
| 옵션·견적 | 55 | **가장 큰 축.** 일반 커머스의 "옵션"과 다르다. 용지×평량×도수×규격×수량×건수×후가공 다축 조합에 캐스케이드·제약이 걸리고, 축 하나가 비면 가격이 아예 안 나온다(책자 페이지수 미입력 시 0원 — `§D`) |
| 원고·파일 | 28 | 커머스 플랫폼이 통째로 미지원하는 인쇄 고유 영역. 업로드·검판·미리보기·에디터·보관이 각각 독립 기능군(`print-kb/wiki/policy/custom-dev.md#CST-01`) |
| 장바구니·주문 | 27 | 표준 커머스 흐름 Cart → OrderSheet → Purchase. 단 인쇄옵션+파일이 카트 항목에 동반돼야 함(`huni-shopby/01_research/commerce-flow-contract.md`) |
| 결제 | 18 | 결제수단 + 결제처리 + 증빙(세금계산서·현금영수증). 인쇄는 B2B 비중이 커서 증빙이 선택이 아님 |
| 배송 | 16 | 배송비 정책(무료기준·제주·도서산간·혼합주문)이 규칙 엔진 수준. 대형 인쇄물은 무료배송 제외 예외까지 필요(`print-kb/wiki/policy/shipping.md#SHIP-03`) |
| 클레임·CS | 20 | 플랫폼 클레임(취소·반품·교환) + **인쇄 고유 불량/재제작**. 인쇄는 맞춤제작이라 착수 후 취소 규칙이 별개(`operations.md#OPS-01`) |

## 3. 인쇄 특수 vs 일반 커머스

| 구분 | 행수 | 비중 |
|---|---:|---:|
| 인쇄특수(Y) | 153 | 43.3% |
| 일반커머스(N) | 200 | 56.7% |

**「Y」 판정 기준**: 그 기능이 일반 쇼핑몰 패키지에 없거나, 있더라도 인쇄 도메인 개념(도수·판형·도련·검판·공정) 때문에
구조를 바꿔야 하는 것. 예 — "수량 선택"은 N이지만 "건수 입력 + 총량=건수×수량"은 Y다(`order-flow-steps.md §A-4·A-5`).

## 4. 필수도 판정 기준

| 등급 | 행수 | 기준 |
|---|---:|---|
| must | 226 | 없으면 **주문 1건이 끝까지 못 간다**. 또는 법·회계상 필수(증빙·개인정보) |
| should | 101 | 없어도 주문은 되지만 운영 부담이나 이탈이 눈에 띄게 커짐 |
| could | 26 | 있으면 좋음. 오픈 후 추가 가능 |

「must」는 오픈 판정용이 아니라 **표준 기능목록으로서의 필수도**다. 후니 10/6 오픈 범위 판정은 L5의 일이다.

## 7. 다음 카드로의 인계

- **L4**에 넘길 것: `std_id`가 병합 원장의 **뼈대**가 된다. L3 `legacy_id`를 여기에 N:M 매핑하고, 표준목록에는 있는데
  legacy에 없는 행이 곧 `new` = **IA가 놓친 기능**이다.
- **L5**가 볼 것: `필수도=must` × `인쇄특수여부=Y` 교집합(107행)이 오픈 임계경로에서 가장 위험한 구간이다.
