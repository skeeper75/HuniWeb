# 프린틀리 데이터 공간 — 후니 먼저 (인쇄소 가기 전까지)

> 준비: 2026-07-04 · 지니 지시 = "인쇄소 가기 전까지 그릇까지 + 인쇄소 연결. 생산과정은 다음 스텝. 후니 먼저. 데이터 쌓을 공간만 준비."
> **이 폴더 = 온톨로지 데이터를 후니부터 하나씩 쌓아가는 조직된 공간.** 지금은 **빈 그릇(템플릿)만** — 채우기는 다음.

## 무엇을 담나 (범위)

```
[니즈] → [추천] → [홍보물 레시피(구성요소)] → [가격] → [인쇄소 연결]  ← 여기까지 그릇 준비
                                                              └──▶ [생산: 파일규칙·잡티켓·장비·배송] = 다음 스텝(그릇 미준비)
```

- **포함**: 업종→목적→홍보물 추천 · 홍보물별 구성요소 레시피(6부류) · 가격 연결 · **인쇄소(벤더) 연결**까지.
- **제외(다음 스텝)**: 인쇄소에 넘긴 뒤의 생산과정(파일 규칙 형성·잡티켓 실행·장비 연결·배송). 벤더/장비 데이터가 있어야 채워지므로 지금은 안 만든다.
- **벤더**: 후니프린팅 먼저. 와우·레드는 같은 구조로 나중에 확장(§35 브랜드-중립 상위 개념 재사용).

## 채우는 법 (다음 스텝부터)

1. `recipes/_INDEX.md`에서 채울 후니 홍보물 하나 고름.
2. `_TEMPLATE.json` 복사 → `recipes/<상품>.json`.
3. 6부류(재료·공정·가격구성요소·옵션·제약·생산가능성)를 **라이브(§33)·권위 엑셀·RED 생산지식**으로 채움.
4. `인쇄소 연결`에 후니 배선.
5. 종단 검증(추천→레시피→가격 실엔진) → `_INDEX.md` 상태 갱신.

## 원칙 (채울 때도 유지)

- **원칙 1**: 이 데이터가 진실원본(로직 하드코딩 금지).
- **원칙 3**: 값(가격·칼선 길이·생산시간)은 **엔진**이 계산. 그릇엔 "축"까지만·값 지어내기 금지.
- **원칙 4**: 모든 슬롯에 근거(node_id·prd_cd·출처). 근거 없으면 비워둠(GAP).
- **원칙 6**: 기존 §33/§35 재사용 우선(중복 mint 금지). 새로 만드는 건 생산가능성 축·인쇄소 연결처럼 없는 것만.
