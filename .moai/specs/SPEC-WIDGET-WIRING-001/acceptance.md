# 수용 기준 — SPEC-WIDGET-WIRING-001

> [HARD] 의례 최소화: 기준은 **기계 판정 가능한 8개**로 한정. 별도 게이트 문서·다중 라운드 없음.
> 검증은 산출물 파일과 콘솔 출력으로만 한다(스크린샷·수기 표 불필요).

| AC | 기준 | 판정 방법 | 실패 조건 |
|---|---|---|---|
| **AC1** 분모 | 스냅샷 `t_prd_products` 활성 행수 == 라이브 실측(260821 기준 266) | `wc -l` + 라이브 SELECT COUNT | 불일치 |
| **AC2** 전수 | `out/wiring-health/*.json` 파일 수 == 분모 | `ls \| wc -l` | 누락 1건이라도 |
| **AC3** 무-mint | 신규 파일이 §plan 5개(어댑터 1·bin 3·html 1) 이하이고, `raw/webadmin/**` 와 `hdx/diagnose/*` 기존 파일 diff 0 | `git status` · `git diff --stat` | 원본 수정 발견 |
| **AC4** 드리프트 0 | 어댑터 결함 카운트가 원본 센서 직접 실행 카운트와 코드별 일치 | 원본 5센서 실행 vs `widget-defects.jsonl` 집계 | 어느 코드든 불일치 |
| **AC5** 엣지 커버 | §3.2 10개 엣지(W1~W5·C1·E1~E4) 전부 산출 JSON 스키마에 존재하고, 각 엣지가 최소 1회 판정됨(결함 0도 판정) | index JSON 의 `edges_evaluated` | 미판정 엣지 존재 |
| **AC6** 읽기전용 | 라이브 DB write 0·DDL 0 | 실행 로그에 INSERT/UPDATE/DELETE/ALTER 0건 | 1건이라도 |
| **AC7** 아티팩트 | 단일 HTML 이 외부 요청 없이 열리고, 상품 선택→계층 드릴다운→단절 엣지 강조→필터가 동작 | 브라우저 실행 1회(스모크) | 기능 1개라도 미동작 |
| **AC8** 결정론 | 같은 스냅샷으로 재실행 시 `wiring-health/*.json` 바이트 동일(타임스탬프 필드 제외) | 2회 실행 후 diff | 차이 발생 |

## 판정 규칙

- AC1~AC6 은 **배치 자체가 출력**한다(사람이 세지 않는다).
- 전체 GO = AC1~AC8 전부 통과. 하나라도 실패 = NO-GO, 실패 항목만 재실행.
- 결함이 **많이 나오는 것은 실패가 아니다** — 이 SPEC 은 진단기이지 교정기가 아니다.
  실패는 "판정하지 못했다/드리프트했다/원본을 건드렸다" 뿐이다.
