## 4. [HARD] 폐기 — 이 세션의 일괄 측정 도구는 믿지 말 것

`_workspace/price-setup/widget-fix/recheck-result.json` 과
`zeroscan/proc-result.json` 의 **`sent`(보낸 공정) 필드는 신뢰할 수 없다.**

증거(자기모순):
- `sent=[]` 인데 가격 내역에 **디지털인쇄비 5,600원**이 찍힌 상품 다수
- 접지리플렛 자리에 **트윈링책자 가격**이 표시 — 상품 전환과 렌더가 어긋남

원인: `window.__last` 가 마지막 요청 하나만 담아 어느 상품 것인지 보장이 없고,
화면 총액도 렌더 지연으로 이전 상품 것이 남는다.

**믿을 수 있는 것은 단건 확인뿐이다** — 한 상품을 열고, 옵션을 고르고, 가격 진단을 읽는 것.
그렇게 확인한 것: 종이슬로건 · 라벨/택 · 프리미엄명함 · 2단접지카드.

다만 **`proc-result.json` 의 대상 선정(34종)과 상품·공식 매핑 정보는 유효**하다 —
그것은 DB 조회로 만든 것이고 브라우저 타이밍과 무관하다.

1. **10종의 원인을 단건으로 규명한다.** 프리미엄엽서 `PRD_000016` 하나를 열어
   후가공 컴포넌트를 클릭하고 **우측 속성 패널의 `proc_filter`** 를 본다.
   필수공정 `PROC_000004` 가 필터에 포함돼 있는지가 첫 질문이다.

2. **수정한 10종을 단건으로 재확인한다.** 일괄 측정 말고 하나씩:
   상품 선택 → 미리보기 → 옵션 전부 선택 → **가격 진단** → 구성요소별 포함/제외 확인.

   - (3번 안) **옵션 참조 공정을 가격에 유입** — `_expand_opt_sels` 「가격 불변 선언」 재검토.
     옵션그룹으로 공정을 노출하는 9종이 여기 걸린다. **개발 사항.**

## 8. 이 세션이 지키지 못한 것

- 일괄 측정 도구를 만들어 놓고 **그 정확성을 먼저 검증하지 않았다.** 자기모순이 드러난 뒤에야
  알았다. 도구가 낸 수치를 근거로 쓰기 전에 **알려진 정답 1건으로 도구를 먼저 시험**해야 했다.
- 백업을 메모리에만 두고 **파일로 즉시 내리지 않았다.** 페이지를 다시 여는 순간 잃었다.
