# WebToProduct 분석 — RED 원본 덱 (프린틀리 청사진)

> 원천: `docs/redprinting/디지털을인쇄생태계를 만드는힘.pdf`(133p·RED Printing & Press·2017.9.12·Johannes Park 발표).
> 목적: 지니의 WebToProduct 원본 확인 → 프린틀리 시스템·리서치 구체화 근거. 이 덱은 **RED의 운영 모델**(참조)이고, 소상공인 상품 카탈로그는 후니 홍보물(§33)이 담당.

---

## 1. WebToProduct 정의 (RED가 만든 용어)

- **Web to Print** = 온라인 상점 + 인쇄. "웹사이트만 있다"는 수준. RED는 "진정한 Web-to-Print를 운영하는 회사를 거의 못 봤다"고 지적.
- **Web to Product**(RED 신조어) = **실생산을 포함하는, 주문→완제품→배송까지 논스톱으로 조직된 시스템.** 비유="온라인 식당"(웹사이트=간판, 진짜 승부는 주방·표준화·통합 운영).
- 디지털 인쇄의 강점 = **개별 소량·복잡 후가공을 스마트하게**(옵셋 대량생산과 경쟁 X). "1 PIECE OK, COMPLICATED DESIGN OK".

## 2. 3대 핵심 원칙 (RED)

1. **MINIMIZING HUMAN INVOLVEMENT** — 반복 공정 사람 개입 최소화(실수↓).
2. **EASY PLATFORM** — 우연히 온 사람도 편한 플랫폼.
3. **CONNECTING EQUIPMENTS** — 모든 장비를 하나의 큰 흐름으로 연결.
- 설계 철학: **"장비엔 기본 기능만, 나머지(파일 관리 등)는 장비 밖에서"** → 오퍼레이터는 장비 작동에만 집중(실수↓·생산성↑). = 프린틀리 원칙 2(3추론 분리)와 동형.

## 3. ★핵심 엔진 = 잡티켓의 진화 (Evolution of Job Ticket)

주문 하나가 생산 전 공정을 관통하는 **데이터 계약**. = 프린틀리 PART 2 계약 연쇄의 실체.
- **잡티켓 필드**: 요일·고객명·배송방법·파일수신/조판 시각·배송지·연락처·아이템·파일명·비고·**용지(substrate)**·메모·**주문수량**·**인쇄 필요 매수(판수)**·**재단 사이즈**.
- **후가공 순서 10단계**: 1.인쇄 2.라미네이션 3.스코딕스 4.finishing 5.커팅 6.라운드코너 7.접지 8.제본 9.악세서리 10.소모품.
- **CORE ENGINE 기능**: PROCESS MANAGEMENT · VARIABLE IMPOSITION · CONSTANT BUG FIX · COLLECTING FEEDBACK. "혁신이 아니라 경청·반응 태도가 개선 엔진".

## 4. ★20단계 WebToProduct 파이프라인 (주문→발송)

```
①주문접수 → ②견적 → ③결제 → ④인쇄파일검사(preflight) → ⑤자동수정 → ⑥똑똑한 조판(imposition)
→ ⑦후가공별 파일분리 → ⑧장비별 파일변환 → ⑨인쇄출력 → ⑩커팅 → ⑪금은박 → ⑫스코딕스
→ ⑬미싱 → ⑭오시 → ⑮반칼 → ⑯재단 → ⑰제본 → ⑱분류 → ⑲포장 → ⑳배송 → 고객 문자발송
```
- 전반부(WEB→견적)=소상공인 대면·추천/견적. 후반부(PRODUCT)=생산·배송. 잡티켓이 둘을 잇는 계약.

## 5. ★장비별 파일변환 매트릭스 (파일포맷 실물 근거)

각 공정/장비가 요구하는 **입고 파일포맷이 다름** — 프린틀리 ⑥ 파일포맷 엔티티의 실 근거.
- **포맷 종류**: `JDF · XML · ZCC · TIFF · PDF · GPGL · PLT · CSV`.
- **공정→포맷 예**: KISS CUT/CREASE/DASHRULE(반칼·오시·미싱)=GPGL/ZCC/PLT · SCODIX=TIFF/JDF · FOIL(금은박)=PDF/JDF · 재단=JDF · 제본=JDF · 실사=PDF/PLT · CMYK 인쇄=PDF.
- **후가공별 파일분리 → 장비별 파일변환 → 각 장비 투입.** 이게 결정론 파일변환 엔진(원칙 3).

## 6. 장비·후가공 인벤토리 (RED 보유)

- **장비**: 인디고(디지털)·커팅플로터·로타리 다이커터·평판 커팅기·버튼 제작기·잡티켓 프린터·카드인쇄기·사진인화기·(스코딕스 울트라·하이콘 유클리드 등 후가공기).
- **후가공(Finishing)**: 라미네이션·스코딕스·금은박(Foiling)·레이저커팅·오시(Creasing)·접지(Folding)·제본(Binding)·재단(Cutting).
- **확장성**: 같은 장비 2대+ **복제(cloning)** + 중앙 통제. **모듈화**(필요 기능만 모듈 선택).
- **관여 인력**: CS·오퍼레이터·포장팀·QC팀·SW개발팀·디자인팀·의사결정권자.

## 7. WEB TO PRODUCT 최종 공식 (RED 결론 슬라이드)

- **WEB**: 고객 정보 수집.
- **PRINT**: 후가공 공정 기반 **자동 견적/프리플라이트/임포지션**. ★"인쇄뿐 아니라 **후가공까지 견적·프리플라이트**" · "인쇄파일+후가공파일 교정" · **후가공 장비 결정(Decision on finishing machine)** · 후가공 단계 기반 임포지션.
- **PRODUCT**: Finishing(라미·스코딕스·포일·레이저커팅·오시·접지·제본·재단) + 분류/포장/배송.

## 8. 프린틀리 매핑 (핵심 시사)

| RED WebToProduct | 프린틀리 대응 | 상태 |
|---|---|---|
| 20단계 파이프라인 | PART 2 런타임 루프(맥락→제안→선택→견적→매칭→파일변환→생산배송) | **거의 1:1 일치** |
| 잡티켓(데이터 계약) | PART 2 계약 연쇄 | 실물 근거 확보 |
| 견적=인쇄+**후가공 포함** | ④ 견적 엔진(evaluate_price) | ★후니 evaluate_price가 후가공까지 견적하는지 점검 필요 |
| 장비별 파일변환 매트릭스 | ⑥ 파일포맷 엔티티 + 파일변환 엔진 | 실 포맷(JDF/ZCC/GPGL/PLT…) 확보 |
| 후가공별 파일분리+장비 결정 | 프리플라이트·임포지션·라우팅 엔진(원칙 3) | 후가공 공정 기반 결정론 |
| 장비=기본기능만·나머지 외부 | 원칙 2(3추론 분리·선언/절차/결정론) | 철학 동형 |

**결정적 시사**: WebToProduct의 견적·프리플라이트·임포지션·파일변환은 **"후가공 공정(finishing process)"을 축으로 자동화**된다. 즉 후가공 순서(10단계)가 생산 파이프라인의 뼈대다. 프린틀리 온톨로지의 사양·장비·파일포맷은 **후가공 공정 축**으로 엮여야 한다.

## GAP
- 이 덱은 RED의 **운영 모델·비전**(2017)이지 소상공인 상품 카탈로그가 아님 → 소상공인 상품(홍보물)은 후니 §33·업종 리서치가 담당.
- 잡티켓·파일변환 매트릭스는 슬라이드 다이어그램 수준(정밀 필드·포맷-공정 대응은 재구성·검증 필요).
- RED 내부 SW 아키텍처(코드)는 비공개 — 파이프라인 형태까지만.
