# 드리프트 전수 스캐너 — 260 상품 커버리지 diff (drift-v1·260707)

**목적:** 「상품 등록 base코드 ≠ 가격 적재 base코드」(base-data 드리프트)를 **전 상품 전수** 탐지.
v4 배치 스캐너(final=0만 봄)가 놓친 **일부 조합만 되는 부분 드리프트**를 커버리지 diff로 적발한다.

## 왜 v4로는 안 됐나
v4는 기본조합(dflt) 1개만 시뮬레이션 → `final>0`이면 OK. 그래서 **기본값은 가격이 있고 일부 값만 미적재**인
경우를 전부 정상으로 오판했다. 예: 프리미엄명함은 기본지(랑데뷰)로 4,500원이 나와 v4=정상이지만,
등록된 특수지 8종은 단가행이 없어 손님이 고르면 **가격 0**.

## 방법 (커버리지 diff)
상품별로 ①양호 baseline 조합 확립(v4 로직 재사용) → ②**가격키 차원(base 구성요소 `use_dims`) 값을
하나씩 스윕**(다른 차원 baseline 고정) → ③상품은 제공하나 `final=0`인 값 = **미커버 셀**.
추가로 ④**구조 드리프트**: 가격 그리드가 요구하는 스칼라 차원이 상품 `prod_dims`에 미등록이면 적발(셀프견적 불가).

- 도구(`batch-scan/`·읽기전용): `drift_scan.js`·`gen_drift.py`·`run_drift.sh`·`analyze_drift.py`.
- 산출: `results/drift-v1.jsonl`·`drift-diagnosis.csv`(상품별)·`drift-cells.csv`(미커버 셀 = 교정 매니페스트 씨앗).
- 사용법: `bash run_drift.sh` (배치). 재스캔=`python3 gen_drift.py "PRD_x,PRD_y" && browse eval /tmp/drift_run.js`.

## ★화이트인쇄명함(PRD_000040) 구조 드리프트 — 교정 완료 (260707)
- **권위(상품마스터260703 r153 + 가격표260705 B06 교차)**: 화이트 인쇄(단면/양면) × 클리어(없음/단면/양면) 2차원. 4유효조합=단면+없음14500·단면+클리어단면16000·양면+없음16000·양면+클리어양면19000. (마스터 r153은 default 1행이라 면수 미기재·단면만 아님.)
- **근본원인**: 라이브 인쇄옵션(단면 opt_id1·양면 opt_id2) **둘 다 논리삭제(del_yn=Y)** + opt_id1 print_opt_cd **NULL** → 활성 print_opt 0 → MISSING_DIM.
- **교정**: ①섹션 endpoint로 2행 복원(del_yn Y→N·opt_id1 print_opt_cd=POPT_000001·단면 기본Y) ②그리드 COMP_NAMECARD_WHITE opt_cd 재키(양면행 490→810·insert1/delete1). **검증: 4조합 전부 권위 일치·제외0.**
- **잔여(오탐·엔진한계)**: 드리프트 스캐너가 클리어양면(810)을 단면 baseline에 스윕해 오검출(상관차원). 클리어 면수는 화이트 면수를 따라야 하는데 **제약엔진이 print_opt_cd(=opt_id·OPT_REF_DIM.06)를 시뮬 cascade(`_SIM_DIM_CONSTRAINT`)에서 미지원** → 제약규칙으로 못 막음. 손님이 (단면+클리어양면) 선택 시 0원. **코드 확장(제약 cascade에 opt_id 추가) 필요 = 개발 전달 후보.**

## ★제약엔진 한계 (지니 질문 답·시뮬레이터 제약 사용방식)
- 시뮬레이터 제약=**프런트 cascade(비활성화) 용도**(`_sim_constraints_meta`)·가격 차단 아님(불가조합=매칭행 없어 0원).
- cascade 지원 차원(`_SIM_DIM_CONSTRAINT`)=siz·plt_siz·mat(usage)·proc·bdl_qty + 옵션그룹/옵션(sel_opt_grps/sel_opts). **도수/인쇄옵션(opt_id·OPT_REF_DIM.06)·셋트(sub_prd_cd)는 모델(VAR_KEY_MAP)엔 있으나 시뮬 cascade엔 없음** → 인쇄면 관련 제약은 현재 시뮬에서 미작동.

## ★결정론 verifier 신설 = 상관차원 오탐 해결 (raw/webadmin/tools/verify_price_coverage.py)
브라우저 스윕의 상관차원 오탐(폼/포맥스)을 **결정론 DB verifier**로 대체. 핵심=**값별 any-row-exists**
(그 값이 어느 행에든 존재하나만 봄→대각 그리드 오탐 원천 제거). verify_load.py와 한 결·읽기전용·exit 0/1.
- 실행: webadmin에서 `../.venv/bin/python tools/verify_price_coverage.py [--prd PRD_x] [--json]`.
- 검출: MISSING_DIM(차원 통째 미등록)·UNCOVERED(등록값 그리드 매칭 없음). 검사=siz/mat/print_opt/opt(스코프)/bdl_qty·보류=proc_cd/plt_siz.
- **검증됨**: 폼/포맥스/화이트=CLEAN(오탐 0)·교정4건=CLEAN·**브라우저가 놓친 base-material 갭 3건 신규검출**
  (아크릴마그넷 MAT_000050 자석·아크릴집게 MAT_000056·아크릴머리끈 MAT_000057 — 부자재가 소재로 등록됐으나 base mat 단가 0·add-on이 final>0로 가림=브라우저 false negative). 권위·화면 확인 후 판정 필요.
- 전수: 완제품 201 → CLEAN 141·DRIFT 3(위 아크릴)·무공식 57(굿즈 가격 미구축·별도 트랙). proc_cd 보류.
- 브라우저 drift_scan.js는 런타임(엔진 실결과) 교차검증용으로 유지.

## 교정 방향 (다음·권위 확인 후 webadmin UI)
각 셀은 **권위(상품마스터/인쇄상품 가격표) 대조 필수** — 두 가지 근본 원인 중 하나:
1. **가격표에 해당 값 셀이 실제로 있는데 미적재** → webadmin UI로 단가행 추가.
2. **가격표에 그 값이 없음(상품이 과등록)** → 상품 옵션에서 제거하거나 base-data 정본 정렬(§17 dedup / §12 basecode 거버넌스).
- 프리미엄명함 특수지 8종: 가격표 프리미엄명함 시트에 해당 지종 단가 있는지 먼저 확인.
- 폼보드/포맥스보드 A3/A2: 가격표에 대형 사이즈 tier 있는지 확인(없으면 상품 옵션 정합).
- 화이트인쇄명함: print_opt_cd를 상품 선택 차원으로 등록(또는 공식 단면 고정).

## 스캐너 한계 (재발방지 메모)
- 스윕은 **한 차원씩·다른 차원 baseline 고정**. 다차원 sparse 그리드(mat이 특정 siz에서만 가격)면 이론상 오탐 가능.
  → DRIFT 판정 셀은 교정 전 **권위/전조합 재확인 권장**(프리미엄명함처럼). 6건은 단일차원 or siz+mat 동반이라 위험 낮음.
- 공정(proc_cd) 커버리지는 미스윕(procs 경유·후속). 옵션그룹(opt_grp:) 미매칭도 별도.
