# 게시 위젯 0원·음수 가격 점검 (2026-08-29)

M4-26. 물음은 「게시된 위젯에서 0원·음수 가격이 나오는 것이 있는가」다. 두 층으로 확인했다.
라이브 읽기 전용 (가격 조회만) · 쓰기 0.

## 답 — 없다

**게시 위젯 분모(재실측) = 192** (2026-08-29. 문서의 193 은 인용하지 않았고, 실측은 **192**다 — 하나 줄었다).

| 층 | 결과 |
|---|---|
| DB 단가행 24,468행 | **음수 0건** · 0원 12건 (**전부 정당**, 아래 §1) |
| 실호출 192위젯 × 2방식 | **ZERO 0건 · NEGATIVE 0건** · 192/192 가격 산출 |
| 관측 total 277건 | 최소 **31원** · 최대 390,000원 · **0 이하 0건** |

## 1. DB 층 — 0원 12건은 전부 정당하다

| 성격 | 건수 | 판정 |
|---|---:|---|
| 옵션 「없음」 기준선 — 고리없음 · 재단만 · 오버로크 | 3 | 정당 |
| `COMP_PP_CORNER_RIGHT` 「귀돌이비」 | 9 | 정당 (아래) |

귀돌이비는 한 구성요소가 `proc_cd` 로 **두 공정을 담는다.** 권위(가격표 「인쇄후가공」 r1
「모서리 (귀돌이, 합가)」)와 **18/18 전건 일치**한다.

| 수량 | 권위 직각 | 라이브 `PROC_000027` 직각모서리 | 권위 둥근 | 라이브 `PROC_000028` 둥근모서리(4방4R) |
|---|---:|---:|---:|---:|
| 1 · 100 | 0 | **0** | 2,000 | **2,000** |
| 300 | 0 | **0** | 4,000 | **4,000** |
| 500 | 0 | **0** | 6,000 | **6,000** |
| 1000 | 0 | **0** | 11,000 | **11,000** |
| 2000 | 0 | **0** | 21,000 | **21,000** |
| 3000 | 0 | **0** | 31,000 | **31,000** |
| 4000 | 0 | **0** | 41,000 | **41,000** |
| 5000 | 0 | **0** | 51,000 | **51,000** |

**0원은 「직각모서리 무료」라는 권위 그대로다.** 12상품이 게시 중이라 고객이 도달하지만 결함이 아니다.

**부수** `COMP_PP_CORNER_ROUND` 「귀돌이비 둥근」이 둥근 9행을 **중복 보유**한다.
어느 상품에도 배선되지 않은 **고아 구성요소**라 가격 영향은 0이며, 데이터 중복 정리 대상이다.

## 2. 실호출 층 — 두 방식으로 교차

한 방식만으로는 「내 조합이 부실해서 안 나온 것」과 「진짜 결함」이 갈리지 않는다. 그래서 두 번 돌렸다.

| 방식 | 조합 구성 | OK | ERR | 0원 | 음수 |
|---|---|---:|---:|---:|---:|
| 1차 `zero_price_scan.py` | 첫 사이즈 + 첫 자재 | 162 | 30 | **0** | **0** |
| 2차 `zero_price_probe2.py` | **실재 단가행의 축 값을 그대로** | 115 | 34 | **0** | **0** |
| 합집합 | — | **192/192** | 0 | **0** | **0** |

**두 방식을 합치면 192개 전부 가격이 산출된다.** 어느 쪽에서도 0원·음수는 나오지 않았다.

각 방식이 놓친 건은 서로 달랐다 — 1차는 `bdl_qty`·`print_opt_cd`·`proc_cd` 를 안 줘서,
2차는 본품 구성요소에 단가행이 없거나(면적계산형) `qty_incr`·페이지수 축이 빠져서다.
**둘 다 도구 한계이지 결함이 아니다.**

## 3. 최저 31원의 정체 — 도구가 만든 인공 조합

접지리플렛 2장 31원 · 소량전단지 4장 31원 · 쿠폰/상품권 12장 31원 · 탁상형캘린더 63원.
인쇄물 값으로는 성립할 수 없는 액수라 원문을 열었다.

```json
{"ok": true, "total": 31, "errors": [],
 "components": [{"name": "용지비(종이별 절가)", "amount": "31"}],
 "supply": 27, "vat": 3, "unit_adj": 4}
```

**용지비 하나만 합산됐다.** 인쇄비가 빠진 이유는 1차가 `print_opt_cd`(인쇄도수)를 주지 않아서다.

3관문 셋째가 이 건을 닫는다 — **위젯은 `print_opt_cd` 를 필수로 노출한다**
(`siz_cd` · `mat_cd` · **`print_opt_cd`** · `qty`). 고객은 반드시 인쇄도수를 고르므로
이 부분 조합에는 **도달할 수 없다. 결함이 아니다.**

### 다만 기록할 것 — 엔진이 부분 합산을 막지 않는다

필수 구성요소가 매칭되지 않았는데도 엔진은 `ok: true` · `errors: []` 로 **31원을 반환한다.**
같은 상품을 축을 채워 부르면 오히려 `판수 환산 불가` 에러가 난다 — **부실하게 주면 통과하고
제대로 주면 막힌다.**

위젯 경유로는 안전하다(위젯이 축을 채워 보낸다). 그러나 **엔진 자체는 방어하지 않으므로**,
Shopby 연동처럼 API 를 직접 호출하는 경로가 생기면 터무니없이 싼 값이 성립할 수 있다.
이번 SPEC 의 교정 대상은 아니고, **연동 설계 시 확인할 사항**으로 남긴다.

## 4. 미검증

- **상품당 대표 조합 기준**이다. 모든 조합을 돌지 않았으므로 「어떤 조합에서도 0원이 안 난다」를
  증명하지는 않는다. 다만 두 방식의 조합 구성이 서로 달랐고 둘 다 0원이 0건이라는 점이 근거를 보탠다.
- 게시 분모가 **193 → 192** 로 하나 줄었다. 어느 상품이 내려갔는지는 추적하지 않았다.
