# 아키텍처 결정 브리프 — §33 확장 vs 독립 §35 KB 후 연합 (§35 Phase 3)

> 작성: 2026-07-04 · mbo-ontology-architect · 방법론 = `mbo-ontology-design` 스킬.
> **[HARD] 이 문서는 결정하지 않는다.** 두 경로를 각각 마이그레이션 노트·장단점·재사용성으로 정리해 **Phase 5 게이트(MB7)+인간 승인** 입력으로 낸다. architecture-neutral 유지.
> **★사용자 결정(승계·MEMORY)**: "아키텍처 커밋 지연·상위 온톨로지·표준 먼저." → 이 브리프는 그 지연 결정의 근거 자료.

> **읽는 법:** 후니(§33)와 와우(§35)를 한 그래프로 묶는 방법이 2가지다 — ① §33 스키마를 다중브랜드로 **확장(머지)** ② §35를 **독립 KB로 짓고 나중에 연합(federate)**. 어느 쪽이든 Phase 3 스키마(상위 개념·교차관계·와우 앵커)는 **그대로** 쓰인다. 이 문서는 두 길의 손익과 갈아타는 절차를 비교표로 정리한다.

## 1. 경로 A — §33 확장 (다중브랜드 진화·머지)

§33 스키마를 v1.1로 올려 신규 5개체·4관계·와우 앵커·brand 축을 **§33 `02_ontology/`에 머지**. 와우 노드를 §33 `03_kb/`에 brand=wowpress로 추가. 한 KB·한 그래프.

### 마이그레이션 노트 (A)
1. **스키마 머지**: §33 `ontology-schema.md` v1.0.2 → v1.1. 개체 17→22, 관계 19→23. §7 일탈표에 §35 델타 등재(브랜드축·2층). **파괴적 변경 0**(순수 추가·기존 E1~E17·R1~R19 의미 불변).
2. **brand 속성 소급**: §33 기존 275노드에 `brand: huni` 일괄 부여(기본값·1회 배치). id·앵커 불변.
3. **lint 확장 반영**: `file-format-spec.md` 화이트리스트(L-4 22종·L-14 23종·앵커 네임스페이스 +와우) + 신설 L-BR/L-AN/L-X/L-UP.
4. **build_graph.py 확장**: 와우 앵커 파서(catalog JSON·_cache CSV) 추가. §33 t_* 파서 무손상.
5. **와우 노드 적재**: `03_kb/`에 `brand/wowpress/` 하위로 와우 product·축 노드 + 교차 엣지.

### 장점 (A)
- **단일 그래프 = 교차 질의 최강**: same_family_as·price_model_differs가 한 그래프 내 엣지 → Q1~Q10 경로 순회 직결(조인 없음).
- **표준·용어집·intent 재사용 즉시**: §33 term·INTENT_* 코퍼스를 와우가 바로 씀(T2 용도 추천 교차).
- **유지보수 1곳**: 스키마·lint·빌드 1세트.
- **★사용자 목표("자연어→추천→가격→주문 확장") 직결**: 한 KB에서 브랜드 무관 추천.

### 단점·위험 (A)
- **§33 골든 오염 위험**: 275노드 안정 자산에 와우가 섞이면 §33 회귀 검증 부담↑. 머지 실수 시 후니 KB 영향.
- **브랜드 결합도↑**: 와우 catalog 노후(2025-10-14)·불확실 데이터가 §33 정본과 한 곳에 → freshness·badge 관리 복잡.
- **롤백 어려움**: 머지 후 "역시 분리" 되돌리기 비용 큼.
- **속도**: §33 안정성 게이트를 와우 적재마다 통과해야(느림).

## 2. 경로 B — 독립 §35 KB 후 연합 (federate)

§35를 **별도 KB**(`_workspace/huni-multibrand-ontology/03_upper_ontology/` 시드 → 독립 그래프)로 짓고, 상위 개념층(E-U)·교차관계를 **연합 레이어**로 둬 §33·§35 두 그래프를 런타임 조인. §33 무손상 유지.

### 마이그레이션 노트 (B)
1. **상위 레이어 파일 신설**: `upper_concept` 22노드·교차엣지를 §35 독립 파일로 시드(이미 Phase 3 산출이 시드).
2. **와우 KB 독립 빌드**: 와우 노드·앵커·lint를 §35 자체 build로. §33 build_graph.py 복제·확장(공유 안 함).
3. **연합 조인 규약**: `instance_of`(브랜드노드→upper_concept)를 **크로스-그래프 참조**로. §33 후니 노드 id(`product-*`)를 §35 상위 레이어가 참조(읽기). §33은 §35를 모름(단방향).
4. **후니 노드 참조 방식**: §35 상위 레이어가 §33 노드를 `ref`(id+앵커)로 인용(복제 아님·§33 무손상).
5. **연합 질의 엔진**: Q1~Q10은 두 그래프를 조인해 순회(§33 후니 서브그래프 + §35 상위/와우 서브그래프).

### 장점 (B)
- **§33 완전 무손상·격리**: 후니 골든 275노드 물리 불변. 회귀 위험 0.
- **와우 불확실성 격리**: catalog 노후·GAP를 §35에 가둠(§33 오염 없음).
- **독립 이터레이션**: 와우/레드 실험을 §33 게이트 없이 빠르게.
- **롤백 쉬움**: §35 폐기해도 §33 영향 0. 아키텍처 후회 비용↓.
- **레드 추가 안전**: 연합 레이어에 red 서브그래프만 append.

### 단점·위험 (B)
- **교차 질의 = 조인 오버헤드**: same_family_as가 크로스-그래프 → 질의 엔진이 두 KB 조인(구현·성능 복잡).
- **중복 유지보수**: 스키마·lint·빌드 2세트(상위 레이어 규약 이중 관리).
- **term/intent 재사용 간접**: §33 코퍼스를 §35가 ref로만 → T2 교차 추천 배선 추가.
- **일관성 드리프트 위험**: 두 그래프 badge·freshness 동기화 규약 필요(H-1 드리프트 교훈 승계).

## 5. 권고 (결정 아님·근거 제시)

> **결정은 Phase 5 인간 승인.** 아래는 architect의 근거 있는 관찰이며 강제 아님.

- **초기(Phase 3~4)는 B(독립) 기울기**: §33 275노드 골든 안정성(H-1 드리프트 2회 실증)·와우 catalog 노후 불확실성을 고려하면, 격리가 안전. Phase 3 산출이 이미 B 시드.
- **최종 목표는 A(단일 그래프)**: 사용자 목표("자연어→브랜드 무관 추천→가격→주문")는 단일 그래프 교차 질의가 직결. 조인 오버헤드는 장기 부채.
- **→ 옵션 C(독립 후 머지) 검토 가치**: B의 안전 + A의 최종 통합. 단 전환 비용을 MB7에서 평가.
- **어느 쪽이든 Phase 3 스키마 재작업 0**: 이 브리프의 핵심 = **결정을 미뤄도 손해 없음**(architecture-neutral 설계 성공). 사용자의 "커밋 지연" 결정이 타당함을 확인.
