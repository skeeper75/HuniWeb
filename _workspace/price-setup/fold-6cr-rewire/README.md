선행: `fold-card-rewire/README.md`(접지비 카드 2단 은퇴) · `dimension-axis-audit-260830.md`(전수 감사)

## 1. 접지비 카드 6크리즈 — 판별축 보강

### 1.1 문제

`COMP_FOLD_CARD_6CR` 의 `use_dims` 가 `["min_qty"]` 뿐이라 **수량만 맞으면 무조건 붙었다.**

지그재그엽서 `PRD_000030` 의 공정(상품뷰어 실측):

| 공정 | 코드 | 필수여부 |
|---|---|---|
| 디지털인쇄 | `PROC_000004` | Y |
| **6단오시접지** | `PROC_000073` | **N (선택)** |
| **6단미싱접지** | `PROC_000074` | **N (선택)** |

접지는 **선택 공정**인데, 고객이 고르지 않아도 5,600원이 붙었다
(위젯 가격 진단 실측: `판별차원 없음 — 선택과 무관하게 항상 매칭`).

2단과 달리 6크리즈는 **이관된 곳이 없다** — 리플렛 4종 어디에도 6단오시접지/6단미싱접지
행이 없다(전수 확인). 따라서 은퇴가 아니라 **이 구성요소 자체에 판별축을 채우는** 방식이다.

### 1.2 조치

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| `use_dims` | `["min_qty"]` | `proc_cd, min_qty, proc_grp:PROC_000056` |
| 단가표 | 48행 (공정 없음) | **96행** — 6단오시접지 48 + 6단미싱접지 48 |

행 분해 근거는 단가표 비고에 이미 있었다 — `[묶음 동일단가: 6단오시접지 / 6단미싱접지]`.
두 공정의 값·수량구간은 동일하다(원본 48행을 그대로 두 벌로 전개). 비고는 각각
`카드접지/6단오시접지` · `카드접지/6단미싱접지` 로 갈랐다.

리플렛 `COMP_FOLD_LEAF_*` 4종과 같은 모양이 됐다.

### 1.3 검증 — 실계산

| 조건 | 결과 |
|---|---|
| 지그재그엽서 · **접지 미선택** (위젯 진단) | 12,748 → **7,148원** — 접지비 5,600원 붙지 않음 |
| 지그재그엽서 · **6단오시접지** 선택 (시뮬레이터) | 접지비 **5,600원** · 매칭 `공정=6단오시접지 PROC_000073` |
| 지그재그엽서 · **6단미싱접지** 선택 (시뮬레이터) | 접지비 **5,600원** · 매칭 `공정=6단미싱접지 PROC_000074` |

저장 후 중복 경고 없음, 잔재 행 없음(96행 = 48+48 정확히).

## 2. 나머지 판별축 없는 구성요소 — 판정

전수 감사에서 나온 8건을 모두 판정했다.

| 구성요소 | 판정 | 근거 |
|---|---|---|
| 접지비 카드 2단 `COMP_FOLD_CARD_2H` | **결함 — 처리 완료** | 이관 완료 후 은퇴 누락 (`fold-card-rewire/`) |
| 접지비 카드 6크리즈 `COMP_FOLD_CARD_6CR` | **결함 — 처리 완료** | 선택 공정인데 항상 매칭 (§1) |
| 접지비 카드 3단 `COMP_FOLD_CARD_3H` | 해당 없음 | 이미 `use_yn=N`(260702 은퇴) |
| 투명명함 완제품가 단면 `COMP_NAMECARD_CLEAR_S1` | **문제 없음** | 상품 `PRD_000039` 의 인쇄옵션이 **단면 1개뿐** — 판별할 것이 없다 |
| 하드커버무선 표지+제본 `COMP_HC_MUSEON_COVERBIND` | **문제 없음 — 의도된 설계** | §2.1 |
| 커팅 완칼+타공 1구 `COMP_CUT_FULL_PERF_1H6` | 손대지 않음 | 공식 0개·상품 0개 (미배선 고아) · §2.2 |
| 커팅 완칼+타공 2구 `COMP_CUT_FULL_PERF_2H6` | 손대지 않음 | 동일 |
| 단가/구성 확인필요 `COMP_ACRYL_PENDING_TBD` | 손대지 않음 | 실무진 컨펌 대기 placeholder |

### 2.1 하드커버무선은 결함이 아니다 — 「표지종이 무관」이 명시돼 있다

공식 `PRF_HC_MUSEON_SET` 의 비고:

> 하드커버책자 세트 부모공식. 표지+제본 합산(**표지종이 무관**·이전사이트 실측) × 부수.
> 내지=구성원 별도.

일반이든 레더든 값이 같다는 것을 **이전 사이트 실측으로 확인해서** 그렇게 적재한 것이다.
판별축이 없는 것이 **의도된 설계**다.

레더링바인더 쪽 공식 이름도 `레더 링바인더 표지+제본 통합(077 COVERBIND 동형)` 으로
**「동형」을 명시**한다. 다만 그 공식의 비고는 비어 있어 근거가 약하다 — 관찰로만 남긴다.

> **교훈**: 「같은 상품 3개에 같은 단가」를 곧바로 결함으로 읽었으면 오판이었다.
> 비고를 읽는 것이 판정이다. (`feedback_baseline_before_defect_claim_260830` 계열)

### 2.2 타공은 이미 정상 축으로 운영 중이다

| 구성요소 | 사용차원 | 배선 |
|---|---|---|
| 타공비 (6mm) `COMP_CUT_PERF_1H6` | `proc_cd, min_qty, proc_grp:PROC_000079` | **정상** — `PRF_DGP_C` 등에서 실사용 |
| 커팅 완칼+타공 1구/2구 | `["min_qty"]` | 공식 0개·상품 0개 |

실제 타공비는 판별축을 갖춘 쪽이 담당한다. 「커팅 완제품가 완칼+타공」 2건은 쓰이지 않는
고아이므로 지금 손댈 이유가 없다. **다만 나중에 어떤 공식에 배선되면 판별축 없이 붙으므로,
배선 전에 판별축을 채워야 한다** — 이 문서가 그 경고다.

## 4. 되돌리는 법

가격구성요소 화면에서 `COMP_FOLD_CARD_6CR` 의 사용차원에서 `공정` 을 빼면
(`["min_qty"]` 로 복귀) 원래 동작으로 돌아간다. 추가한 48행(`PROC_000074`)은
그리드에서 선택 후 삭제한다. 금액은 원본과 동일하므로 값 복원은 필요 없다.
