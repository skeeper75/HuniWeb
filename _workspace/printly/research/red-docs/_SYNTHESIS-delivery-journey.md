## 1. 전 여정 = 16단계 무인 파이프라인 (RED가 이미 자동화·증명)

RED 자동화 시스템 기획서(50p)가 밝힌 주문→배송 16단계. WebToProduct 덱 20단계의 구체·확정본.

| 구간 | 단계 | 결정론 엔진 | 근거 |
|---|---|---|---|
| **WEB (고객 앞단)** | 1 템플릿 제공 · 2 파일 제작 · 3~4 주문·업로드 | — | 기획서 p여정표 |
| | 5 **Preflight 유효성검사** | 파일 검사 | 자동견적/파일처리 특허 |
| | 6 **Preprocess 전처리** (레이어 분리·14종 후가공 별색) | 레이어 엔진 | 〃 p3·p6~20 |
| | 7 **자동 견적** | 기본인쇄비(테이블 룩업)+후가공비(레이어 기하: 길이/면적/개수) | 〃 p4 |
| | 8 썸네일·견적 제공 · 9 고객 검수 · 10 결제 | — (고객/PG) | 〃 p5·p21 |
| **PRINT (생산 준비)** | 11 **데이터 검증** (원본↔미리보기 이미지매칭) · 12 주문 승인 | 이미지매칭(SURF) | 〃 p21 |
| | 13 **자동 조판** (Object/Nesting Locator→다중주문 통합→판수 최소→PDF Gen→File Convert→JDF+소요시간) | 조판·배치 엔진 | 자동조판 V1/V3/V4 |
| **PRODUCT (생산·배송)** | 14 **생산** (인쇄→후가공 14종: Cut·Crease·Fold·KissCut·Foil·Emboss·White·Scodix… + **자동 커팅** 1·2차 재단선) | 장비별 엔진·커팅 엔진 | 자동화 기획서 p19~34·자동커팅 특허 |
| | 15 **이미지매칭 물류** (완성물 스캔→DB 매칭→회원/주문/배송 복원) · 16 배송 | 이미지매칭(SURF) | 자동화 기획서 p15 |

**아키텍처 상위 그림**(회사소개서 p9): 고객 **PDF 단일 진입점 → "RED DATA ANALYSIS CENTER" → 400여 장비로 toss.** = 특허 C3 장비 가상화·파일포맷 논리/가상 2층의 실물.

**★핵심 사실**: 스펙(상품+사양 축+후가공 레이어+파일)만 확정되면 **7~16단계는 전부 결정론 엔진**이다. RED는 이걸 14만 회원·250 사이트 규모로 **무인 운영**한다(전문 디자이너 없이 파일처리 자동화가 명시 목표). 즉 **생산 여정은 "이미 풀린 문제"이고 벤더가 소유**한다.

## 2. 결정론 엔진 4종 (전부 값=엔진·온톨로지는 축까지·D-18 동형)

| 엔진 | 입력(축) | 출력(값) | 프린틀리 경계 |
|---|---|---|---|
| 자동 견적 | 상품 규격 + 후가공 레이어 기하 | 기본비 + 후가공비 | 값=벤더 엔진(RED도 "가격테이블 룩업"까지만·값은 테이블) |
| 파일 처리 | 업로드 PDF·14종 별색 레이어 | 생산적합 파일·미리보기 | 온톨로지=후가공 축·계산클래스(길이/면적/개수)까지 |
| 자동 조판 | 사이즈·수량·재질·형태(정형/비정형)·장비특성 | 배치좌표·판수 | 온톨로지=전략 축(gang·nesting·판수최소·Large Format)·값=엔진 |
| 자동 커팅 | 커팅선·모양·재질 | 커팅 경로(오일러 패스·Bezier)·1·2차 재단선 | 온톨로지=커팅 후가공 축·값=엔진 |

> RED조차 **값은 엔진/테이블에 위임하고 프로세스는 축·계산클래스까지**만 다룬다 → 프린틀리 "견적=벤더 엔진, 온톨로지=축까지"(D-18) 경계와 **동형**. 이 문서들이 그 경계를 실물로 증명.

## 3. ★프린틀리의 자리 — 지니가 하려는 바 (정밀)

**생산 여정(7~16)은 벤더 소유·이미 자동화(RED가 증명).** 프린틀리는 이걸 재구현하지 않는다. 프린틀리 = **여정의 맨 앞 + 오케스트레이션 + 온톨로지**:

```
[고객 자연어 요구]
   ↓  ① 온톨로지 해석 (자연어→intent 원자→상품·사양·후가공)   ← 프린틀리 핵심·지금 정립 대상
   ↓  ② 추천·견적 (벤더별 엔진 호출·값=엔진)
   ↓  ③ 알맞은 벤더 라우팅 (능력·포맷·장비 매칭)
[벤더의 16단계 생산 여정] ← 후니/와우/레드 각자 소유·자동화됨
   ↓
[고객이 원하던 인쇄물 수령]  ← 북극성
```

- **어려운 건 생산이 아니다**(풀린 문제·벤더 몫). 어려운 건 **"고객이 원하는 걸 정확히 이해해 올바른 상품·사양·벤더로 잇는 것"** = 온톨로지 지식.
- 그래서 **지금 최우선 = 온톨로지 중심 데이터 정립**(북극성 직결). 최종 데모 = 온톨로지-스튜디오식 질의+시각화.

### 정립해야 할 온톨로지 데이터 (이 문서들이 준 구체 근거)
1. **후가공 공정 14종 = 1급 개념** (RED 별색 레이어 어휘: Cut·Crease·Fold·KissCut·DashRule·Punch·Emboss·White·Marking·Gold/SilverFoil·Brail·Scodix·CMYK). §35 CIP4/XJDF Intent와 매핑할 벤더 앵커.
2. **견적 과금 단위 = 속성** (길이/면적/개수 계산클래스). "후가공비를 크기 아닌 실 가공선으로" — 온톨로지 속성.
3. **상품 pool + 사양 축** (낱장물·제본물·자재+제작 3버킷·상품제안서 근거).
4. **★업종→마케팅 목적→홍보물 intent 엣지 = keystone.** RED 문서엔 없다(상품 pool만) → **프린틀리가 신규 저작**해야 함(§35 keystone 일치·파일럿 recommendation-layer가 그 시작).
5. **벤더 능력·포맷·장비** (다중벤더 라우팅·후가공→포맷→장비 삼각 매핑).

---

## 4. 한 줄 정의

> **프린틀리 = 고객이 평소 말로 원하는 인쇄물을 말하면, 온톨로지 지식이 그것을 정확한 상품·사양·벤더로 해석하고, AI 에이전트가 알맞은 벤더의 (이미 자동화된) 생산 여정에 연결해 실제로 받게 하는 것.** 지금은 그 해석을 가능케 하는 **온톨로지 중심 데이터를 세우는 단계**다.
