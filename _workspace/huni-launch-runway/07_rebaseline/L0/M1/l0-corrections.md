## 🔴 C-1 — §2 optionInputs 규약이 낡았다 (치명 · 보안 + 계약)

### L0 가 쓴 것
> 「**실제 사양은 어디 있나** — Shopby 의 `optionInputs` 두 칸에 실린다:
> - `huni_token` — 1시간 서명 견적 토큰
> - `huni_order` — `{total, qty, summary, qtyRule, editors, files}` JSON」

### 현행 계약 (후니가 발행한 정본)

SDK 개발가이드 §11 「샵바이 연동 규칙」 — **2026-08-27 개정, 「이전 안내에서 바뀐 것」 표 전문**:

| 항목 | 이전 안내 | **지금** |
|---|---|---|
| 텍스트 옵션 | 등록 0개 | **`huni_order` · `huni_item` 2개 등록 완료** |
| 토큰 위치 | 정해진 자리 없음 | **샵바이에는 넣지 않는다. 토큰 전용 라벨을 일부러 만들지 않았다** |
| 요약 내용 | 제한 없음 | **사람이 읽는 요약 한 줄만** |
| 토큰 보관 | 쇼핑몰이 DB 테이블 생성 | **후니 API 가 대신 보관**(`cart/*`) |

명시적 금지 (같은 문서 §9-05 「반드시 피해야 할 것」):
> **✕ 토큰을 샵바이 텍스트 옵션에 넣기**
> 「텍스트 옵션은 **주문조회 응답으로 그대로 읽힙니다**. 이제 쇼핑몰이 토큰을 가질 일 자체가 없지만, 혹시 예전 코드가 남아 있다면 빼 주세요.」

> 「요약에는 **원고 파일 키·편집기 프로젝트 ID·금액 내역이 들어가지 않습니다.** 텍스트 옵션은 주문조회 응답으로 그대로 읽히기 때문입니다.」

### 자사몰 실코드 — 낡은 방식이 그대로 살아 있다

`huni-skin-shopby/src/components/product/huni-widget.tsx:55-81` `buildOptionInputs()`:
```ts
const order = {
  total: display.total, qty: display.qty,
  summary: r.summary ?? null,
  qtyRule: rr.qty_rule ?? rr.qtyRule ?? null,
  editors: r.payload?.editors ?? null,   // ← 편집기 prjid
  files:   r.payload?.files   ?? null,   // ← S3 원고 파일 키
};
const inputs: OptionInput[] = [
  { inputLabel: "huni_token", inputValue: r.token },   // ← 서명 토큰(수 KB)
];
inputs.push({ inputLabel: "huni_order", inputValue: JSON.stringify(order) });
```
동일 패턴이 `src/lib/api/requote.ts:73-74` 에도 있다.
`grep -rn "huni_item\|cart/items\|Huni-Server-Key" src` → **0건.**

### 무엇이 문제인가

| # | 문제 | 근거 |
|---|---|---|
| 1 | **서명 토큰이 주문조회로 노출된다** | 가이드 §9-05 명시 금지 |
| 2 | **S3 원고 파일 키가 주문조회로 노출된다** | 가이드 「요약에 원고 파일 키…들어가지 않습니다」 |
| 3 | **Edicus 프로젝트 ID(`prjid`)가 노출된다** | 같은 곳. `prjid` 는 「인쇄용 데이터를 뽑을 때 쓰는 열쇠」 |
| 4 | **`huni_token` 라벨이 샵바이 상품에 등록돼 있지 않을 가능성** | 가이드: 「라벨이 상품에 등록돼 있어야 `optionInputs` 로 값을 실을 수 있다」. 후니는 `huni_order`·`huni_item` 2개만 등록했다 → **값이 조용히 안 실릴 수 있다** |
| 5 | **토큰 길이 절단 위험** | 가이드: 「수 KB라 컬럼 길이를 잘못 잡으면 **조용히 잘리고**」 → `bad_token` 422 |

### 교정본 (§2 「실제 사양은 어디 있나」 대체)

> **현행 계약(2026-08-27~)**: 사양·금액·토큰은 **후니 항목 보관소**(`t_wgt_cart_items`)가 보관한다.
> 샵바이 `optionInputs` 에는 **두 칸만** 실린다.
>
> | 라벨 | 값 | 쓰임 |
> |---|---|---|
> | `huni_item` | `item_id`(36자 UUID, **불변**) | 기계가 읽는 키 — 장바구니 화면·주문 등록이 이걸로 후니 기록을 찾는다 |
> | `huni_order` | `summary`(사람이 읽는 요약 **한 줄**) | 셀러어드민 주문 상세에서 담당자가 봄 |
>
> **토큰·원고 키·prjid·금액 내역은 샵바이에 넣지 않는다.**
> 레거시(토큰 직접 보관 + `/handoff/requote`)도 **계속 지원**되나, 그 경우에도 **토큰을 텍스트 옵션에 넣는 것은 금지**다.
>
> **현재 자사몰 구현은 레거시 경로 + 금지 항목 탑재 상태다.** → **M2 · 쇼핑개발 조치 필요.**

### 미확인
- `huni_token` 라벨이 샵바이 상품에 실제로 등록돼 있는지 (샵바이 셀러어드민 미확인)
- 그래서 이 코드가 **동작하는지 조용히 실패하는지** 미확인 — 라이브 주문 0건이라 실증 불가(E-2)
- **판정 주체: M2**

## 🔴 C-2 — §2 `orderCnt = round(총액 ÷ 10)` 은 계약 위반

### L0 가 쓴 것
```
위젯이 계산한 총액  →  orderCnt = round(총액 ÷ 10)
```

### 계약 (SDK 가이드 §9-05 「반드시 피해야 할 것」)
> **✕ 저희가 준 금액을 반올림·보정해서 샵바이에 담기**
> 「`orderCnt` 는 `total ÷ 10` 을 **그대로** 쓰세요. 나눠떨어지지 않으면 저희가 `price_unit_mismatch` 로 거절합니다 — **임의 보정은 곧 청구액 오차**이니 그때는 저희에게 알려 주세요.」

### 서버 측 가드는 실재한다
`widget_api.py:3229`:
```python
if total is not None and int(total) % SHOPBY_PRICE_UNIT != 0:
    _logger.error("price_unit_mismatch …")
    return None, _err("주문 금액을 만들지 못했습니다. …", 422, "price_unit_mismatch")
```

### 자사몰 실코드
`src/lib/api/widget-order.ts:33-35`:
```ts
export function amountToOrderCnt(total: number): number {
  const t = Number(total) || 0;
  return Math.max(1, Math.round(t / SHOPBY_AMOUNT_UNIT));   // ← round
}
```
주석은 「총액은 10원 배수라 반올림은 정확」이라고 방어하지만, **이 `round` 는 가드를 무력화한다.**
후니 가격 규칙이 바뀌어 10원 배수가 깨지는 순간 — 서버는 `price_unit_mismatch` 로 **시끄럽게 거절**하려 하는데, 클라이언트가 이미 반올림해 넘겼다면 **조용한 청구액 오차**가 된다.

### 교정본
> `orderCnt = total ÷ 10` (**나눗셈 그대로, 반올림 금지**).
> 나눠떨어지지 않으면 그것은 **오류 신호**다 — 보정하지 말고 후니에 알린다.
> 서버 가드: `price_unit_mismatch` 422 (`widget_api.py:3229`, `SHOPBY_PRICE_UNIT`).
> 참고: 청구액이 **10원 미만**이면 절삭하지 않는다(0원 판매 방지) — 「이 가드가 걸리는 유일한 정상 경로」.

**판정 주체: M2 · 쇼핑개발**

## 🟠 C-3 — §3 종단 경로에 「장바구니 항목 보관소」가 통째로 없다

### L0 다이어그램
```
HO -->|huni_token + huni_order| CART
CART -->|optionInputs, orderCnt=총액÷10| SCART
CART --> RQ --> RQT     (재견적)
```

### 실제 (SDK 가이드 §9 · `urls.py:261-264` 실측)

`POST /handoff` 와 샵바이 장바구니 **사이에 후니 API 4종이 있다.** 전부 **서버-투-서버**(`X-Huni-Server-Key` 필수, 브라우저 호출 불가 — CORS 미개방).

| 단계 | 호출 | 용도 |
|---|---|---|
| ① 담기 | `POST /api/w/v1/cart/items` | token → **`item_id`** + `summary` + `total` + `qty_rule` |
| ② 장바구니 화면 | `POST /api/w/v1/cart/items/fetch` | item_id 배열(≤50) → 줄마다 금액·요약·**status** |
| ③ 수량 변경 | `PUT /api/w/v1/cart/items/{item_id}` `{qty\|copies}` | 금액 재계산 + **토큰까지 원자적 갱신** |
| ④ **결제 직전 갱신(필수)** | `PUT /api/w/v1/cart/items/{item_id}` (수량 생략) | 「**④는 없으면 결제 자체가 안 됩니다**」 |
| ⑤ 주문 등록 | `POST /api/w/v1/order/register` `{order_no, line_no, item_id}` | |
| ⑥ 삭제 | `DELETE /api/w/v1/cart/items/{item_id}` | 빠뜨려도 무해(30일 자동 정리) |

**②의 줄별 `status`**: `ok` · `expired`(30일 경과) · `product_unpublished` · `not_found`
→ 「한 줄이 죽어도 나머지 줄은 그리세요」 — 전체 거절 아님.

**보안 규칙(가이드 §9-03-② 「중요」)**: 「브라우저가 보낸 `item_ids` 를 그대로 중계하지 마세요 — 고객 A 가 남의 `item_id` 를 넣어 **다른 고객의 주문 요약과 금액을 읽을 수 있습니다**(제작물 제목에 실명이 들어가는 경우가 많습니다). `item_ids` 는 **인증된 고객 세션으로 샵바이 `GET /cart` 를 호출해 받은 결과에서만** 뽑으세요.」

**호출 상한**: 장바구니 전용 버킷 **사이트당 분당 600회** (브라우저 가격조회 240회/분과 분리).

### 교정본 — §3 다이어그램에 추가할 노드
```

  --> CI["/api/w/v1/cart/items (S2S)<br/>토큰 보관 → item_id"]
```

## 🟠 C-4 — §9 「Shopby 프로모션 충돌 미확인」 : 계약 문서에 답이 있다

L0 §9: 「**Shopby 프로모션(쿠폰·적립금·배송비)이 「10원 상품 × N」 구조와 충돌하는지 미확인.** 돈이 걸린 미확인이다.」

**SDK 가이드 §11 이 이미 답한다** (전부 실제 문서·라이브 데이터로 확인했다고 명시):

| 기능 | 판정 | 이유 |
|---|---|---|
| **쿠폰** | ✅ **안전** | 금액 기준 계산 |
| **적립금** | ✅ **안전** | 금액 기준 계산 |
| **수량 기준 배송비** | 🔴 **영구 금지** | 「켜는 순간 배송비가 폭발」 |
| **상품 중량 기준 배송비** | 🔴 **영구 금지** | 같음 |
| **최대구매수량** | 🔴 금지 | 수량 = 금액이므로 |
| **즉시할인** | 🔴 금지 | 수량 기준 |
| **재고** | ⚠ **제약** | 「재고 × 10원 = 그 상품으로 받을 수 있는 **누적 결제금액 한도**」. 재고 관리를 끄는 설정이 **샵바이에 존재하지 않는다**(문서 전수 확인). 최대값 시 약 214억원어치 |

추가 확정 사실:
- **판매가 10원 일괄 적용 완료** — 「판매 중인 전 상품(**226개**)의 판매가를 10원으로 일괄 변경했습니다(2026-08-26). 재고·전시·판매상태는 건드리지 않았고 전수 대조로 확인했습니다.」
- 왜 100원이 아니라 10원인가 — 「청구액은 언제나 10원 배수라 … 수량이 1/10 로 줄어 재고 소모·주문서 표시·알림 문구가 전부 10배 가벼워집니다」
- ⚠ **100원 기준으로 만들었다면 금액이 10배 틀어진다** (가이드 명시)

### 교정본
> §9 의 이 항목을 **미확인에서 내리고** §2 「파생 제약」으로 승격한다.
> 남는 미확인은 **「샵바이 셀러어드민에서 위 금지 설정이 실제로 꺼져 있는가」** 하나뿐이다 — 그것은 **설정 점검 항목**이지 조사 항목이 아니다.
> **런웨이 체크리스트 항목**: 「수량·중량 기준 배송비 OFF 확인」 · 「최대구매수량 OFF 확인」 · 「즉시할인 OFF 확인」 · 「재고 수량 = 결제 한도 설정 확인」 · 「판매가 10원 226개 유지 확인」

**판정 주체: M2** (충돌 상세는 M2 카드의 `promotion-conflict.md`)
