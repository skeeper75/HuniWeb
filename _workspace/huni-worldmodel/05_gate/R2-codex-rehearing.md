## 3. 본 재심자의 독립 렌즈 — R2 게이트 명세 축

codex 판정을 신뢰하지 않고, R2 렌즈의 고유 질문("분모와 감시 대상이 같은 우주인가")을 직접 적용했다.

### 3.1 FIX-3 — G0.5 분할이 자기모순을 제거했는가

원 위반(A1)의 실체: 개정 전 G0.5 는 **분모 = `DIM_META` 12축**, **감시 대상 = `OPT_REF_DIM` 7축 × 5표면** 으로 두 집합이 겹치되 동일하지 않았다. 규정대로 구현하면 드리프트 0에서도 상시 FAIL 한다 → RULE-05 ④(분모) 위반.

교정 후 실측(`design-FINAL.md:709-710`, `:451-452`, `:455-475`):

| 게이트 | 감시 대상 | ④ 분모 | 같은 우주인가 |
|---|---|---|---|
| **G0.5a** | `OPT_REF_DIM` 7축이 표면 5벌(`views.py:61-69` / `:1882-1890` / `:1893-1901` / `:3670-3678` / DB 트리거)에서 동일한가 | **축 7종 × 표면 5벌 = 35쌍** | **예** — 감시 축 집합과 분모 축 집합이 동일(`OPT_REF_DIM`), 표면 수도 동일(5) |
| **G0.5b** | `DIM_META` 12축이 표면 3벌(`DIM_META` / `pricing` 상수집합 / `t_prc_component_prices` 실컬럼)에서 동일한가 | **축 12종 × 표면 3벌 = 36쌍** | **예** — 감시 축 집합과 분모 축 집합이 동일(`DIM_META`), 표면 수도 동일(3) |

두 우주가 겹치되 동일하지 않다는 사실은 **projection map**(`:461-472`)으로 명시 문서화됐고, `.06`(행 식별자 `opt_id`)·`.07`(`sub_prd_cd`)의 비사상과 역방향 비사상 7항이 열거되어 있다. `.06` 비사상은 게이트 독립 재실측(R-6)으로 확정된 사실이다.

**판정: RULE-05 ④ — 위반 미확정(CLOSED).** 분모와 감시 대상이 각 게이트 내에서 동일 우주다. 드리프트 0에서 상시 FAIL 하는 구조는 제거됐다.
**동반 RULE-12 ① — 위반 미확정(CLOSED).** 게이트 정의처 분열은 projection map 이라는 단일 정의처(맵 파일 해시를 G0.5a 산출물에 스탬프, `:459`)로 닫혔다.

### 3.2 FIX-4 — clone 단일 경로 + G1.1 이 RULE-13 ② 를 닫았는가

원 위반(A2)의 실체: G6 오라클이 라이브 `/validate`·`/handoff` 리플레이를 요구해 **라이브 write** 를 유발하는데(`widget_api.py:135` `t_wgt_widgets` UPDATE, `:1677`·`:1733` handoff logs INSERT/DELETE), 백업·DRY-RUN·undo 가 부재 → RULE-13 ②(라이브 write 단계에 백업·DRY-RUN·undo 중 하나라도 빠지면 위반) 위반.

교정 후 실측:
- **경로 축소** — `:59` §0 'G6 실행 환경' 행 + `:720` G6 + `:721` 폐기 기록: 리플레이는 **clone DB 에서만**, 라이브 대상 리플레이 경로는 **폐기**. `:721` 은 폐기 사유를 `_gate` → `_touch_used` → `:135 .update()` 호출 사슬로 코드 좌표까지 적시한다.
- **제외의 정당화 결박** — `:713` G1 분모 정정은 제외 2테이블을 명시하되 **"[HARD] 근거 없는 제외는 RULE-13 ② 우회다. 두 제외는 반드시 G1.1 과 한 쌍으로만 성립한다"** 로 결박한다.
- **대체 계측** — `:714` G1.1 은 ①유발 행 수 == 예상 조합 수 ②그 외 증분 0 ③**종료 시 undo 후 원복**(handoff logs 0행 복귀, `t_wgt_widgets` 원 `last_used_*` 복원)을 요구하고, 미실행 시 **G1 을 46테이블 전수로 되돌리고 리플레이 자체를 금지**한다.
- **동일성 검사** — `:720` clone 생성·폐기 절차 + clone↔라이브 동일성 검사(테이블별 `count` + `max(upd_dt)`)를 리플레이 전후로 실행.

violation_test ② 는 *"라이브 write 를 수반하는 단계에 백업·DRY-RUN·undo 중 하나라도 빠지면 위반"* 을 묻는다. clone 단일 경로화로 **라이브 write 를 수반하는 단계 자체가 0** 이며, clone 상의 부작용에는 undo·원복·전후 동일성 검사가 붙었다.

**판정: RULE-13 ② — 위반 미확정(CLOSED).** ①(fail-open 금지)은 `:759-772` 11지점 전수표로, ③(신선도)은 `:344` `source_digest` + `:711` G0.9 판정 거부 + `:718` 골든 라이브 재-SELECT 로 각각 충족.
**동반 RULE-14 ② — 위반 미확정(CLOSED).** 인간 승인 게이트 없는 라이브 write 가 경로에서 사라졌다. 주문 확정은 `:654` 사람 확인 후 `/handoff` 서명.

루브릭 v1.0 의 18규칙 중 **자율성 경계·ESTC 3단 축에 대응하는 규칙이 없다.** `.claude/rules/moai/core/adversarial-verification-governance.md` §8.4 — *"루브릭이 재지 못하는 축은 규칙에도 없다 … 규칙에 없는 결함은 루브릭 개정 안건으로 제기하며, 개정 전까지 위반 등급을 낼 수 없다"* — 에 따라 **판정하지 않는다.** 없는 규칙을 만들어 재는 것이 FP-4 의 정확한 정의다.

**상태: 루브릭 부재로 판정 불가 (미검증 ≠ 통과, §6.6).**

## 6. codex 오판 의심 건

**0건.** codex 는 위반을 1건도 주장하지 않았으므로 오판(FP-1~FP-4)의 성립 여지가 없다. 인용 좌표 22건 전건이 원본에서 실재 확인되어 FP-2 도 0건이다.

**주의 사항 1건(오판 아님)** — codex 의 RULE-05 해석은 *"4항이 **모두** 없으면 위반"* 이라는 문언을 문자 그대로 읽어 "게이트표에 4열이 있다"를 통과 근거로 삼았다. 본 재심자는 더 엄격하게 **게이트 행 단위로 4항 값의 실재**를 전수 확인했고(§3.3), 그래도 결론이 같다. 즉 codex 의 느슨한 적용이 결론을 바꾸지 않았다.

## 7. 범위 밖 관찰 (판정 미산입 · §2.3 J-3 / §8.4 루브릭 개정 안건 후보)

아래 2건은 **위반 주장이 아니다.** 5요건을 갖추지 못했거나(§2.1 기본값=각하) 대응 규칙이 없다(§8.4). 다음 라운드 루브릭 개정 심의 자료로만 등재한다.

1. **G0.5a 의 "추가 1항"이 분모 35쌍에 산입되지 않는다** — `:451` 은 `print_opt_cd` 열거 결과 집합 == `_dim_options` 클로저 산출 동일성을 G0.5a 의 추가 감시 대상으로 두고, `:709` 는 projection map 파일 해시 스탬프를 도구 열에 둔다. 그러나 ④ 분모는 "35쌍"이다. **위반은 아니다** — violation_test ④ 는 분모의 *존재*를 묻지 확인 항목의 *망라성*을 묻지 않으며, 원 A1 위반(두 집합이 서로소여서 상시 FAIL)과 달리 이것은 명시된 가산 항이다. 이 축으로 위반을 주장하는 것은 FP-4 다. **자기 반증조건**: violation_test ④ 가 "분모가 전 확인 항목을 망라해야 한다"고 규정한다면 이 관찰은 위반으로 승격한다 — v1.0 은 그렇게 규정하지 않는다.
2. **G1 제외 사유 문언과 clone 단일 경로의 정합** — `:713` 은 제외 사유를 "G6 clone 리플레이가 INSERT/DELETE 유발"로 쓰는데, 리플레이가 clone 전용이면 라이브 46테이블 해시는 원리상 흔들리지 않는다(제외가 보수적으로 과잉일 수 있다). **효과상 무해**하고(G1.1 이 개별 계측), 이 축을 재는 규칙이 v1.0 에 없다(gate-report §5.4 개정안 ② "신설 RULE-19 문서 내부 정합"은 **제안 단계이며 미채택**). 따라서 §8.4 에 따라 **위반 등급을 낼 수 없다.**
