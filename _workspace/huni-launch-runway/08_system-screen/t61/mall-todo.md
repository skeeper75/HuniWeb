1. **위젯 이음매의 남은 일은 전부 huni-mall 쪽이다.** 발급하는 쪽(webadmin)의 4개 엔드포인트는 다 있다

2. **재견적은 장바구니에만 달려 있다.** 유일한 호출부가 `src/components/cart/cart-page.tsx:126`(수량 변경)과

3. **`order/register` 의 `item_id` 경로는 서버키가 필수인데, huni-mall 에는 서버키 env 자체가 없다.**

   회원 외부ID** 4건은 원장 판정의 전제를 바꾼다(§5).

**Top → Down 우선순위** — 작업량이 아니라 **뒤에 막혀 있는 일의 수**로만 정렬했다.

1. **⑤ 이전·배선** — ①②③④ 전부가 「어느 도메인에서 도는가」 위에 선다. 특히 도메인이 정해져야

2. **① 위젯 임베드** — ②의 금액·주문등록이 여기서 나온 토큰 위에 선다. 서희항 API 계약과 맞물린 자리.

### 지금 상태 — 세 다리 중 한 다리만 놓였다

| 다리 | 원장 | 실측 |
|---|---|---|

`order/register` 의 수신 계약을 직접 열어 확인한 것(`widget_api.py:5591-5680`):

- 사양의 출처는 **`token` 또는 `item_id` 중 하나**.
- **`order_no`·`line_no` 둘 다 필수** — 없으면 400(`missing_order_no`·`missing_line_no`), 길이 상한 초과도 400.
- **`item_id` 경로는 `X-Huni-Server-Key` 필수** — 스위치(`WAPI_SERVER_KEY_REQUIRED`)와 무관하다.
  주석이 그 이유를 적어 뒀다: 열어 두면 아무 브라우저나 주문 등록과 **원고 승격(tmp→order 복사)** 을 일으키고,
  진짜 주문번호를 선점당하면 정상 등록이 409 로 죽어 접수가 막힌다.
- 멱등이다(재전송 시 게이트 미적용 — 응답 유실 재전송이 409 로 죽으면 원고가 tmp 30일에서 소멸하기 때문).
- `work_size` 는 **서버가 다시 계산**한다 — 몰이 보낸 값을 저장하지 않는다.

→ **김동학이 정할 것**: `token` 경로로 갈지 `item_id` 경로로 갈지. `item_id` 로 가면 몰이 토큰을 한 번도
보관하지 않아도 되지만 **서버키 배선(`STD-SYS-045`)이 선행**이다.

## 5. Shopby 3갈래 — 어디까지가 김동학 일인가

카드의 특별 지시대로 **한 기능을 세 갈래로 가른다**.

| 갈래 | 뜻 | 담당 | 판정 근거가 되는 자리 |
|---|---|---|---|
| **호출 코드** | huni-mall 이 Shop API / Server API 를 부르는 코드 | **김동학** | `src/lib/api/client.ts:14`(server API 프록시 `/api/shopby`) · `src/app/api/shopby/[...path]/route.ts` |
| **config** | 셀러어드민(`service.shopby.co.kr`)에서 설정·등록만, 코드 0 | **최숙진** | `t56/rejudge.csv` evidence 의 `service.shopby.co.kr/...` URL |
| **provided** | 샵바이가 그대로 제공, 우리 작업 0(확인만) | 일 아님 | 아래 §5-1 |

**전수 자동 분류는 하지 않았다.** evidence 문자열로 「샵바이 접점」을 세려 했으나 신뢰할 수 없었다 —
몰의 자기 도메인이 `shopby.huniprinting.co.kr` 이고 저장소 이름이 `huni-skin-shopby` 라
문자열 `shopby` 가 **샵바이와 무관한 행에도 들어간다**(무보정 121행 → 두 토큰 제외 시 42행, 그 42행에도
몰 도메인 URL 이 남는다). 그래서 **행마다 사람이 판정한 것만** 아래에 적는다.

### 5-1. t56 의 `provided` 23행 — headless 관점 재확인

23행 전부 `owner_now=김동학` · 판정 `provided` 다(`verdict=provided and owner_now=김동학` 로 재추출).
성격별로 갈라 보면:

| 묶음 | 행 | headless 재판정 |
|---|---|---|
| **셀러어드민 운영 화면** — 주문·클레임·회원·게시판·리뷰·통계·감사로그 | `STD-ADO-001`·`004`·`007`·`022` · `STD-ADC-001`·`003`·`006`·`007`·`008`·`009`·`010`·`011` · `STD-FIN-001`~`006`·`011` · `STD-SYS-003` (21행) | **provided 유지.** 운영자는 셀러어드민을 그대로 쓴다 — headless 여부와 무관하다 |
| **고객 대면이 섞인 것** | `STD-SHP-016`(배송 상태 알림 발송) · `STD-PRM-009`(사진 리뷰 추가 보상) (2행) | **provided 유지하되 config 짝 행이 필요**하다 — 아래 |

**`STD-SHP-016`**: 샵바이가 보내는 것은 맞다. 그러나 headless 라 **알림 본문의 주문조회 링크가 어느 몰을
가리키는지**가 자동으로 정해지지 않는다 → NEW-M10(config · 최숙진 확인).

**`STD-PRM-009`**: 보상 지급은 샵바이가 한다. 그러나 **리뷰를 쓰는 화면은 huni-mall 몫**이다
(`STD-MYP-012` 내 리뷰 작성 = 김동학 · 남은 일). 「샵바이 몰에서 리뷰를 쓴다」는 전제가 headless 에서
깨지므로, **API 로 등록한 리뷰에도 보상이 붙는지** 확인이 필요하다(§8 결정 안건).

**관리 provided ↔ 고객 화면 build 의 짝이 원장에 실재하는지 확인했다 — 8쌍 전부 있다.**

| 셀러어드민(provided) | huni-mall 고객 화면(김동학 · 남은 일) |
|---|---|
| `STD-ADC-007` 공지사항 관리 | `STD-INF-005` 공지사항 고객 화면 · `STD-CLM-018` 공지·FAQ 열람 |
| `STD-ADC-008` FAQ 관리 | `STD-INF-006` FAQ 고객 화면 |
| `STD-ADC-009` 상품Q&A 답변 관리 | `STD-CAT-013` 상품 Q&A 게시 · `STD-CLM-017` Q&A 등록 |
| `STD-ADC-010` 1:1 문의 답변 관리 | `STD-CLM-016` 1:1 문의 등록 |
| `STD-ADC-011` 리뷰 관리·블라인드 | `STD-MYP-012` 내 리뷰 작성 · `STD-CAT-014`·`015` 리뷰 노출 |

**한 곳이 비어 있다.** `STD-SYS-003`(관리자 작업 감사로그)은 셀러어드민 provided 인데,
huni-mall 에는 **자체 `/admin` 이 따로 있다**(`STD-SYS-001` 관리자 계정 · `STD-SYS-002` 권한 제어 · 둘 다
김동학 남은 일 · `STD-SYS-024` 가 `/admin` 보호 라우트를 실측으로 확인했다). **몰 자체 관리화면의 작업은
샵바이 감사로그가 덮지 않는다.** 이 문서는 행을 새로 만들지 않고 사실만 적는다 — 판단은 지니·서희항.

## 6. 리드 5축 초안에서 고친 것 — 4건

카드가 「5축은 리드 초안이다 — 근거를 열어 보고 안 맞으면 고치고 이유를 적는다」고 했다.

**정정 1 — 철회(리드 판정 260919).** 초판은 「⑤의 페이지빌더 Lightsail 이전은 성립하지 않는다」고 적었다.
**틀렸다.** 증거 읽기는 맞았는데(`pie-canvas-model.md:20` Vercel icn1 호스팅 · `:97` REST 미노출)
**귀속 전제가 틀렸다** — 「파트너사」를 제3자 제품으로 읽었으나, 지니 확정(260919)에 따르면
**그 파트너사가 곧 김동학 대표**다. 페이지빌더는 김동학 대표가 작업한 부분이고, 후니프린팅에 맞게
제작해 **Lightsail 로 모두 통합**할 예정이다.

→ Vercel 호스팅·REST 미노출·`/sites` 500 은 **옮길 수 없다는 근거가 아니라 출발 상태**다.
⑤에 되살렸고(NEW-M17 + 하위 6건), 초판이 ④에 뒀던 NEW-M12 는 버리지 않고 **그 하위 작업**으로 옮겼다.
이 문단을 지우지 않고 남겨 두는 이유는, 다음 세션이 같은 문서를 읽고 같은 결론에 다시 도달하지 않게 하기 위해서다.

**정정 2 — `STD-ADC` 는 7이 아니라 6이다.** 7번째로 세었을 `STD-ADC-014`(인쇄 가이드 콘텐츠 관리)는
t56 이 **재배정→서희항**으로 판정했다. 김동학 몫이 아니다.

**정정 3 — 초안 10개 접두의 합은 남은 일을 다 덮지 않는다.** 초안이 든 접두 합은 163행이고 남은 일은 189다.

## 7. 카드의 217·187 과 내 189 — 2행 차이

카드는 「재판정 후 217행·남은 일 187」이라고 적었다. 내가 `a83dc44b` 의 `rejudge.csv` 를 직접 센 값은
**219 / 189** 다. 차이는 `owner_proposed` 가 **3인 공동**이거나 **역할 접미가 붙은** 2행에서 난다.

| row_id | `owner_proposed` | 성격 |
|---|---|---|
| `STD-CAT-034` | `김동학+서희항+최숙진` | 3분할 — 김동학 몫은 「표시」 |
| `BLK-S4-6` | `김동학·PM+신우진` | 「김동학·PM」 이라는 복합 표기 |

이 2행을 빼면 정확히 **217 / 187** 이 된다. 리드가 어느 기준으로 세었는지는 내가 관측한 것이 아니라
**추정**이다 — 다만 두 행 다 김동학이 **관여**하므로 이 문서는 189를 분모로 쓰고, 두 행은 각각
④(`STD-CAT-034`)·⑤(`BLK-S4-6`)에 남겼다.
