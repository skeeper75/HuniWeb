# t44 판정 — 셋트 책자 표지 판형·단가 재판정 (2026-09-04)

지니 관점(「Max Page 로 표지 크기를 정하고 그보다 큰 판형을 처리한다」)으로
t9 의 R5·R6·R1 을 재판정했다. **R5 는 뒤집혔고, R6 은 유지됐고, R1 은 성격이 바뀌었다.**

## 3. ③ R1 명세 + DRY-RUN — 단가 재산정이 아니라 판형 철회

480x320 이 애초에 불필요한 판형이므로, 그 단가를 면적비례로 올리는 것은
**잘못된 판형을 정당화하는 교정**이다. 판형을 걷는 쪽이 옳다.

### 가격 영향 0 실증 (`price_parity_check.txt`)

표지 6개 자재 전건 316x467 단가 = 480x320 단가(70.64 / 77.75 / 93.30 / 77.75 / 93.30 /
142.20). 판걸이도 1 = 1. → **판형을 되돌려도 청구액 무변동**, 동시에 t9 이 지적한
4.09% 미반영은 **원인이 소멸**한다.

### DRY-RUN 결과 (`r1_remediation.sql` / `dryrun.log`)

```
BEFORE  pansu(316x467, 표지A4) = 0 · pansu(480x320, 표지A4) = 1
        판형 풀: PRD_000290/292 각각 [316x467 공통 dflt Y] + [480x320 item=SIZ_000633]
UPDATE 1 (SIZ_000633 → 재단 446x297 · 작업 452x303)
UPDATE 2 (480x320 사이즈전용 배선 2행 논리삭제)
AFTER   pansu(316x467, 표지A4) = 1
        판형 풀: PRD_000290/292 각각 [316x467 공통 dflt Y] 만
NOTICE  교정 후 316x467 판걸이 = 1 · SIZ_000641 잔여 배선 = 0
ROLLBACK → 원상 확인(454x297 · 판걸이 0)
```

### ⚠ COMMIT 전 선결 — 실무 리스크

A안은 표지를 **8mm 좁힌다**. 현재 자재로는 안전하지만(최대두께 0.170 → 책등 26),
시트의 34mm 여유는 두께 **0.2233mm** 용지까지 커버한다. 그보다 두꺼운 내지를
나중에 등록하면 표지가 모자란다. **§5 질의 2 의 답이 먼저다.**

대안 B: 454x297 을 유지하되 블리드 없이 조판 → 316x467 에 판걸이 1(3mm 여유).
표지를 안 줄여도 되지만 재단 안전여백을 포기하므로 인쇄 실무 판단이 필요하다.

## 4. 부기 — 하드커버 표지치수는 엔진 산출물이 아니다

`t_proc_spine_calcs` 의 하드커버무선제본(PROC_000023)은 `cover_incl_yn='N'` 이라
엔진이 표지 두께를 아예 안 본다. 표지 사이즈 SIZ_000634/635 는 A5/A4 각 1개씩
고정 상수이고 페이지수에 따라 변하지 않는다.

다만 책등 **보드 라인업 상한이 26mm**(MDF 10~26 × 304/218)이고 이는 엔진 산출 책등
26mm 와 정확히 일치한다 — 보드 라인업 자체가 Max Page 로 짜여 있다는 뜻이라,
532x355 는 이미 Max Page 봉투로 보인다. **더 줄일 여지는 없다.**

## 5. 실무진 확인 질의 (COMMIT 전 선결)

1. **무선/PUR A4 표지를 454→446 으로 8mm 좁혀도 되는가?**
   좁히면 권위 판형 국4절에 들어가고 신설 판형이 불필요해진다.
2. **시트의 책등 여유 34mm 는 무엇을 위한 값인가?** (현재 산출 26mm)
   두꺼운 내지용 헤드룸이면 A안 대신 대안 B 를 택해야 한다.
3. **480x320 · 550x375 는 실재하는 인쇄판인가?**
   권위 판형 어휘(316x467·330x660·330x540·330x470·304x629)에 둘 다 없다.
4. **하드커버 케이스 랩 치수의 산출 근거는?**
   보드 + 책등보드로 폭이 80·98mm 모자란다 — 경첩 홈·싸개 접힘 규칙이 어디에도 없다.
