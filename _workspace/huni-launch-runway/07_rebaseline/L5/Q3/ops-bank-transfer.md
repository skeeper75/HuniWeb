# 무통장입금 운영 절차 — 실무진용 1장

> 작성 2026-09-02 · 카드 `L0/CARDS-Q.md` §Q3 · 근거 전건 `L0/N1/` 문서
> 대상: **셀러어드민에 로그인해 입금확인을 누르는 실무진**
> 이 문서는 **입금확인 하나**에 대한 것이다. 나머지 주문 진행은 사람이 하지 않는다.

---

## 0. 딱 한 줄

**입금대기 목록에서 [입금확인 처리]만 누른다. 그 뒤의 버튼은 하나도 누르지 않는다.**

---

## 1. 왜 이 절차가 생겼나

샵바이가 PG 승인 전에 **무통장입금**을 먼저 풀어 줬다. 그래서 지금 이런 주문이 가능하다.

```
고객이 무통장 선택 → 주문 성립 「입금대기」 → (실무진이 입금확인 클릭) → 「결제완료」 → 이후 자동
```

**「입금확인 처리」는 사람이 눌러야만 일어나는 유일한 단계다.** 가상계좌·에스크로는 PG 가 자동으로 처리해서 손댈 것이 없다(근거 `shopby-order-state-machine.md` T4·T5 · `selleradmin-ops.md` §1.1 ②).

---

## 2. 매일 하는 일 — 3단계

### ① 입금대기 목록을 연다

**셀러어드민 > 주문 > 입금대기 주문** (`order/deposit-wait`)

여기 있는 건이 **입금 확인 대상**이다. 가상계좌·에스크로 건이 섞여 있으면 **손대지 않는다** — PG 가 자동 처리한다.

근거: `selleradmin-ops.md` §1.1 ② (`order/deposit-wait.mdx:11`, `:28-30`)

### ② 입금이 실제로 들어왔는지 통장에서 확인한다

셀러어드민 화면은 **입금 사실을 알지 못한다.** 사람이 통장을 보고 판단한다.

- 입금자명·금액이 주문과 맞는가
- 부분 입금·초과 입금은 아닌가

**맞지 않으면 누르지 않는다.** 한 번 누르면 「결제완료」로 넘어가고, 그때부터 생산 흐름이 자동으로 돈다.

### ③ [입금확인 처리]를 누른다

| 항목 | 내용 |
|---|---|
| 어디서 | **입금대기 주문 목록에서만** 가능하다. 전체주문 조회 화면에서는 안 된다 |
| 결과 | 주문상태가 **「결제완료」**로 바뀐다 |
| 되돌리기 | 이 전이는 **결제완료로만** 갈 수 있다(다른 상태로는 못 바꾼다) |

근거: `shopby-order-state-machine.md` T4(`order/deposit-wait.mdx` ①) · B2(`order/list.mdx` ③ 첫 불릿) · `selleradmin-ops.md` §1.2 「예외 둘」(`order/list.mdx:76-78`)

## 3. [HARD] 여기서 멈춘다 — 그 뒤 버튼은 누르지 않는다

**「결제완료」 다음부터는 후니 서버가 자동으로 올린다.**

```
결제완료 ─▶ 상품준비중 ─▶ 배송준비중 ─▶ 배송중 ─▶ 배송완료 ─▶ 구매확정
          └────────── 전부 후니 서버가 한다 ──────────┘
```

**사람이 먼저 누르면 무슨 일이 생기나:**

| 문제 | 왜 |
|---|---|
| **고객 취소권이 사라진다** | 「입금대기·결제완료 = 즉시 취소 가능」, 「상품준비중부터 = 취소요청 후 담당자 승인」. **상품준비중을 미리 누르면 고객이 즉시 취소를 못 하게 된다** |
| 생산 상황과 화면이 어긋난다 | 후니는 **실제 생산 접수가 확정되는 순간** 상품준비중으로 올린다. 사람이 먼저 누르면 실제로는 아직 아무것도 시작 안 됐는데 화면만 진행된 상태가 된다 |
| 송장이 꼬인다 | 송장번호는 **출고 시 후니가 등록**한다. 고객 배송조회도 그때 자동으로 열린다 |

근거: `selleradmin-ops.md` §1.2 [HARD] 블록(`sdk-guide-live-20260902.txt:755-759`, `:895-898`, `:925-928`, `:1398-1400`) · `shopby-order-state-machine.md` §취소 경계표(`:929-936`)

**실무진이 셀러어드민에서 하는 일은 「읽기·응대·조회」다. 상태 운전이 아니다.** 예외가 입금확인 하나뿐이다.

---

## 4. 주의할 것 3가지

### 4-1. ★ 입금기한이 지나면 자동으로 취소된다 — 되돌릴 수 없다

입금기한을 넘기면 시스템이 **자동취소**한다. 결과는 `취소완료[환불없음]`이다.

**그리고 그 뒤로는 그 주문을 살릴 수 없다.** 고객이 뒤늦게 입금해도 주문은 이미 없다 → **환불 처리**로 가야 한다.

| 왜 기한이 짧아야 하나 | 값 |
|---|---|
| 원고 파일 임시 보관 기간 | **30일** |
| 입금기한이 그보다 길면 | **입금 전에 원고가 사라진다** |
| 권장 입금기한 | **3~7일** |

근거: `shopby-order-state-machine.md` C1(`claim-order/cancel/condition.mdx` 1행 · `order/deposit-wait.mdx` ②) · 「가상계좌(무통장) 입금기한은 짧게」(`sdk-guide:937-940`)

> **미확인**: 무통장 입금기한의 **기본값과 설정 화면 위치**는 매뉴얼에 명시돼 있지 않다(`shopby-order-state-machine.md` §미확인 9번). **지금 값이 얼마인지 화면에서 확인이 필요하다.** 30일보다 길게 잡혀 있으면 원고가 위험하다.

### 4-2. ★ 재고가 「입금대기」부터 깎인다 — 미입금이 쌓이면 결제가 막힌다

**입금대기 상태의 주문부터 이미 재고가 차감된다**(`order/deposit-wait.mdx` §Callout).

후니는 **금액을 수량 칸으로 표현**한다(판매가 10원 × 수량 = 금액). 그래서 **15,000원짜리 주문 하나가 재고를 1,500개 소진한다.**

**미입금 주문이 쌓이면 재고가 마르고, 재고 = 결제 한도이므로 새 주문이 막힌다.**

→ **입금대기 목록을 매일 비우는 것**이 그래서 중요하다. 입금이 안 들어온 건은 기한을 기다리거나 [취소 처리]로 정리한다.

근거: `shopby-order-state-machine.md` §4-2 재고 차감 표 · `:274`

### 4-3. ★ 고객에게 나가는 알림에 「가짜 수량」이 찍힌다

후니는 금액을 수량으로 표현하므로, **샵바이가 고객에게 직접 보내는 알림에 「1,500개」 같은 숫자가 노출된다.**

| 노출면 | 누가 보내나 | 가짜 수량 |
|---|---|---|
| 주문 알림 — **알림톡** | 샵바이 | **노출됨** (치환항목 `count`, `productNames` 는 「상품명(수량)」 형식) |
| 주문 알림 — **SMS(LMS)** | 샵바이 | **노출됨** (알림톡 실패 시 같은 문구로 대체 발송) |
| 주문 알림 — **메일** | 샵바이 | **노출됨** |
| **현금영수증 · 세금계산서** | 샵바이 | **노출됨 — 품목·수량 표기** |
| **셀러어드민 주문 화면 · 판매 통계** | 샵바이 | **노출됨 — 실무진이 매일 본다** |
| 결제창(PG) | 샵바이→PG | 노출 안 됨(금액은 정상, 상품명만) |
| 자사몰 화면·거래명세표 | 자사몰 | **노출 안 됨**(통제 가능) |

★ **무통장 알림 3종이 정확히 여기 걸린다** — 「입금대기」·「주문접수완료」·「입금확인」 알림 전부 수량 치환을 포함한다.

**실무진이 알아야 할 것:**
- 셀러어드민 주문 화면에서 **「10원 × 1,500개」로 보이는 것은 정상이다.** 진짜 사양은 `huni_order` 요약 한 줄에 들어 있다
- **고객이 「1,500개 주문한 적 없다」고 문의하면** → 금액을 수량으로 표현하는 방식 때문이며 실제 인쇄 수량은 주문 요약을 보라고 안내한다
- **세금계산서·현금영수증에도 이 숫자가 찍힌다.** 이건 아직 대응책이 정해지지 않은 항목이다(원장 A-21 · 차단 등급)

근거: `headless-boundary.md` §A-2-0 (가이드`:949-951`, `:1035`, `:1044-1048`) · §A-2-1 노출면 전수표(가이드`:1412-1415`) · 알림 항목표(가이드`:1419`)

## 5. 이번 관통 때 같이 남길 것 (1회성)

무통장 실주문 1건을 관통할 때, **입금확인 직후 화면을 캡처**해 두면 닫히는 항목이 여러 개다.

| 캡처할 것 | 무엇이 닫히나 |
|---|---|
| **주문 상세** 화면 | A-1(주문 화면 항목 확인) · `huni_order` 요약이 실제로 어떻게 보이는지 |
| **거래명세서** 출력 | A-4 · 수량 표기 형식(현재 「미확인」) |
| **판매 통계** 화면 | A-6 · 가짜 수량이 통계를 어떻게 왜곡하는지(현재 「미확인」) |

**상세 관통 절차는 `L5/Q2/e2e-bank-transfer-runbook.md`가 정본이다.** 이 문서는 입금확인 부분만 다룬다.

```
  ✕ 상품준비중 · 배송준비중 · 배송중 · 배송완료 · 구매확정 버튼

```
