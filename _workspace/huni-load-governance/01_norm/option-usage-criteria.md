## 1. 옵션 정당 3용도 (이 셋만 KEEP 자격)

### U-1 — 혼재 묶음 (BUNDLE)
한 선택지가 **자재+공정 등 2개 이상 축을 동시에** 의미한다.
- **근거 신호**: 옵션아이템의 ref가 복수 축을 가리킴(item_seq 다중: seq1~=자재.03, 마지막 seq=공정.04) 또는 공정 상세 json 동반.
- **예**: 아일렛=금속링 **자재**(t_mat) + 현수막에 박는 **타공 공정**(t_proc). 각목+끈=자재 2 + 공정 1(seq 3행).
- **왜 옵션인가**: DB는 자재·공정을 각각 별도 등록하되, option_items+template이 둘을 묶어 **주문접수 + 생산작업지시(자재 BOM + 공정)** 모두 성립하게 하는 유일 장치.
- **경계**: 순수 공정(열재단·bare-hole 타공)은 자재 없는 process-only → U-1 아님(U-3만).

### U-2 — 기준정보 밖 선택
손님이 골라야 하는데 **기초마스터 6축(자재·사이즈·도수·인쇄옵션·공정·판형) 어디에도 대응 축이 없다.**
- **근거 신호**: 260702 권위 시트에 선택 축이 실재하는데 기준정보 바인딩으로 표현 불가.
- **예**: 접지 방식·커팅 모양·편집 옵션 등 물리 축이 아닌 손님 결정.
- **왜 옵션인가**: 축이 없으니 옵션이 유일한 손님 선택 표현.

### U-3 — 생산 전달
선택 결과가 **생산(작업지시)에 자재·공정 정보로 전달돼야** 한다.
- **근거 신호**: webadmin/주문 흐름의 소비 지점(SKU·작업지시)에 그 값이 자재 BOM/공정으로 흘러야 함.
- **예**: 후가공 공정 선택(코팅·박)이 생산 라우팅에 반영.
- **왜 옵션인가**: 선택→생산 전달 경로가 옵션+template.

> 한 옵션이 U-1·U-3을 동시에 만족할 수 있다(아일렛=혼재 묶음이자 생산 전달). **U 하나 이상이면 KEEP 자격.**

## 2. 판정 절차 [HARD] (auditor가 그대로 실행)

```
옵션 1건 발견
├─ ① 이 옵션이 없으면 [손님 선택 / 가격 / 생산] 중 무엇이 안 되는가?
│      ↳ 아무것도 안 막힘 → 잡음/중복 후보(3단계로)
├─ ② 그 일을 기준정보 바인딩(자재/사이즈/도수/공정/판형·수량규칙)이 이미 하고 있는가?
│      ↳ 예(중복) → 옵션은 잉여. MOVE-기준정보 후보
│      ↳ 아니오 → U 태깅으로
└─ ③ U-1/U-2/U-3 중 하나라도 태깅되는가?
       ↳ 예 → KEEP(단, 불완전하면 EXTEND)
       ↳ 아니오 → 처분 후보 → §3 처분 6종 결정
```

**중복의 정의**(핵심 적발 대상): "기준정보를 적재하고 **똑같이 옵션도 넣은 것**." 자재/사이즈/도수/공정/판형이
이미 기준정보로 바인딩돼 가격·생산이 성립하는데 옵션에도 같은 값을 넣어 이중 관리하는 경우 = MOVE-기준정보.

## 3. 처분 6종 결정 규칙

| 처분 | 조건 | 액션 | 라우팅(실 COMMIT) |
|------|------|------|-------------------|
| **KEEP** | U-1/U-2/U-3 중 ≥1 충족·완전 | 유지 | — |
| **RETIRE** | 어느 U도 아니고 중복도 아니며 **잡음**(Test 그룹·items 0·잔재) | use_yn/del_yn=N 정리 | §7 dbmap |
| **MOVE-기준정보** | 기준정보 축으로 이미 표현되는데 옵션도 **중복 등록** | 옵션 제거, 기준정보 바인딩만 존치 | §7 dbmap |
| **MOVE-제약** | 옵션그룹이 **조건부 관계를 흉내**(CN-6 오용) | 정규 그룹 1개 + 명시 제약(CN-1~4)으로 이관 | §31 constraint-rules |
| **MOVE-템플릿** | addon성(부속 가산상품)을 옵션으로 넣음 | addon `t_prd_templates` 레이어로 | §7 / §21 addon |
| **EXTEND** | 옵션 자체는 정당(U 충족)하나 **불완전** — 명명 분열·ref 누락·색상축 파편화 | 정규화/보강(그룹명 통일·ref 연결) | §12 basecode + 물리제약분만 §31 |

## 4. BLOCKED 분리 규칙 [HARD] — 가격종속 옵션은 정리 시 파손

- **가격종속 판정**: 옵션이 **가격사슬에 참여**한다 = ref_dim_cd로 **단가행을 매칭**하거나 가격구성요소를 참조해
  evaluate_price 결과에 기여한다(0이 아닌 금액 유발/변동).
- **규칙**: 가격종속 옵션은 RETIRE/MOVE로 즉시 처분하면 **가격 파손**(견적 0·저청구·선택지 손실). →
  **BLOCKED로 분리**하고 실무진 답변/승인 큐로. 처분은 대체 배치(기준정보 바인딩·제약)가 가격을 무손상으로
  이어받음이 **evaluate_price/evaluate_set_price로 입증된 뒤에만**.
- **최우선 가드[HARD]**: **손님 선택지 손실 0(오차단 0)**. 옵션을 지워 손님이 고르던 것을 못 고르게 되면
  = 매출 차단. 어떤 처분도 선택지를 없애서는 안 된다(대체 표현으로 옮길 뿐).
- **실무진 IMPORT 존중[HARD]**: 실무진이 IMPORT 시트로 등록한 자재/옵션은 "배선 안 됐다"는 이유로 삭제 금지 —
  배선·단가를 채워야 할 갭이지 처분 대상이 아니다([[formula-components-wiring-subtrack-260701]]).

## 6. 판정 산출 형식 (Phase 2 auditor 인계 계약)

각 옵션 1행 = { prd_cd · 그룹명 · opt 수 · **U 태깅(U-1/U-2/U-3/없음)** · **처분(KEEP/RETIRE/MOVE-기준정보/
MOVE-제약/MOVE-템플릿/EXTEND/BLOCKED/AMBIG)** · **가격종속(Y/N)** · 근거(라이브 신호·SOT) · 가격 파손 모드 }.

- **오차단 0 자기점검**: 처분이 RETIRE/MOVE면 "이 옵션이 없어지면 손님이 못 고르게 되는 선택이 있는가?"에
  **No**여야 통과(대체 배치가 선택을 이어받음). Yes면 BLOCKED.
- **최종 검증**: 처분 후 evaluate_price/evaluate_set_price **PRICE≠0·이중합산 0**(vessel-norm §최종 잣대).
- 근거 없는 판정 0(빈 근거 셀 금지).
