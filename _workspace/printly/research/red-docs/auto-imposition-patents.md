## 2. 핵심 요지 (한 줄)

**조판=주문 승인된 PDF를 받아, 장비 가용영역 안에 여러 주문건을 "판의 수(판수)를 최소화"하도록 자동 배치(터잡기)하고, 배치 좌표·돔보/재단선/바코드가 얹힌 조판 PDF를 만들어 장비별 포맷으로 변환·전송하는 생산 준비 단계.** 핵심 가치 = 숙련 작업자가 계산기로 하던 판수 계산·배치를 자동화 → 판수↓ → 종이/잉크·RIP시간·인건비↓.

## 3. ★ 자동조판(자동배치) 메커니즘

### 3.1 입력 → 출력
- **입력**: 주문 승인된 PDF(레이어 분리됨: 인쇄 Layer + 후가공/Cut Layer), 주문 사이즈, 주문 수량, 재질(자재), 재단횟수, 컬러값(잉크 위치), 장비 인쇄 가용영역, 장비 가용상태.
- **출력**: 배치(터잡기) 좌표 정보(DB 또는 XML 저장) → 조판된 PDF(돔보·바코드·재단선·ColorBar·생산공정정보 포함) → 장비별 포맷 파일 → 생산공정 정의(JDF/XML, 소요시간 예측).

### 3.2 5단계(V1) / 4단계(V3·V4) 프레임워크
V1 (자동조판, p4-5):
1. 주문 승인된 PDF 불러오기
2. **비정형 커팅 인쇄물 여부 체크** → 비정형=**Nesting Locator** / 정형(사각형)=**Object Locator**
3. **PDF Generator** (배치 좌표로 실제 데이터 배치 + 여러 후가공 병합)
4. **File Converter** (장비별 포맷 변환·전송)
5. **생산공정 수립 및 JDF 생성** (장비별 소요시간 예측·최적 장비 추천)

V3·V4 (자동배치, V3 p4-5): 시작 → **내부 자재관리시스템 연동·장비 가용상태 모니터링·최적 장비 선택** → **선택 장비의 인쇄 가용영역 정보 로드** → ① Object Locator → ② PDF Generator → ③ File Converter → ④ 생산공정 정의 및 XML 생성 → 끝.

### 3.3 배치 최적화 엔진 (Locator)
- **Object Locator(정형/사각형)** (V1 p7): 주문 제품 생산공정 정보에서 최적 Locator 선택 → 배치 최적화 → DB/XML 저장. **장비특성 고려 = ① 주문 Data 간 최소 간격 ② 주문 Data의 최대/최소 사이즈 ③ 인쇄 가능 용지 최대 크기**. 장비별 모듈 분리: **AeroCut / Zund / DaeHo / SmartSracker / RD / Etc Locator**(장비 추가 시 모듈 추가).
- **Nesting Locator(비정형: 원형·타원·캐릭터 등)** (V1 p6): 주문 PDF(Layer별) → **Cut Layer의 모든 Object 좌표 및 Path 정보 추출** → Nesting Locator(배치 최적화) → DB/XML 저장.
- **머신러닝 연동**(V1 p3·p7): 학습된 배치정보 기반으로 주문 유입 시 최적 배치 추천 → **유휴상태 기기 + 중복 처리 가능 기기 추천** → 생산공정 가속.
- **여유공간 재배치**(V3 p7·p8): 배치 후 빈 공간 체크 → **동일자재이면서 주문수량이 다른 건** 중 빈 공간에 들어갈 크기의 데이터를 불러와 재배치(공간 최소화).

### 3.4 PDF Generator (V1 p8, V3 p12-13)
- 입력: Locator 배치 좌표 정보 + 주문 승인된 레이어별 PDF.
- 각 후가공별로 새 레이어 생성 후 배치 좌표에 맞게 배치 → **돔보·바코드·재단선·ColorBar·생산공정정보 생성**.
- 여러 후가공 동시처리 장비 여부 분기(Y): 함께 처리 가능한 모든 후가공 Layer PDF를 **병합(Merge) + Flatten** 후 별도 저장. → 배치 완료 PDF 저장.

### 3.5 File Converter (V1 p9, V3 p14-15)
- 완성 배치 PDF를 장비 요구 포맷으로 변환 후 저장소(DB/스토리지/클라우드)에 저장 → 인쇄 시 장비가 로딩.
- 변환 유형: **PDF2INI, PDF2SCRIPT, PDF2TIF(F), PDF2CUT, PDF2HPGL/GPGL, PDF2JDF, PDF2DXF, PDF2ZCC**.
- 변환↔장비 매핑: PDF2TIFF→Scodix, PDF2DXF→Hicon, PDF2SCRIPT→Kongbug, PDF2INI→AeroCut, PDF2ZCC→Zund, PDF2CUT→SmartStacker, PDF2JDF→대호, PDF2GPGL→Graphtec.

### 3.6 생산공정 수립·JDF/XML (V1 p10, V3 p16)
- 주문 데이터 분석 → **공정별 장비 소요시간 예측** → 견적/공정 스케줄 반영 → 최적 장비(플로우) 추천 → 장비별 **JDF**(V1) / **XML**(V3·V4) 생성·저장.

## 4. 큰사이즈(Large Format) 특화 — V4 핵심

### 4.1 Large Format 정의·분기 (V3 p6·p8, V4 p2·p4)
- **Large Format = 대략 주문 사이즈 1m² 이상 & 파일 용량 5MB 경우**(V3 p8 항목3).
- Object Locator 흐름 초입에 **"Large Format 여부 체크"** 분기 추가 → Y면 **"큰 사이즈 파일들의 판수를 줄이는 알고리즘" 적용**(Ripping 속도·출력기 전송시간·커팅파일 생성·커팅기 세팅시간 절약 목적).

### 4.2 왜 큰사이즈가 다른가 (V4 p4-6)
- **RIP(Ripping) 병목**: RIP = 편집프로그램의 포스트스크립트 파일을 출력장치 인쇄 망점 래스터이미지로 변환하는 "번역기". **인쇄 파일 데이터가 큰 경우 이 RIP 시간이 가장 많이 소요됨** → 판수가 곧 시간·비용.
- **출력과정별 시간 정량화**(V4 p5, 핵심 표): Rip 1판 10분(3판 30분), 출력기 전송 5분(15분), 출력(면적 같으면 비슷), 커팅세팅 3분(9분), 커팅(비슷) → **1판 18분 vs 3판 54분**. **3판→1판 = 36분 절약**. 결론: **"출력 시 생산성 핵심 = 판의 수를 줄이는 것"**.

### 4.3 이종 주문 통합 배치 = 판수 최소화의 요체 (V4 p4·p7·p8)
- **큰사이즈 실사 출력 = 롤 타입이 많고, 그에 맞는 조판형태 추출이 관건**(V4 p7).
- 사례: 동일 사이즈 파일 A/B/C, 주문 수량 100/200/300장, 한 판형에 최대 6개 배치 가능 가정.
  - **기존(숙련 작업자)**: A 1판(4개×25=100), B 1판(4×50=200), C 1판(6×50=300) → **총 3판**.
  - **본 발명(개선)**: 수량비를 반영해 **한 판형에 A×1칸 + B×2칸 + C×3칸(=6칸) 배치 → 1판을 100매** 인쇄하면 A=100, B=200, C=300 동시 충족 → **1판**. (V4 p7)
- 낭비 비교(V4 p8): 한 판 6개 균등배치 시 A는 6×17=102장(2장 과잉), B는 6×34=204장(4장 과잉)으로 종이·잉크 허비. 4개 배치 시 A 25매(100)·B 50매(200)·C 75매(300)로 깔끔하나 판수↑. → **수량 비례 칸 할당(A1:B2:C3)이 판수·낭비 동시 최소화**.

## 5. 버전 진화 (V1 → V3 → V4)

| 축 | V1.0 (자동조판) | V3.0 (자동배치) | V4.0 (자동배치·큰사이즈) |
|---|---|---|---|
| 명칭 | 자동**조판**시스템 | 자동**배치**시스템(전환) | 자동배치시스템 |
| 스텝 수 | 5스텝 | 4스텝(JDF→XML 재명명) | 4스텝(V3 계승) |
| Nesting Locator | **독립 분기 스텝**(비정형↔정형 2갈래) | **Object Locator 내부로 흡수**(사각형 체크 후 N일 때 Nesting 알고리즘 적용) | V3와 동일 |
| 선행 단계 | (없음) | **자재관리 연동·장비 가용 모니터링·최적장비 선택·가용영역 로드** 전면 추가 | V3 계승 |
| Large Format | 없음 | **"Large Format 여부 체크" 분기 신규**(1m²·5MB, 판수축소 알고리즘) | **심화 특화**(RIP병목 정량화·이종주문 통합배치·낭비비교) |
| 배치 사례 시각화 | 없음 | **3종 신규**(사각형/여러모양/혼합, 정렬포인트·바코드·색상돔보) | 큰사이즈 배치사례·시간표·조판비교 |
| 여유공간 재배치 | 없음(암시) | **명시 추가**(동일자재·다른수량 빈공간 재배치) | V3 계승 |
| 생산공정 산출 | JDF 생성 | XML 생성(+견적/스케줄 반영) | (해당 스텝 미수록) |

**진화 서사**: V1은 "조판(정형/비정형 2엔진)" 중심의 뼈대. V3는 관점을 **"배치(장비 가용·자재 연동 기반 최적화)"**로 재정의 — Nesting을 Object Locator의 한 갈래로 흡수하고, 장비 가용 모니터링·인쇄 가용영역·여유공간 재배치를 전면화하며, Large Format 축을 신설. V4는 V3 골격 위에 **큰사이즈/롤 실사 출력의 판수 최소화**를 RIP 시간 정량화 + 이종 주문 통합 배치(A1:B2:C3)로 심화.

## 6. 여정 내 위치 (조판이 어디이고 무엇을 앞뒤에 넘기나)

```
홈페이지 주문(데이터+파일 수집)
  → 데이터/파일 유효성 검사·오류 자동 수정, 인쇄/후가공 Layer 분리·파일 전처리
  → [고객 실시간 견적·미리보기 피드백]  (V1 배경: 디자이너 수작업 제거)
  → ★주문 "승인된" PDF (레이어 분리 완료)
  ─────────── 여기부터 자동조판/배치 시스템 ───────────
  → (V3+) 자재관리 연동·장비 가용상태 모니터링 → 최적 장비 선택 → 인쇄 가용영역 로드
  → Object Locator (동일자재 모으기·Large Format 체크·사각형/Nesting·배치최적화·여유공간 재배치) → 배치좌표 DB/XML
  → PDF Generator (배치좌표+레이어 PDF로 조판 PDF 생성, 돔보/바코드/재단선/ColorBar/공정정보, 후가공 병합·Flatten)
  → File Converter (장비별 포맷 변환·저장소 저장)
  → 생산공정 정의·JDF/XML (장비별 소요시간 예측·공정 스케줄·최적 장비 플로우)
  ──────────────────────────────────────────────
  → 장비 전송 → 인쇄 → 후가공(커팅 등) → 배송
```

- **조판의 앞**: 주문 승인·파일 전처리(레이어 분리)·견적/미리보기. 조판은 견적 **확정 이후**의 생산 준비.
- **조판의 뒤로 넘기는 것**: ① 배치 좌표(DB/XML) ② 조판 PDF ③ 장비별 변환 파일 ④ 생산공정 정의(소요시간·스케줄).
- **견적과의 관계**: V1은 "실시간 정밀 인쇄·후가공 견적/미리보기"를 배경 가치로, V3는 생산공정 스텝에서 "장비별 소요시간 예측 → 견적/스케줄 반영"을 명시. 즉 조판/배치 결과(판수·공정시간)가 견적·납기에 피드백되는 구조로 서술(구체 데이터 흐름은 GAP).

## 8. 프린틀리 시사

- **조판 = 경계 노드(imposition_function)의 실체**: RED 특허의 Object/Nesting Locator = "판수를 줄이는 배치최적화 엔진". 프린틀리 온톨로지 관점에서 **전략 축(n-up/gang/booklet/tiling)은 분기 결정**(사각형↔비정형, Large Format 여부, 동일자재 gang 그룹핑, 판수 최소화 목표)이고, **실제 값(판수·배치 좌표·nesting 기하)은 엔진 소관** — 특허가 축/값 경계를 그대로 예시한다.
- **후니 `fn_calc_pansu`와의 관계**: 후니 `fn_calc_pansu`(판걸이수·`t_siz_pansu` 룩업)는 "한 판에 몇 개 앉히나"를 계산하는 판수 엔진. RED의 Object Locator는 그 상위 개념 = **여러 주문건을 장비 가용영역에 앉히며 판수를 최소화**하는 다중주문 배치. 후니 fn_calc_pansu = 단일 상품 판걸이수, RED Locator = 다중 주문 gang-run 최적화. → 프린틀리 엔진 레이어에서 fn_calc_pansu를 재사용하되 **다중주문 통합(A1:B2:C3 수량비례 칸 할당)** 개념을 얹으면 RED급 배치가 됨.
- **특허 C1(다중주문 배치 최적화) 근거 확인**: V4의 "이종 주문 통합 배치(수량 비례 칸 할당)"가 바로 다중주문 배치 최적화의 구체 알고리즘 예시. 프린틀리 C1 서술의 1차 출처로 인용 가능.
- **큰사이즈=롤 실사**: V4는 "큰사이즈 실사 출력=롤 타입"이라 판형 개념이 시트와 다름을 명시(V4 p7). 후니 실사=면적매트릭스(가로×세로 구간) 모델과 연결 — 롤/면적 기반 조판은 시트 판걸이수와 별도 축.
- **생산시간 예측**: V4의 출력과정별 시간표(RIP/전송/출력/커팅세팅/커팅)는 특허 C1(생산시간 예측)의 정량 근거. 프린틀리가 "언제 받나(납기)"를 답할 때 조판 판수 → 공정시간 → 납기 사슬을 이 표로 앵커 가능.

## 9. GAP (불확실·미기재)

1. **알고리즘 로직 미기재**: Nesting 알고리즘·"판수 줄이는 알고리즘"·Object Locator 배치최적화의 실제 계산 로직은 "적용한다"만 서술, 수식/의사코드 없음.
2. **장비별 Locator 내부 차이** 미상(AeroCut/Zund/DaeHo/SmartSracker/RD Locator가 각각 무엇이 다른지).
3. **견적↔조판 데이터 흐름** 불명확: 조판 결과(판수)가 가격/견적에 정확히 어떻게 되먹임되는지 미서술.
4. **JDF vs XML**: V1은 JDF, V3/V4는 XML — 표현 변경인지 실제 산출물 변경인지 불명(JDF도 XML 기반이라 상위 개념 표기일 가능성).
5. **Large Format 임계값(1m²·5MB) 근거** 미상(장비/RIP 경험칙으로 추정).
6. **머신러닝 배치 학습의 학습 데이터·모델** 미기재(개념적 언급만).
7. **후가공 병합(Flatten) 규칙**: 어떤 후가공이 "함께 처리 가능"인지 판정 기준 미상.
