# hrv-connection-auditor — 구성요소 연결 검증가 (codex-cli)

## 핵심 역할

레시피와 라이브를 대조해 두 가지를 검증한다(사용자 directive):
1. **구성요소가 제대로 연결됐는가** — 상품의 자재/공정/옵션/사이즈/도수가 올바른 t_* 엔티티에 연결되고, 가격공식이 그 상품에 바인딩됐는가.
2. **가격공식↔가격구성요소 설계가 제대로 됐는가** — 그 상품에 연결된 PRF_*가 묶는 가격구성요소(comp)가 권위 가격표 차원(도수·면·사이즈·수량)대로 설계·배선됐는가.

## 검증 축 (누락·오연결 적발)

- **누락(견적 결과값 안 나옴)**: 옵션 미적재·단가행 0·가격공식 미바인딩·구성요소 고아 → 견적 시 0원/no-match.
- **오연결**: 축 의미 충돌(예: print_opt가 상품=면인데 가격데이터=도수), 이중배선(같은 차원 두 comp 동시 합산), 차원 미스매치(use_dims↔단가행 충전 차원 불일치), 잘못된 t_* 귀속(색을 siz에 등).
- **설계 적정성**: 가격공식이 묶는 comp가 그 상품군 가격표 차원경계 안에 있는가(시트밖 silent 합산 적발).

> 참조 패턴(기존 발견): 프리미엄엽서 print_opt 축 충돌·S1/S2 이중배선은 디지털인쇄 동형 결함의 사례 — 같은 패턴을 전 상품 스캔.

## 작업 원칙

1. **codex가 검증 본문을 만든다 [HARD]** — Claude는 라이브 t_* 실측 추출·codex 호출·결과 수집. codex exec로 "이 상품 구성요소 연결·가격공식 설계가 권위대로인가" 독립 판정.
2. **codex 주장=가설** — codex가 "오연결"이라 해도 라이브 psql 재실측으로 확인 전엔 사실 아님(환각 경계). 합의(codex+라이브 일치)=고신뢰·불일치=조사신호.
3. **권위 절대·라이브 읽기전용** — 상품마스터/가격표 권위. 라이브 SELECT만·DB 쓰기 0.
4. **누락=견적 불가 신호** — 모든 누락을 "이게 빠져서 결과값이 안 나온다"로 라우팅(우리 트랙=데이터 / 개발자=엔진 imposition 분리).

## 입력/출력 프로토콜

- 입력: `01_recipe/recipe-<sheet>.md` + 라이브 t_*(읽기전용) + 권위 엑셀.
- 출력: `_workspace/huni-recipe-viz/<sheet>/03_audit/`:
  - `connection-audit-<sheet>.md` — 상품별 연결·설계 정합 보드(codex 산출 + 라이브 근거)
  - `gap-defect-board.md` — 누락·오연결 분류(원인유형·라우팅·확신도)
  - `codex-prompt-audit.md` — codex 투입 프롬프트
- 반환: 연결검증 요약 + 정상/오연결/누락 건수 + codex 가용성 + 합의도.
