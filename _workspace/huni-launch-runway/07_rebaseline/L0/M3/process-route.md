## 1. webadmin 이 가진 것 / 가지지 않은 것

### 1.1 가진 것 — 공정 **마스터**와 상품↔공정 **연결**

| 테이블 | 컬럼 | 뜻 |
|---|---|---|
| `t_proc_processes` (활성 **143**) | `proc_cd` · `proc_nm` · `upr_proc_cd`(상위공정, 2단 계층) · `prcs_dtl_opt`(JSON 상세옵션) · `side_sel_yn`(면별선택) · **`disp_seq`(표시순서)** · `work_margin_*`(작업여백 4방) · `cust_desc`(고객노출설명) | 공정 사전 |
| `t_prd_product_processes` | PK(`prd_cd`,`proc_cd`) · **`mand_proc_yn`(필수공정여부)** · `dtl_opt_rng`(상세옵션 허용범위) · **`disp_seq`(표시순서)** | 이 상품에 붙는 공정 |

### 1.2 [HARD] `disp_seq` 는 **표시순서이지 생산순서가 아니다**

`models.py` `db_comment='표시순서'`. 위젯·관리화면에서 **보여 주는 차례**를 정하는 값이다.
공정라우트가 요구하는 **선후관계**(디지털출력 → 코팅 → 재단 → 제본)는 이 컬럼으로 표현되지 않는다.

### 1.3 가지지 않은 것

- 공정 **순서(선후관계)** 를 담는 컬럼·테이블
- 라우트 **케이스**(낱장인쇄형·스티커형·책자형…) 라는 개념
- **팀/파트 귀속**(디지털인쇄팀·스티커가공파트·인쇄후가공팀·제본·특수인쇄가공팀·봉재가공파트·굿즈가공)
- 팀 간 **출고/입고** 이동
- **리드타임 / 제작기간**

라이브 테이블 검색(`information_schema`, `%route%`·`%mes%`·`%ship%`·`%deliv%`·`%pack%`) 결과: `t_ord_orders` · `t_ord_artworks` · `t_ord_webhooks` **3개뿐**(+백업 1). **라우트 그릇이 아예 없다.**

## 2. 18개 라우트 전수 (공정관리 PDF §02)

> ⚠ **PDF 자체의 번호 오류**: 라벨이 `Case1`~`Case17` 인데 **`Case5` 가 두 번**(책자 / 커버·클립보드) 쓰였다. 실제 라우트는 **18개**다. 데이터화할 때 재채번이 필요하다.

기호: `→` 순차 · `⋯` **점선 박스 = 선택 공정**(코팅·쿨코팅·조립/후가공) · `[출고]`/`[입고]` = **팀 간 이동** · `∥` 병렬 투입 · `/` 택1

| # | 라벨 | 라우트 | 포장 |
|---:|---|---|---|
| 1 | 낱장인쇄 | 디지털출력 [출고] → ⋯코팅 → 재단 | 1차포장 |
| 2 | 스티커 | 디지털출력 [출고] → ⋯코팅 → (반칼커팅/완칼커팅) [출고] → 재단 | 1차포장 |
| 3 | 인쇄후가공 | 디지털출력 [출고] → ⋯코팅 → 재단 → **오시/접지/타공/귀돌이 · 수동도무송 등** | 1차포장 |
| 4 | 책자(링제본) | 디지털출력 [출고] → ⋯코팅 → 재단 → [입고] **링제본** | (표기 없음) |
| 5 | 책자 | 디지털출력 [출고] → ⋯코팅 → 재단 → [입고] (**중철제본 / PUR제본 / 떡제본**) → 재단 | 1차포장 |
| 5′ | **커버/클립보드** *레더+싸바리 | (디지털출력 [출고] ∥ 패브릭출력) → [입고] **싸바리** → ⋯조립/후가공 | 1차포장 |
| 6 | 실사/사인 | 실사출력 → ⋯쿨코팅 → ⋯조립/후가공 | **1차포장+박스포장** |
| 7 | 투명실사 | 라텍스(화이트)출력 → ⋯조립/후가공 | **1차포장+박스포장** |
| 8 | 커팅 | 레이저커팅 / 시트커팅 | **1차포장+박스포장** |
| 9 | 봉제미싱 | 패브릭출력 → [입고] **봉제미싱** | 1차포장 |
| 10 | UV단품 | UV 평판출력 | 1차포장 |
| 11 | 투명클립보드 | UV 평판출력 → 레이저커팅 → 조립/후가공 | 1차포장 |
| 12 | 아크릴가공 | UV 평판출력 → 레이저커팅 → [입고] **아크릴가공** | 1차포장 |
| 13 | 전사 | 전사인쇄 | 1차포장 |
| 14 | 도장 | 도장제작 | 1차포장 |
| 15 | **외주공정** | 동판제작 → 박작업 → [입고] **생산본부** | (생산본부로 회수) |
| 16 | 재고상품 | 상품액세서리 | 1차포장 |
| 17 | **외주제작** | 책자제작 / 실사현수막 / 합판인쇄 / 고주파 (전부 회색=외주) | 1차포장 |

### 관측되는 구조 규칙

1. **코팅은 거의 항상 선택**(점선). 라우트 1~5 에서 건너뛸 수 있다.
2. **재단이 두 번 나오는 라우트가 있다** — 책자(5): 제본 전 재단 + 제본 후 재단(삼면재단).
3. **[입고] 태그가 붙는 공정 = 다른 팀에서 받아오는 공정** — 링제본·중철제본·싸바리·봉제미싱·아크릴가공·생산본부. 이것이 Summary 「To Do List」의 `제본입고 / 봉제미싱입고 / 아크릴가공입고 / 박작업입고` 와 짝이다.
4. **박스포장까지 가는 것은 부피가 큰 것**(실사/사인·투명실사·커팅) 뿐이다.
5. **라우트 15·17 은 외주** — 외주공정(공정만 밖에 맡김)과 외주제작(제작 전체를 밖에 맡김)이 다르다.

## 7. 파일 서버 구조 (주문프로세스 PDF p.12 §06-1 파일 FLOW)

```
                        AMAZON  ←→  MES  ←→  통신해야함  ←→  후지필름 생산컨트롤타워
원본파일 UP → 접수파일 UP                                      모션원 프리프레스 커스텀
                                                              후지필름 랜더서버
오프라인주문 · 발주팀(비즈하우스 다운로드) · 발주팀(후지필름 랜더파일)
                        ↓ 네트워크로 가져옴 / 접수파일 이동
                    파일서버 + NAS  ← 신규구입 · 접수파일 취합 / 조판파일생성
```

공정별 폴더 구조는 전부 **`년도 > 날짜(발주일자)`** 로 동일하다:
디지털인쇄 · 실사출력 · 레이저커팅 · 시트커팅 · 커팅 · UV인쇄 · 패브릭인쇄 · 전사인쇄 · 화이트인쇄 (9개)

DOWN + **파일명 RENAME** 이 걸리는 지점은 4곳: **출력팀 · 실사출력팀 · 커팅파트 · 쿠마샵**.
> PDF 에 「**외주발주는?**」이라는 미해결 물음표가 출력팀 밑에 그대로 남아 있다.

**파일명 규약** (§06):
```
품목_출력사이즈_양단면_소재명_거래처명_고객명_파일고유번호_수량
1002_접지카드_92x50_D_랑240_BIZ_박현정_30146712_00100ea.pdf
```
- 앞의 `1002` = **발주일 또는 파일서버 등록일**
- 양면 `D` / 단면 `S` · 거래처 `BIZ`/`FUJI`/`HUNI` · 수량 5자리 `00100ea`
- 상품군마다 조합이 다르다 — 디지털인쇄 / 캘린더 / 스티커 / 실사출력 / 배너·현수막 / 패브릭인쇄 / 시트커팅 / 레이저커팅 (8종)
- **PDF 가 스스로 남긴 물음표들**: 「품목명으로 하기에는 중복사양이 있음」 · 「제작수량과 출력수량의 차이가 있을때는?」(전 8블록 반복) · 「4도/5도가 있어서 파일명에 구분필요한가?」 · 「칼선파일에 대한 구분 / 양단면 표기는? / 조판후 수량은?」 · 「일부상품에는 종이정보가 없음 넣어줘야함」 · 캘린더 「페이지 필요없나?」
- **1차 목표**(p.5 §05): 「주문과 파일의 매칭으로 **썸네일 자동생성** / **판매처에 상관없이 상품과 파일명의 일관화**」 · 「**MES 의 상품과 사용자의 상품을 매칭**하여 파일네임을 일관화해야 합니다」 ⇒ **이것이 `MES_ITEM_CD` 매핑(5.6%)이 필요한 진짜 이유다.**

## 8. 조판(imposition) — 라우트 앞에 있는 사람 작업

주문프로세스 PDF p.5 §05 Pain point 「조판」이 상세하다. **전부 사람이 AI(Illustrator)에서 한다.**

| 대상 | 사람이 하는 일 |
|---|---|
| 아크릴상품 | **아크릴원판 396×480 에 5도/9도 구분하여 배치하고 돔보 넣음** → 출력파일(PDF)과 칼선파일(AI CS4)을 **분리하여 분리분배** |
| 스티커 외 커팅상품(스티커·배경지·모양커팅) | **조판(판걸이+아이마크)** 출력파일(PDF)과 칼선파일을 구분하여 분리분배 |
| 다도안 상품 | **판걸이·건수·수량에 따른 조판** |
| 도장상품 | AI 에서 조판 후 **흑백출력**하여 생산에 전달 |

조판 후: 썸네일출력 · 의뢰서출력 → **팀별 또는 담당자에게 분리전달** / 외주상품은 포장출고팀에 / 외주공정 필요 상품은 외주관리자에게.

**자동합성(아이락) 경우**는 출력팀에서 바로 다운로드. 단 **「자동합성되어도 조판·파일수정·굿즈상품의 경우 발주팀으로 다운됨」** — 즉 자동합성이 조판을 없애지는 않는다.

## 9. 라우트를 데이터화할 때 필요한 최소 그릇 (제안 · 미구현)

> 이 절은 **제안**이다. 설계 확정본이 아니다.

| 필요한 것 | 왜 |
|---|---|
| 라우트 마스터 (18케이스 · 재채번) | 상품 → 라우트 귀속 |
| 라우트 단계 (라우트 × 순번 × 공정 × 필수/선택 × 팀) | 선후관계 interlock의 근거 |
| 상품 → 라우트 매핑 | 지금은 「상품마스터(공정) SHEET」를 사람이 봄 |
| 팀/파트 마스터 (8팀 + 외주처) | 권한·이동 |
| 공정 실적 (주문항목 × 단계 × 상태 × 시각 × 작업자) | 1차·2차 산출데이터 |
| 인쇄타입 → 파일포맷 → 다운로드 권한 매핑 | §6.2 |

**[미확인]** 위 그릇을 **MES 가 이미 가지고 있는지**. MES 는 이미 「공정별 현황표」를 그리고 있으므로 **일부는 있을 가능성이 높다.** MES 담당에게 확인해야 한다 — 없는 것만 만들어야 중복 구축을 피한다.
