##### 왜 축③이 이걸 통과시켰나 — 비교기의 구조적 맹점

```python
def cell_key(row_label, col_label):
    """(종류, 값) 쌍 2개를 집합으로. 축 이름 순서에 의존하지 않는다."""
    return frozenset([label_kind(row_label), label_kind(col_label)])
```

`frozenset` 이라 `(가로1400, 세로900)` 과 `(가로900, 세로1400)` 이 **같은 키**다. 두 축이 같은 종류
(`NNNmm`)면 전치가 구조적으로 보이지 않는다. M4-3 이 「축 이름 순서를 믿지 말자」고 넣은 설계가
그 대가로 **전치를 통과시킨다.** 그래서 축③은 `PRD_000138` 을 `matched=80` **PASS** 로 적었다.

**축③ 판정은 이 13상품에 대해 신뢰할 수 없다.** 비교기에 축 방향 검사를 넣어야 한다.

| **한 조합만으로 「가격이 안 나온다」 판정** | 1차 스캔 ERR 30건이 대부분 내가 축(`bdl_qty`·`print_opt_cd`·`proc_cd`)을 안 준 탓이었다 | **조합 구성이 다른 2방식으로 교차**한다. 합집합이 분모를 채우면 각자의 ERR 은 도구 한계다. 2차는 **실재 단가행의 축 값을 그대로** 실어 「정의상 단가가 있는 조합」을 만든다 |
| **엔진이 부분 합산을 막아 줄 것이라 가정** | 필수 구성요소가 빠졌는데 `ok:true`·`errors:[]` 로 31원(용지비만)이 반환됐다 | 부실 조합이 **에러 없이 통과**할 수 있다. 위젯은 축을 채우니 안전하지만 **API 직접 호출 경로는 다르다**. 낮은 total 은 `components` 배열을 열어 **무엇이 빠졌는지** 확인한다 |
| **0원 옵션에 단가행이 없어도 된다고 가정** | 마감 필수 옵션이 0원이라 단가행이 없어도 될 것 같지만, 고르는 순간 「주문할 수 없습니다」가 난다(M4-25 결함 A) | **0원짜리도 단가행이 있어야 한다.** 판별식은 비교군 — 같은 형태에서 `0.00` 행이 있는 상품(124·139)은 통과하고 없는 상품(133·134)만 차단된다 |
| **도구 매칭을 완화해 1건 더 잡기** | 숫자 부분집합 허용으로 규조토 사각 1건을 잡으려다 서로 다른 사양이 엮여 **OK 46→45 · 미판정 10→12** 로 나빠졌다 | 완화는 **판정 품질 지표로 검증**하고, 나빠지면 되돌린다. 엄격 매칭이 놓친 건은 수동 확인으로 문서에 남긴다 — **도구 한계는 미검증이 아니다** |
| **축④ 판정을 그대로 신뢰** | 축④ PASS 인 133/134 가 옵션 선택 시 차단되고, FAIL 인 138/139 는 실호출 전건 정상이었다 | 축④는 **곱은 축 기준의 판정**이다. 안 곱은 축(옵션·수량규칙)의 결함은 PASS 뒤에 숨고, FAIL 은 성립불가 조합·도구 한계일 수 있다. **FAIL 사유 원문을 읽어 분류**한다 |
| **권위 시트를 하나로 가정** | 상품마스터 「실사」 c26(10,000)을 권위로 삼아 「3,000원 과소청구」라는 없는 결함을 만들었다. 실제 권위는 가격표 「포스터사인」 c11(7,000)이고 라이브도 7,000 이었다(M4-23, 지니가 실제 표를 제시해 뒤집힘) | 같은 항목이 여러 시트에 있고 **값이 다르다**. 가격 사안의 권위는 **가격표**다. 그리고 **한 시트 안에서도 A열 블록만 훑으면 우측(c10~) 가격 블록을 통째로 놓친다** — 배너 추가옵션·가공옵션 권위가 거기 있었다 |
| **base 죽음을 곧 가격 결함으로** | base `use_yn='N'` 인 템플릿을 결함으로 셌다 | 템플릿에 단가가 있으면 base 가 죽어도 가격은 정상이다(천정고리 6,500 API 실증). 단가가 **없을 때만** 가격 경로가 끊긴다 |
| **근사매칭이 만드는 가짜 불일치** | 권위 「실외용배너거치대」 1행에 라이브 단면·양면 2건이 붙어 한쪽이 불일치로 나왔다 | 근사매칭이 권위 한 행에 2건 이상 붙이면 **판정 보류**(모호). 값 차이를 결함으로 굳히지 않는다 |
| **문서가 적은 코드 결함을 코드 확인 없이 인용** | 「`axis4.py:95` 필터 누락」을 그대로 받아 「조합 6→3」이라는 틀린 결론을 냈다(M4-21→M4-22 정정) | 함정표·§G 의 코드 관련 진술은 **닫혔을 수 있다**. 인용 전에 해당 파일을 열어 현재 상태를 본다. 이 항목 자체가 그 예다 |
| **스윕이 곱은 축 ≠ 가격축 전부** | 사이즈·자재 분모는 28/28 OK 인데 옵션 가격축 5상품이 통째로 빠져 있었다(38~92조합) | 분모를 검증할 때 「센 것이 맞나」뿐 아니라 **「빠뜨린 축은 없나」**를 함께 본다. `use_dims` 를 펼쳐 곱해야 할 축 목록을 먼저 만든다 |
| **권위 블록을 상품명으로 찾기** | 「권위 블록 미대응」으로 5건이 UNVERIFIED 로 남았다 | 블록 제목은 상품명과 다른 규칙으로 적힌다 — 2상품이 한 블록에 합쳐지거나(`시트커팅 (무광 / 홀로그램)`), 어순이 뒤집힌다(`미니보드스탠딩` ↔ `미니스탠딩보드`). 상품명 매칭이 실패하면 **블록 제목을 전수로 훑어 사람 눈으로 대응**시킨다. 블록 안에서 상품은 행, 사이즈는 열이다 |
| **위젯 축 = 가격축 착각** | 위젯이 `mat_cd` 를 노출하니 자재를 대조 축으로 잡는다 | 위젯 노출 축과 `use_dims`(가격축)는 **다르다**. 위젯 `cfg` 는 축(`ref_key`)만 선언하고 선택지 값은 담지 않는다(`WGT_SRC_TYPE.01` = DB 유도). 값은 DB 로 대조한다 |
| 스윕 곱집합 | 성립 불가 조합을 결함으로 센다 | 자재명에 사이즈가 박힌 상품(`A3 폼보드(화이트) 5mm`)은 `A2 사이즈 × A3 자재` 조합이 애초에 없다. 제약규칙의 몫이지 가격 결함이 아니다 |
