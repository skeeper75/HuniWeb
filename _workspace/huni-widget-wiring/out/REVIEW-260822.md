### 4-4. [중간] AC5는 구조상 실패할 수 없다

`build_wiring_health.py:284`
```python
edges_evaluated = sorted(edges_seen | set(EDGES))
```
실제로 판정된 엣지 집합에 **전체 엣지 상수를 합집합**한다.
AC5 판정 방법이 "index JSON 의 `edges_evaluated`"이므로(acceptance.md:19),
**어떤 엣지도 판정되지 않아도 AC5는 PASS한다.** 이 PASS는 증거가 아니다.

실제로 이번 산출에서 E2 결함은 `widget-defects.jsonl` 에 0건이다(가격 레이어 승계분에만 존재).

### 4-6. [중간] AC3 증거가 성립하지 않는다

### 4-7. [중간] 크래시 침묵 방지 수정은 유효하나 범위가 좁다

리드 지정 3번 항목. `widget_wiring_dx.py:60-70`:

```python
if proc.returncode not in (0, 1): raise RuntimeError(...)
rows = [json.loads(ln) for ln in proc.stdout.splitlines() if ...]
if proc.returncode == 1 and not rows and proc.stderr.strip():
    raise RuntimeError(f"{script} 크래시(exit 1·JSON 0)")
```

**유효한 부분**: progress.md에 기록된 실제 사고(`raw/webadmin/.venv` 에 django 부재 →
센서 크래시가 exit 1로 묵음 통과)를 정확히 막는다. 이번 실행에 `[환경 FAIL]` 결함 0건이므로
5센서 모두 정상 기동했다는 점도 확인했다.

**남은 구멍 2가지**:

1. `exit 1 · JSON 0행 · stderr 비어 있음` 조합은 여전히 "결함 0건"으로 통과한다.
2. 더 중요 — 크래시가 잡혀도 **상품별 verdict는 영향받지 않는다**.
   `_env_defect` 는 `prd_cd=None` 이라 `build_wiring_health.py:106-107` 에서 `*GLOBAL*` 로 빠지고,
   266상품은 그대로 OK/WARN으로 산출된다. 즉 **센서 하나가 죽어도 아티팩트는 정상으로 보인다.**

**권고**: 센서 실패 시 해당 엣지를 쓰는 전 상품 verdict를 `NOT_EVALUATED` 로 강등한다(4-3과 같은 조치).

### 4-8. [낮음] 아티팩트 표시 결함 2건

### 4-9. [낮음] `diagnose_remediate.py` 수정분 — 문제 없음
