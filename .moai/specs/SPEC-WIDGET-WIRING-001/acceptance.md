# 수용 기준 — SPEC-WIDGET-WIRING-001 v0.2.0

> [HARD] 의례 최소화 유지. 기준은 기계 판정 가능한 것만.
> v0.1.0 대비: AC3·AC5 판정 방법 교체(리뷰 §4-5·4-6), AC9~AC13 신설(렌즈 B·정정 반영).

## 렌즈 A (v0.1.0 승계 · 일부 교체)

| AC | 기준 | 판정 방법 | 실패 조건 |
|---|---|---|---|
| **AC1** 분모 | 스냅샷 활성 상품 수 == 라이브 실측 | 스냅샷 행수 vs `SELECT COUNT` | 불일치 |
| **AC2** 전수 | `wiring-health/*.json` 수 == 분모 | 파일 수 | 누락 1건이라도 |
| **AC3** 무수정 ★교체 | `raw/webadmin/**` 무변경 — **그 디렉토리는 별도(nested) git 저장소**이므로 그 저장소 안에서 `git status --porcelain`(M/A/D 0) + 보호파일 mtime·커밋 SHA 대조로 증명. 상위 저장소의 `git diff` 는 증거로 인정하지 않는다 | nested repo status + 실행 전후 SHA256 해시 | tracked 수정 1건이라도, 또는 해시 변경 |
| **AC4** 드리프트 0 | 어댑터 결함 카운트 == 원본 센서 직접 실행 카운트(코드별 **대조표를 보고서에 실제로 기록**) | 원본 5센서 실행 vs `widget-defects.jsonl` | 불일치 또는 대조표 미작성 |
| **AC5** 엣지 커버 ★교체 | 각 엣지가 **실제로 판정 시도됐음**을 센서 실행 로그로 증명 — 산출 상수의 합집합(`edges_seen ∪ EDGES`)은 증거로 인정하지 않는다 | 엣지별 `evaluated_by`(센서명·실행시각·처리 상품수) 기록 | 어느 엣지든 `evaluated_by` 공백 |
| **AC6** 읽기전용 | 라이브 write 0 | 실행 로그 INSERT/UPDATE/DELETE/ALTER 0 | 1건이라도 |
| **AC7** 아티팩트 | 외부 요청 없이 열리고 목록·드릴다운·단절 강조·필터 동작 | 브라우저 스모크 1회 | 기능 1개라도 미동작 |
| **AC8** 결정론 | 같은 스냅샷 재실행 시 산출 바이트 동일(타임스탬프 제외) | 2회 실행 diff | 차이 발생 |

## 판정 규칙

- 전체 GO = AC1~AC13 전부 통과. 하나라도 실패 = NO-GO.
- **결함이 많이 나오는 것은 실패가 아니다.** 실패는 ① 판정하지 못함 ② 드리프트 ③ 원본 훼손
  ④ 미검사를 통과로 표기 ⑤ 위험 문구 잔존 — 다섯 가지뿐이다.
- v0.1.0 리뷰가 지적한 "AC 통과가 증거가 못 되는 구조"(AC3·AC5)는 위 교체본으로 닫는다.
