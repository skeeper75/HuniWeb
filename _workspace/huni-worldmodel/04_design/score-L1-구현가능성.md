## 2. 설계안 A — 선언적 월드모델 · **6 / 10**

### 2.1 강점 (규칙 근거)

- **RULE-05 (BLOCKER) 충족 + 이 렌즈에서 3안 중 유일한 자산**: A는 게이트 G-A~G-F 6종에 4항(대상·도구·임계·분모)을 모두 채웠을 뿐 아니라, **임계 초과 시 무엇을 버리고 무엇으로 후퇴하는지를 사전선언**했다 — "G-B가 FAIL하면 컴파일 계층을 버리고 선언+GAC 전파+support tuple 3개만 남는 축소판으로 후퇴하며, 정보이득 대화는 성립하지 않는다고 인정한다"(design-A:468). 구현가능성 렌즈에서 이것은 큰 값이다: 가장 비싼 미검증 부품(지식 컴파일)이 실패했을 때 **설계 전체가 아니라 그 부품만 버리는 경로**가 문서에 있다. B·C에는 이 수준의 계층별 후퇴 선언이 없다(C §7-1의 "관리자·CS 도구로 강등"이 유사하나 게이트표 밖 산문이다).
- **RULE-13 (MAJOR) 충족 + 절차 재사용**: 라이브 write 3종 세트를 새로 발명하지 않고 기존 `dbm-load-execution` R1~R6 게이트 절차를 그대로 재사용한다고 명시했다(design-A:429). 신규 운영 절차 학습 비용 0.
- **RULE-08 (MAJOR) 충족**: `t_wm_support_tuples`가 N-19(전수 열거·사전계산 적재)와 다른 이유를 "결과가 아니라 축 쌍 사영이며 상한이 곱이 아니라 합"으로 명시 논증했다(design-A:186-190). 이 논증은 성립한다 — 감점 대상이 아니다.

### 2.2 감점 ① — **RULE-12 (MAJOR) 위반 확정**: 새 지식의 편집 표면이 존재하지 않는다

**위반 조항**: RULE-12 norm — *"그 정의를 **누가 어느 화면에서 유지하는지**를 명시한다. 새 지식은 **실무진이 편집 가능한 표면**(폼빌더 역파싱 가능한 정형 shape)에 착지해야 한다"*(evaluation-rubric.md:109).

**실패 시나리오 (재현 가능 형태)**
- 입력: 실무진이 파일럿 명함 상품에 대해 "박(후가공) 선택 시 동판비 구성요소가 부가된다"는 효과 1행을 `t_wm_effects`에 등록하려 한다.
- 기대: webadmin의 어느 화면에서 `prd_cd / act_dim_cd / act_val_cd / eff_typ_cd / tgt_cd / auth_anchor` 6칸을 채워 저장.
- 실제(예상): **그 화면이 존재하지 않는다.** webadmin 관리 화면은 `admin.py:1922`의 `admin.site.register(_model, _admin_cls)` 루프가 `models.py` 선언 모델(`M.*`)을 순회해 생성한다(V5 실측). `t_wm_effects`용 Django 모델을 `models.py`에 추가하는 것은 `raw/webadmin/**` 수정이며, A 자신이 §0에서 **"`raw/webadmin/**` 0줄"**로 못 박은 범위(design-A:18)와 정면 충돌한다. 남는 경로는 psql 직접 INSERT뿐이다.

**근거**
- `raw/webadmin/webadmin/catalog/admin.py:1922` — 등록 루프의 유일한 진입점.
- `design-A-declarative-worldmodel.md:18` — "코드 수정 범위: `raw/webadmin/**` **0줄**".
- `design-A-declarative-worldmodel.md:166` — "폼 필드와 컬럼이 1:1이므로 왕복(round-trip)이 항등이다". 이 문장은 **폼의 존재를 전제**하는데, 그 폼이 생성되는 유일한 기전이 §0에서 금지된 수정 뒤에 있다. 즉 역파싱 항등 논증은 참이되 **공허하게 참**이다.
- A 자신의 W-1(design-A:511-513) — "이 설계의 성패는 실무진이 288개 상품의 효과를 몇 개나 적어 주는가에 달렸다". 편집 표면 부재는 이 성패 조건을 **구조적으로 봉쇄**한다.

**적용 범위**: `t_wm_effects`(정의 원본·사람이 채움) · `t_wm_phrases`(문구 원본·사람이 편집) · `t_wm_escalations`(실무진 처리 큐 — 처리하려면 화면이 필요) 3개 테이블 전부. `t_wm_support_tuples`·`t_wm_quote_states`·`t_wm_predictions`·`t_wm_anchor_index`는 기계 생성물이므로 해당 없다.

**자기 반증조건**: `models.py` 수정 없이 `t_wm_*`의 실무진 편집 화면을 만드는 경로(별도 Django 앱 등록·외부 admin 인스턴스·기존 폼빌더 재사용 등)가 A 문서 안에 이미 기술되어 있음을 제시하면 이 지적을 철회하고 오판 FP-1로 자기 집계한다.

**교정 방향 (RULE-12를 어떻게 만족시킬 것인가 · 루브릭 §2.2(e))**
1. 효과 선언의 착지점을 신규 테이블이 아니라 **이미 폼빌더를 보유한 `t_prd_product_constraints`** 로 잡는다(A 스스로 여집합 금지형 `.02` 규약을 승계한다고 했으므로 어휘 충돌 없음). 또는
2. `models.py`에 모델 3개를 추가하는 **1회성 webadmin 수정**을 RULE-04의 명시적 예외 안건으로 승격시켜 인간 승인 절차에 올린다 — 숨기지 말고 비용으로 계상한다. 또는
3. 첫 조각에서 편집을 포기하고 **빌더 스크립트 생성물 전용**으로 선언한 뒤, 실무진 편집 표면은 후속 트랙으로 명시 이관한다(현재 문서는 이 이관을 하지 않았다).

### 2.3 감점 ② — **RULE-16 (MINOR) 위반 확정**: 판면효율 축의 원천이 값을 내지 못한다

**위반 조항**: RULE-16 norm — *"각 축마다 데이터 원천을 명시한다. **원천 없는 축은 도입하지 않는다**"* / violation_test (b) 데이터 원천(evaluation-rubric.md:143-144).

**실패 시나리오**
- 입력: 롤아웃이 가격·가능성이 동률인 후보 2개를 "판면효율"로 정렬하려 `fn_best_plate(prd_cd, item_siz_cd, scope)`를 재호출한다.
- 기대: 1장당 소요 판면적 값을 받아 정렬 키로 사용.
- 실제: **`RETURNS varchar`** — 반환값은 최효율 판형의 `siz_cd` 하나뿐이다. 효율값 `q.n / q.usable_area`는 서브쿼리 안에서 계산되어 `ORDER BY`에만 쓰이고 함수 밖으로 나오지 않는다. 정렬 불가.

**근거**: `raw/webadmin/sql/33_fn_best_plate.sql:33`(`RETURNS varchar`) · `:44-45`(usable_area 계산) · `:53`(`ORDER BY (q.n::numeric / q.usable_area) DESC`) · `:56`(`RETURN best_cd`). A의 주장은 design-A:305 — "`fn_best_plate` **가 이미 계산하고 버리는 값** … 함수 재호출로 획득".

**복구 경로 2개가 각각 다른 규칙에 걸린다**
- (가) `sql/33`을 수정해 효율값을 반환 → `raw/webadmin/**` 수정 전제 = RULE-04 (c) 위반(BLOCKER).
- (나) 외부에서 `fn_calc_pansu` + `t_siz_sizes` 여백 컬럼으로 효율을 재계산 → 기하 규칙의 **두 번째 정의** = RULE-12 ① 위반(MAJOR).

**대조 근거 (이 지적이 특이하지 않다는 증거)**: 설계안 B는 **정확히 같은 이유로 같은 축을 도입하지 않았다** — "`fn_best_plate`의 판면적 효율값(`sql/33_fn_best_plate.sql:48`)도 도입하지 않음 — 반환하려면 SQL 수정이 필요해 RULE-04에 걸린다"(design-B:434). 동일 사실을 놓고 B는 절제했고 A는 채택했다.

**자기 반증조건**: 효율값을 반환하는 `fn_best_plate` 오버로드 또는 동등 뷰/함수가 라이브에 실재함을 SELECT로 보이면 철회한다.

**교정 방향**: 판면효율 축을 첫 조각에서 **제거**하고(RULE-16 "원천 없는 축은 도입하지 않는다" 직접 이행), 필요하면 B·C처럼 판걸이수 룩업 히트 여부(`t_siz_pansu` 존재 조회)만으로 신뢰도 플래그를 만든다 — 이것은 SQL 수정 없이 가능하다.

### 2.4 감점하지 않은 것 (렌즈상 우려이나 규칙 근거 부족 → 미확인)

- **신규 스택 최대**: 지식 컴파일러 라이브러리가 미확정이고(BDD/CUDD·dd / MDD / d-DNNF c2d·D4 중 미선택, design-A:556), 신규 라이브 테이블 7개 DDL + 적재 승인 사이클, 플래너(model counting·정보이득), 검증 스크립트 4종이 동시에 필요하다. 1인~소수 조직 부담은 3안 중 명백히 가장 크다. **그러나 루브릭에 "신규 스택 총량"을 재는 규칙이 없다.** 즉석 잣대 생성을 금지한 §0.1 ①에 따라 **감점하지 않는다.** 점수(6점)에는 위 확정 위반 2건만 반영했고, 이 항목은 렌즈 서술로만 남긴다.
- **재컴파일 무효화 빈발(W-6)**: 단가행 23,573행이 다른 트랙에서 계속 갱신되므로 `source_digest` 불일치 → 판정 거부가 잦아질 수 있다. A가 §10 W-6에서 스스로 적었고 라이브 갱신 빈도를 실측하지 않았으므로 **미확인**(J-4 회피).
- **import 경로 오기**: design-A:318은 `from webadmin.catalog import pricing`이라 썼으나 `pricing.py:40`은 `from catalog import models as M`이고 Django 앱 루트는 `raw/webadmin/webadmin/`이다. 올바른 형태는 `from catalog import pricing`(+ `webadmin/`을 sys.path에). **오탈자 수준이며 어느 규칙에도 해당하지 않아 감점하지 않는다.**

## 3. 설계안 B — 지식 우선 (GraphRAG) · **8 / 10** · 감점 0

### 3.1 강점 (규칙 근거 + 실측)

- **RULE-04 (BLOCKER) 충족의 질이 높다**: 라이브 `t_*`에 테이블을 **하나도 신설하지 않고**(design-B:178) 파생·상태를 `wm.db` SQLite 오버레이에 둔다. `huni_wm/`은 webadmin 트리 밖 드롭인이며 import만 한다. → 구현가능성 렌즈에서 이는 "적재 승인 사이클 0회로 첫 조각 도달"을 뜻한다. A가 첫 조각(S1)에서 `t_wm_support_tuples` 적재(=라이브 write, 백업·DRY-RUN·undo·인간 승인 4단계)를 요구하는 것과 대비된다.
- **재사용 기반이 실물로 확인됨 (V3)**: `graph.db` 실재, `option_refs` 298건, `use_dims` 보유 price_component 132/134. B의 논지 2번("새로 채굴하지 않고 이미 있는 두 사실의 조인으로 파생된다", design-B:32)의 **양쪽 입력이 모두 실재**한다. 파일럿 상품 PRD_000016 선정 근거(option_group 3개·`R_DEMO_EXC` 상호배제·판걸이수 충돌 GAP 노드)도 KB 실측 인용으로 뒷받침된다(design-B:364-370).
- **RULE-12 (MAJOR) 충족의 방식이 구조적**: 차원 어휘를 **선언하지 않고 라이브에서 조회**하므로 소스코드에 차원 이름 리터럴 목록이 존재하지 않는다(design-B:293). 5벌이 6벌이 되는 경로가 코드 구조상 막혀 있다 — 규율이 아니라 구조로 막았다.
- **RULE-05 (BLOCKER) 충족 + 자기 편향 노출**: A1~A9에 4항 완비. 더해 §9-1에서 "파일럿이 유리한 상품을 골랐다는 자백"을 스스로 적고 2차 파일럿 의무를 명시했으며(design-B:459), §9-2에서는 **순수 SQL 대조군을 첫 조각에 넣어** 자기 논지의 과잉 프레이밍 가능성을 측정 대상으로 만들었다(design-B:467). 구현가능성 렌즈에서 이는 "쓸모없는 계층을 조기에 버릴 수 있는 장치"다.

### 3.2 순위를 C에 내준 이유 (감점이 아니라 렌즈 척도)

1. **첫 조각의 성립이 미확인 매핑 1건에 걸려 있다.** B §12-3이 스스로 적었다 — `option_refs` 타깃 타입(`material-*` 등)과 `use_dims` 키(`mat_cd` 등)의 대응표를 **코드로 확인하지 않았고, 어긋나면 A1이 즉시 실패한다**(design-B:541). B는 이것을 A1 게이트로 반증 가능하게 만들었으므로 **RULE-05 위반이 아니다.** 그러나 이 렌즈의 질문("첫 조각까지 도달하는 경로가 실재하는가")에는 "0단계 매핑 확정 이후에야 알 수 있다"가 답이 된다. C는 재사용 심볼 11종이 **이미 전건 실재 확인됨**(V2)이라 이 불확실이 없다.
2. **지식 계층 자체가 오버헤드일 가능성을 B가 인정한다.** §9-2 — 판정은 전부 라이브 재-SELECT가 하므로 그래프의 몫은 축 열거·팬아웃·감사 앵커·설명 4가지뿐이고, "①②는 라이브 SQL 3개로 대체 가능"이 나오면 논지가 과잉 프레이밍이 된다(design-B:461-467). 여기에 KB 스키마 델타 등재·`PRAGMA query_only` ATTACH 규율·해시 불변 CI(A8)의 유지비가 붙는다. C는 이 계층 자체가 없다.
3. **V8 실측이 감사 앵커의 실제 정밀도를 낮춘다**: KB `source` 2,705행 중 xlsx 앵커 0건. B가 §h RULE-11에서 "셀 단위가 아니라 시트·열 범위"라고 이미 한계 기록했으므로 위반은 아니나, "그래프가 감사에서 값을 한다"는 남은 지분 중 하나가 실측상 약하다.

### 3.3 감점하지 않은 것

- **표 이름 불일치**: design-B:293은 `SELECT DISTINCT jsonb_array_elements_text(use_dims) FROM t_prc_component_prices`라 썼고 §N-4(design-B:264)는 `t_prc_price_components.use_dims`라 쓴다. `models.py:253`에 `use_dims` 필드가 있으나 어느 모델인지까지 확정하지 않았다. **문서 오기 수준이며 어느 규칙에도 해당하지 않아 감점하지 않는다.** 파일럿 0단계에서 확정 필요 — 미확인으로 기록.
- **9-1 최대 약점(P-05 사각지대)**: B가 스스로 "돈이 가장 크게 새는 케이스가 이 설계의 파생에는 보이지 않는다"고 적었다(design-B:455-457). 그러나 이것은 **탐지 후 PROVISIONAL 강등 + `GAP_affect_undefined_*` 강제 등재**로 가시화되며, 충전은 §7/§18 소관이라 RULE-15 ③에 따라 흡수 금지다. **이를 결함으로 세우면 루브릭 J-3(하네스 경계 밖 지적) 자동 각하**에 걸리므로 감점하지 않는다.
- **9-3 신선도×응답성(축 하나당 20왕복)**: A9로 측정 대상화됨. C의 G7과 동종 위험이며 우열을 가릴 실측이 없다 — 미확인.

## 4. 설계안 C — 시뮬레이터 루프 · **9 / 10** · 감점 0 · **승자**

### 4.1 강점 (규칙 근거 + 실측)

- **RULE-04 (BLOCKER) 충족 + 재사용 표면이 100% 실증됨**: C가 이름을 대고 재사용을 선언한 private 심볼이 **11종 전건 실재 확인**(V2). 이 렌즈에서 이것이 결정적이다 — C의 첫 조각은 "존재가 확인된 함수들을 import해 묶는 것"이며, 새로 발명해야 하는 알고리즘이 0이다. 특히 `_price_gap_errors`의 가족형 쌍 면제 규칙을 **함수 본문 그대로 재사용**한다는 판단(design-C:318)은 재구현 시 즉시 드리프트가 나는 지점을 정확히 짚었다(`widget_api.py:455-477` 실재 확인).
- **라이브 write 0건**: `sim_rollout/sim_decision/sim_observation`이 라이브 밖 사이드카에 있다(design-C:274). DDL·마이그레이션·적재 승인 사이클이 첫 조각 경로에 **전혀 없다.** A(라이브 신규 테이블 7개)와의 차이가 가장 크게 벌어지는 지점이다.
- **부작용 0 보장을 새로 논증하지 않고 복제한다**: `assistant_tools.run_sql`의 `SET TRANSACTION READ ONLY` + `statement_timeout` + 무조건 롤백 방어선을 그대로 복제(design-C:223, `assistant_tools.py:689-701`). 새 안전 논증을 만들지 않고 **라이브에서 이미 검증된 논증을 재사용**하는 것은 구현가능성 렌즈의 정확한 미덕이다.
- **RULE-06 (MAJOR) 충족이 자료구조 수준**: `feasible != "PROVEN_OK"` → `price.amount`가 **스키마상 반드시 None**(design-C:201). "제약 위반 조합의 가격"이 존재할 수 있는 자료구조 자체를 제거했고, G2가 `jq 'select(.feasible!="PROVEN_OK" and .price.amount!=null)'`로 기계 검증한다. 규율이 아니라 타입으로 막았다.
- **RULE-13 (MAJOR) 충족 + private 의존의 조용한 실패 봉쇄**: G0이 매 실행 전 `_bindings.py` 전 심볼을 `getattr`로 확인해 fail-closed로 멈춘다(design-C:419). C 스스로 "무수정 재사용의 대가"로 인정한 위험(§8-(3))에 기계적 검출기를 붙였다.
- **첫 조각이 3안 중 최소**: 만드는 것 4개 — `_bindings.py` · `JointTransition` · `frontier/rollout` · 게이트 스크립트. Actor LLM·Explainer·Ledger·ReachabilityProbe를 S1에서 **뺐다**(design-C:404) — "월드모델이 정확한지 먼저 재는 것이 순서"라는 판단은 P-09(전이함수 오차 미측정) 우선순위와 일치하며, 첫 조각까지의 경로가 3안 중 가장 짧고 실재한다.
- **파일럿 상품을 코드값으로 단정하지 않고 선정 기준 5항으로 선언**(design-C:406-413) + "조건을 만족하는 상품이 0건이면 그 사실 자체가 S1의 첫 산출물"이라는 처리까지 규정. B가 §9-1에서 자백한 "유리한 상품 선택" 편향을 구조적으로 회피했다.

### 4.2 1점을 남긴 이유 (감점 아님 — 규칙 위반 없음)

- **G7 임계가 [추정]이고 첫 반증 지점이 비용이다.** C 스스로 "G7에서 가장 먼저 깨진다"고 적었고(design-C:438), 근거로 든 `_component_rows_bulk`의 동작을 실측 확인했다 — `TPrcComponentPrices.objects.filter(comp_cd__in=...)`로 해당 comp_cd의 **전 행을 끌어와 파이썬에서 처리**한다(`pricing.py:290-296`). 후보 40개 스윕이 이 비용을 40배 한다는 C의 서술은 **정확하다**. 다만 실측값이 없으므로 이것은 감점이 아니라 **첫 실측 대상**이다.
- **RULE-14 ① 해석 분기 (기록만, 감점 없음)**: violation_test ①은 "미확정 슬롯이 남은 상태에서 자동으로 기본값을 채워 확정하는 경로가 있으면 위반"이다. C는 "롤아웃으로 결과 불변이 증명된 슬롯의 자동 채움"을 **기본값 off + 실무진 승인 필요**로 규정했다(design-C:486). 가격·가능성이 불변임이 증명된 슬롯이라도 물리적으로 다른 산출물이 나갈 수 있다는 우려는 성립하나, ⓐ 되묻기가 정상 경로로 정의되어 있고(§5 T3) ⓑ 활성화에 인간 승인이 필요하므로 "자동으로 채워 확정하는 경로"라 단정하기 어렵다. 루브릭 §5-2에 따라 **해석이 갈린 사실 자체를 기록**하고 위반으로 확정하지 않는다.
- **RULE-07 자기 신고 "부분 충족"**: C는 스스로 부분 충족이라 적었으나(design-C:479), violation_test는 (a) 그릇 위치 (b) 대조 절차 둘 중 하나라도 없으면 위반이고 C는 **둘 다 있다**(사이드카 3테이블 + O1/O2/O3 채널). 따라서 **위반 아님** — 자기 신고를 그대로 확정 위반으로 옮기면 J-4에 걸린다. C의 겸손을 감점으로 환산하지 않는다.
- **세트 상품 1차 범위 밖**(design-C:310, `pricing.py:860-862` 근거): 범위 선언이며 미충족이 아니다. 규칙에 "범위 완전성" 축이 없으므로 감점 대상 아님.

## 6. 패한 안에서 승자(C)에 반드시 이식해야 할 아이디어

우선순위 순. 각 항목에 "왜 C에 없는가 / 어느 규칙을 강화하는가"를 붙인다.

### G-1. [A → C] 차원 정의 파리티 린트 (A §4.4 · G-D)
`views.py`의 5개 표면(`VAR_KEY_MAP:61-69` / `DIM_REF_MODELS:1882-1890` / `_DIM_LABEL_FIELDS:1893-1901` / `_IMPACT_SECTIONS:3670-3678`) + DB 트리거 `fn_chk_opt_item_ref`의 **축 집합 동일성**을 빌드마다 검사하고 불일치 1건이면 FAIL시킨다(A design-A:462 G-D).
**C에 없는 이유가 위험이다**: C는 "import만 하므로 6벌이 되지 않는다"로 RULE-12를 충족하지만(design-C:320), **5벌이 이미 서로 갈려 있다면 어느 벌을 import했느냐에 따라 판정이 달라진다.** A는 이것을 "가장 싸게 드러나는 반증"으로 1순위에 놓았다(design-A:545). C의 G0(심볼 실재)은 이름의 존재만 보고 **내용의 일치**는 보지 않는다. 게이트 G0.5로 추가할 것.

### G-2. [B → C] `only_comps` 반사실 스윕을 감사 지표로 승격 (B A1)
B의 `affect_sweep.py` — 각 option_item on/off × `evaluate_price(only_comps=…)`로 **어느 구성요소가 실제로 바뀌는가를 관측으로 확정**하고, 정밀도 1.000 / 재현율 ≥0.95를 요구한다(design-B:378).
**C에 이식해야 하는 이유**: C는 `only_comps`를 "코팅만 빼면?" 수준의 what-if로만 쓴다(design-C:308). B의 스윕을 넣으면 **P-05(판별차원 0 상시과금 — 실측 동판비 5,000~64,000원)를 탐지 지표로 승격**시킬 수 있다. C가 §8-(5)에서 "시뮬레이터는 의미론 공백을 고치지 못하고 틀린 값을 충실히 재현한다"고 자인한 바로 그 구멍에 대한, 라이브 수정 없는 최소 대응이다. C의 게이트표에 G8로 추가.

### G-3. [B → C] 무부작용 검증을 실행 가능한 측정으로 교체 (B A2)
C의 G1은 "스윕 전후 `pg_dump --data-only` 해시 비교"(design-C:420)인데, 라이브 Railway에 대한 `pg_dump`는 권한·시간·용량 부담이 크다. B의 A2는 **라이브 46테이블의 `count(*)` + `max(upd_dt)` 해시 비교**(design-B:379)로 같은 성질을 훨씬 싸게 잰다.
**이식 형태**: G1의 1차 측정을 A2 방식으로 바꾸고, `pg_dump` 해시는 파일럿 종료 시 1회 확인으로 강등.

### G-4. [B → C] 순수 SQL 대조군을 첫 조각에 포함 (B §9-2)
B는 자기 논지가 과잉 프레이밍일 가능성을 감추지 않으려고 "(가) 그래프 경로 / (나) 순수 라이브 SQL 경로"를 둘 다 구현해 결과를 대조하는 대조군을 first slice에 넣었다(design-B:467).
**C에 필요한 이유**: C도 §8-(6)에서 **"이 설계가 성공해도 그것은 '에이전트가 잘한다'가 아니라 '엔진이 이미 좋았다'의 증거일 수 있다"** 고 자백했다(design-C:465). 그 자백을 산문이 아니라 **측정**으로 바꾸는 장치가 정확히 B의 대조군이다. S1에 "루프 없이 기존 `/price` + `_sim_disallowed` 직접 호출" 대조군을 넣어, 루프의 순증분을 수치로 남긴다.

### G-5. [B → C] 파일럿 편향 방지 조항 (B §9-1)
B는 "파일럿이 유리한 상품을 골랐다는 자백"을 적고 **2차 파일럿을 `use_dims` NULL 보유 상품으로 반드시 잡을 것**을 의무화했다(design-B:459).
**이식 형태**: C의 파일럿 선정 5기준(design-C:406-412)에 6번째 조건 — "`use_dims`가 빈 구성요소 ≥1을 포함" — 을 **2차 파일럿 의무**로 추가. C의 5기준은 "잘 배선된 상품"을 고르게 편향돼 있어, G4(전이함수 정확도)가 쉬운 상품에서만 통과할 위험이 있다.

### G-6. [A → C] 게이트 실패 시의 계층별 후퇴 선언을 게이트표 안으로 (A §8.3)
A는 "G-B FAIL → 컴파일 계층을 버리고 축소판으로 후퇴, 정보이득 대화는 성립하지 않는다고 인정"을 **게이트 정의의 일부**로 적었다(design-A:468-470). C는 같은 성질의 판단("p95 > 2s면 고객 실시간 루프는 성립하지 않고 관리자·CS 도구로 강등되며 §5 종단 시나리오는 폐기된다")을 §7-1 산문에만 두었다(design-C:438).
**이식 형태**: G7 행에 "임계 초과 시 판정 = 고객 실시간 루프 폐기 · 관리자/CS 도구로 강등 · §5 폐기"를 **게이트 결과값**으로 명기. 임계 미달이 "재설정" 대신 "무엇을 버리는가"로 귀결되게 만든다.

### G-7. [A → C] 신규 평가 지점별 fail-closed 동작 전수표 (A §7 ①)
A는 신규 평가 지점 5개 각각에 대해 예외 발생 시 동작을 표로 못 박았다(design-A:415-421 — 통과 처리 0건). C는 fail-closed를 3지점(IntentValidator·G0 바인딩·RenderGuard)에만 명시했다(design-C:485).
**이식 형태**: `JointTransition` (a)~(f) 6개 호출 각각의 예외 동작(특히 `_price_gap_errors`·`tmpl_combo.resolve`·`t_siz_pansu` 조회 실패)을 표로 확장. `evaluate_price` 예외 시 **0원 대체 금지**를 A처럼 명문화(design-A:420) — C의 `price.amount=None` 규약과 정합한다.

## 8. 미확인 · 이 심사의 한계

1. **라이브 DB를 조회하지 않았다.** 본 심사의 실측은 저장소 내부 파일(`raw/webadmin` 소스 · `sql/33` · 로컬 `graph.db` · `01_authority` CSV)에 한정된다. 라이브 `t_*` 현재 상태는 D8 인용이며 재-SELECT하지 않았다. 3안 모두 착수 시 N-13에 따른 재실측이 선행되어야 한다.
2. **G7/A9/G-B의 성능 임계는 어느 안에서도 실측되지 않았다.** 세 설계의 응답성 우열은 이 심사가 판정할 수 없다 — 전부 첫 파일럿 실측 대상이다.
3. **`models.py:253`의 `use_dims` 소속 모델을 끝까지 확정하지 않았다.** B의 표 이름 불일치(§3.3)를 확정 결함으로 올리지 않은 이유다.
4. **A의 `t_wm_effects` 편집 표면 감점은 "현재 webadmin 구조"에 근거한다.** 별도 Django 앱·외부 admin 인스턴스 등 우회 경로의 실현 가능성 자체는 검토하지 않았다 — A 문서가 그것을 기술하지 않았기 때문이며, 기술이 제시되면 §2.2(d)에 따라 철회 대상이다.
5. **이 렌즈는 설계의 "좋음"이 아니라 구현가능성만 잰다.** 루브릭 §5-5와 같은 한계를 승계한다 — C가 9점인 것은 "가장 옳다"가 아니라 "가장 붙이기 쉽고 첫 조각 경로가 실재한다"는 뜻이다. 특히 C 스스로 인정한 **의미론 공백 미해결(§8-(5))** 과 **LLM 기여분이 작다(§8-(6))** 는 다른 렌즈에서 다르게 채점되어야 한다.
6. **웹 검색 미사용.** 본 문서는 저장소 내부 파일과 선행 산출물만을 근거로 하므로 `Sources:` 절을 두지 않는다. 외부 1차 출처는 각 R 문서의 `Sources:` 절이 보유한다.
