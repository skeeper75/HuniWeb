# 제약 필요상황 규정 방법론

## 왜 규정이 먼저인가
옵션그룹으로 제약을 흉내내다 관리가 무너진 것이 이 하네스의 출발점이다. "어떤 문제에 어떤 도구를 쓰는가"를 먼저 못박지 않으면, 제약규칙도 같은 방식으로 오염된다(아무 데나 쓰이는 규칙 더미).

## CN 분류체계
| 유형 | 정의 | RULE_TYPE | 근거 원천 | 유도 방식 |
|------|------|-----------|----------|----------|
| CN-1 물리·제조 불가 | 도메인상 만들 수 없는 조합 | .02 금지 | 권위 엑셀·인쇄 도메인 | 수동(근거 필수) |
| CN-2 단가행 부재 엇갈림 | 가격 격자 sparse — 팔 가격이 없는 조합 | .01/.03 | component_prices 실측 | ★단가행 자동 유도 |
| CN-3 필수 동반 | X 선택 시 Y 필수 | .03 | 권위 엑셀·도메인 | 수동 |
| CN-4 상호 배제 | X·Y 동시 불가 | .02 | 권위 엑셀·도메인 | 수동 |
| CN-5 범위·증분 | 수량/치수 min·max·incr | .02/.03 | 권위 엑셀 | 수동 — 상품 컬럼/옵션 정의에 이미 있으면 제약 금지(중복) |
| CN-6 옵션그룹 오용 이관 | 옵션그룹 분열로 조건부 관계를 흉내낸 사례 | 재설계 | 라이브 CPQ 실측 | 이관 설계(그룹 정규화+명시 제약) |

★CN-2 핵심: 단가행 부재는 자동 차단이 아니다. evaluate_price는 매칭 실패 시 0원을 반환하고 제약을 안 보므로([[constraint-builder-contract-demo-260702]]), 제약 없으면 0원 견적이 그대로 노출된다. 129/130 데모가 이 유형.

## 도구 결정 트리 [HARD]
```
조합 문제 발견
├─ 근본이 기초데이터 모델링 결함인가(예: 자재명에 사이즈 내장)?
│   → 근본 교정은 별도 트랙(§7/§12) 라우팅. 제약은 "증상 완화" 태그로 병기 가능.
├─ 모든 조합에서 선택지 자체가 무의미한가?
│   → 옵션그룹/차원 정리(선택지 집합 축소). 제약 아님.
└─ 조건부 관계인가("A를 고르면 B는 ~해야")?
    → 제약규칙. 옵션그룹으로 표현 금지(그룹 폭발=관리 곤란).
```
경계 원칙: **옵션그룹=선택지 집합, 제약=선택지들 사이의 조건부 관계.**

## 절차
1. 분모 확정 — 라이브 활성 상품(del_yn='N') 목록.
2. 재사용 스캔 — §21 `03_cpq_link/`(제약·옵션 정합 보드), §26 무결성(sparse), §27 wiring, `_foundation/live-snapshot/`, 권위 추출 CSV에서 CN 후보 채집.
3. 갭 실측 — 재사용으로 안 닫히는 축만 라이브 SELECT(읽기전용).
4. 옵션그룹 오용 스캔 — 같은 의미축이 여러 그룹으로 분열·그룹명에 조건이 박힌 패턴·조합별 그룹 복제 패턴을 CPQ 테이블에서 검출.
5. 체크리스트 조립 — 상품마다 CN 유형별 후보/해당없음 명시(누락 0의 자). 근거 없는 후보 금지, 경계 모호는 AMBIG(사용자 컨펌 큐).
