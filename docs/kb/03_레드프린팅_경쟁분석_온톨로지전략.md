# 레드프린팅 경쟁분석 — 온톨로지 부트스트랩 전략

> 출처: 260702 통화 P3(17:40–23:00), P5(56:30–1:05). 신우진의 레드프린팅 연구소장 경력과 통화 발언, 기존 벤치마킹 세션(인터랙티브 CPQ 그래프 시각화 도구의 기준)을 결합. 목적은 경쟁사 관찰 자체가 아니라 **경쟁사 공개 데이터를 후니프린팅 온톨로지의 학습 코퍼스로 쓰는 전략**의 문서화다.

## 1. 통화에서 확정된 방향

### 1.1 "엑셀 → AI 자동 분석"은 기각

- 김동학: "구조화된 게 아니라서 안 될 것 같다. AI가 만든 사람의 의도를 어떻게 알아."
- 합의: **① 룰을 상호 협의로 정의 → ② 룰에 따라 학습 → ③ 스킬/에이전트에 절차로 고정.** ("룰을 만들어야 돼" — 김동학)

### 1.2 온톨로지가 최초 작업

신우진(20:07): "이게 우리의 최초의 작업이 될 것. 온톨로지를 만들어야 자연어('나 이런 거 만들고 싶어')를 분석해 상품을 추천할 수 있다. 데이터가 의미론적으로 정리돼 있어야 파싱하든 뭘 하든 한다. DB에 그냥 때려 넣을 수는 없다."

### 1.3 코퍼스 소스 = 경쟁사 옵션 구조

신우진(20:41): "레드프린팅 부쉈듯이(분해했듯이), 웹사이트들의 옵션이 곧 상품 구성 요소다. 코팅이면 단면/양면, 부자재는 뭔지 — 비교 분석할 수 있는 사이트가 엄청 많다. 그걸 다 집어넣고 '의미가 비슷한 것끼리 모아라' 하면 된다."

기대 효과: AI가 **블리드=여백, 작업사이즈=제작용, 재단사이즈=완성물, 출력용지=조판 모판** 같은 도메인 개념을 경쟁사 표기 다양성 속에서 스스로 정렬 — 단, §1.1의 룰(용어집)이 seed로 있어야 함.

## 2. 레드프린팅이 기준 벤치마크인 이유

| 근거 | 내용 |
|------|------|
| 내부자 지식 | 신우진이 레드프린팅 연구소장 출신 — 옵션 구조·운영 방식을 UI 이면까지 해석 가능. 에디쿠스도 레드프린팅 주문 트래픽으로 단련된 이력("레드프린팅에서 스파르타 다 했잖아") |
| 기존 세션 자산 | RedPrinting 벤치마킹 기반 인터랙티브 CPQ 그래프 시각화 도구(React+SVG) 개발 진행 중 — 옵션 노드·제약 엣지 모델의 참조 원형 |
| 시장 포지션 | 통화 언급 시장 구도: 선두 약 1천억, 상위 10곳 300억대, 이하 30~50억 — 레드프린팅은 다품종 디지털 인쇄 온라인화의 국내 대표 사례로, 후니프린팅이 목표하는 상품 폭과 가장 유사 |

## 3. 경쟁 환경에서 얻은 전략 인사이트 (P5)

1. **폐쇄 시장 = 진입 장벽 = 우리의 해자.** 업체와 대화 자체가 그들의 용어로만 가능("얘는 인쇄도 모르네" 순간 신뢰 상실). 통화에서 소개된 **실무진 확인 요청서** 관행(전문 용어를 풀어 질문 배경까지 적는 문서)은 지식 수집 프로세스로 시스템화할 가치가 있음.
2. **선행 실패 사례의 공통 원인 = 부분 장악.** "에디터만 장악, 템플릿만 장악, 인쇄는 하청 → 가격 통일 실패." 시사점: CPQ의 경쟁력은 에디터·템플릿·**가격·생산까지의 수직 통합**이며, 이것이 자동견적 엔진이 전체 사업의 코어인 이유.
3. **뒷단(생산·암묵지)은 프런티어 AI 기업이 진입 못 하는 버티컬** — 앞단(디자인)은 자동화가 고도화될수록, 파일→장비 변환과 견적 암묵지의 가치가 상대적으로 커짐.

## 4. 온톨로지 부트스트랩 실행안

### 4.1 파이프라인

```
[Seed 용어집]  후니 엑셀 용어 + 01문서 도메인 사전 + 실무진 확인 요청서 축적분
      ↓
[코퍼스 수집]  레드프린팅·와우프레스 등 옵션 트리 크롤/정리 (상품→옵션그룹→옵션값→가격축)
      ↓
[정렬(alignment)]  동의어 클러스터링: 모서리=귀돌이, 오시=누름선, 완칼=왕칼=도무송…
      ↓
[스키마 매핑]  후니 option_groups/option_items (ref_dim_cd + ref_key1/ref_key2 복합 키)로 귀속
      ↓
[검증]  30개 검증 레퍼런스 케이스 + SSOT v0.4 대조
```

### 4.2 산출물 정의

| 산출물 | 형식 | 용도 |
|--------|------|------|
| 용어집(glossary) | canonical_term / synonyms / definition / process_mapping | 옵션 명명 표준, NL 검색 |
| 옵션 구조 비교표 | 상품군 × (후니 vs RP) 옵션 그룹 매트릭스 | 옵션 커버리지 갭 발견 |
| 제약 패턴 카탈로그 | RP UI에서 관찰되는 옵션 간 활성/비활성 규칙 | JSONLogic 제약 작성의 레퍼런스 |
| 가격축 비교 | 상품군별 가격 결정 차원(사이즈/수량/소재/가공) 대조 | 아키타입 분류 교차 검증 |

### 4.3 주의점

- 경쟁사 **가격 값 자체**를 복제하는 게 아니라 **구조(차원·옵션 체계·용어)**를 학습 대상으로 한정 — 후니 가격은 자체 원가·협의가 체계 유지.
- RP 옵션 구조는 참조일 뿐 권위 소스가 아님. 권위는 항상 상품마스터(02 문서 §4). 충돌 시 후니 엑셀 우선.
- 크롤 데이터는 시점 스냅숏 — 수집일 메타데이터 필수.
