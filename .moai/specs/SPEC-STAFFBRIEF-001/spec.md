## 1. 배경·목적

지니(운영자)가 2026-09-09 실무진 발표를 준비한다. 청중은 **비개발자 실무진**이며, 발표의 목적은 후니프린팅 시스템의 ①사이트 현황 ②고객이 보는 위젯 ③운영자가 쓰는 웹어드민 을 한 번에 이해하는 것이다.

이를 위해 **브리핑 원고(md) → 단일 셀프컨테인드 HTML 리포트(+에이전트용 md twin)** 를 만들고, 렌더 근거·AC 판정을 카드 증거 디렉터리(`.moai/reports/t45/`)에 남긴다. 조사는 이미 완료됐다(research.md). run-phase 는 **소비·재실측·렌더·검증**만 한다.

성공 기준 한 줄: **실무진이 이 자료만으로 "게시된 위젯이 무엇이고, 무엇이 아직 살 수 없으며, 운영 화면에서 무엇을 하는지"를 날짜·수치까지 정확하게 이해한다.**

## 4. 제약

- **C-1 읽기전용**: 라이브 DB 접근은 `SELECT` 만, 자격증명은 메인 체크아웃 `.env.local`(RAILWAY_DB_* 키). PII 는 카운트만, 상품명만 select.
- **C-2 마감**: 2026-09-08 완성(발표 D-1). 리뷰·인쇄 여유가 없다.
- **C-3 스킬·설정 경로**: moai-domain-html-report 스킬과 report.yaml 은 메인 체크아웃에만 존재(미트래킹) — 절대경로 판독, 카드 워크트리로 복사하지 않는다.
- **C-4 발표 환경 미확정**: 프로젝터·인쇄 여부와 무관하게 **인쇄 안전(print-safe) 설계가 기본값**(plan.md §B 결정 D-7 — NEEDS CLARIFICATION 없음).

## 5. 요구사항 (GEARS)

형식: `REQ-SB-NNN` — GEARS 패턴 키워드(Ubiquitous / **When** / **While** / **Where** / `shall not`) + 한글 조항. [HARD] 표기 항목은 단일 위반이 종료를 막는 차단 조항.

### 5.1 수치 소급·입력 사실

- **REQ-SB-001** — Ubiquitous. 리포트에 실리는 모든 수치·사실 주장은 research.md 의 근거(`파일:라인` · SELECT 실측) 또는 run-phase 신규 읽기전용 SELECT 실측으로 **소급 가능**해야 한다. 추정·기억에 의한 수치 기재 0건. [HARD]
- **REQ-SB-002** — **Where** 매뉴얼 내용을 인용하는 모든 곳에서, 작성자는 2026-09-06 재생성본(`admin-manual.html` · `widget-manual.html` · `admin-quickstart.html`)을 권위로 삼아야 하며, `*.260824-baseline.html` 을 현재 상태로 제시해서는 안 된다(`shall not`). — 카드 전제 교정 사실(§2.1).
- **REQ-SB-003** — **When** 스냅샷에서 온 숫자(8/22 감사 · 8/27 재진단 등)를 인용할 때, 작성자는 측정 시점 라벨을 그 숫자에 붙여야 한다.
- **REQ-SB-004** — **When** 「현재값」 성격의 지표(운영 활성 상품 · 게시 위젯 · 공식 바인딩 상품 · 주문 수)를 본문에 실을 때, 작성자는 렌더일 읽기전용 SELECT 재실측값을 사용해야 하며, 스냅샷 값(194 등)을 현재값처럼 실어서는 안 된다(`shall not`).
- **REQ-SB-005** — **Where** 렌더일 재실측이 불가능한 경우(DB 접속 장애), 작성자는 research 의 2026-09-07 실측값에 그 시점 라벨을 명시하고 본문 머리에 측정 시점을 고지해야 한다(라벨 없는 「현재값」 사용 금지).

### 5.2 정직한 서술 — 과대포장 금지 7종(research §2.7 — 7번 인지 항목은 §5.6 REQ-SB-024 리스크 의무로 부호화)

- **REQ-SB-006** — **When** 게시 위젯 현황을 서술할 때, 작성자는 「게시됨 ≠ 주문 가능」을 명시해야 한다(2026-08-22 감사: 194개 중 98개 가격계산 막힘 · 재현율 65%(2026-08-27 재진단에서 확인) 한계 함께). "N개 전부 주문 가능"형 서술 금지(`shall not`).
- **REQ-SB-007** — 작성자는 라이브 위젯(Web Component + Shadow DOM, 바닐라 JS)과 React 재구현 트랙(harness 작업 산출)을 구분 없이 서술해서는 안 된다(`shall not`). 라이브 위젯 소개 문맥에 React/shadcn/Zustand 어휘를 쓰지 않는다.
- **REQ-SB-008** — **When** 상품 뷰어(product-viewer)의 조회 결과를 소개할 때, 작성자는 **2026-06-10 내장 스냅샷** 기준임을 명시해야 한다.
- **REQ-SB-009** — 계획만 존재하는 기능(파트너 사이트 포털 · 다국어 · StepTab · 수량별 가격표 모달 · 출고예정일/배송비/예상무게)은 「계획」 라벨 없이 구현된 것처럼 서술되어서는 안 된다(`shall not`).
- **REQ-SB-010** — **When** 가격 바인딩 현황(활성 중 미바인딩 90)을 언급할 때, 작성자는 시작가·템플릿가 경로 병존을 함께 밝혀야 하며, 「가격 없는 상품 90개」로 단정해서는 안 된다(`shall not`).
- **REQ-SB-011** — **When** Edicus 연동을 소개할 때, 작성자는 SDK 가이드(최신) 기준의 실동작(`/editor/resolve` · 사용자 토큰 서버 대리 발급 · prjid 기록)으로 서술해야 하며, "설계만 됐다"고 깎아내려서는 안 된다(`shall not`).

### 5.3 렌더 계약

- **REQ-SB-012** — 리포트는 moai-domain-html-report 스킬(판독: 절대경로 또는 Skill() — plan D-9)로 렌더되어야 하며, mode 는 `status` · 오디언스는 `basic` 이어야 한다. 이 두 값은 run-phase 에서 재선택되어서는 안 된다(`shall not`). [모드 확정 봉쇄]
- **REQ-SB-013** — 산출물은 단일 셀프컨테인드 `.html` 파일이어야 하며, 외부 JS/CSS 의존이 0건(허용 예외: 폰트 CDN 전 티어 · mermaid CDN basic 티어 + noscript 폴백)을 유지해야 한다.
- **REQ-SB-014** — 산출 HTML 크기는 120KB(=122,880 바이트, 1024 진법 — plan §B D-6) 이하여야 한다. 초과 시 섹션 축소 또는 부록 분리로 대응하고 예산을 상향하지 않는다.
- **REQ-SB-015** — 디자인 토큰은 후니 정본 팔레트(primary **#5538B6** · SKILL.md 본문 SSOT)를 따라야 하고, 폰트는 **Noto Sans KR** 로 오버라이드(`--sans`/`--serif`)되어야 한다. tailwind-tokens.md 의 #553886 계열을 사용해서는 안 된다(`shall not`).
- **REQ-SB-016** — 발표에 필요한 정보는 mermaid 블록에만 존재해서는 안 된다(`shall not`) — 동일 정보가 인라인 SVG 또는 산문에도 있어야 한다(오프라인·인쇄 폴백).
- **REQ-SB-017** — md twin 은 에이전트·컨텍스트 주입용 핵심 사실 요약이어야 하며, basic 티어 부풀림(비유 · worked example 산문)이 md 에 반영되어서는 안 된다(`shall not`). [HARD]

### 5.4 데이터 접근·작업 안전

- **REQ-SB-018** — **When** run-phase 가 LiveDB 에 접근할 때, 접근은 메인 체크아웃 `.env.local` 자격증명 · `SELECT` 전용 · PII 는 카운트만 이어야 하며, 쓰기 질의를 실행해서는 안 된다(`shall not`). [HARD]
- **REQ-SB-019** — **While** 리포트 작성이 진행되는 동안, 작업자는 `raw/webadmin/**` 소스와 라이브 DB 데이터를 수정하지 않아야 한다(`shall not`). 산출물은 문서(md · html · 증거)뿐이다. [HARD]

### 5.5 산출 경로·증거

- **REQ-SB-020** — 렌더 output_path 는 카드 증거 디렉터리(`.moai/reports/t45/`)로 명시 지정되어야 하며, 스킬 기본값(`<cwd>/reports/<slug>-<date>.html`)으로 두어서는 안 된다(`shall not`).
- **REQ-SB-021** — 카드 증거 디렉터리에는 판정 정본 `verdict.md`(AC 판정 · 렌더 파라미터 · 파일 크기 · as-of 라벨 · 재실측 쿼리)가 포함되어야 한다.
- **REQ-SB-022** — **When** 카드 커밋을 만들 때, 커밋은 증거 디렉터리 산출물(html · md 원고 · md twin · verdict.md · 실측 기록)을 포함해야 하며, 메인 체크아웃의 미트래킹 자산(스킬 본체 · report.yaml)을 카드 워크트리로 복사해 커밋해서는 안 된다(`shall not`).

### 5.6 비개발자 이해성·구조

- **REQ-SB-023** — **Where** 전문용어(차원 · 단가유형 · 옵션 3층 · 게시/버전 · 제약규칙 등)가 첫 등장하는 곳에서, 원고는 인라인 평어 정의를 그 자리에 제공해야 한다.
- **REQ-SB-024** — 리포트 본문 구조는 research §6 권장 뼈대(메트릭 4장 → §1 한눈에 보기 → §2 고객이 보는 것=위젯 → §3 운영자가 쓰는 것=웹어드민 → §4 데이터 품질 → §5 직접 확인해 볼 것 → 리스크/계획)를 기본 골격으로 따라야 하며, status 모드의 구조 계약(메트릭 카드 · 하이라이트 · 캐리오버)과 충돌하지 않아야 한다. 리스크/계획 섹션은 계획 기능 목록과 함께 **인지 리스크 2건**(옵션코드 재번호 시 위젯 참조 파손 가능 · 회귀 테스트의 데이터 오염 탐지 한계 — research §2.7-7)을 반드시 포함해야 한다.

### 5.7 발표 환경 방어

- **REQ-SB-025** — **When** 렌더가 완료되면, 작성자는 오프라인 발표에 대비한 백업 자산(렌더 결과의 PDF 또는 전체 페이지 스크린샷)을 카드 증거 디렉터리에 확보해야 한다(폰트 CDN 오프라인 리스크 방어).
