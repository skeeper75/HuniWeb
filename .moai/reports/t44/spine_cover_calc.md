# t44 ① 책등·표지 크기 산출 — Max Page 기준 (2026-09-04)

> 지니 관점(원문): 「무선과 같이 책등이 포함되는 상품은 Max Page 를 중심으로 계산을 해서
> 표지의 크기를 정하고 그 표지의 크기보다 큰 판형을 처리한다」

이 관점이 옳다. 그리고 t9 이 「권위 모순」·「search-before-mint 위반」으로 판정한 두 건 중
**하나(R5)는 이 관점으로 보면 결론이 뒤집힌다.**

숫자는 전부 **운영 코드를 그대로 import 해서** 뽑았다(`maxpage_spread.py`가
`catalog.spine_calc.calc_spine` 을 직접 호출). 손으로 옮겨 적은 값은 없다.

## 1. 운영 엔진의 책등·펼침 산식 (읽은 코드)

`raw/webadmin/webadmin/catalog/spine_calc.py`

```
block_thickness_um  : 내지(SEMI_ROLE.01)만 합산. 낱장두께 × ⌈pages ÷ sides⌉
cover_thickness_um  : cover_incl_yn='Y' 일 때만 표지두께 × 2
raw = block + cover + spine_mgn_mm
round_spine_um      : .01 정수 올림 / .02 짝수 올림 / .03 규격표(링)
spread_w = 표지가로 × 2 + 책등        ← spine_calc.py:319~322
spread_h = 표지세로
```

`spine_calc.py` 모듈 주석이 산식의 권위를 못박는다:

> 무선/PUR 계열(정수·짝수 올림)의 펼침 사이즈는 표지를 좌우로 펼친 인쇄판 크기 —
> `spread_w = 표지가로 × 2 + 책등`, `spread_h = 표지세로` 고정식이다.

### 「표지가로」가 무엇인가 — 설계의도는 완제품 사이즈다

`spine_widget.py:223~234` 역방향 폴백 주석(260823-x8m):

> **무선책자류는 표지가 완성 사이즈를 그대로 따른다(재단 후 표지 판형 = 완제품 판형).
> 이런 상품은 사이즈 컴포넌트를 구성원이 아니라 본품(공통)에 두므로 표지 구성원에는
> siz_cd 선택이 실리지 않는다.**

→ 설계의도상 표지 펼침의 밑변은 **완제품(내지) 재단폭**(A5 148 / A4 210)이다.
라이브는 표지 구성원에 자체 사이즈(SIZ_000632/633)를 달아 이 의도에서 벗어나 있다(§4).

## 4. 라이브 표지 사이즈와의 차이 — 시트 여유 34mm vs 실산출 26mm

| | 라이브·권위 시트 재단 | Max Page 산출 재단 | 차이 | 내포 책등 |
|---|---|---|---:|---:|
| A5 (SIZ_000632, r62) | 330 x 210 | 322 x 210 | **+8** | 330−296 = **34** |
| A4 (SIZ_000633, r63) | 454 x 297 | 446 x 297 | **+8** | 454−420 = **34** |

**권위 시트의 표지 재단치수는 책등 34mm 를 내포한 Max Page 봉투다.**
실제 엔진 산출은 26mm — 시트가 **8mm 더 여유**를 잡았다.

그 8mm 가 이 카드의 전부다. §플레이트 판정(`plate_verdict.md`)에서 보듯,
A4 표지가 국4절 316x467 을 벗어나느냐 마느냐가 정확히 이 8mm 에서 갈린다.

### 34mm 여유의 의미 — 헤드룸

책등 34mm 를 채우려면 블록 33.5mm → 낱장두께 33.5 ÷ 150 = **0.2233mm**.
현재 등록된 내지 최대두께는 0.170 이므로, 시트 여유는 **약 0.223mm 두께 용지까지**
커버한다. 지금 없는 두꺼운 내지를 나중에 넣을 여지를 남긴 값으로 읽힌다
— 이 해석의 진위는 실무진 확인 사항이다(`plate_verdict.md` §질의 2).

## 5. 하드커버(072·077)는 이 산식의 적용 대상이 아니다

하드커버 표지는 종이를 접는 것이 아니라 **보드(MDF)를 싸는 케이스**다.
라이브 자재(`mat_depths.txt`)가 그것을 보여준다:

| 자재 | 성격 | depth |
|---|---|---:|
| MAT_000624 MDF(204x304mm)_A4 | A4 표지 보드 | (없음) |
| MAT_000625 MDF(142x218mm)_A5 | A5 표지 보드 | (없음) |
| MAT_000626~701 MDF(10~26 x 304/218mm)_책등 | 책등 보드 9종 | 10 ~ **26** |

- 책등 보드 상한 **26mm** 는 §3 의 엔진 산출 책등 26mm 와 정확히 일치한다
  — 보드 라인업 자체가 Max Page 를 기준으로 짜여 있다는 방증.
- 그러나 케이스 랩 치수(SIZ_000634 390x268 · SIZ_000635 532x355)는
  `spread_w = 표지가로×2 + 책등` 으로 **재현되지 않는다**:
  - A5: 142×2 + 26 = 310 vs 라이브 390 → 차 80
  - A4: 204×2 + 26 = 434 vs 라이브 532 → 차 98
  - 높이 차는 A5 50 · A4 51 로 거의 같은데(싸개 접힘 ≈ 25mm) 폭 차만 80·98 로 벌어진다.
- 즉 케이스 랩에는 **경첩 홈(가짐)·싸개 접힘**이 더 들어가는데 그 규칙이 코드에도 DB에도
  없다. `cover_incl_yn='N'` 이라 엔진은 표지 두께조차 안 본다.

→ **하드커버 표지치수는 엔진이 만들지 않는 상수다.** 그러므로 여기에 대해서는
「Max Page 로 계산해 보니 더 작더라」는 논증을 쓸 수 없다(`plate_verdict.md` R6).
