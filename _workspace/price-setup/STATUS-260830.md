## 1. [HARD] 알려진 결함 — 아직 안 고쳤다

**`dim_vals` 축을 격자 생성기가 읽지 않는다.**

일부 구성요소는 차원값을 `t_prc_component_prices.dim_vals`(jsonb)에 담는다:

```
COMP_PP_CREASE_1L (오시비)   dim_vals = {"줄수": 1|2|3}   → 라이브 30행
COMP_PP_VARIMG_1EA (가변이미지) dim_vals = {"개수": N}
COMP_PP_VARTEXT_1EA (가변텍스트) dim_vals = {"개수": N}
```

`m1_grid.py` 의 `live_rows()` 는 `dims`(=`_comp_dims`) 컬럼만 키로 쓰고 `dim_vals` 를 무시한다.
그 결과 **오시비 30행을 10행으로 세고**, 존재하지 않는 「수량 0 · 줄수 빈칸」 조합을 누락으로 만들어 냈다.

`/grid/` 응답은 `dim_vals` 를 `param_keys` 로 펼쳐 행 키에 넣는다(`price_views.py` `price_grid`
— `for k in param_keys: r[k] = dv.get(k)`). 생성기도 같게 해야 한다.

**이 결함은 `param_keys` 를 가진 모든 구성요소의 분모·누락·잉여 수치를 오염시킨다.**

**규칙은 이미 있었다.** `huni-webadmin-manual-first.md`(매뉴얼→실화면→코드→DB)는 항상 로딩되는

## 4.5 [HARD] `use_dims` 는 실제 차원이 아니다 — 화면이 정본이다

**같은 형태로 두 번 틀렸다.** DB 의 `use_dims` 만 보고 차원을 판단하면 축을 놓친다.

| 구성요소 | `use_dims` (DB) | 실제 화면 헤더 | 놓친 축 |
|---|---|---|---|
| `COMP_PP_CREASE_1L` 오시비 | `["proc_cd","min_qty",...]` | 적용일·공정·**줄수(줄)**·수량·고정·비고 | `dim_vals` 의 줄수 |
| `COMP_FOIL_PROC_LARGE_STD` 박 대형 | `["proc_cd","min_qty",...]` | 적용일·공정·**가로(mm)**·**세로(mm)**·수량·고정·비고 | 가로·세로 |

박 3,328행의 정체(2026-08-30 화면 실측):

```
⚠ 공유 마스터 — 공식 4개 · 상품 5개가 함께 사용 · 3328행 (고정금액)
🔧 공정그룹: 대형박 (공정 컬럼=하위공정)

비고: 「대형 박가공비 등급A·가로70이하×세로30이하·수량10이상 (flatten·grade=추적)」
```

**권위의 등급(A~E) 축을 가로×세로로 펼쳐 넣은 것**이다(`flatten·grade=추적`).
그래서 권위 후가공_박 246셀 ↔ 라이브 약 9,300줄이 된다. **누락이 아니라 의도된 전개다.**
(`M3-REUSE-260829.md` §3 의 `gen_foil_load.py` — 「등급 A~E 를 DB 에 안 싣고 조인 소거로
(가로,세로,수량)→가격 환원」 — 이 도구가 만든 것으로 보인다. 코드는 확인하지 않았다.)

⇒ **차원 확인은 반드시 `/admin/price-viewer/comp/{comp_cd}/edit/` 화면에서 한다.**
