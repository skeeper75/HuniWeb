## 0장. 이 가이드의 핵심 답변

### 0.1 통화 내용만으로 두 엑셀 분석이 가능해지는가 — **가능하다**

결론부터: **이번 통화는 두 엑셀을 읽기 위한 "복호화 키(decoding key)"다.** 통화 전에는 이 엑셀들이 "구조화되지 않은 암호"(김동학 표현)였으나, 통화에서 신우진이 설명한 개념을 대입하자 셀 값 하나하나가 의미를 갖는다. 실제 검증 결과:

| 통화에서 설명된 개념 | 엑셀에서 확인된 위치 | 일치 |
|---------------------|---------------------|------|
| "프리미엄엽서 73×98은 수량 15개씩 증가" | 디지털인쇄 R3: 판수 15, 최소 15, 증가 15 | ✅ |
| "국4절 316×467, 사방 5mm 못 씀(그리퍼)" | 판걸이수 R2: 316x467, "사방 5mm제외" | ✅ |
| "엽서북은 계산하면 11,000원보다 비싸서 고정가로 협의" | 엽서북떡메 R5: 2부 = 11,000원 | ✅ |
| "아크릴 양면=9도, 단면=7도로 생산 전달" | 아크릴 R1: "양면9도 / 단면7도 통용" | ✅ |
| "책 = 내지+표지+면지 3개 결합" | 계산공식집 R82: 내지+표지+면지 인쇄·코팅 합산 | ✅ |
| "1옵션이 오시+접지 두 공정으로 분해" | 접지옵션 R1: "카드접지 단가(오시+접지)" | ✅ |
| "색상: 빨강=필수, 주황=선택, 회색=내부" | 디지털인쇄 Row1 배경색 3종 확인 | ✅ |

즉 통화는 엑셀 분석의 **필요조건이자 충분에 가까운 조건**이다. 통화 없이 엑셀만 보면 "롤", "계산식", "가격포함" 같은 표기가 무엇을 숨기는지 알 수 없다. 통화가 그 숨은 로직을 지목해 주었다.

### 0.2 두 엑셀에 어떻게 접근할 수 있어 보이는가 — **3단 접근**

통화가 알려준 접근 경로는 다음과 같다.

```
[1단계] 계산공식집초안을 먼저 읽는다 (엑셀 안의 "설명서")
   → 상품군마다 판매가 공식 + 참조시트가 명시돼 있음. 여기가 출발점.

[2단계] 공식이 참조하는 시트로 내려간다
   → 각 항목([인쇄비], [용지비]…)이 어느 가격표 시트의 어느 축을 참조하는지 추적.

[3단계] 상품마스터로 옵션·노출 규칙을 확정한다
   → 색상 코드로 required/optional/internal 구분, 판걸이수로 수량 규칙 확정.
```

이 순서가 중요한 이유: 상품마스터부터 보면 옵션의 "가격 의미"를 알 수 없고, 가격표부터 보면 "어떤 상품이 이 테이블을 쓰는지" 알 수 없다. **계산공식집이 둘을 잇는 지도**다. (통화에서 신우진이 "이 두 개를 던진다고 AI가 연결하지 못한다"고 한 이유가 이것 — 지도를 사람이 먼저 읽어야 한다.)

## 1장. 두 파일의 역할과 권위 구조

### 1.1 파일 = 데이터베이스의 3대 레이어

| 파일 / 시트 | DB 레이어 | 역할 | 권위 |
|------------|----------|------|------|
| 상품마스터 (11개 상품시트) | **상품·옵션 정의** | 무엇을 팔고, 어떤 옵션을 어떤 순서로 노출하는가 | ★ 최상위 권위 |
| 상품마스터 / MAP | **카탈로그 분류** | 7대 그룹 × 카테고리 상품 트리 | 분류 권위 |
| 상품마스터 / 계산공식집초안 | **견적 로직 명세** | 상품군별 판매가 공식 + 참조 지도 | 로직 권위 |
| 인쇄상품가격표 (17개 가격시트) | **단가 테이블** | 각 원가 요소의 실제 금액 | 가격 권위 |
| 인쇄상품가격표 / 판걸이수 | **조판 기준** | 사이즈→UP수→조인 | 조판 권위 |
| 인쇄상품가격표 / 출력소재(IMPORT) | **소재 사전** | 용지 마스터·단가 | 소재 권위 |

> **지침 1-A**: DB 설계 시 이 6개 권위를 서로 다른 테이블군으로 분리하고, **상품마스터를 SSOT(Single Source of Truth)로 못 박는다.** 충돌 시 항상 상품마스터가 이긴다. (통화: "상품마스터라고 하는 애가 권위가 있는 애")

### 1.2 시트 인벤토리 (실측)

**상품마스터 13시트**: 계산공식집초안 / MAP / 디지털인쇄 / 스티커 / 책자 / 포토북(가격포함) / 캘린더 / 디자인캘린더(가격포함) / 실사 / 아크릴 / 문구(가격포함) / 굿즈파우치(가격포함) / 상품악세사리(가격포함)

**인쇄상품가격표 19시트**: 판걸이수 / 출력소재(IMPORT) / 디지털인쇄비 / 코팅 / 접지옵션 / 인쇄후가공 / 커팅타공 / 스티커 / 합판도무송스티커 / 봉투제작 / 명함포토카드 / 후가공_박(소형) / 엽서북떡메 / 제본 / 후가공_박(대형) / 아크릴 / 포스터사인 / 굿즈파우치(구간할인) / 후가공_박(백업)

> **주의**: 시트명의 "(가격포함)"은 통화에서 신우진이 말한 그 "암호"다 — 별도 가격표 없이 마스터에 직접 가격이 박혀 있고, 옵션은 display-only인 상품군. `후가공_박(백업)`은 운영 백업본이므로 적재 대상에서 제외한다.

## 2장. 상품마스터 해부

### 2.1 3단 행 구조 (전 상품시트 공통)

```
Row 1: 그룹 헤더 (배경색 = 옵션 역할)  ← 메타데이터, 여기가 핵심
Row 2: 서브 헤더 (열 이름)
Row 3~: 데이터. 상품 하나가 여러 행(사이즈 variants) 차지
```

### 2.2 색상 코드 = 옵션 역할 (실측 검증)

디지털인쇄 시트 Row1 배경색 4종을 실제로 읽은 결과:

| 배경색 | Hex | 역할 | 해당 열(실측) | 온톨로지 분류 |
|--------|-----|------|--------------|--------------|
| 🟤 베이지 | `FFC4BD97` | 시스템/식별 | 구분·ID·MES ITEM_CD·상품명 | metadata |
| 🔴 빨강 | `FFE06666` | **필수 노출** | 사이즈·주문방법·종이·제작수량 | required |
| 🟠 주황 | `FFF6B26B` | **선택** | 인쇄·별색인쇄·코팅·커팅·접지·후가공·박·추가상품 | optional |
| ⬜ 회색 | `FFD9D9D9` | **내부 전용** | 파일사양(판수·블리드·작업사이즈·재단사이즈·출력용지규격·출력파일 등) | internal |

> **지침 2-A**: 회색(internal)은 CPQ의 **출력이 아니라 MES/생산 핸드오프의 입력**이다. 고객 위젯에 노출하지 않되, 견적 계산과 작업지시서 생성에는 반드시 사용한다. (통화: "바깥에서 보이면 안 되지만 생산·가격을 위해 필요, JPG 같은 출력파일 포함")

### 2.3 열 상세 (디지털인쇄 기준, 실측)

| 그룹 | 열 | 내용 | CPQ 용도 |
|------|-----|------|---------|
| 식별 | A~D | 구분·ID·MES ITEM_CD·상품명 | PK, MES 연동키 |
| 사이즈(필수) | E | "73 x 98 mm" 형식 | 옵션값 + 판걸이수 조인키 |
| 파일사양(내부) | F~M | **판수**·블리드·작업사이즈·재단사이즈·출력용지규격·파일명약어·출력파일·폴더 | 조판·생산 |
| 주문방법(필수) | N~O | 업로드·편집기 | 주문 채널 분기 |
| 종이(필수) | P | "*별도설정" 또는 "아트250" | 소재 조인키 |
| 인쇄(옵션) | Q | 단면/양면 | 인쇄비 축 |
| 별색인쇄(옵션) | R~V | 화이트·클리어·핑크·금색·은색 | 별색비 축 |
| 코팅~접지(옵션) | W~Y | | 각 가격시트 참조 |
| 제작수량(필수) | Z~AC | 건수·**최소·최대·증가** | 수량 규칙 (min/max/step) |
| 후가공(옵션) | AD~AH | 모서리·오시·미싱·가변텍스트·가변이미지 | 후가공비 |
| 박(옵션) | AI~AK | 박/형압·크기·박칼라 | 박 매트릭스 |
| 추가상품(옵션) | AL~AM | 추가상품·추가가격 | 부가 |

> **위젯 테스트 연결**: 통화 P7에서 김동학이 프리미엄엽서를 테스트하며 "수량 min/max/step 데이터가 없다"고 한 것은 이 **AA·AB·AC 열**을 가리킨다. 실측 결과 R3에는 이미 15/10000/15가 채워져 있다 — 위젯 DB 크롤 시 이 열이 누락됐을 가능성이 높다. (8장 참조)

### 2.4 행의 이중 역할 (통화 19:51 "이 순서대로 옵션이다")

- **사이즈행**: E열에 사이즈 값이 있는 행 = 하나의 사이즈 variant.
- **비사이즈행**: E열이 비고 Q열(인쇄) 등에만 값 = 같은 상품의 옵션값 나열.
  - 실측: R3(73×98, 단면) / R4(98×98, 양면) — R4의 "양면"이 98×98 전용인지 전 사이즈 공통인지 엑셀엔 미명시. → **옵션-사이즈 매핑 규칙(302건 분류)** 적용 대상.

## 3장. 인쇄상품가격표 해부 — 19시트 분류

### 3.1 시트를 아키타입으로 그룹핑

| 아키타입 | 가격표 시트 | 조회 방식 |
|---------|-----------|----------|
| **기초 단가(원자)** | 디지털인쇄비·코팅·접지옵션·인쇄후가공·커팅타공·제본 | 수량행 × 옵션열 |
| **원자합산 소재** | 출력소재(IMPORT) | 크기별 단가 × 출력매수 |
| **고정가(테이블)** | 명함포토카드·봉투제작·스티커·합판도무송스티커·엽서북떡메 | 다차원 조회 |
| **면적매트릭스** | 아크릴·포스터사인 | 세로행 × 가로열 |
| **박 매트릭스** | 후가공_박(소형)·후가공_박(대형) | 동판비 + 크기×등급×수량 |
| **구간할인** | 굿즈파우치(구간할인) | 수량 구간 |
| **조판 기준** | 판걸이수 | 사이즈 → UP수 |

### 3.2 각 기초 단가 시트의 축 (실측)

**디지털인쇄비**: `수량(국4절 출력매수) × [흑백1도/CMYK/화이트/클리어/핑크] × [단면/양면]`. 수량이 많을수록 단가 하락(R4=3000 → R9=900).

**접지옵션**: `제작수량 × [2단/3단/6단]`. 헤더에 "카드접지 단가(오시+접지)" 명시 — **오시와 접지가 이미 합산된 옵션 레이어 가격**임을 시트 자체가 선언(7장 근거).

**후가공_박(소형)**: 동판비(80×40mm = 5,000원, *아연판) + 면적별 A~E군 × 칼라 × 수량행. → `박 = 고정 동판비 + 매트릭스 박비`.

## 4장. 계산공식집초안 — 암묵지의 로제타석

### 4.1 이 시트가 왜 결정적인가

통화에서 신우진이 "암묵지"라 부른 것 — 계산하면 시장가보다 비싸서 협의한 가격, 롤 계산, 결합 공식 — 이 **대부분 이 시트에 이미 명문화**돼 있다. 실측 결과 35개 이상 상품군의 판매가 공식과 참조시트가 적혀 있다. **CPQ 견적 엔진의 명세서가 곧 이 시트다.**

### 4.2 공식 유형별 발췌 (실측)

**원자합산형 — 엽서 계열** (R3~12):
```
판매가 = 인쇄비 + 코팅비 + 용지비 + 후가공비 + 추가상품
 (1) 출력매수 = 주문수량 / 판걸이수                → [판걸이수]
 (2) 인쇄비(4도) = [수량행단가] × 출력매수          → [디지털인쇄비]
 (3) 별색인쇄비 = [인쇄비단가] + [출력매수 수량행]×[칼라열] → [디지털인쇄]
 (4) 코팅비 = [수량행단가]×[코팅타입열] × 출력매수   → [코팅]
 (5) 용지비 = [크기별 기준단가] × ([출력매수]+5장 손지율) → [출력소재]
 (6) 후가공비 = [제작수량행]                        → [인쇄후가공]
 (7) 후가공박(대형) = [면적별동판비] + [A~E군][칼라 수량행 합가] → [후가공_박(대형)]
 (8) 추가상품 = 목록별 가격적용
```

**원자합산형 — 책자 계열** (R63~89), 통화의 "내지+표지+면지":
```
판매가 = 내지인쇄비 + 표지인쇄비 + 표지코팅비 + [면지인쇄비 + 면지코팅비] + 제본비 + 용지비 + 후가공비
 (1) 내지인쇄비 = [총내지매수행][도수열] × 총내지매수
 (2) 총내지매수 = 부수 × (페이지수 / 판걸이수)        ← 책등·조판 연동
 (3) 제본비 = [수량행][제본종류열]                   → [제본]
 (하드커버링책자만 면지 항목 추가 — R82~89)
```
> 트윈링책자는 표지·코팅에 ×2 계수(R76~77), 하드커버링은 면지까지 결합(R82). 통화의 "제본 방식마다 표지 유무가 다르다"가 계수로 구현돼 있음.

**고정가형 — 명함**(R32~35): `판매가 = [수량행][소재×면열] + 후가공비`. "명함/포토카드 시트 가격은 용지 포함가"(R39) — 통화의 "가격포함" 해설과 일치.

**면적매트릭스형 — 실사**(R100~101): `판매가 = [세로mm행][가로mm열]` → [포스터/사인].

**면적매트릭스형 — 아크릴**(R106~110): `판매가 = 소재별면적[세로행][가로열] × 수량별구간할인 + 후가공`. 카라비너·코롯토는 별도 할인(R113~117) — 통화의 "카라비너는 별도 구간" 확인.

### 4.3 공식집을 CPQ 규칙으로 변환하는 지침

> **지침 4-A**: 각 공식의 `[참조시트]`를 FK로, 각 항목을 `price_component` 레코드로 만든다. 항목 유형은 4종으로 수렴한다:
> - `lookup_matrix`: [행][열] 조회 (인쇄비, 박, 아크릴, 실사)
> - `per_sheet`: 출력매수 × 단가 (인쇄·코팅·용지)
> - `per_quantity`: 제작수량행 조회 (후가공, 제본, 접지)
> - `fixed`: 협의 고정가 (엽서북, 봉투, 명함테이블)

> **지침 4-B**: `출력매수 = 주문수량 / 판걸이수`, `총내지매수 = 부수 × 페이지수 / 판걸이수` 두 공식이 거의 모든 원자합산형의 뿌리다. 이 두 줄을 **imposition 서비스의 공용 함수**로 구현하고, 손지율(+5장) 같은 보정 파라미터를 인자로 받게 한다.

## 5장. 세 가지 가격 아키타입 정밀 정의

통화에서 신우진이 AI와 명명했다는 3분류가 공식집 태그(`[원자합산형]`, `[고정가형]`, `[면적매트릭스형]`)로 실재한다. 상품군을 이 세 개로 라우팅한다.

### 5.1 원자합산형 (sheet_based)

- **정의**: 원가 요소를 조각내어 각각 계산 후 합산. 재계산 가능(원가 투명).
- **대상**: 엽서 전 종류, 모양엽서/라벨텍, 배경지/헤더택, 소량전단지, 접지리플렛 계열, 썬캡, 캘린더, 책자 전 종류.
- **엔진**: `Σ component_i`, 각 component는 4.3의 4종 중 하나.

### 5.2 고정가형 (negotiated table)

- **정의**: 원자합산으로 계산 시 시장가 초과 → 협의가를 테이블로 고정. **재계산 불가**.
- **대상**: 명함 전 종류, 오리지널박명함, 포토카드, 봉투, 자유형/규격 스티커, 타투/스티커팩, 합판도무송, 엽서북/떡메, 문구, 굿즈/파우치, 상품액세서리, 아크릴 코롯토/카라비너, 폼보드·포맥스·액자·배너·시트커팅 등.
- **엔진**: 다차원 `lookup`. **`price_origin: negotiated` 메타 필수** — 가격 개정 시 원자합산형과 다르게 관리(통화: 시장 역산 가격).

### 5.3 면적매트릭스형 (area_matrix)

- **정의**: 가로×세로 격자의 교차 지점 조회. 수량 구간할인이 인쇄가공비에만 적용.
- **대상**: 실사·현수막(포스터사인), 아크릴 본체.
- **엔진**: `matrix[세로][가로] × 구간할인 + 후가공(제작수량당)`.

> **지침 5-A**: 상품마다 아키타입은 1개가 원칙이나, 후가공(박·모서리 등)은 아키타입과 무관하게 add-on으로 합산된다. 즉 **주계산(아키타입) + 애드온(공정별)** 2단 구조.

## 6장. 판걸이수 — 세 시트를 잇는 조인 키

### 6.1 구조 (실측)

판걸이수 시트 열: `사이즈옵션명 | 재단사이즈 | 블리드 | 작업사이즈 | 상품 | 판걸이 | 디지털인쇄(국4절) | (3절) | 인쇄가능영역 | 원형아이마크영역(완칼)`

실측 예: `73×98mm → 재단 73×98, 블리드 1, 작업 75×100, 상품=엽서, 판걸이=18, 국4절 316×467, 사방 5mm제외`.

### 6.2 조인 관계

```
상품마스터.사이즈(E) ──┐
                      ├── 판걸이수.사이즈옵션명 ── 판걸이수(UP수) ── 출력매수 공식
가격표.출력용지규격 ────┘         (조인 키: 316×467 = 국4절)
```

> **지침 6-A**: 판걸이수 시트를 **imposition 서비스의 데이터 소스**로 삼는다. `작업사이즈 = 재단사이즈 + 블리드×2`가 시트에 실재하므로(73×98 → 75×100), 검산 규칙으로 쓴다. "상품" 열에 "엽서 / 엽서북내지"처럼 복수 상품이 한 사이즈를 공유(R4~5)하므로 **복합 매핑** 허용.

### 6.3 그리퍼(인쇄 불가 영역) 처리

"사방 5mm제외" = 그리퍼 영역. 상품 유형별로 여백이 다르다(통화). 완칼 상품은 "원형아이마크영역" 별도 존재. → imposition 계산 시 `상품유형별 여백 파라미터` 필수.

## 7장. 옵션 2계층 모델 — 고객 옵션 ↔ 생산 공정

### 7.1 핵심 원리 (이번 프로젝트 최대 설계 인사이트)

**고객이 고르는 옵션 1개 ≠ 생산 공정 1개.** 실측 근거:
- 접지옵션 시트 헤더: "카드접지 단가**(오시+접지)**" — 옵션 1개가 공정 2개.
- 아크릴 시트 헤더: "양면**9도** / 단면**7도** 통용" — 고객은 단/양면, 생산은 도수.

### 7.2 2계층 테이블 설계

```
[옵션 레이어] option_item        (고객 노출, 가격 조회 단위)
     │  예: "2단가로접지"
     ▼  option_to_process 매핑
[공정 레이어] production_process  (MES 전달, 작업지시 단위)
     예: 오시 → 접지  (순서 있음: route)
```

> **지침 7-A**: `option_to_process` 매핑 테이블을 신설한다. 컬럼: `option_item_id, process_seq, process_cd, process_param`. 접지=오시(seq1)+접지(seq2), 양면=도수변환(param=9도) 등. 이 테이블이 없으면 MES 작업지시를 생성할 수 없다 — MES_ITEM_CD 94% 미완성 문제와 직결.

### 7.3 옵션 4용도 (통화 27:51) → 스키마 태그

| 용도 | 태그 | 처리 |
|------|------|------|
| 선택하게 하는 옵션 | `ui_select` | 위젯 노출 |
| 상품 관련 옵션 | `product_def` | 상품 정의 |
| 가공 필요 옵션 | `process_param` | 공정 파라미터 |
| 추가상품 옵션 | `upsell` | 부가 판매 |

## 8장. 데이터 정합성 이슈와 검증 로그

실측 중 발견된 불일치 — 적재 전 해소 대상.

| # | 이슈 | 실측 | 조치 |
|---|------|------|------|
| 1 | **판수 불일치** | 디지털인쇄 R3 판수=15 vs 판걸이수 R2 판걸이=18 (둘 다 73×98) | 어느 쪽이 권위인지 확정 필요. 판걸이수 시트가 조판 권위(6장)이므로 18이 유력. 마스터의 15는 구버전 잔재 가능성 → **신우진 확인 필요** |
| 2 | 위젯 수량 누락 | 통화서 "min/max/step 없다" | 마스터엔 존재(AA/AB/AC). 크롤 매핑 누락 → 재크롤 |
| 3 | "*별도설정" 9건 | 디지털인쇄 종이열 | 소재를 사이즈·상품별로 별도 지정하는 플래그. 출력소재 시트와 규칙 매핑 필요 |
| 4 | 상품 수 편차 | 실측 ID보유행 합계 191 vs 통화 "280" vs 스킬 검증 "243" | 191=대표 상품, 243=variants 포함, 280=세트 전개 포함으로 추정. **집계 기준 통일 필요** |
| 5 | 굿즈파우치 86건 | (가격포함) 시트에 집중 | display-only 대량군. 별도 적재 트랙 |

## 9장. 접근 순서 지침 — 무엇부터 손대는가

통화가 알려준 우선순위 + 실측을 결합한 착수 순서. "덜어내기" 원칙 적용 — 동작하는 코어 먼저.

```
STEP 1. 계산공식집초안 → 견적 규칙 카탈로그로 구조화
        (35개 공식을 4.3 유형으로 태깅. 이것이 엔진 명세)

STEP 2. 판걸이수 → imposition 서비스 구현
        (출력매수·총내지매수 공용 함수. 거의 모든 원자합산형의 뿌리)

STEP 3. 기초 단가 6시트 → price_component 테이블 적재
        (디지털인쇄비/코팅/접지옵션/인쇄후가공/커팅타공/제본)

STEP 4. 상품마스터 → option_group/option_item + 색상 3분류
        (required/optional/internal, display_order = 열 순서)

STEP 5. option_to_process 매핑 신설 (7장)
        (오시+접지, 도수변환… MES 연동 선행)

STEP 6. 아키타입별 엔진 3종 구현 + 검증 30케이스
        (원자합산 → 고정가 → 면적매트릭스 순, 엽서 1종으로 E2E 먼저)

STEP 7. 제약조건(JSONLogic) 이관
        (위젯 발동조건 테스트 문법과 정합)
```

> **최종 지침**: STEP 1~2 없이 STEP 3 이하로 가면 통화의 실패 사례("부분 장악")를 반복한다. **공식집(지도) → 판걸이(뿌리 공식) → 데이터**의 순서를 지킬 것. 상품 1종(프리미엄엽서)으로 STEP 1~6을 관통하는 수직 슬라이스를 먼저 완성해 엔진을 검증한 뒤 확대한다.
