## 2. RULE-13 ② — 실패 검출과 되돌리기 [렌즈 R2 주 대상]

### 2.2 교정본 적용 결과 — ② 항 축자 적용

**(가) "라이브 write 를 수반하는 단계"가 교정본에 존재하는가 — 전수 추적**

- §0 신설 행 'G6 실행 환경': **clone DB 단일 경로. 라이브 대상 리플레이는 경로 자체를 폐기** (`:59`) — 폐기 근거로 `/handoff` → `t_wgt_handoff_logs` INSERT/DELETE(`widget_api.py:1677`·`:1733`), `/validate` → 공통 게이트 `_gate` 의 `t_wgt_widgets` UPDATE(`widget_api.py:135`) + rate-limit 캐시 mutation(`:195-196`)을 축자 인용.
- §7 G6: *"스윕 조합을 **clone DB 환경에서만** … **라이브 대상 리플레이 경로는 폐기**"* (`:720`)
- §7 'G6 오라클 경로 폐기 기록': *"[HARD] '라이브 `/validate` 단독 오라클'은 폐기됐다"* + 부작용 사슬 좌표 전건 (`:721`)
- §4.7 O2 채널: *"★FIX-4 정정: '초기엔 파일럿 리플레이로 대체'는 라이브 write 를 유발하므로 폐기한다. O2 는 clone 환경 리플레이 관측 또는 실사용 유입 대기 둘 중 하나로만"* (`:538`)
- §7 G10(FIX-5 신설)도 리플레이를 **clone 환경**으로 명시 (`:725`)
- §12-2 비목표: *"라이브 DB에 단 한 행도 쓰지 않는다 … 이 선언이 성립하려면 G6 리플레이가 clone DB 에서만 실행되어야 한다"* (`:976`)

→ **라이브 write 를 수반하는 단계가 0건**이다. ② 의 전건(antecedent)이 성립하지 않으므로 **위반이 성립하지 않는다.**

**(나) 그럼에도 남긴 안전망 — 근거 없는 제외의 봉쇄**

②를 "우회"로 만족시키는 경로(분모에서 몰래 빼기)를 설계가 스스로 봉쇄했다:
- G1 분모 제외 2테이블(`t_wgt_handoff_logs`·`t_wgt_widgets`)에 대해 *"**[HARD] 근거 없는 제외는 RULE-13 ② 우회다.** 두 제외는 반드시 아래 **G1.1** 과 한 쌍으로만 성립한다"* (`:713`)

## 7. 범위 밖 신규 발견 (판정 미산입 · 기록만)

- **렌즈 R2 게이트 명세 물음에 대한 답**: FIX-3 과 FIX-4 는 **게이트 명세의 자기모순을 실제로 제거했다.** G0.5 의 분모/감시 대상 불일치(A1)는 두 게이트 분할 + projection map 으로 닫혔고, G6 오라클의 라이브 write(A2)는 clone 단일 경로 + G1.1 대체 계측으로 닫혔다. **분모와 감시 대상은 이제 같은 우주다.**
