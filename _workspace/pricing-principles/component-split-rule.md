# 가격구성요소 묶기/쪼개기 판정 규칙

> 질문: 「가격공식과 가격구성요소가 어떤 식으로 구조화돼 연결되는가. 디지털인쇄처럼 하나의
> 구성요소에 담아도 되는 것과 분리를 해야 하는 것을 나누는 기준은 무엇인가.」
>
> 계산 사슬(공식 → formula_components → price_components → component_prices → 차원매칭 → 할인)
> 자체는 `.claude/rules/moai/domains/huni-pricing-engine-map.md` 가 이미 확정했다. 이 문서는
> 그 위에서 **왜 어떤 요금은 한 구성요소에 담기고 어떤 요금은 쪼개지는가**만 다룬다.
>
> 실측일 2026-08-28. 라이브 수치는 재실측 전제.

---

## 0. 규칙 — 3문장

**하나의 가격구성요소는 「하나의 가격표(격자)」다.** 그래서 어떤 요금이 본품과 **같은 격자에
같은 축으로** 값이 적히면 그 요금은 본품 구성요소 안에 담기고(묶음), **다른 축이 필요하거나
고객이 따로 고르거나 할인이 따로 걸려야 하면** 자기 구성요소를 갖는다(분리).

권위 엑셀이 이미 그 판정을 내려 두었다 — 본품 격자 헤더에 「출력+코팅+가공 **포함가**」라고
쓴 것은 묶음이고, 옆에 「◯◯ **추가가격**」 표를 따로 그린 것은 분리다. 라이브 118공식 중
**109개가 이 규칙에 부합하고 9개가 어긋난다**(어긋남 = 배너/현수막 2건 + 아크릴 7건).

## 1. 판정 체크리스트 (검사 가능한 형태)

어떤 요금 X 를 본품 구성요소에 담을지 쪼갤지는 아래를 순서대로 물어 결정한다.
**Q1~Q4 중 하나라도 「예」면 X 는 자기 구성요소를 가져야 한다. 전부 「아니오」면 묶는다.**

| # | 질문 | 「예」일 때 | 근거 |
|---|---|---|---|
| **Q0** | X 가 **따로 팔리는 물건**인가(자체 기성품 상품 레코드를 갖고, 여러 상품에 붙고, 본품 수량과 무관하게 개수로 계산되나) | 구성요소가 아니라 **추가상품 템플릿**(`t_prd_templates`) | §2.4 |
| **Q1** | X 의 값이 **본품 격자에 없는 축**으로 갈리는가(옵션·자재·공정이 본품 축과 다름) | **분리** | pricing.py:176-232 |
| **Q2** | 고객이 X 를 **본품과 독립적으로 고르는가**(안 고를 수도 있는가) | **분리** | §2.2 |
| **Q3** | X 에 **다른 할인**이 걸려야 하는가(수량할인이 X 에는 안 붙거나 X 에만 붙어야 하나) | **분리 + 할인을 구성요소 스코프로 연결** | §5 |
| **Q4** | X 가 **여러 상품이 공유하는 원자**인가(용지비·디지털인쇄비처럼 한 벌 관리해 N상품이 참조) | **분리**(공유 원자) | §2.3 |
| — | 전부 아니오 | **묶음** — 본품 완제품가 한 구성요소 | §2.1 |

추가로 **[HARD] 구조적 상한**: 한 상품이 실제로 값을 받을 수 있는 `opt_cd` 구성요소는 **1개**뿐이다.
Q1/Q2 로 쪼갠 결과 한 공식에 서로 **다른 옵션그룹**을 쓰는 `opt_cd` 구성요소가 2개 이상 생기면
그 설계는 라이브에서 성립하지 않는다(§4).

## 2. 근거 — 권위 엑셀이 경계를 이미 그어 두었다

### 2.1 「포함가」= 묶음 (헤더 문구가 선언이다)

들어가는 것**이다. 값이 본품 사이즈 축 하나로 완결되므로 별도 격자가 필요 없고, 그래서
한 구성요소다. 디지털인쇄가 「하나에 담아도 되는」 예로 지목된 것도 같은 이유가 아니라
**정반대 이유**로 쪼개져 있다 — §2.3 참조(디지털인쇄는 묶음의 예가 아니라 분리의 예다).

### 2.3 디지털인쇄는 「묶음의 예」가 아니라 「최대 분리의 예」다

상품마스터 260822_1 첫 시트 「계산공식집초안」이 운영진 자신의 선언이다(행 4-12):

```
[원자합산형: 프리미엄엽서 / 코팅엽서 / … / 프리미엄상품권]
판매가 = 인쇄비 + 코팅비 + 용지비 + 후가공비 + 추가상품
```

라이브 `PRF_DGP_A`(엽서·상품권·슬로건, 게시상품 10개)는 이 문장 그대로 **구성요소 10개**다 —
`COMP_PRINT_DIGITAL_S1` · `COMP_PRINT_SPOT_WHITE_S1` · `COMP_PAPER` · `COMP_PP_CORNER_RIGHT` ·
`COMP_PP_CREASE_1L` · `COMP_PP_PERF_1L` · `COMP_PP_VARTEXT_1EA` · `COMP_PP_VARIMG_1EA` ·
`COMP_COAT_MATTE` · `COMP_COAT_GLOSSY`. 접지카드+박(`PRF_DGP_E_FOIL`)은 **14개**로 라이브 최대다.

왜 이렇게까지 쪼개졌나 — **Q4(공유 원자)** 때문이다. 실측:

| 구성요소 | 참조 공식 수 |
|---|---|
| `COMP_PAPER` 용지비(종이별 절가) | **13** |
| `COMP_PRINT_DIGITAL_S1` 디지털인쇄비 | **13** |
| `COMP_PP_VARTEXT_1EA` 가변텍스트 / `COMP_PP_VARIMG_1EA` 가변이미지 | 각 **7** |
| `COMP_COAT_MATTE` / `COMP_COAT_GLOSSY` | 6 / 5 |
| `COMP_FOIL_SETUP_LARGE` 외 박·형압 6종 | 3~4 |

용지 단가가 바뀌면 고쳐야 할 곳이 **1군데**다. 묶어 놓았다면 13공식 × 상품 수만큼 격자를
다시 채워야 한다. 즉 디지털인쇄 계열의 분리는 「가격을 정확히 만들기 위해서」가 아니라
**한 벌 관리를 위해서**다.

거꾸로 실사(포스터사인) 계열은 **묶음이 바로 그 공유를 산다**:

| 구성요소 | 담긴 상품 | 격자 |
|---|---|---|
| `COMP_POSTER_ARTPRINT_PHOTO` 「실사 완제품가 (아트프린트·접착방수·아트패브릭·방수)」 | 4 | 52셀 1벌 |
| `COMP_POSTER_CANVAS_FABRIC` 「실사 완제품가 (캔버스패브릭·레더아트프린트·메쉬프린트·타이벡)」 | 4 | 52셀 1벌 |

측정(`_workspace/postersign-audit/authority.csv`, 권위 셀 788개 파싱본 기준): 두 4상품 묶음의
**본품 격자가 셀 단위로 완전히 동일**하다 — 아트프린트/방수/접착방수/아트패브릭 4블록이
52셀 전부 같은 값, 캔버스패브릭/레더아트프린트/타이벡/메쉬프린트 4블록도 52셀 전부 같은 값.
값이 같으니 격자를 4벌 두면 4배로 어긋날 뿐이다. **구성요소 이름에 4상품을 다 적어 둔 것이
「이건 의도된 공유」라는 운영진의 표시**다.

⇒ **Q4 는 양방향이다.** 값이 상품마다 다르면 원자를 쪼개 공유하고, 값이 상품마다 같으면
완제품가째로 공유한다. 어느 쪽이든 목표는 「단가 한 벌」이다.

### 2.4 구성요소가 아니라 추가상품 템플릿이 되는 경계 (Q0)

같은 「추가가격」 표인데 배너거치대·천정고리만 템플릿으로 갔다. 실측된 차이:

| | 우드행거+면끈 / 현수막 가공옵션 | 배너거치대 / 천정고리 |
|---|---|---|
| 값이 갈리는 축 | **본품 사이즈**(A4/A3/A2)·본품 옵션 | 본품과 무관(단일가 7,000/23,000/25,000/6,500) |
| 자체 상품 레코드 | 없음 | **있음**(`PRD_000315~317` 등 기성품, `t_prd_product_addons` 6행) |
| 여러 상품 공유 | 해당 상품 전용 | **PET배너+메쉬배너 공용**(엑셀 `L229` 문구와 일치) |
| 계산 위치 | `base_amount` 안(할인 대상) | 계산 **밖**에서 별도 합산 |

⇒ **본품 치수에 종속돼 값이 갈리면 구성요소, 독립 물건이면 템플릿.** 우드행거는 A4/A3/A2 로
16,000/18,000/20,000 이라 본품 사이즈를 알아야 값이 나온다 — 템플릿(선택값 미주입, map §4)으로는
계산이 안 된다. 거치대는 사이즈 무관 단일가라 템플릿으로 충분하다.

| 엑셀 선언 | 시트 행 | 라이브 형태 |
|---|---|---|
| 원자합산형(엽서·리플렛·책자·캘린더·썬캡) | 3~29, 63~98 | S3 |

| 면적매트릭스형(실사·현수막) | 100~101 | S1(단품) / S2(옵션 있는 것) |

**아크릴만 엑셀이 「+ 후가공」을 명시적으로 분리해 적었고, 라이브도 분리돼 있다**(행 107·110:
`판매가 = 인쇄가공비 x 수량별구간할인 + 후가공`, `후가공 = 제작수량당 부과`). 실제로
`COMP_ACRYL_CLEAR3T`(인쇄가공비, `PRICE_TYPE.02` 합가형)가 8공식에서 공유되고, 그 위에
키링/마그넷/뱃지/집게/스마트톡/명찰/머리끈이 각각 자기 부자재 구성요소(`PRICE_TYPE.01` 단가형
= 제작수량당)를 얹는다. **Q4(공유) + Q3(할인 분리)가 동시에 걸린 교과서 사례.**

## 4. 잘못 묶었을 때 / 잘못 쪼갰을 때의 고장 방식

### 4.1 쪼개야 할 것을 묶으면 — 격자 폭발 + 미선택 과금

일반현수막 실측 수치로: 본품 격자 **86셀**(가로 5 × 세로 18 남짓), 가공옵션 **6행**,
추가옵션 **4행**. 지금 구조는 86 + 6 + 4 = **96행**. 묶으면 86 × 7 × 5 = **3,010셀**이 되고,
가공가가 바뀔 때마다 3,010셀을 다시 채워야 한다. 게다가 고객이 「추가없음」을 골라도
격자 어딘가에 값이 있으면 매칭돼 붙는다.

### 4.2 [HARD] 쪼갰는데 실제로는 하나만 살아난다 — `opt_cd` 단일값 상한

`selections` 는 **평평한 dict** 이고 `opt_cd` 는 **스칼라 하나**다(`pricing.py:45-46` `NON_QTY_DIMS`,
`widget_api.py:688-696` `_prep_selections`). 렌더러가 옵션그룹 선택을 가격축으로 실을 때의
코드가 그 상한을 그대로 적고 있다:

```javascript
// widget_renderer.js:4250-4266
/* 가격 차원이 옵션코드(use_dims=opt_cd, 그룹 범위)인 상품(260801, 배너사이즈):
   … 멀티 그룹은 단일값 차원에 못 실어 제외. */
if (_optCand && sel.opt_cd == null && !it.mbr_prd_cd) { … sel.opt_cd = _ov; }
```

`sel.opt_cd == null` 가드 = **먼저 걸린 옵션그룹 하나만 실린다.**

라이브에서 **서로 다른 옵션그룹의 `opt_cd` 구성요소를 2개 가진 공식 2건**:

| 공식 | 구성요소 (옵션그룹) |
|---|---|
| `PRF_POSTER_BANNER_N` 일반현수막 | `COMP_BANNER_OPTION`(OPT_000003) + `COMP_BANNER_ADDON`(OPT_000004) |
| `PRF_POSTER_BANNER_M` 메쉬현수막 | `COMP_BANNER_MESH_OPTION`(OPT_000285) + `COMP_BANNER_MESH_ADDON`(OPT_000023) |

위젯 실측(`t_wgt_widget_items`, `PRD_000138`): `opt_cd` 차원 위젯이 **1개**(라벨 「가공 / 추가」)이고,
OPT_000003·OPT_000004 는 옵션그룹 위젯(`WGT_SRC_TYPE.02`, 가격 무관)으로 따로 있다.

`PRF_PHOTOCARD_NORMAL`(`COMP_PHOTOCARD_SET` + `COMP_PHOTOCARD_BULK`)도 `opt_cd` 구성요소 2개지만
**같은 그룹 OPT_000084** 라 서로 배타 선택지다 — 충돌 아님. 판정 기준은 「2개」가 아니라
「**서로 다른 옵션그룹 2개**」다.

> **[가설 — 미검증]** 위 2건에서 고객이 가공옵션과 추가옵션을 동시에 고르면 한쪽만 과금될
> 것으로 보인다. 매칭 실패는 `no_match` 라 경고조차 나지 않는다(`pricing.py:799-811`, map §5 갈래 2).
> **확정하려면**: `PRD_000138` 로 `selections={siz_cd,…, opt_cd: <OPT_000003 값>}` +
> 옵션그룹 OPT_000004 선택을 함께 넣어 `evaluate_price` 를 실제 호출하고 `components[].included`
> 를 본다. 코드 경로는 확정이나 최종 금액 영향은 이 문서에서 재계산하지 않았다.

## 5. 할인 레이어와의 상호작용 (sub-question 4)

`t_prd_product_discount_tables.comp_cd` 가 스코프를 정한다(`pricing.py:963-1021` `_component_discounts`,
`:930-960` 총액). 라이브 실측:

```
총액 스코프(comp_cd='')                       125행
구성요소 스코프(comp_cd≠'')                     1행  ← PRD_000146 아크릴키링 / COMP_ACRYL_CLEAR3T
                                                     DSC_ACR_QTY 「아크릴 카테고리 수량별 구간할인」
```

**질문의 전제를 정정한다.** 「묶인 구성요소는 구성요소 스코프 할인을 못 받는다」는 사실이
아니다 — 묶여 있어도 `comp_cd` 링크는 걸 수 있다. **정확한 제약은 이것이다: 묶으면 그 안의
일부만 깎을 수 없다.** 할인 대상의 최소 단위가 구성요소이기 때문이다.

그리고 이 제약이 실제 모델링을 **정확히 한 건 만들어 냈다.** 「계산공식집초안」 행 109가
`(2) 수량별할인 = 인쇄가공비에만 적용` 이라고 못 박았고, 라이브의 유일한 구성요소 스코프
할인이 바로 그 `COMP_ACRYL_CLEAR3T` 다. **아크릴이 쪼개진 이유의 최소 하나는 할인이다.**

### 5.1 [발견] 같은 모양인데 7건은 그 분리를 살리지 못한다

`COMP_ACRYL_CLEAR3T` + 부자재 구조를 가진 8상품의 할인 스코프 실측:

| 상품 | 공식 | 총액할인 | 구성요소할인 |
|---|---|---|---|
| `PRD_000146` 아크릴키링 | `PRF_ACRYL_KEYRING` | 0 | **1** ✅ 시트 행 109 준수 |
| `PRD_000147` 아크릴마그넷 | `PRF_ACRYL_MAGNET` | 1 | 0 ❌ |
| `PRD_000148` 아크릴뱃지 | `PRF_ACRYL_BADGE` | 1 | 0 ❌ |
| `PRD_000149` 아크릴집게 | `PRF_ACRYL_CLIP` | 1 | 0 ❌ |
| `PRD_000150` 아크릴스마트톡 | `PRF_ACRYL_SMARTTOK` | 1 | 0 ❌ |
| `PRD_000152` 아크릴명찰 | `PRF_ACRYL_NAMETAG` | 1 | 0 ❌ |
| `PRD_000153` 아크릴명찰(골드실버) | `PRF_ACRYL_NAMETAG_GS` | 1 | 0 ❌ |
| `PRD_000154` 아크릴 머리끈 | `PRF_ACRYL_HAIRBAND` | 1 | 0 ❌ |

총액 스코프는 `base_amount` 전체(= 인쇄가공비 **+ 부자재**)를 깎는다. 시트는 부자재(후가공)를
할인 대상에서 빼라고 적었다. ⇒ **쪼개는 것만으로는 할인이 갈라지지 않는다. 할인 링크를
구성요소 스코프로 걸어야 완성된다.** 7건이 절반만 되어 있다.

> 단, `PRF_CLR_ACRYL`(단일 구성요소, 6상품)처럼 부자재 구성요소가 없는 공식은 총액 = 구성요소
> 이므로 총액 스코프가 맞다. 위 7건만 어긋난다.

## 6. `use_dims` 의 `opt_grp:` 는 무엇을 사는가 (sub-question 3)

### 6.1 런타임 가격계산에는 아무 영향이 없다 [코드 확정]

- `opt_grp:` 는 `NON_QTY_DIMS` 에도 `TIER_DIMS` 에도 없어 `_row_matches`(`pricing.py:136-148`)가
  아예 읽지 않는다.
- `pricing.py:778-781` 은 판별차원 계산에서 `opt_grp:` 토큰을 제외한다 — 이건 **매칭이 아니라
  「판별차원 없음 — 선택과 무관하게 항상 매칭」 진단 문구**를 오작동시키지 않기 위한 것이다.
- `price_views.py:141-155` `split_scopes` 가 dim 목록에서 떼어낸다: 주석 verbatim
  「토큰은 dim 이 아니라 DIM_ORDER/DIM_META 필터에 자동 제외되어 기존 readers 에 안전」.

### 6.2 사는 것은 단 하나 — 단가표 그리드의 옵션 드롭다운 범위

`price_views.py:1341-1346` `_opt_cd_options(opt_grp)`:

```python
qs = M.TPrdProductOptions.objects.exclude(del_yn="Y")
if opt_grp:
    qs = qs.filter(opt_grp_cd=opt_grp)
```

`opt_grp` 가 없으면 **라이브 전 상품의 살아있는 옵션 329개**가 드롭다운에 뜬다. 있으면 그
그룹 것만 뜬다. 즉 `opt_grp:` 는 **적재 오입력 방어**를 산다. (Edicus 쪽은 의미가 다르다 —
`edicus_views.py:18-19` 가 「가격구성요소 전용 의미론」이라고 명시.)

### 6.3 언제 그룹 스코프로 좁혀야 하나

**`opt_cd` 를 쓰는 구성요소는 예외 없이 `opt_grp:` 를 함께 적는다.** 그 값들이 어느 한 상품
옵션그룹에서 온 이상, 스코프 없는 드롭다운은 「같은 이름 다른 상품 옵션」을 고를 여지를
그대로 남긴다.

라이브 미준수 **2건**(살아있는 것 기준):

| 구성요소 | use_dims | 실제 옵션 소속 |
|---|---|---|
| `COMP_POSTEROPT_LINEN_FINISH` 린넨 마감가공비 | `["opt_cd","min_qty"]` | 5개 값 전부 `OPT_000096` / `PRD_000124` |
| `COMP_PHOTOBOOK_BASE` 포토북 기본가 | `["siz_cd","opt_cd","min_qty"]` | (표지타입 그룹 — 미확인) |

`COMP_POSTEROPT_LINEN_FINISH` 는 `opt_grp:OPT_000096` 를 붙이면 드롭다운이 329 → 5로 좁아진다.
(참고: 그 그룹의 `OPV-000024`(하이픈)는 `t_prd_product_options` 마스터 자체가 그렇게 채번돼
있어 단가표 오타는 아니다 — 확인함.)

## 7. 규칙 적합성 집계

세 가지 **기계 검사**로 판정했다. 「해당 없음」은 통과로 세지 않고 검사에서 제외했다.

| 검사 | 대상 | 통과 | 위반 |
|---|---|---|---|
| **C1** 한 공식에 서로 다른 옵션그룹의 `opt_cd` 구성요소 2개 이상 없음 | 118공식 | 116 | **2** (`PRF_POSTER_BANNER_N`, `PRF_POSTER_BANNER_M`) |
| **C2** 시트가 부분 할인을 명시한 계열에서 할인이 구성요소 스코프 | 아크릴 8공식 | 1 | **7** (§5.1) |
| **C3** 권위 시트의 「추가가격」 별도 표 → 별도 그릇 | 포스터사인 9표 | 9 | 0 |
| **C4** `opt_cd` 구성요소에 `opt_grp:` 스코프 | 살아있는 구성요소 중 `opt_cd` 사용분 | (전체 중) | **2** (§6.3, 경고 등급) |

**부적합 공식 = 9개**(배너/현수막 2 + 아크릴 7, 중복 없음). **적합 = 109 / 118.**
C4 위반 2건은 계산 결과를 바꾸지 않는 적재-안전 등급이라 위 9건에 포함하지 않았다.
