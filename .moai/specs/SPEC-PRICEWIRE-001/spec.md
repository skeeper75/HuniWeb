## 1. 배경과 분모

### 1.1 목표는 두 층이다

종료 조건 "게시 위젯 전량에서 가격이 0원/-원 없이 나온다" 는 독립된 두 층으로 갈린다(research.md §1).

- **1차 = 배선**: 가격 소스 부재(E1)·공식→구성요소 미배선(E2)·단가행 미도달(E4) → `final=0`.
- **2차 = 정확도**: 판수 환산(E5)·수량 경계(Q1)·셋트 합산(S1) → 0원이 아니라 **저청구**. 돈영향 실측 `undercharge 841 · overcharge 0 · unknown 578 · none 12`(`_workspace/huni-widget-wiring/out/wiring-health-index.json`).

본 SPEC 의 **우선순위 1 = 배선**(값이 나오는 것), **우선순위 2 = 정확도**. 정확도 층은 **검증·원장화 범위로만 포함**하며 그 교정은 후속 SPEC 으로 이월할 수 있다(§2.2). 다만 E5 를 E4 에 흡수하는 것은 금지된다(선행 `SPEC-WIDGET-WIRING-001/spec.md:233-234` [HARD]).

**M0 실행에서 드러난 두 결함 계열의 층 귀속** (근거 정본: `progress.md §E.2 M0-1c`·`M0-1d`·`M0-1e`):

- **할인 적용 범위 위반(REQ-PW-023) = 1차층 인접**. 값 자체는 나온다(0원 아님). 그러나 권위 「계산공식집초안」 row 109 `(2) 수량별할인 = 인쇄가공비에만 적용` 에 반해 후가공·부속까지 할인이 걸려 **권위 대비 저청구**가 된다. E5·Q1 과 달리 교정 수단이 **가격 뷰어 「적용 대상」 한 필드**이며 엔진 변경이 전혀 없다(`pricing.py:963 _component_discounts` 가 이미 구현·동작 중). 따라서 정확도 층 이월 대상이 아니라 **교정 범위 안**이다.
- **추가상품 템플릿 단가 부재(REQ-PW-024) = 정통 1차층**. `widget_api.py:1860 _addons_strict` verbatim `계산 불가(amount=None)면 422 로 막는다 — 0원 폴백은 조용한 언더차지다` — 값이 틀리게 나오는 게 아니라 **견적이 거부**된다. 우선순위 1 에 직결한다.

### 1.2 분모 확정 — 1줄 [HARD · C3 해소]

> **본 SPEC 의 분모 = 판정 실행 시점의 라이브 게시 상태**다 — `t_wgt_widgets` 중 `sts_typ_cd='WGT_STS_TYPE.02'`(게시됨) 이고 `COALESCE(del_yn,'N')='N'` 인 위젯, 그리고 그에 대응하는 상품 `prd_cd`.

### 4.4 검증·종료

- **REQ-PW-018** — **When** 전량 검증 스윕을 수행할 때, 검증기는 기존 도구만 재사용해야 한다: `verify_zero_quote.py` · `lens_b_runner.py` · `audit_published_prices.py`. 신규 판정 알고리즘 mint 금지.
  - **[HARD] 할인 범위 위반(REQ-PW-023)의 계측 수단 = 라이브 읽기전용 SELECT**. 위 3종 중 `verify_zero_quote.py` 는 `final=0` 만 보므로 **저청구는 구조적으로 잡히지 않는다** — 할인 범위 위반은 값이 나오되 권위 대비 낮게 나오는 결함이다. 따라서 REQ-PW-023 의 종료 판정 근거는 `t_prd_product_discount_tables.comp_cd` 를 상품별로 조회하는 **라이브 읽기전용 SELECT** 로 한다(빈 `comp_cd` = 총액 스코프 = 위반 후보).
  - 이 SELECT 는 **기존 SQL 조회이지 신규 판정 스크립트가 아니다** — 판정 알고리즘·심각도 등급을 새로 만들지 않고, 권위(「계산공식집초안」 할인 원리)와 라이브 필드값을 1:1 대조할 뿐이다. 따라서 본 조항의 mint 금지에 저촉하지 않는다. 쓰기는 수행하지 않는다(SELECT 전용).
  - 정리: 3종 도구는 **0원·엔진오류 계열**의 종료 판정 도구이고, 라이브 읽기전용 SELECT 는 **저청구 계열(REQ-PW-023)**의 종료 판정 도구다. 둘은 대체 관계가 아니라 담당 결함군이 다르다.
- **REQ-PW-019** — **When** 스윕 결과를 분류할 때, 검증기는 각 미매칭 건을 (A)진짜 결함 / (B)정상 미매칭(「가족 분담 면제」) / (C)미선택 차원 3분류로 사유와 함께 원장화해야 한다(t8 골격 승계).
