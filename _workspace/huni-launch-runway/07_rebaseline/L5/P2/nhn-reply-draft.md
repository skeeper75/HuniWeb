## [답변 1] 저희 「견적엔진」이 무엇인가

**한 줄로 말씀드리면 — 사내 인쇄 가격표를 데이터베이스에 담아 두고, 고객이 고른 옵션 조합에 해당하는 금액을 찾아 계산해 주는 저희 자체 서버 프로그램입니다.**

### 무엇을 받고 무엇을 내보내나

| 구분 | 내용 |
|---|---|
| 받는 것(입력) | 상품 1종 + 옵션 조합 — **사이즈/판형 · 용지(자재) · 인쇄 도수 · 후가공 · 페이지/묶음수 · 수량** |
| 내보내는 것(출력) | **총 청구액 1개(원)** |
| 계산 방식 | 규칙 기반 계산. **같은 입력 → 항상 같은 출력**(무작위·시세·시간 요소 없음) |
| 값의 출처 | 후니 사내 **권위 가격표(엑셀 2종: 상품마스터 · 인쇄상품 가격표)** 를 그대로 데이터베이스에 적재한 값 |
| 위치 | 후니 자체 서버(장바구니·결제·주문은 전부 샵바이) |

### 왜 이런 것이 필요한가 — 인쇄물의 특성

인쇄 주문제작은 **똑같은 「명함」이라도 용지·도수·후가공·수량 조합에 따라 원가가 전혀 다릅니다.**
그래서 인쇄업계는 상품마다 하나의 판매가를 붙이지 않고, **조합별 단가표**를 씁니다. 저희 견적엔진은 그 단가표를 프로그램으로 옮긴 것입니다.

### 값이 바뀌는 때는 언제인가

**사내 가격표를 개정할 때뿐입니다.** 개정은 저희가 사람 손으로 하고, 개정 전후로 같은 조합의 값이 달라집니다.
**고객의 구매 행위 자체는 값을 바꾸지 않습니다.**

## [답변 2] 「구매 시점 가격 변동」의 기준과 실제 조합 수치

### 기준 — 시점 기준의 변동은 없습니다

| 질문 | 후니 답 |
|---|---|
| 시간에 따라 변하나요 | **아니오.** 시간·재고·시세에 연동되는 요소가 없습니다 |
| 고객마다 다르나요 | **아니오.** 회원 등급별 차등가는 쓰지 않습니다 |
| 그럼 무엇이 금액을 바꾸나요 | **고객이 고른 옵션 조합과 수량, 그 둘뿐입니다** |
| 수량은 어떻게 반영되나요 | 수량 구간별 할인율이 가격표에 이미 적혀 있고, 그 표대로 적용합니다 |

### 실제 조합 수치 — 저희 상품 하나를 예로 듭니다

**상품: 아크릴키링 · 기본 사이즈 · 수량 1,000개**

| 항목 | 값 |
|---|---|
| 최종 청구액 | **2,550,000원** |
| 계산식 | (인쇄·가공비 × 수량구간 할인율) + 후가공비 |
| 값의 근거 | 후니 권위 가격표 「계산공식집초안」 |
| 재현성 | 같은 조합을 몇 번 계산해도 **2,550,000원** |

**같은 상품군에서 옵션만 바꾸면** (모두 수량 1,000개 기준)

| 상품 | 최종 청구액 |
|---|---|
| 아크릴키링 | 2,550,000원 |
| 아크릴마그넷 | 2,050,000원 |
| 아크릴뱃지 | 2,550,000원 |
| 아크릴집게 | 2,250,000원 |
| 아크릴스마트톡 | 5,400,000원 |
| 아크릴머리끈 | 1,750,000원 |
| 아크릴지비츠 | 600,000원 |

보시는 대로 **조합마다 값이 미리 정해져 있습니다.** 구매 시점에 저희가 값을 지어내는 것이 아닙니다.

### 그렇다면 왜 「옵션 사전 전수등록」이 어려운가

이 부분이 저희가 가장 도움을 구하고 싶은 지점입니다.

**수량이 연속된 값이기 때문입니다.** 고객은 1개부터 수만 개까지 아무 수량이나 넣을 수 있고, 수량마다 금액이 다릅니다.
사이즈·용지·도수·후가공까지 곱하면 **한 상품의 조합 수가 실용적으로 열거 불가능한 규모**가 됩니다.
(저희 판매중 상품은 **226개**이고, 조합 수 전체는 아직 세어 보지 않았습니다 — **미확인**으로 남깁니다.)

### 현재 저희가 쓰고 있는 우회 방법

2026-08-26 미팅에서 **「외부 금액을 주문에 직접 지정할 수 없다」**는 회신을 주셨고, 그에 맞춰 저희는 이렇게 바꿨습니다.

| 항목 | 현재 상태 |
|---|---|
| 상품 판매가 | **10원**으로 통일 (판매중 226개 일괄 변경 완료 · 2026-08-26) |
| 주문 수량 | **청구액 ÷ 10** — 예) 15,000원 주문이면 수량 1,500 |
| 결과 | 결제 총액은 정확합니다 |

**다만 이 방법에는 부작용이 있습니다.** 셀러어드민 주문 화면·거래명세서·현금영수증·세금계산서·알림 문자에 **「단가 10원 × 수량 1,500」**으로 표기됩니다. 실제 거래는 「명함 200장」인데 증빙 어디에도 그 내용이 남지 않습니다.

## 저희가 여쭙고 싶은 것

위 설명을 전제로, 아래 두 가지에 대한 안내를 부탁드립니다.

**[질문 A] 주문 시점 옵션 등록이 상품 심사에 걸리는가**
저희가 검토 중인 방식은, 고객이 결제하기 직전에 **그 조합 하나만** Server API 로 옵션에 등록하고 그 금액으로 결제받는 것입니다.
이때 **상품이 「승인대기」 상태로 전환되어 판매가 멈추는지** 알려 주세요. 멈춘다면 이 방식은 저희가 쓸 수 없습니다.
(참고로 `PUT /products/options` 쓰기 자체는 저희 테스트 상품에서 정상 동작을 확인했고, 호출 후 원상복구까지 마쳤습니다.)

**[질문 B] 정산이 어느 금액을 권위로 삼는가**
위 「10원 × 수량」 구조에서, **정산 금액의 근거가 되는 값이 무엇인지** 알려 주세요.
주문 라인의 실제 결제 금액인가요, 아니면 상품 판매가 × 수량을 다시 계산한 값인가요.
저희는 아직 실제 결제를 한 건도 하지 못해(결제대행 승인 대기 중) **직접 확인할 방법이 없습니다.**

| 정산이 라인 금액을 권위로 쓰는지 | **미확인** — 위 질문 B |
