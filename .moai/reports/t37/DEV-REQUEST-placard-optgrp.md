# DEV-REQUEST — 현수막 부자재 미청구 (과소청구 3,000~8,000원/건)

> 카드: t37 · 원본 실측: `.moai/reports/price-defects-260904/FINDINGS.md` §결함3 (리드 세션 260904 실측, 재조사 없이 그대로 인용)
> 이 결함은 전부 코드(위젯 collect · pricing 라우팅 · widget_api 면제 로직) 수정 사항 — 가격구성요소 측 우회 불가(그룹 합치기 = 옵션그룹/공식 변경이라 불허). 실무진 전달 문서만.

## ⚠ t35와의 관계 (별건 명시)
관련 기존 카드: **t35**(use_dims opt_grp 다중 스코프 · split_scopes). **이번 t37 건은 t35의 전 단계 문제**다 — t35는 이미 여러 opt_grp 스코프를 다룰 수 있게 된 이후의 다중 스코프 처리를 다루지만, t37은 그보다 앞선 단계인 **"선택값을 담는 슬롯 자체가 opt_cd 1개뿐"** 인 구조적 결함이다. t35 작업과 중복되지 않으며, t35 완료 여부와 무관하게 별도로 처리 필요.

## 요약
현수막(PRD_000138 일반현수막 등) 상품이 옵션그룹 2개(가공 OPT_000003 · 부자재 OPT_000004)를 모두 선택 가능한 UI를 제공하지만, 내부적으로 selections 슬롯이 opt_cd 1개뿐이라 두 번째 그룹(부자재) 선택값이 조용히 버려진다. 경고·차단 없이 **0원으로 누락 청구**된다.

## 증상
PRD_000138 일반현수막: 옵션그룹 2개(가공 OPT_000003 · 부자재 OPT_000004)를 고객이 둘 다 고를 수 있으나 부자재 금액이 0원(제외). errors/warnings 없음.

## 라이브 실측
- 그룹/옵션: OPT_000003 가공 = OPV_000006~011(6종 3,000~5,000) · OPT_000004 부자재 = OPV_000013~016(4종 3,000~8,000)
- 구성요소: `POSTER_PLACARD_FINISHING` `["opt_cd","min_qty","opt_grp:OPT_000003"]` · `POSTER_PLACARD_ADDON` `["opt_cd","min_qty","opt_grp:OPT_000004"]`
- 위젯 WGT_000262 배치: row3 = OPTGRP OPT_000003, row4 = OPTGRP OPT_000004 (둘 다 UI에 노출됨 — 고객은 둘 다 고를 수 있다고 인지)
- 영향 상품: PRD_000138 일반현수막(FORM_POSTER_PLACARD) · PRD_000139 메쉬현수막(FORM_POSTER_MESHPLACARD, OPT_000023/000285)

## 코드 근거(3층 버그)
1. `widget_renderer.js` `collect()` ~4996행: `if (_optCand && sel.opt_cd == null …) sel.opt_cd = _ov` → **selections.opt_cd 슬롯이 1개뿐**이라 첫 OPTGRP(가공)만 담기고 두 번째(부자재)는 버려짐
2. `pricing.py:860` `opt_grp:` 토큰을 dim 목록에서 제거만 하고 라우팅에는 미사용 → 두 구성요소(FINISHING/ADDON)가 결국 같은 `sel["opt_cd"]` 하나를 봄
3. `widget_api.py:1022` 가족분담 면제 로직 `(d, v) in covered` → 가공 옵션이 OPV_000011과 매칭됐다는 사실만으로 부자재 축의 빵꾸까지 "커버됨"으로 면제 → **경고 0·차단 0·조용한 0원 청구**

## 정량 영향
5000×900 현수막 + 봉미싱 + 각목(900↓) + 끈 조합 기준:
- 정상: 36,000(본품) + 4,000(봉미싱) + 4,000(각목+끈) = **44,000원**
- 현재: **40,000원** (부자재 4,000원 누락)
- 상품/조합별 **3,000~8,000원 과소청구** (OPV_000013~016 단가 범위)

## 제안 수정안

### ① 응급 조치 (손실 즉시 정지)
`widget_api.py:1022` 가족분담 면제 규칙에서 `opt_cd` 축을 제외 — 부자재 미선택 상태가 "커버됨"으로 잘못 면제되어 주문이 그대로 통과하는 것을 막는다. 이 조치만으로 손실이 즉시 정지되지만, 대신 현재 구조상 주문 자체가 차단될 수 있음(경고/에러로 전환) — 사용자 경험 영향 있으니 배포 시점 조율 필요.

### ② 본 수정 (구조적 해결)
- `widget_renderer.js` `collect()`: selections를 그룹별 키(`sel["opt_grp:G"]`)로 분리 저장하도록 변경
- `pricing.py`: use_dims 의 `opt_grp:G` 토큰을 실제 라우팅에 사용 — 해당 구성요소가 `sel["opt_grp:G"]` 키를 보고 opt_cd 자리에 매핑. 단일 그룹만 있는 기존 상품은 `sel["opt_cd"]` 폴백으로 하위호환 유지.

### 후속 제안
`t_wgt_handoff_logs` 로 부자재 선택 시 발생한 실손실(과소청구분)을 집계 — 이미 발생한 주문 건에 대한 사후 정산/영향 범위 파악용.

## 우선순위 / 긴급도
**High** — 라이브 서비스 중인 소비자 주문에서 실제 매출 손실이 계속 발생 중이며(경고/차단 없음), 영향 상품이 2개(PRD_000138, PRD_000139)로 확인됨 — 동일 패턴 상품군 전수 점검 필요.
