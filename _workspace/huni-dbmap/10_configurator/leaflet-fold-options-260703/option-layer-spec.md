## 0. 한 줄 결론

두 상품에 047과 동형인 **4개 옵션그룹(인쇄·종이·코팅·후가공) + 코팅×종이두께 금지 제약 1건**을 설계했다. 참조하는 차원행(자재·공정·도수)은 **전건 라이브 실재(트리거 통과 확인 완료)** → 핵심 레이어는 **BLOCKED 0**. 단 **사이즈+접지(fold)**는 (a) 048 사이즈 차원 0건 (b) fold를 사이즈에 합성 vs 별도 공정축으로 볼지 **AMBIG** 이므로 **미설계·결정 큐**로 분리했다. 신규 차원 mint **없음**(전부 라이브 코드 재사용).

## 4. 종이 평량 매핑 (코팅 제약 key)

평량은 **자재명 텍스트**(`t_mat_materials.mat_nm`, 예 "아트지 150g")에 내장 — 별도 평량 컬럼 없음. 047 라이브 제약도 평량 컬럼을 읽지 않고 **thin(<180g) 자재코드를 열거**한다. 동일 메커니즘 채택.

- **thin(<180g) 판정**: 자재명 정규식 `(\d+)g` 파싱; 이름에 평량이 없는 특수지는 **047 라이브 검증 리스트**를 canonical로 채택(같은 mat_cd = 같은 물리지 = 같은 평량).

### 048 (44 종이 중 thin 15종 — 047 검증 리스트와 완전 일치)
`MAT_000072,073,076,077,078`(백색모조지100/120·아트지100/120/150) `086,087,088`(스노우지100/120/150) `095,096,097`(앙상블100/130/160) `104,105,106`(몽블랑100/130/160) `125`(한지170)
→ 나머지 29종(아트지180↑·스노우지180↑·앙상블190↑·랑데뷰·특수지 등) = 코팅 가능.

### 049 (5 종이 중 thin 2종)
`MAT_000083`(아트지 150g 3절) · `MAT_000110`(몽블랑 130g 3절) = 코팅 불가. `093`(스노우지250)·`111`(몽블랑190)·`112`(몽블랑240) = 코팅 가능.

> ★ 코팅 제약 buildable = **YES** (양 상품). 평량 정보가 종이 옵션→자재행에 실재(이름 내장)하고, 047과 동일 열거식으로 표현 가능.

## 5. 코팅×종이두께 제약 (§31 wave-4 연계)

- rule_cd = `R_EXCL_COATING_THIN_PAPER`, rule_typ_cd = **RULE_TYPE.02(금지)**.
- JSONLogic 형태 = 047 verbatim 구조: `{"!":{"and":[{"or":[코팅 유광/무광 sel_opts]},{"or":[thin mat_cd__usage_cd 열거]}]}}`.
- var 계약: `sel_opts`(선택된 opt_cd 배열) + `mat_cd__usage_cd`(결합키, 예 `MAT_000083__USAGE.07`) — [[constraint-builder-contract-demo-260702]] 정합.
- err_msg: "코팅은 두꺼운 종이(180g 이상)에서만 가능합니다. 종이를 180g 이상으로 바꾸거나 코팅을 빼 주세요."
- §31 wave-4가 UI 폼빌더 정형 shape로 재확인·조정할 때 쓸 파라미터:
  - **축1**: 코팅 옵션(유광/무광 opt_cd) — 048/049 각각 생성된 코팅 opt_cd 2개.
  - **축2**: thin 종이 열거(048=15 mat_cd / 049=2 mat_cd) — §4 리스트.
  - 패턴 = C-10 금지형(.02) — RAW 아닌 폼빌더 확인가능 shape.

## 7. AMBIG — 사이즈 + 접지(fold) (미설계·결정 큐)

fold를 어디에 두느냐는 **가격에 영향**하고 권위가 양면적이라 임의 결정 금지:

| 후보 | 근거 | 함의 |
|------|------|------|
| **A. 사이즈에 합성**(권장·047 정합) | 권위 사이즈열이 `A4 (3단접지)` 단일 드롭다운으로 제시 · 047이 사이즈 옵션그룹 미생성(사이즈=차원 직접선택) · fold별 작업사이즈 동일(A4 flat) | product_sizes에 (base×fold) 조합행 필요(048=8, 049=3) = **L1 선적재 GAP**. L2 접지 옵션그룹 불필요. fold 비용=사이즈 가격에 내재 |
| **B. 접지=별도 공정축** | fold 공정 코드 실재(PROC_000060 3단·071 병풍·106 대문·107 반접지) · 권위 "★사이즈선택:A4/A3" = size↔fold 캐스케이드 시사 | 접지 옵션그룹(OPT_REF_DIM.04) + size↔fold 호환 제약 필요. 048은 fold 공정 0건 등록 = 선적재 필요 |

결정 필요(사용자/실무진). **본 설계는 A/B 어느 쪽도 만들지 않음** — 핵심 목적(코팅 제약)에는 불필요하고 잘못 만들면 가격 파손.

## 9. FK 위상정렬 + 적재 순서

1. **선행(L1, 라이브 실재 확인됨)**: product_materials / product_processes / product_print_options — 핵심 레이어 참조 대상 전건 OK.
2. option_groups → options → option_items (apply.sql, 멱등 UPSERT).
3. constraints → (compile) constraint_json.
4. (AMBIG 결정 후) product_sizes 선적재 → 사이즈/접지 레이어.

멱등: 전 INSERT `ON CONFLICT ... DO UPDATE`(복합PK). undo = 논리삭제(del_yn='Y', 물리 DELETE 금지). dryrun = apply를 BEGIN..ROLLBACK 래핑(COMMIT 절대 금지).
