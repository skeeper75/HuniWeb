# RED 특허출원 분석 — 개선·보완·확장·수정·추가 (프린틀리)

> 원천: `docs/redprinting/20200319_레드프린팅_특허출원.pdf`(5p·출원 2020-03-19·베러웨이시스템즈 Shin,Woo-Jin/Charles Shin·Kredix Simon Choi).
> 목적: WebToProduct의 **기술 청구항**을 프린틀리에 어떻게 반영할지. ★4청구항 전부 **결정론 엔진(원칙 3) 영역** — AI/온톨로지는 축 선언·엔진 호출까지, 계산은 엔진(patent가 원칙 3을 실증·강화).
> ★[정정] 이 특허는 **지니(사용자) 본인이 WebToProduct 개발 시 작성·발명자 등재**. 즉 경쟁사 제약이 아니라 **프린틀리의 자산**(직접 활용 가능). §7 재작성.
> ★[정정] 프린틀리 정체 = 후니 내부 시스템 아님. **후니프린팅·와우프레스·레드프린팅 등 여러 벤더 엔진을 연결하는 소상공인 맞춤 AI 인쇄 에이전트(브로커)** = §35 다중브랜드 온톨로지+라우팅의 런타임 실현체. WebToProduct 엔진(지니 특허)을 이 브로커에 연결.

## 1. 특허 4청구항 요약

| # | 청구항 | 요지 | 프린틀리 대응층 |
|---|--------|------|-----------------|
| **C1** | **생산 최적화(생산소요 시간 예측)** | 다량 주문 사전분석→장비 최적 생산계획. 전체 Path 길이·복잡도 계산→**출력 시간 예측**→주문목록 재구성(30분→32분 최적화). 선분 성격(직선 빠름/곡선 느림)·가속도·Cutter Up/Down 시간 | ★리드타임 엔진 + 임포지션/배치 최적화 |
| **C2** | **생산 데이터 최적화(프리플라이트)** | 원본 파일→생산 적합 형태 변형: ①중복객체 제거 ②초소형객체 제거 ③중복 선분/곡선 제거 ④예각→커팅가능 완화 ⑤객체순서=물리 커팅순(롤근접) | ★preflight_function(커팅 특화) |
| **C3** | **장비 가상화(Device Virtualization)** | 이종 장비 동시 지원→**단일 API**. 논리 데이터→장비특성 변환(dpi 254/500/1016·회전·커터/레이저/오프셋·USB/Serial/TCP-IP·오프셋교정·중앙정렬·spooler)→출력. "고도화된 프린터 드라이버" | ★파일변환 엔진 아키텍처(장비·파일포맷) |
| **C4** | **무센서 커팅(Sensorless Cutting)** | 모터 전류 제어(Current Feedback)로 센서·더블슬라이드 없이 압력조절. 기구 단순화 | ✗ 하드웨어(범위 밖) |

## 2. 추가 (Add — 특허가 드러낸 우리에게 없던 것)

### 추가-P1 — 생산 소요시간 예측 엔진 [리드타임 근본]
- **무엇**: C1의 "Path 복잡도→출력시간 예측". 우리 ⑦ 배송 엔티티는 `deliveryLeadTime`(생산 리드타임)을 축으로 뒀으나 **계산 원천이 없었다**(GAP). C1이 그 엔진.
- **프린틀리**: 신규 경계 노드 `production_time_function`(온톨로지=시간 영향 축[복잡도·수량·후가공]·엔진=Path 분석 시간계산). quote_function/routing_function 동형. **리드타임=이 엔진 산출**로 확정 → 배송·라우팅에 공급.
- **경계**: AI/온톨로지는 "시간이 무엇에 달라지나"까지·값=엔진(원칙 3).

### 추가-P2 — 주문 배치/네스팅 최적화
- **무엇**: C1의 "주문목록 재구성"(여러 주문을 장비별로 최적 배치·gang-run/nesting). 우리 임포지션 엔진 범위에 없던 **크로스-주문 최적화**.
- **프린틀리**: `imposition_function` 범위 확장(단일 주문 판걸이 → 다중 주문 배치 최적화). 후니 합판(gang-run)·판걸이수(fn_calc_pansu)와 연결.

## 3. 확장 (Extend — 기존 개념 확장)

### 확장-P1 — 프리플라이트를 "커팅 데이터 최적화"까지
- **무엇**: 우리 `preflight_function`은 일반(재단선·해상도). C2는 **커팅 특화 프리플라이트**(중복/초소형 객체 제거·예각 완화·커팅순 재정렬)를 구체화.
- **프린틀리**: preflight 축에 커팅 데이터 최적화 규칙 추가(도무송/반칼/레이저커팅 상품 특화). "디지털 원본은 다 되나 물리 제한 발생→원본 수정" = 프리플라이트의 본질.

### 확장-P2 — ★파일포맷을 "장비 가상화"로 (덱 매트릭스의 성숙형)
- **무엇**: 덱은 "장비별 파일변환 매트릭스"(N×M raw 포맷)를 보여줬으나, C3은 그 **성숙한 해법=장비 가상화**. 논리 출력 잡 → 가상 드라이버(장비별) → 물리 출력. 통합 시스템은 **단일 API**만 봄.
- **프린틀리 시사(중요)**: ⑥ 파일포맷을 "장비 X는 포맷 Y 요구"의 정적 매트릭스로만 보지 말고, **`logical_print_job` → `device_virtual_driver` → 물리출력** 3층으로. 장비 추가 = 가상 드라이버 1개 추가(전 변환 재배선 X). 파일변환 엔진 아키텍처의 핵심.

## 4. 개선 (Improve — 기존 설계 정밀화)

### 개선-P1 — 파일포맷 엔티티 모델을 논리/가상 2층으로
- 현행(Step1 ⑥): `file_format`이 장비 요구 속성 나열. → **개선**: `logical_output_contract`(논리·장비무관) + `device_profile`(dpi/회전/방식/포트/변환규칙·C3 속성) 분리. 온톨로지=이 축 선언·값변환=가상화 엔진.
- 이유: 덱 매트릭스(raw)보다 C3 가상화(추상)가 확장·감사에 유리. search-before-mint상 CIP4 DeviceCapabilities와 정합.

### 개선-P2 — 임포지션/프리플라이트를 Path/객체 레벨로
- C1/C2는 페이지가 아니라 **Path·객체 레벨** 처리(선분 복잡도·객체 순서). preflight/imposition 경계 노드 정의에 "객체/Path 단위" 명시 → 커팅·후가공 정밀도.

## 5. 보완 (Complement — 빈틈 채움)

- **보완-P1**: ⑦ 배송 `deliveryLeadTime`의 계산 공백 → 추가-P1(생산시간 예측 엔진)이 채움.
- **보완-P2**: 라우팅(장비/인쇄소 결정)에 **시간·복잡도 기준** 부재 → C1 시간예측 + C3 가상화가 "어느 장비가 이 잡을 몇 분에" 판정 근거 공급. routing_criterion에 `production_time` 축 추가.

## 6. 수정 (Modify — 방향 교정)

- **수정-P1**: ⑥ 파일포맷을 "N×M 포맷 매트릭스"(덱)로 확정하려던 것을 **"논리 API + 장비 가상화"(C3)로 교정.** 매트릭스는 가상화 드라이버 내부 구현 세부지, 온톨로지 1급 모델이 아님. (개선-P1과 짝.)

## 7. IP = 지니 자산 [정정]

- ★이 특허(WebToProduct 최적화)는 **지니 본인이 발명·등재**. 즉 프린틀리가 **직접 활용할 수 있는 자산**이다(경쟁사 제약 아님). C1 시간예측·C2 커팅 프리플라이트·C3 장비가상화·C4 무센서커팅 = 지니 WebToProduct 엔진의 검증된 방법.
- **프린틀리 구조상 위치**: 프린틀리(브로커·AI 에이전트) = 온톨로지 오케스트레이션. 그 아래 **벤더별 엔진**을 연결 —
  - **후니프린팅** = evaluate_price(견적)·후니 생산.
  - **와우프레스** = jobcost API(견적)·와우 생산.
  - **레드프린팅** = 레드 견적·**지니 WebToProduct 엔진**(C1~C3 최적화·장비가상화)로 생산.
  - 각 벤더 엔진은 각자 소유·계약이나, **지니 WebToProduct 엔진 방법(이 특허)은 지니 것**이라 프린틀리·연결 벤더에 자유 적용 가능.
- **경계(원칙 3 유지)**: 벤더가 누구든 온톨로지·에이전트는 **견적/프리플라이트/시간예측/파일변환을 판단하지 않고 각 벤더 엔진을 호출**. 값·최적화=엔진 권위(§35 D-18 브랜드별 quote_function·D-ROUTE 동형).
- **표준 병행**: 지니 엔진 외 부분(신규 벤더 연결·상호운용)은 CIP4 JDF/DeviceCapabilities·Ghent GWG 표준 어휘로(search-before-mint).

## 8. 프린틀리 반영 요약 (우선순위)

1. **개선-P1 + 수정-P1 (파일포맷=논리/가상 2층)** — ⑥ 엔티티 모델 교정. 덱 매트릭스 → C3 가상화. 확장·감사 유리.
2. **추가-P1 (생산시간 예측 엔진=리드타임)** — ⑦ 배송·라우팅의 시간 축 근본. 신규 경계 노드.
3. **확장-P1 (커팅 특화 프리플라이트)** — 도무송/반칼 상품 정밀.
4. **지니 특허=프린틀리 자산** — 벤더별 엔진 연결(후니/와우/레드), 지니 WebToProduct 엔진(C1~C3) 자유 활용. 온톨로지는 벤더 무관·엔진 호출까지(§35 브랜드별 엔진 경계).

## GAP
- G-PAT-1: 특허 **출원서 요약본**(5p·다이어그램) 수준. 정식 청구항 전문·등록 여부·청구범위 정밀 경계는 KIPRIS 등 원본 확인 필요(IP 판단 전 필수).
- G-PAT-2: C1 시간예측 알고리즘 상수·C3 가상화 API 스펙 상세 비공개(형태까지).
- G-PAT-3: 이 반영은 **엔진 설계 방향**까지. 실 엔진 선정(표준/상용/자체)은 후속·법무 병행.
