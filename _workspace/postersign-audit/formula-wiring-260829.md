# 공식↔가격구성요소 배선 검증 — 디지털인쇄 과소청구 20상품 (2026-08-29)

M4-27. 지니 지적에서 출발했다 — 「계산공식초안에 맞게 가격구성요소와 가격공식이 매핑되어 있는지가
**전제**이고, 확인만 하고 넘어가면 **그 공식에 연결된 모든 상품이** 무너진다」.

그 전제를 검증하자 **인쇄물 20상품에서 인쇄비가 통째로 빠지는 과소청구**가 나왔다.
라이브 읽기 전용 (가격조회·설정조회) · 쓰기 0.

## 0. 내가 순서를 거꾸로 밟았다

M4-21~26 은 전부 **「단가 값이 권위와 같은가」**를 봤다. 그 앞에 **배선**이 있다 —
배선이 어긋나면 값이 맞아도 가격이 안 나온다. 그리고 공식은 여러 상품이 공유하므로
**하나가 어긋나면 그 공식 쓰는 상품이 전부** 무너진다.

M4-25 에서 찾은 결함 A(마감 필수 옵션 단가행 없음 → 주문 차단)가 이미 그 형태였는데,
나는 2상품 문제로만 적고 넘어갔다. 그리고 **가격 설계의 정본인 「계산공식집초안」 시트(첫 시트)를
이번 세션에 한 번도 열지 않았다.**

## 1. 권위 — 계산공식집초안

상품군마다 유형(원자합산형 / 고정가형)과 **판매가 전개식**이 적혀 있다.

```
[원자합산형: 프리미엄엽서 / 코팅엽서 / 스텐다드엽서 / 투명엽서 …]
판매가 = 인쇄비 + 코팅비 + 용지비 + 후가공비 + 추가상품
  (1) 출력매수 = 주문수량 / 판걸이수        [판걸이수]
  (2) 인쇄비(4도) = [수량행단가] x 출력매수   [디지털인쇄비]
  (3) 별색인쇄비 …  (4) 코팅비 …  (5) 용지비 …  (6) 후가공비 …
```

**핵심**: 전개식 어디에도 「공정을 고른다」가 없다. **인쇄비는 무조건 붙는 항목**이다.

## 3. 실측 — 위젯 축만 vs 필수공정 추가

가장 반박하기 어려운 형태로 쟀다. 상품마다 두 번 부르고 **차액**을 본다.

- `base` = **위젯이 노출하는 축만** (고객이 실제로 만들 수 있는 조합)
- `with` = `base` + 그 상품의 **필수 공정**(`mand_proc_yn='Y'`) `proc_cd`

프리미엄엽서 105장 · 같은 조합:

```
위젯 축만        → total=424    components=[용지비 424]
+ proc_cd 추가   → total=9,424  components=[디지털인쇄비 9,000, 용지비 424]
```

**위젯은 `proc_cd` 를 노출하지 않는다**(축 = `siz_cd` · `mat_cd` · `print_opt_cd` · `qty`).
고객이 줄 방법이 없으므로 **위젯으로 주문하면 인쇄비를 내지 않는다.**

## 4. 원인 — 구조 차이 하나로 갈린다

| 계열 | 본품 구성요소 `use_dims` | 결과 |
|---|---|---|
| 실사·포스터 (정상 91쌍) | `["siz_width","siz_height","min_qty"]` — **`proc_cd` 없음** | 위젯 축만으로 매칭 |
| 스티커 (정상) | `["siz_cd","mat_cd","min_qty"]` — **없음** | 매칭 |
| **디지털인쇄 (결함 20)** | `["proc_cd","plt_siz_cd","print_opt_cd","min_qty","proc_grp:PROC_000001"]` | **매칭 실패** |

`COMP_PRINT_DIGITAL_S1` 단가행 **625행 전부 `proc_cd` 를 갖는다** — `proc_cd` 없이 매칭될 행이
**하나도 없다.** 그런데 위젯은 그 축을 주지 않는다.

그리고 엔진은 이 미매칭을 **에러로 막지 않는다** — 해당 구성요소만 빠진 채 `ok:true` 로 합계를 낸다
(M4-26 §3 에서 이미 관측된 성질). 그래서 **조용히 싼 값이 나간다.**

### 판별식 — 「필수인데 안 붙는 것」만 결함이다

간극 축 자체는 넓다(전 게시 192 중 70상품 · 282 구성요소 · `proc_cd` 229 · `coat_side_cnt` 36 …).
그러나 **선택형 후가공**(오시·미싱·귀돌이)은 고객이 안 골랐으니 **안 붙는 게 정상**이다.
결함은 `mand_proc_yn='Y'` **필수 공정이 안 붙는 경우**로 좁혀지며, 그것이 위 20건이다.

## 5. 해결 방향 (권고 — 실행 안 함)

권위 전개식에 「공정 선택」이 없다는 점이 방향을 정한다. **인쇄 방식은 고객 선택 사항이 아니다.**

| 안 | 내용 | 평가 |
|---|---|---|
| **B. 엔진이 필수 공정을 자동 주입** | `mand_proc_yn='Y'` 공정을 서버가 `selections` 에 채운 뒤 계산 | **권고.** 권위와 맞고, 위젯·데이터를 건드리지 않으며, 20상품이 한 번에 닫힌다 |
| A. 위젯이 `proc_cd` 를 노출 | 고객에게 인쇄방식을 고르게 함 | 권위에 없는 선택지를 만든다. 필수 1종뿐이라 UI 낭비 |
| C. `use_dims` 에서 `proc_cd` 제거 | 단가행도 `proc_cd` 무관하게 재적재 | 인쇄방식이 둘 이상인 상품에서 축이 필요해질 수 있어 위험. 625행 재적재 부담 |

어느 안이든 **개발자 판단이 필요한 코드/데이터 변경**이며, 이번 SPEC 은 **진단까지**다.

**부수 권고**: 엔진이 「필수 구성요소 미매칭」을 조용히 넘기지 말고 **에러로 막거나 경고**해야 한다.
지금은 과소청구가 정상 응답으로 나간다.

## 6. 미검증

- `BASE-FAIL 11건` — 위젯 축만으로는 기준가조차 안 나오는 상품. 별도 확인 필요
- API 가 `proc_cd` 를 **하나만** 받아, 필수 공정이 여럿인 상품의 **합산 누락액**은 재지 못했다
  (각각 따로 잰 값만 있다)
- 위젯이 실제로 보내는 payload 는 직접 캡처하지 않았다. 위젯 **설정 API 의 노출 축**을 근거로 삼았다
- 20건의 누락액은 **각 상품 첫 사이즈·첫 자재·수량 1(또는 최소단위)** 기준이다. 실제 주문 분포와 다르다
