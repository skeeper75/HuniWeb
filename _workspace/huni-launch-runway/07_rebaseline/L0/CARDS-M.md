## 지니가 준 구조 사실 (조사 전제 · 재확인 불요)

1. `huni-skin-shopby` = 쇼핑몰 웹사이트 **전반 구현부**.
2. `raw/webadmin` = **위젯**이 구현된 곳. 위젯에 **상품 구성요소 + 가격 구성요소가 결합**돼 있고, **파일업로드·Edicus 기능이 위젯에 포함**된다. 상품에서 **편집 버튼을 누르면 Edicus 가 동작하도록 이미 구현**돼 있다.
3. **이 위젯이 임베딩되어 들어가는 곳이 쇼핑몰이다.**
4. 쇼핑몰 ↔ webadmin 은 **SDK 와 API 로 리소스를 공유**한다. **이 부분은 webadmin 매뉴얼에 자세히 있다.**
5. 전체 코드+DB 가 결합되어 보이는 사이트 = **환경변수에 있는 webadmin 사이트**. 거기서 실제 동작을 확인할 수 있다.
6. 쇼핑몰은 **shopby(NHN 헤드리스 커머스)** 를 **server API** 로 연동한다.
7. **MES 가 별도 시스템으로 있다.** 위젯에서 **생산에 관한 자재와 공정을 전달**하면 MES 가 그에 맞게 **생산지시**를 하고, 이후 생산 프로세스대로 진행되며 **상태값을 서로 주고받으며** 처리한다.
8. **프리플라잇**(접수 전 PDF 검사) 아키텍처가 필요하다 — 파일업로드된 PDF 를 접수 전에 검사한다.
9. 인쇄데이터 → 생산 → **전체 공정라우트** → 포장 → 고객 배송.
10. 이 영역은 지니 + 서희항 대표(위젯 개발)가 레드프린팅에서 총괄시스템을 개발한 경험으로 **할 수 있는 영역**이지만 **리스트에는 나와야 한다**.

## M1 — 위젯 본체 (`plan-huniweb`)

**질문**: 위젯은 고객에게 무엇을 시키고, 무엇을 만들어내며, 그것을 어디로 넘기는가.

**순서 [HARD] — 어기지 마라**
1. **webadmin 앱 내장 매뉴얼 2종 정독이 첫 단계다.** 코드를 먼저 열지 마라.
2. 라이브 webadmin 사이트 접속 → 위젯 실동작 관찰(상품 하나를 끝까지 몰아보되 **주문 직전에 멈춰라**).
3. 그다음 코드(`raw/webadmin/webadmin/catalog/` widget 관련)로 매뉴얼·실동작을 뒷받침.

**조사 축**
- 위젯의 **상품 구성요소 ↔ 가격 구성요소 결합 구조** — 고객 선택이 어떻게 가격으로 닿는가
- **파일업로드** 전 경로 — 어떤 파일을, 어떤 검사를 거쳐, 어디에 두는가(S3), 언제 무엇이 막히는가
- **Edicus 편집** 전 경로 — 편집 버튼 → 무엇이 열리고 → 무엇이 돌아오는가(prjid 등) → 그것이 주문에 어떻게 실리는가
- 위젯이 **생산용으로 만들어내는 것** — 자재·공정 정보가 어떤 형태로 나오는가 (**M3 의 입력이다 · 반드시 특정하라**)
- 위젯이 쇼핑몰로 넘기는 것 — handoff 토큰·`huni_order` 스키마의 실제 필드 전수
- 위젯 버전·사이트키·게시 상태가 무엇을 좌우하는가

**산출** `L0/M1/`: `widget-anatomy.md`(위젯 해부) · `customer-journey.md`(고객이 겪는 단계 전수) · `artwork-flow.md`(업로드·편집 경로) · `production-payload.md`(★생산으로 넘기는 자재·공정 데이터 명세 — M3 인계) · `l0-corrections.md` · `progress.md`

## M2 — 연동 계약 3종 (`run-huniweb`)

**질문**: 세 시스템이 서로 무엇을 약속하고 있는가. 그 약속이 깨지면 무엇이 무너지는가.

**조사 축 — 계약 3종**
- **C1 쇼핑몰 ↔ webadmin (SDK + API)**: SDK 가 무엇을 제공하는가, `/api/w/v1/*` 27 엔드포인트 각각의 계약(요청·응답·인증·멱등·실패), 리소스 공유가 실제로 무엇을 공유하는가
- **C2 쇼핑몰 ↔ Shopby (server API)**: 헤드리스 연동 구조, 무엇을 Shopby 원장에 맡기고 무엇을 우리가 갖는가, `optionInputs` 우회의 전모
- **C3 접점 6가지 확정**: handoff 토큰 스키마 · `optionInputs` 규약 · `orderCnt=총액÷10` 규칙 · `order/register` S2S · shopby webhook · 토큰 만료/재견적. **지금까지 어느 항목에도 안 잡혀 있던 것들이다 — 별도 항목으로 세워라.**

**반드시 답할 것** — lead 미확인으로 남긴 돈 걸린 질문:
- **Shopby 쿠폰·적립금·배송비가 「10원 상품 × N」 구조와 충돌하는가?** 충돌하면 얼마가 어떻게 틀어지는가

- 게스트(비회원) 구매가 이 브리지 위에서 성립하는가

**순서 [HARD]**

**조사 축**
- **MES 인계**: 위젯이 넘기는 자재·공정(M1 `production-payload.md` 가 입력) → MES 가 받는 형태 → **생산지시** 발행. 인계 방식(API? 파일? DB?) · 인증 · 실패 시 · **미구현이면 미구현이라고 판정하라**

- **★프리플라잇**: 업로드된 PDF 를 **접수 전에** 검사하는 구조. 무엇을 검사하는가(재단선·블리드·해상도·폰트·색상·페이지수) · 어디서 도는가 · 실패 시 고객에게 무엇이 보이는가 · **현재 구현 여부**. `aws-architecture-huni.pdf` 에 인프라가 있을 수 있다
